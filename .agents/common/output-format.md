# 输出与沟通规范（通用）

## 语言与风格

- 中文回复。
- 先结论/方案，后细节；关键决策附理由。
- 不堆术语，不写空话。

## 长文落盘（强约束）

- 任意超过 300 字的结构化产出（PRD / 架构方案 / 评审报告 / ADR / 测试报告 / 用例集），**写文件**，不要贴在消息里。
- 消息只回：`路径 + ≤150字摘要 + 结论/阻塞`。
- **引用而非复制**：派发/评审一律给路径（如 `docs/prds/<file>.md#<section>`），禁止把长文全文或附件推进线程——接收方自己读文件，发起方上下文不留副本。

## 检查清单

- 交付前自查清单。
- 汇报时**只报未过项**：`未过：R-XX-03；其余 pass`。
- 禁止逐条复述全部通过项。

## 消息模板（通用）

```text
[编号/主题] | to=<会话> | role=<角色> | repo=<路径>
范围：做 X；不做 Y
引用：docs/...md#section（禁止贴全文）
交付：<产物类型>；长文落盘路径
回执级别：lite（默认）| full
摘要：≤150字
阻塞/决策点：<无 或 列出>
```

## 回执模板（通用，两级）

**派发时由 PM 声明回执级别，未声明默认 `done(lite)`。** 前缀 `[编号] done` 不变（PM 追讨与红线均按 `done` 匹配），括号内为级别。

### done(lite)：默认——无阻塞、无风险的常规任务（单行）

```text
[编号] done(lite) | <role> | 清单：未过<项 或 无> | 测试：<命令> exit=<n> <文件数>/<例数>/<红数> | 变更：<f1,f2（>3 个写前 3 + "等 N 个"）> | 详情：docs/reports/<编号>.md
```

### done(full)：出现阻塞/风险/需决策，或 PM 指定

```text
[编号] done(full) | <role>
摘要：≤150字
清单：已核对 checklists/<role>.md；未过：<项 或 无>
变更：<文件/模块级>
测试：<命令 + exit code + 文件数/例数/红数（或错误数）>
风险/阻塞：<无 或 列出>
详情：<路径>
```

**两级通用硬性**：

1. 回执即声明已读 `checklists/<role>.md` 并逐项核对（未过项必须列出）——**未核对不回执**。
2. 「测试」必须给**全量门禁精确数字**（命令 + exit code + 文件数/例数/红数或错误数）；只跑子目录或只写「pass」不算回执 —— PM 打回（见 intercom-protocol「终态回执」）。
3. **有阻塞/风险/需决策 → 必须 `done(full)`**，`lite` 不得吞掉需 PM 拍板的事。
4. 详细全文落盘 `docs/reports/<编号>.md`，**禁止**把长报告贴进线程。

## 反模式（禁止）

- 在消息里粘贴角色卡/PRD/输入信封全文。
- 复述需求原文而非结论与差异。
- 把长报告直接 `send` 污染线程历史。
- 汇报时逐条罗列全部通过项。

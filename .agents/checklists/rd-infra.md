# 工程基座红线与交付检查清单

> 角色卡只常驻最硬红线；本文件在**交付前**读取并逐项核对。
> 汇报只报未过项：`未过：I-XX-03；其余 pass`（见 output-format）。

## 硬性红线（完整 8 项）

- [ ] 仓库内无密钥/机器特定值（token、私钥、绝对家目录路径）
- [ ] 脚本/迁移/安装器**幂等**（连跑 2 次 effect = 0 且 rc = 0）
- [ ] 新增 CI 权限/scope/Secret 逐项给出「为什么必需」，无 `*`/admin
- [ ] 守卫/校验带**失败演练**（破坏 ⇒ 报错 ⇒ 还原复绿）
- [ ] **不自验自己的守卫**（验收由 `qa`/`pm` 独立执行）
- [ ] 不写死仓库名/相对路径/包管理器（跨项目兼容）
- [ ] 未改项目 `AGENTS.md` 红线、业务源码/测试断言、他人未提交文件
- [ ] 全范围门禁 rc=0 且回执**精确数字**（命令 + exit code + 条数/文件数）；**计数类数字（用例数/断言数/`files=`/行数）取数命令单源见 `tests/README.md`「取数命令四条」**（本清单不复写命令），回执须带 **HEAD sha + 静默工作区**（`git status --porcelain` 空 + 无并行会话同 worktree 跑门禁），缺项则该数字不作验收依据

## 幂等 / 权限 / 自证 速查

- **幂等自证**：`cmd; cmd` ⇒ 第 2 次 effect = 0、rc = 0、无重复条目。
- **权限最小化**：每条权限/Secret 一句「为什么必需」；能只读就不写，能给单仓就不给组织级。
- **三段证据**：正常 rc=0 · 故意破坏 rc=1 并报出该项 · 还原后复绿。
- **对照数字**：每项给「改动前 → 改动后」（耗时/体积/条数/宽度…）；单跑不算。
- **敏感值**：日志/回执不输出 secret/token；错误体截断。

## 实现纪律核对（M20261107 · 交付前逐条勾 · 执行者：rd-infra）

> **本批不适用的项写「不适用：<一行理由>」；留空或硬勾均视为未完成**（依据 `deliverable-docs.md §三`）。
> 依据：`#84` P1 / `#86` P1 / `#86` P3-1 / `#88` P3-③ / `#90`（标题通道竞态）。**先定性再给修法**：能复现的失败机制写清后，才谈改动。

- [ ] **数据通道**：跨 shell / 跨进程传值走**文件 / 参数 / 返回值**；调用方在子 shell 内时**禁插值全局**（否则 `set -u` 下中止 ⇒ SKIP 变 FAIL）
- [ ] **各态 wired 断言**：成功 / 失败有输出 / 失败无输出 / 无凭据 / 超时 五态各有断言，结果只能是 SKIP 或 PASS；每态都做过一次「造该态 ⇒ 得该结果」的实跑
- [ ] **断言作用域 + 变异自证**：断言写明作用域并在交付物里给「改空 / 改错 ⇒ 必红」的变异运行记录（自证跑过，不是声称）
- [ ] **新增/改 lint 或守卫：输出确定性** —— 多条命中按 **`文件:行号` 排序**输出（幂等、可 diff），不依赖遍历顺序 / 时间戳 / 并发完成序
- [ ] **不做顺手改**：需要把某条纪律机制化（改脚本 / 测试）时**另立任务**，不在文档批里夹带

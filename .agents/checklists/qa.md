# 测试工程师红线与交付检查清单

> 角色卡只常驻最硬红线；本文件在**交付前**读取并逐项核对。
> 汇报只报未过项：`未过：R-XX-03；其余 pass`（见 output-format）。

## 硬性红线（6 项；其余并入下方交付清单，不在此复制）

- [ ] 私自修改现有功能代码？
- [ ] 未经用户确认就执行测试？（执行前先列清单，经用户 / PM 开工确认卡圈定范围）
- [ ] 测试未通过就允许发布？（含回归：冒烟 + 受影响用例；未过未放行）
- [ ] 使用生产数据测试？（须脱敏/测试数据；**环境版本须记录**）
- [ ] 未跑**全范围门禁**（不是子目录）并回执精确数字？（PM 不重复跑，回执数字即验收唯一依据；全范围口径见项目 `AGENTS.md`；**计数类数字（例数/文件数/断言数/行数）取数命令口径单源见 `tests/README.md`「取数命令四条」**，不以最大编号推断；回执须带**三件套**（定义单源见 @.agents/common/output-format.md「回执硬性」第 3 条），缺任一项该数字不得作验收依据）
- [ ] 视觉/UI 呈现类验证未按「视觉验收四判据」逐项勾（声明视口 / 截图或降级理由 / 空·加载·错误态 / 2 秒测试）？（**人工 / 系统截图（不含无头浏览器自动化）可作验收证据；本仓不做浏览器自动化 / 截图 diff 对比** —— 口径见 skills/test-design.md；无能力按 BR4 降级写「未验证实际视觉」；用户验收清单仍须产出）

## 视觉验收四判据（判定**细目**只在 @.agents/skills/design-loop.md §六；本节只留可勾项）

> 四项**逐项勾选**，不允许合并成一句「视觉已验」；无法勾的项写「不适用 + 一行理由」。人工/系统截图可作证据，本仓不做浏览器自动化与截图 diff。

- [ ] **① 声明视口**（细目见 design-loop §六）
- [ ] **② 截图或降级理由**（同上）
- [ ] **③ 空 / 加载 / 错误态**（同上）
- [ ] **④ 2 秒测试**（同上）

## 复核「可执行性」核对（M20261107 · 每次复核逐条勾 · 执行者：QA）

> **本批不适用的项写「不适用：<一行理由>」；留空或硬勾均视为未完成**（依据 `deliverable-docs.md §三`）。
> 判据是「这条纪律**能否被机械执行**」，不是「文档里有没有写」（依据：`#86` P3-1 / `#88` P3-③ —— 两次都是文案声称收紧、实测仍整段匹配）。

- [ ] **数据通道**：被测实现的数据传递确实走**文件 / 参数 / 返回值**（读了实现代码确认，未依赖全局）；子 shell / 子进程场景实跑过
- [ ] **各态 wired 断言**：五态（成功 / 失败有输出 / 失败无输出 / 无凭据 / 超时）各有一条断言，且结果是 **SKIP 或 PASS**（**不得 FAIL 或中止**）；缺态即判不合格
- [ ] **断言作用域**：断言文本能指出作用域（整段 / 某行 / 某字段）；对「某行 / 某字段」的断言，抽一条实测「让该字段不匹配」仍绿即为不合格
- [ ] **变异自证**：交付物含「改空 / 改错 ⇒ 必红」的变异运行证据（自己复跑一次，不只看回执抄录）

## 交付检查清单（完整 18 项）

- [ ] 测试计划含范围与风险评估（测什么/不测什么）
- [ ] 用例覆盖等价类/边界/主路径/异常，且可追溯 AC
- [ ] 接缝确认已作为 PRD 阶段输入：PM 列候选 → QA 确认/修正 → 写入 PRD「AC」首行，用例按确认后的接缝组织
- [ ] 分层测试与 DDD 分层对齐
- [ ] 缺陷全量入库、信息完整、生命周期闭环
- [ ] 测试报告含统计、遗留风险、发布建议
- [ ] 造数/探针类测试：回滚清单**覆盖全部业务表**（**无外键时无级联兜底**，须按项目实际表逐一列出）+ 收尾跑**通用孤儿扫描**（逐表按项目实际的用户表/外键列执行 `<fk_col> NOT IN (SELECT id FROM <user_table>)`，如 `user_id NOT IN (SELECT id FROM users)`）并**附逐表数字**作为门禁
- [ ] UI 四态（加载/空/错误/成功）与反馈模式按 UX Playbook 核对；无硬编码色值残留（rd-fe 侧已扫）
- [ ] UI 呈现类交付：用户验收清单已产出（最低覆盖集按范围取用，每项含 测什么/怎么操作/预期结果/对应 AC），落**任务目录**的 `user-acceptance.md`（约定见 @.agents/checklists/deliverable-docs.md §十），回执附路径
- [ ] 环境/运行方式按 AGENTS.md；已遵守项目约束
- [ ] PR 评论已贴全量门禁精确数字 + 预览环境结论（**攒批口径**：每批 2–3 个任务跑一次全量 + 逐任务目标用例，发版前必跑；2026-11-26 用户拍板）
- [ ] 未在 PM 验收通过前以「测试已过」催促合并（合并由 RD 在 PM 授权后执行）

# 交付文档写作规范（写文档前 / 交付前读取）

> 适用：PRD、ADR、评审报告、测试报告、调研报告、发布说明、任务回报（写进 `docs/` 的长文）。
> 不适用：派发消息与回执（格式固定、必须短，见 @.agents/checklists/comm-templates.md）。

## 一、四条原则

1. **默认读者是「接手的人」**：他要的是**结论 / 约束 / 怎么验收 / 证据在哪**，不是你的思考过程。
2. **首屏给结论**：前 20 行内必须有 TL;DR（目标 · 结论 · 影响 · 待办）——只看首屏也能行动。
3. **写决策不写过程，写差异不复述**：与代码 / 上游文档重复的内容一律用指针（`路径#小节`）。
4. **超预算就删，不是加长**：每份文档有长度上限；超了先删「常识 / 过程 / 全量罗列」，仍超才另附文件。

- **PRD**：上限 ≤150 行；必须留下 9 模块结论、范围/非范围、AC；禁止 抄竞品原文、贴代码；**非范围必带理由**。模板见 `@.agents/templates/prd.md.example`。
- **ADR**：上限 ≤60 行；必须留下 决策、对照模式、参考来源；禁止 大段代码、教程式背景。
- **评审报告**：上限 ≤60 行；必须留下 可行性、风险、取舍、待拍板点；禁止 复述 PRD。
- **测试报告**：上限 ≤80 行；必须留下 范围、结果数字、缺陷、风险、建议；禁止 日志/截图全文。
- **调研报告**：上限 ≤120 行；必须留下 结论摘要、来源、适配三栏；禁止 无来源断言。
- **设计报告**：上限 ≤80 行；必须留下 9 项骨架（信息架构 / 流程 / 视觉规范 / token / 状态 / 断点 / 可用性 / 无障碍 / 降级产物）+ 降级档位 + 逐条 AC 结论；禁止 贴实现源码、把「缺工具」写成阻塞、写真实实例 URL/凭证。骨架与禁写清单见 §九。
- **发布说明**：上限 ≤60 行；必须留下 版本号、**用户可读**行为变化、升级/回滚说明；禁止 复述提交日志全文、纯编号/类名。写法见 @.agents/common/release-notes.md。
- **任务回报**：上限 ≤50 行；必须留下 变更清单、门禁数字、未过项、风险；禁止 复述需求、贴 diff。
- **用户验收清单**：上限 ≤40 行（执行步骤可附后续详细清单文件）；**必须留下** 覆盖项（测什么/怎么操作/预期结果/对应 AC）+ 回填栏；禁止 内部术语、自动化断言（读者 = **最终用户**）。写法见 @.agents/skills/test-design.md「视觉/UI 呈现验证」，模板见 `templates/user-acceptance.md.example`。

**一律下沉**（写进正文就违规）：全部用例（测试）、方案全文与压测数据（ADR）、抓取正文（调研）、背景长叙与竞品原文（PRD）、通过项罗列（报告类）——需要时另存文件给指针。

## 二、通用骨架（每份文档都要）

```text
# <标题>
- 状态：草稿 / 待确认 / 已定稿 · 更新：YYYY-MM-DD · Owner：<角色>
- 指针：上游 PRD / 关联 ADR / 调研报告（路径）
```

- 结尾一行修订：`- 修订：YYYY-MM-DD <一句话>`；**只在结论变化时新增**，不记措辞调整。
- 压缩对比**优先用列表**；引用代码用 `path/file.ext:12`，**不贴代码块**（超过 10 行必改引用）。
- **确需表格时**（例外与判据见 §七）：列数 **≤4**、行数 **≤5**；单元格只放短结论（约 ≤20 字），长内容下沉为列表；**消息/线程里表格 ≤3 列**（否则终端折行错乱）；表内不放代码块。
- 术语首次出现给半句话解释；中文；不写「我们认为 / 如上所述 / 众所周知」。

## 三、PRD（9 模块不删，每项设上限）

> 9 模块是**验收闸门**，不得删；简洁靠「每项 1–3 句 + 允许不适用」实现。

- 首屏 TL;DR（≤5 行）：做什么 · 给谁 · 成功标准 · 不做什么
- 9 模块：**每模块一小节**，内容用列表承载（**不用表格**）；每项 **≤3 句 / ≤60 字**；不适用项写「不适用：<一行理由>」，**不许留空、不许写废话**
- **非范围必带理由**：每条非范围后跟一行理由（即写「不适用」也要给理由），否则视为未完成
- **表格适用范围（T580 边界，防两规矩打架）**：**卡片与台账可用表格** —— 开工确认卡（`kickoff.md`，10 字段两列）、`docs/tasks-state.md`（批次索引表 / 6 列卡摘要表）、清单类结构；**`prd.md` / 报告 / ADR 的正文仍禁表格**（改用列表 + 加粗字段名）。机判：新布局 `docs/<任务号>-*/prd.md` 正文出现表格 ⇒ 结构探针点名（历史 `docs/prds/` 不追溯）；`kickoff.md` 与台账用表格 ⇒ 不报违规（`tests/t4/cases/54` 两向钉住）。
- **AC 必须按五覆盖分组**（主路径 / 异常 / 边界 / 负向闭环 / 设计一致性）：**缺组 = 结构性缺失**，不是排版问题；某组不适用 ⇒ 组内写「不适用：<一行理由>」，**不得删组**。
- **`###` 阈值规则**：`###` 仅在某模块 **≥4 条 或 ≥10 行** 时使用，否则保持纯列表。为什么：PRD 上限 150 行，全铺三级标题会吃掉约 24% 预算（每级标题 ≥2 行空白），且 4 行以内的短模块被标题切成碎片反而难读。**例外**：§七 AC 恒用 `###` 五组（结构性分组，不受阈值约束）。
- AC 逐条 Given/When/Then，一条一行
- 推演细节（RICE 打分过程、5 Whys 展开、同类产品调研明细）落**任务目录**的 `research.md`（或 `<topic>-调研.md`）或附录，**正文只留结论 + 指针**（目录约定见 §十）
- **⛔ PRD 正文不使用表格** ⇒ 改用**有序 / 无序列表 + 加粗字段名**（如 `- **版本**：1.12.3`）。最常被误写成表格的三处：**需求清单（用户故事 / 条目）· 验收标准（AC）· 范围 / 非范围**。

## 四、ADR（≤60 行，按 `wc -l` 全文）

```text
背景(≤5 行) → 决策(1–3 句) → 理由(四步法要点，每点一行) → 对照模式清单(模式/适用条件/代价/不采纳理由)
→ [后果与风险] → [限制与已知边界] → [相关指针] → 参考来源(链接 + 访问日期，恒末节)
```

- **必写 5 节**：`## 背景` / `## 决策` / `## 理由` / `## 对照过的备选模式` / `## 参考来源`；**可选 3 节**：`## 后果与风险` / `## 限制与已知边界` / `## 相关指针`。标题逐字、不编号、顺序固定（`参考来源` 恒为末节）。
- **头部恰 4 字段**：`状态` / `更新` / `Owner` / `指针`；`出具日` = 文件名日期前缀（不单设字段），`落地版本` = `状态` 值（不单设字段）。
- **状态值域 4 值**：`提议` / `已接受（待落地）` / `已接受（已落地 vX.Y.Z）` / `已废弃（被 <yyyy-mm-dd-slug> 取代）`（本仓 ADR 无编号，禁 `ADR-N` 写法）。
- **禁写 / 下沉清单**（写进正文即违规，一律另存**同任务目录**的 `arch-review.md`）：实施闸门 / 接线清单 / 交接实现 / 判定式全文 / 用例集。**边界优先于上限**：超长先下沉，不放宽 60 行。
- **出具日**：历史 ADR = 文件名日期前缀（`docs/adr/YYYY-MM-DD-<主题>.md`）；**任务目录内的 `adr-<topic>.md` 无前缀 ⇒ 出具日 = 索引「决策时间线」那一行的日期**（§十）。
- 骨架唯一载体（单源）：@.agents/templates/adr.md.example；模式对照法见 @.agents/skills/arch-patterns.md；索引骨架见 @.agents/templates/adr-index.md.example。

## 五、测试报告（≤80 行）

```text
范围 / 不测 → 环境与命令 → 结果（用例数 / 通过 / 失败 / exit code）→ 缺陷表（严重度/复现/影响/状态）
→ 未覆盖与风险 → 发布建议
```

- **用例集单列文件**（任务目录内 `cases.md`，约定见 §十）；报告只放汇总与失败项。
- 通过项不逐条罗列，写 `未过：无` 即可。

## 六、调研报告（≤120 行）

```text
结论摘要(≤5 行) → 清单表(项目 × 纳入 × 依据) → 来源([标题](URL) · 访问 YYYY-MM-DD · 一句话结论)
→ 适配三栏(它解决什么/适用条件/本项目差异) → 未检索到项
```

- 抓取正文**不进正文**；协议与边界见 @.agents/skills/research.md。

## 七、排版：默认不使用表格

- **默认不用表格**：内容一多就难以阅读（列被挤压 / 需横向滚动 / 移动端尤甚），且在 **diff 中难以审阅**。
- **适用文档类型（全角色文档产物）**：**PRD** · ADR · 评审 / 测试报告 · 调研报告 · 发版说明 · 评审回执 · `tasks-state` · 缺陷池 · **用户验收清单** 等 —— 一视同仁。
- **首选替代**：有序列表 / 无序列表（首选）· 分级小标题 · **加粗字段名 + 正文**（`- **版本**：1.12.3`）· 引用块（注意事项）· 代码块（命令 / 配置）。
- **允许表格的例外（窄口径，须给判据）**：① **严格二维对照**且**规模很小**（建议 **≤5 行且 ≤4 列**）；② **逐列比较**确有必要（如版本对照、参数矩阵）且**读者需要并排比较**；③ **机器可读 / 需被解析**的结构化清单 —— 含 **③b `docs/README.md` 的三段索引表**（行数不限、列数 ≤4，表头逐字即机读契约，见 §十）。
- **表格若必须用 ⇒ 硬要求**：列数少 · 单元格短（⛔ 不塞长句 / 多段）· 表头自解释 · ⛔ **不得用表格承载「需要解释的推理 / 因果」**。
- **不追溯改写历史文档**：本规则只对**之后新写 / 新改**的文档生效 ⇒ ⛔ 不得据此大规模重排既有文档（避免无谓 diff 与破坏归档）。

**同一内容的两种写法（照此改）**

⛔ **坏**（表格塞长句，列被挤压、难以并排阅读）：

```text
| 模块 | 内容 | 说明 |
| 登录 | 支持手机号+验证码 | 验证码 60s 有效，失败 3 次锁定 |
| 导出 | 支持 CSV/JSON | 单次上限 1 万行，超出分批 |
| 通知 | 站内信 + 邮件 | 可在设置里逐类关闭 |
```

✅ **好**（有序列表 + 加粗字段名）：

```text
1. **登录** —— 支持手机号 + 验证码；验证码 60s 有效，失败 3 次锁定。
2. **导出** —— 支持 CSV / JSON；单次上限 1 万行，超出分批。
3. **通知** —— 站内信 + 邮件；可在设置里逐类关闭。
```

**PRD 场景对照（需求条目）**

⛔ **坏**（需求清单做成表格）：

```text
| 编号 | 用户故事 | 验收标准 |
| R1 | 作为用户我要筛选任务 | 能按标签/状态/时间筛，结果实时刷新 |
| R2 | 作为用户我要批量删除 | 多选后一键删，可撤销，二次确认 |
```

✅ **好**（有序列表 + 加粗字段名 + 每条 AC 一行）：

```text
1. **R1 筛选任务**
   - 用户故事：作为用户，我要按标签 / 状态 / 时间筛选任务。
   - AC：筛选结果实时刷新；清空条件后恢复全量。
2. **R2 批量删除**
   - 用户故事：作为用户，我要多选后一键删除。
   - AC：删除前二次确认；删除后可撤销。
```

## 八、反模式

- 把「过程」当内容：讨论、尝试、失败路径、工具输出。
- 同一内容出现在多处（该用指针）。
- 全量罗列：全部通过项、全部用例、全部日志。
- 用篇幅证明工作量——**文档的价值是让别人少读，不是多读**。
- 宽表（≥5 列，或单元格塞长句）——按 §七 改分条列表。

## 九、设计报告（≤80 行）

```text
信息架构 → 流程 → 视觉规范 → token → 状态 → 断点 → 可用性 → 无障碍 → 降级产物
```

- **落点**：**任务目录**的 `design.md`（一次需求一份，登记 `docs/README.md`；历史 `docs/designs/` 与 `docs/designs/README.md` 冻结只读）；缺项写「不适用：<一行理由>」，**不留空、不写废话**。目录约定见 §十。
- **必留**：9 项结论 + 本次**降级档位**（文字规格 / ASCII 线框 / 分步作图指令，见 @.agents/skills/uiux-design.md §二）+ 逐条 **AC 编号** 的 PASS/REJECT 意见。
- **禁写 / 一律下沉**：实现源码与代码片段（回 `rd-fe`/`rd-be`）· 主观评价（无 AC 编号即无效）· 截图与导出图全文 · Penpot 凭证 / 真实实例 URL（只留帧链接 + ≤5 行要点摘录）· 用例集（回 `qa`）· 「因缺工具阻塞」的表述（应走降级阶梯）。
- **口径指针**：逐项要点与可用性/无障碍基线见 @.agents/skills/uiux-design.md §一/§四；闸门语义（BR2/BR2a）见 @.agents/prompts/uiux-designer.md §五；默认不用表格（§七）。
- **循环口径单源**：任务路由 / 灰模先行 / 参考→概念 / 外视评审 / 视觉验收 / 偏好持久化见 @.agents/skills/design-loop.md（本节不复制步骤）。

## 十、任务目录与索引（路径约定正文唯一）

> **本节是全仓唯一正文**：其他机制文件（`github-flow.md` / `common/*.md` / `checklists/{pm,qa,rd-infra}.md` / `skills/*.md`）只许给指针，不复制本节内容（防双源）。
> 启用判据（结构自描述，**无日期开关**）：`docs/README.md` 存在且三段标题逐字齐 ⇒ 已在新布局。

- **目录**：`docs/<任务号>-<slug>/`。任务号 = `T<编号>` 或维护型 `M<YYYYMMDD>-<slug>`（**共用同一命名空间**，不靠前缀区分）；slug 全小写连字符。一次任务 = 一个目录 = 一个 PR。
- **历史冻结**：`docs/{prds,reports,adr,designs,research,releases}/` 为 2026-11-27 前历史 —— 不改名、不迁移、不建软链、不追加；既有 Issue / PR 里的老链接继续有效。
- **目录内文件**（扁放，唯一允许的子目录 `assets/`）：**8 类主产物固定名** —— `prd.md` · `arch-review.md` · `adr-<topic>.md` · `design.md` · `impl-<role>.md` · `qa-verify.md` · `followups.md` · `release-notes-v<X.Y.Z>.md`；**其余用自由后缀**（`user-acceptance.md` · `retro.md` · `review.md` · `cases.md` · `research.md` · `repro.*` · `<topic>-调研.md`）。固定名只锁主产物，不锁全集。
- **索引 = 唯一一级入口**：`docs/README.md`，三段固定顺序、每段一张表、**表头逐字**：
  - 任务批次（**4 列**）：`任务号 | 目录 | 一句话 | Issue/PR` —— 机读前两列；**不含版本列**（版本只在版本段，防双源）
  - 版本（3 列）：`版本 | 权威路径 | 发布日期`
  - 决策时间线（4 列）：`日期 | 决策 | 任务号 | 状态` —— 决策格内 `[决策](adr-*.md)` 相对链接；状态只判前缀（`提议` / `已接受` / `已废弃`）
- **机读文法**：任务号 `^T[0-9]+$` 或 `^M[0-9]{8}-[a-z0-9-]+$`；目录首段 = 任务号；版本 `^v[0-9]+\.[0-9]+\.[0-9]+`；日期 ISO `YYYY-MM-DD`；**单元格禁 `|`**；解析前**先剥 ``` 围栏**。markdown 变体（改标题 / 增列）一律判「结构非法」，不给容错。
- **双向断言**（`check` 的 `  ! 索引` 探针，**warn-only**：不计 `warn=`、不改 rc；「删一行必须红」由 `tests/t4/cases/53` 承载）：目录 ↔ 行 · 版本 ↔ 文件（同版本唯一 + basename = `release-notes-<版本>.md` + 文件须在）· `adr-*.md` ↔ 时间线 · `docs/*.md` ⊆ {README, tasks-state, tasks-archive, INSTALL, ARCHITECTURE}。索引是唯一发现入口 ⇒ 忘加行 = 全仓不可发现，故探针提示常驻摘要。
- **版本权威份唯一**：发版说明由 PM 在发布时点名**归属任务**，落该目录的 `release-notes-v<X.Y.Z>.md`，索引版本段登记一行；**同一版本全仓只有一份**（并存期的唯一判据 = 同版本仅一文件，不靠路径白名单 —— 「两处都写」是异常而非并存）。`docs/releases/` 冻结只读。
- **活文件例外**（位置不变、不属于任何任务，**就这 5 项**）：`docs/tasks-state.md` · `docs/tasks-archive.md` · `docs/INSTALL.md` · `docs/ARCHITECTURE.md` · 索引 `docs/README.md` 本身。新增例外须同时改本节 + `check` 断言 + 该 PRD §五。
- **ADR 登记**：`adr-<topic>.md` 进任务目录，同时必须在索引「决策时间线」恰 1 行；`docs/adr/README.md` 为历史索引，冻结不追加。**出具日** = 时间线那一行的日期（历史 ADR 仍用文件名日期前缀）。
- **骨架**：@.agents/templates/task-docs/prd.md.example（PRD）· report.md.example（实现 / 评审 / QA / 复盘）· release-notes.md.example（发版说明）。

## 十一、开工确认卡与台账（结构正文唯一）

> **本节是卡字段与台账结构的唯一正文**：其余机制文本（`skills/github-flow.md` / `checklists/pm.md` / 模板注释）只许给指针，不复制字段清单与表头。
> 机判口径：`check` 的 `  ! 台账` 探针 **warn-only**（不计 `warn=`、不改 rc、摘要常驻回显）；「删一行必须红」由 `tests/t4/cases/54` 承载。

- **开工确认卡**：落 `docs/<任务号>-<slug>/kickoff.md`，**固定 10 字段**（表格两列，表头逐字 `| 字段 | 内容 |`）：`任务号` · `目标（一句话）` · `角色链` · `AC 指针` · `门禁` · `红线` · `待澄清 / 待拍` · `设计类` · `发布节奏` · `用户确认结论`。骨架：`@.agents/templates/task-docs/kickoff.md.example`。卡一旦确认，字段不得静默修改；要改就追加一行「变更记录（日期 · 改了什么 · 谁同意的）」。
- **台账主文件** `docs/tasks-state.md`（活文件，不属于任何任务）：
  - **`## 批次索引（已完成批次 → 归档锚点）`** —— 表头逐字 `| 任务号 | 归档锚点 | 状态 | 完成日期 |`；每行锚点须为 `docs/tasks-archive.md#<锚点>` 且该锚点**存在**（`<a id="…"></a>`）；主台账**目标 ≤300 行**。
  - **活批次**：每个一次 `## <任务号> · <slug>` 段，段内一张**6 列卡摘要表**（表头逐字 `| 任务号 | 目标 | 角色链 | 状态 | 完成日期 | 卡指针 |`）+ 交付记录。
  - **流转状态 6 值**（值域外一律判错）：`待开工` · `进行中` · `待验收` · `已合并` · `已发布` · `已关闭`。单调向前；已合并后又发生关闭类事件 ⇒ **以最后发生者为准**（状态 `已关闭`，变更记录写明原合并 sha）。
  - **完成日期**：`YYYY-MM-DD`；未完写 `—`。语义 = 合并日 / 发布日（覆盖前者）/ 未交付即关闭的关闭日。
- **完成即收**：状态进入 `已合并` / `已发布` / `已关闭` ⇒ **删该批次的卡摘要行与 `kickoff.md` 指针**，只在「批次索引」留一行（`kickoff.md` 本体与报告/PRD 保留，不占台账）。
- **历史搬家**：归档批次整体搬 `docs/tasks-archive.md`，每批次一段（`<a id="…"></a>` + `## <任务号> · <标题>`）；**只允许加二级标题与去重，事实字段（sha / Issue / PR / 数字）一字不改**。
- **谁改**：卡字段与台账结构归 PM（本节）；`check` 断言与 `cases/54` 归 `rd-infra`；新增卡字段或状态值须同批改 ① 本节 ② `check` ③ 模板 ④ 该 PRD §五。

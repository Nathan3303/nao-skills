# pm-to-spec（成熟需求直出 PRD）

> 入口分支：需求**已成熟**（命中 §一 判定）时跳过 grill，走「接缝 → 综合 → 缺口检查 → 出稿」；不成熟仍走 @.agents/skills/pm-grill.md 五层追问。
> 产出物一律叫 **PRD**（禁 `spec` 作并列术语）；格式 = 头部 + TL;DR + 9 模块（见 @.agents/checklists/deliverable-docs.md §三）。

## 一、成熟度判定（4 条，任一命中即可走综合）

1. **已有 grill 结论**：本需求已跑完五层追问并澄清。
2. **已有原型 / 设计稿**：用户或 RD 已给出界面 / 交互稿。
3. **已有 ADR 或架构评审回执**：`docs/adr/` 或 arch 回执已定关键取舍。
4. **用户明示「讨论已充分」**：用户显式表示可直接成稿。

- **一条都不命中 → 仍走 grill**，不得跳过；命中后也只在缺口处定点补产，不重复盘问。
- 判定结论写入 PRD 头部指针（来源：grill 结论 / 原型 / ADR），供回执核对。

## 二、接缝步骤（写 PRD 前先定可测接入点）

- **PM 列候选 → QA 确认**：PM 只列 1–3 个候选接入点；最终以 QA 确认为准（QA 可改为更高 / 更少）。
- **理想 1 个接缝**：接缝越少越好。
- **优先复用已有接缝**：已有测试 / 调用入口优先于新建。
- **能高不高低**：能在高层稳定接口测，就不下沉到实现细节。
- 结论写入 PRD「七、AC」首行：`验证接缝：<接入点>（QA 已确认 YYYY-MM-DD）`；不适用写「不适用：<一行理由>」。
- **一致性闸门（AC8）**：PRD 接缝与 QA 用例范围不一致 → PM 验收**打回**，对齐后重新验收（不得带不一致合入）。

## 三、对话综合流程

1. **判成熟度**（§一）：不命中 → 回 grill。
2. **列接缝候选 → 请 QA 确认**（§二）。
3. **综合上下文成稿**：按 §四 映射把已有讨论填进 9 模块；只综合已知，不重新盘问。
4. **缺口检查**（§五）：缺口未清空不得出稿。
5. **自核路径无关判据**（§六）→ 落 `docs/prds/` + 更新索引。

## 四、上游 7 节 → 9 模块映射（列表，非表格）

上游 `to-spec` 模板 7 节按下述归位；**实现决策 / 测试决策不落 PRD 正文**，只留指针：

1. **问题证据** ← 上游「问题陈述」。
2. **目标指标** ← 上游无对应：取 5 Whys + 北极星拆解；无依据即记缺口（§五）。
3. **范围/非范围** ← 上游「用户故事」+「范围外」（非范围必带理由）。
4. **用户场景** ← 上游「解决方案」（能力 / 关键路径视角）。
5. **业务规则** ← 上游「解决方案」+「补充说明」中的状态 / 权限 / 边界 / 不变量。
6. **NFRs** ← 上游「补充说明」的业务视角基线；无则写「不适用：<理由>」。
7. **AC** ← 上游「用户故事」逐条转 Given/When/Then；首行为验证接缝（§二）。
8. **上线闭环** ← 上游「补充说明」（灰度 / 监控 / 回滚）；缺则按项目默认并记缺口。
9. **变更治理** ← 上游「补充说明」（正式流程 + 版本记录）。
- **上游「实现决策」** → ⛔ 不写正文，指针 `docs/adr/`。
- **上游「测试决策」** → ⛔ 不写正文，指针 QA 用例范围（`docs/reports/`）。

## 五、缺口检查（缺口未清空不得出稿）

逐条核对，缺一即列缺口并定点补产（补产靠 grill / 原型 / ADR / 用户拍板）：

- 目标指标（北极星拆解 + 预期值）
- NFRs（性能 / 安全 / 兼容性业务基线）
- 上线闭环（灰度 / 监控 / 回滚）
- 变更治理（正式流程 + 版本记录）

处理顺序：先输出**缺口清单**（编号 + 缺口 + 影响）→ 定点补齐 → 复检清空 → 才可出稿。**不得**带着缺口直接成稿。

## 六、路径无关判据清单（AC1，第三方逐条可核）

- 头部齐（状态 / 更新 / Owner / 指针）
- TL;DR ≤5 行（做什么 · 给谁 · 成功标准 · 不做什么）
- 9 模块无空（不适用项写「不适用：<理由>」）
- AC 逐条 Given/When/Then + 五覆盖（主路径 / 异常 / 边界 / 负向闭环 / 设计一致性）
- 非范围含理由
- 战略筛子 + RICE 结论在
- 正文无表格
- ≤150 行
- 落 `docs/prds/` 且索引更新
- Issue 只有摘要 + 指针（正文在 `docs/prds/`）

> 判据与 @.agents/checklists/deliverable-docs.md §三、@.agents/checklists/pm.md 一致；模板见 @.agents/templates/prd.md.example。

## 反模式

- 不判成熟度就直接盘问（重复澄清轮次）。
- 接缝由 PM 单方拍定、未经 QA 确认。
- 带缺口出稿；写「实现决策 / 测试决策」正文；用 `spec` 作并列术语或替代 PRD 直发 tracker。

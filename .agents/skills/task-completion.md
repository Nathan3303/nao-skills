# 任务完成协议（DoD + 遗留项三出口 + 分级复盘）

> 与「派发 → 回执 → 验收 → 合并」**正交**：那条链路管「怎么交付需求」，本文件管「怎么判定一个任务单元真的完成」。
> 既有闸门**只指针不改写**：终态回执 @.agents/skills/pm-operations.md §一 · 验收闭环 · 合并闸门 · 回执模板 @.agents/checklists/comm-templates.md。

## 一、任务单元

- **交付型**：`T<issue-id>`（有 Issue）或降级批次号（`nao/<批次-slug>`）。
- **维护型**：`M<YYYYMMDD>-<slug>`（如 `M20261014-pi-ext-update`）——外部命令/依赖/环境动作，通常无 PRD。
- 两套粒度共存，台账字段一致；一个任务单元 = 一个 DoD 实例 = 一条收尾回执。

## 二、DoD 四类骨架（逐任务实例化，不套模板空话）

1. **产物**：落盘路径（第三方可独立读到）；无产物写「无（理由）」。
2. **验证**：可执行判据 —— 命令 + exit code + 数字（文件数/例数/红数），或结构断言；禁「看起来没问题」。
3. **遗留项**：按 §四 三出口，**零遗留也必须显式写「无」**。
4. **交接**：状态外部化（`docs/tasks-state.md`）+ 会话回收/重开 + 接手者第一动作。

实例化时机：**开工确认卡**上逐任务写死（@.agents/skills/pm-operations.md §二），验收时按同一份 DoD 核对。

## 三、维护型补充判据（命令 exit 0 ≠ 完成）

命令 `exit 0` **不构成**完成。输出中每条 `warn` / `error` / `pending approval` / `N vulnerabilities` 必须归入：
**已处置**（附命令与结果）｜**显式接受**（理由 + 到期日）｜**转台账**（含 owner）。

- **依赖类必须两项决策**：`npm audit`（逐告警处置/接受）与 `install-scripts`（批准或拒绝 pending script）——**不许留空跳过**。
- 证据落 `docs/reports/<编号>-followups.md`（一行一条：编号/来源/严重度/出口/到期）；可执行项同步进项目 backlog（本仓 = `docs/tasks-state.md` 待派发队列）。
- 超阈值（安全类 / 到期未决 >30 天）升 Issue。
- **首个实例**：`docs/reports/M20261014-pi-ext-update-followups.md`（`pi update --extensions` 4 漏洞 + 1 待批脚本，exit 0 但留 3 项遗留）。

## 四、遗留项三出口（无第四出口）

- **关闭**：已解决（附验证）。
- **接受**：降级 + 理由 + **到期日**（缺到期日 → 验收打回）。
- **转办**：进 `docs/tasks-state.md` 待派发队列或 Issue（含 owner）。
- 「先放着」「后续再看」**不是出口**。
- 无 `tasks-state` 的下游项目回落到「Issue 或报告末尾遗留段」，不阻塞。
- 回执形态：`遗留：无 | <n> 项 → <台账|tasks-state|Issue|接受(到期)>`（@.agents/checklists/comm-templates.md）。

## 五、分级复盘

- **L0 一行（默认）**：四字段 `结论 / 遗留 / 日期 / 编号`，落台账（如上例 §四 L0 段）。
- **L1 完整复盘**：`docs/reports/<编号>-retro.md` 四节 —— 发生了什么 / 根因 / 改了哪条机制 / 可验证防线。
- **L1 触发（五条，命中任一）**：返工 ≥1 次｜漏闸｜事故｜同类问题第二次出现｜用户投诉。
- 反面示例：单次文档笔误改回 → L0 一行即可；同批两次因未读对方卡版本导致返工 → 命中「返工 ≥1」+「同类第二次」→ L1。

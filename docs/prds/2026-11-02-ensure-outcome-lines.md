# PRD：`ensure` 输出语义三态互斥（成功 / 跳过 / 失败）

- 状态：待开工确认 · Owner：PM · 更新：2026-11-02
- 编号：**T539**（源自转办项 `T536-O1`）· 版本预期：**v0.21.3（PATCH）· 与 T538 攒批内容一并发布**
- 优先级：中（用户可见的行为误导，不是纯美观问题）· 战略筛子：**通过**

## TL;DR（≤5 行）

- **做什么**：`ensure` 拉起的三种结果（**成功 / 已在运行而跳过 / 创建 pane 失败**）各打印**恰好一行且互斥**的结果行；末尾摘要行给出三类计数（成功 N / 跳过 M / 失败 K）。
- **给谁**：所有跑 `ensure` 的人 —— 现在「失败」也会打印 `[tmux] 已拉起 …`，用户据此以为会话起来了。
- **成功标准**：失败与跳过分支**零** `已拉起` 行；成功分支行**逐字不变**（既有断言不破）；摘要行三类计数之和 = 本批目标数。
- **不做什么**：不改拉起方式 / 布局 / prompt 注入 / **退出码语义**（rc 仍为 0，另议）。

## 一、问题证据

- **静态铁证（PM 只读行段）**：
  - `spawn_tmux`（`nao-fleet.sh:1062`）在宿主窗口缺失时 `return 0`；`:1067-1070` 在 `split-window` 失败时 `warn ×2` 后 `return 0` —— **两者都不向调用方回报「没建成」**。
  - `spawn_one`（`:1105-1107`）在 `spawn_tmux` 之后**无条件**执行 `log "[tmux] 已拉起 $name @ $repo（layout=…）"`。
  - ⇒ **pane 未创建成功时，仍会打印一行「已拉起」**。
- **现状三态输出对照**：
  - 成功 = `[tmux] 已拉起 X @ R（layout=…）` + 末尾摘要 `已拉起 N 个会话；就绪后…`
  - 已在运行（跳过）= 仅 `warn 已在运行…跳过` ⇒ **无假行**（此分支不调 `spawn_one`）
  - pane 创建失败 = `warn pane 创建失败…` + **假的 `[tmux] 已拉起 X`**（且 `SPAWN_OK` 不增，摘要行不打印 ⇒ 用户看到「已拉起」但末尾没有摘要，进一步自相矛盾）
  - 宿主窗口解析失败 = 解析处 `warn` 一次 + **每个角色各一条假「已拉起」**
- **危害定性**：用户按「已拉起」去找会话，`status` / `intercom list` 里没有 ⇒ 误判为「舰队工具坏了」；且与 T536 新增的摘要行叠加后，同一批里可能既出现假「已拉起」又**没有**摘要行，自相矛盾。
- **历史**：T536 QA 把该缺陷判为「既存 · 接受」并转办 `T536-O1`（当时受 BR3「既有行不得改」约束未动）；本批正是因为**要改既有输出语义**才单独立项。
- **实测边界（PM 踩过的坑，写进 PRD 防误判）**：设 `NAO_TMUX_HOST_WINDOW=@999999`（非法 id）**不会**触发失败分支 —— 解析失败会**降级**到 `$TMUX_PANE`/名册并成功拉起。构造失败分支需让 `split-window` 本身失败（窗口过窄/已达上限），或用桩。
- **5 Whys**：用户被骗 ← 失败分支也打印成功行 ← `spawn_tmux` 用 `return 0` 表达「跳过/失败」← 调用方默认「返回即成功」← 从未定义过「结果三态」这个契约。

## 二、目标指标

- **北极星**：三态输出**互斥率 = 100%**（任一目标在一次 `ensure` 中恰有一行结果，且该行与实际结果一致）。
- 次指标：「用户看到已拉起但会话不存在」的误判 = 0（失败分支 `已拉起` 行计数 = 0）。
- 观测：用例断言「失败分支 `grep 已拉起` = 0」、「摘要三类计数之和 = 目标数」。

## 三、范围 / 非范围

- **范围**
  1. **A · 结果三态契约**：`spawn_tmux` 以**显式状态**回报「成功 / 跳过 / 失败」（实现方式由 rd 定：返回值 + `set -e` 兼容写法，或输出结果标记由调用方判定；**不得**用「不打印就算成功」这种隐式约定）。
  2. **B · 每目标恰一行结果**：成功 → `[tmux] 已拉起 …`（**内容逐字不变**）；跳过 → 既有跳过 `warn` 保留（不加成功行）；失败 → 失败 `warn` 保留（不加成功行）。
  3. **C · 摘要行三类计数**：末尾摘要由「已拉起 N 个会话」扩展为「成功 N / 跳过 M / 失败 K」（**仅在至少一个目标产出结果时打印一行**；三类全 0 不打印，行为与现状一致）。
  4. **D · 用例**：新增 `tests/t4/cases/22`（或并入现有最贴合用例，由 rd 判断并说明理由），覆盖 ① 成功 1 行 ② 跳过 0 假行 ③ 失败 0 假行 ④ 混合批次计数守恒；失败分支用**桩**（`tmux` 桩令 `split-window` 失败），不依赖真实窗口过窄。
- **非范围**（各带理由）
  - **不改退出码**：失败时 rc 仍为 0。理由 改 rc 会让「部分失败」的批次语义复杂化（CI/脚本已在用 rc=0），且 T536-O1 的诉求是「输出语义分层」；rc 语义另立需求。
  - 不改拉起方式 / 布局 / prompt 注入 / 模型白名单：理由 与本缺陷正交。
  - 不合并现有的两行失败 `warn`（`pane 创建失败` + `已跳过该 pane…`）：理由 那两行是诊断信息不是结果行，合并会丢信息；本批只保证**不加成功行**。
  - 不改 `--force` / 判重逻辑：理由 跳过分支的判定不在本批范围。

## 四、用户场景

- **画像 A（人，终端）**：一批拉起 3 个角色，1 个失败 → 立刻能看到「失败 1」，不会去 `intercom list` 找那个不存在的会话。
- **画像 B（CI/脚本）**：从摘要行拆出三类计数（rc 不变，故不破坏既有脚本），需要区分时可用摘要解析（不推荐，但可行）。
- **画像 C（排查）**：失败原因仍在两条 `warn` 里，未被摘要行覆盖。
- **关键路径**：`ensure` → 逐目标 `spawn_tmux`（状态）→ 结果行（互斥）→ 摘要（三类计数）。
- **页面状态**：不适用（CLI）。

## 五、业务规则

- **BR1 成功行逐字不变**：`[tmux] 已拉起 <name> @ <repo>（layout=<layout>）` 的内容与格式不得改动（既有断言与用户习惯依赖它）；`--model` 变体同样不变。
- **BR2 失败/跳过零假行**：失败与跳过分支**不得**输出任何含「已拉起」的字样。
- **BR3 计数守恒**：摘要行三类计数之和 = 本次 `ensure` 的目标数；`--task` / `--card` / `--force` 各分支同样计入。
- **BR4 rc 语义不变**：任一目标失败时 rc 仍为 0（本批不改退出码；若将来改，须单独立项并给出迁移说明）。
- **BR5 单行摘要**：摘要行仍**恰一行**（T536 的「一行」契约不破），多角色不刷屏。
- **BR6 零回归**：不带任何新参数、单角色成功场景的既有输出**逐字等价**（唯一新增 = 摘要行内部的计数细化，若改措辞须给出旧→新对照并说明为何必要）。

## 六、NFRs

- **兼容**：`check` / `npm test` 输出不变；`tests/t4` 既有用例（尤其 `cases/12` 落点、`cases/19` 归属、`cases/20/21` 卡会话）不得回归。
- **可核性**：用例断言「失败分支 `已拉起` = 0」「摘要三类之和 = 目标数」= 全部判据；失败用桩构造，**不依赖真实窗口状态**（可复现）。
- **可诊断**：失败原因仍由两条 `warn` 承载，摘要只报数不报因。
- **不适用**：性能 · 安全 · 并发压测。

## 七、AC

- **AC1（主路径 · 成功）**：单角色成功拉起 ⇒ 恰 **1** 行 `[tmux] 已拉起 …`（与旧版**逐字相同**）+ 摘要行含「成功 1 / 跳过 0 / 失败 0」。
- **AC2（跳过 · 零假行）**：目标已在运行（不给 `--force`）⇒ 跳过 `warn` 1 行 · **`已拉起` 行 = 0** · 摘要「成功 0 / 跳过 1 / 失败 0」。
- **AC3（失败 · 零假行 + 桩）**：用 `tmux` 桩令 `split-window` 返回非 0 ⇒ 失败 `warn` 在位 · **`已拉起` 行 = 0** · 摘要「成功 0 / 跳过 0 / 失败 1」· **rc 仍为 0**（BR4）。
- **AC4（混合批次 · 计数守恒）**：一批 3 目标（1 成功 + 1 跳过 + 1 失败，用桩构造）⇒ 每目标恰一行结果 · 摘要三类计数 = 1/1/1 · 合计 = 3 = 目标数。
- **AC5（设计一致性 · 零回归 + 门禁）**：① 单角色成功场景旧版 vs 新版输出对照（**允许**摘要行内容变化，其余逐字等价）；② `check` rc=0（roles=6 · files=50 或变化有说明）· `npm test` rc=0 · `tests/t4` 用例数与断言数**均增加**（给新旧对照）· 发布口径 `test:t4:full` 非白名单 NOTE=0 · `roles.yaml` diff = 0；③ 桩用例的临时 tmux 环境**不得**触碰生产会话（沿用 `env -u TMUX` + 隔离 socket 纪律）。

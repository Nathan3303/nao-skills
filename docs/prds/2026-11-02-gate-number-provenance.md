# PRD：门禁数字的可复现口径（T536-O3 落地）

- 状态：待开工确认 · Owner：PM · 更新：2026-11-02
- 编号：**T538**（维护型批次，源自转办项 `T536-O3`）· 版本预期：**v0.21.3（PATCH）**
- 优先级：中 · 战略筛子：**通过**（不新增功能，只消灭「同一命令两种结论」的争议成本）

## TL;DR（≤5 行）

- **做什么**：把「回执里的门禁数字怎么产生」写成一次口径 —— ① 门禁必须在**静默工作区**执行 ② 回执必须记 **HEAD sha** ③ 每个计数类数字必须给「**命令 + 输出**」；并把四条计数命令**集中到一处**（`tests/README.md`），其余文件只留指针。
- **给谁**：PM / QA / RD 三侧写回执的人，以及读回执做验收的人。
- **成功标准**：任何计数类数字都能被一条命令复现；「同一命令不同结论」可用 HEAD + 工作区状态解释；命令串在仓库中只有一处正文。
- **不做什么**：不改任何脚本/门禁实现、不新增自动校验、不增加清单项数。

## 一、问题证据

- **同型数字误报 3 次**（同一根因：把最大编号当例数）：T535 报「19/19」→ T536 报「18/19」→ M20261102 报「21 例」（实测均应为 20）。T536 已做 L1 复盘（`docs/reports/2026-11-01-T536-retro.md`），防线落在 PM 卡 + `tests/README.md`，但 **RD 侧没有**。
- **数字标签错 2 次**（M20261102 批内）：报告写「2 文件 → 3 文件」后仍写「+7 −1」（实为 `+5 −1`）、「O2–O4 追加 = 1 文件」（实为 2 文件）。QA 判「第 3 次同型计数不严」。
- **同一命令两种结论**：RD 报 `test:t4:full` 5 跑 2 FAIL（`rc=124` / `timeout 120`），QA 独立跑 7 次全 PASS（单跑 8–15 s），PM 空载再跑 1 次 PASS。三方都没错 —— 但**回执里没有「在哪个 HEAD、工作区是否干净、有无并行会话」**，导致只能靠推断（`M20261102-F2`）。
- **口径分散**：用例数命令现在只在 `.agents/checklists/pm.md:110` 有正文，`tests/README.md:33` 是描述性段落；**断言数 / `files=` 的取数命令没有任何一处成文**（`grep -c '\[PASS\]'`、`find ... | wc -l` 只在 PM 卡那条里被顺带提到）。
- **5 Whys**：数字对不上 ← 回执只给结果不给「怎么算的 + 在什么状态下算的」← 口径散落在三份清单且各写各的 ← 每次都由「哪个人先遇到」决定写在哪 ← 没有单一事实源。

## 二、目标指标

- **北极星**：回执中「无法用一条命令复现的计数类数字」= **0**。
- 次指标：命令串正文重复度 = 1 处（其余为指针）；RD 侧同型误报在下 2 批内 = 0。
- 观测：`grep` 断言（命令串出现次数）、样例回执逐条对照能判「合格 / 不合格」。

## 三、范围 / 非范围

- **范围**
  1. **A · 回执字段口径**：`common/output-format.md` 的「测试」字段补三条 —— ① 门禁须在**静默工作区**执行（`git status --porcelain` 空 + 无其他会话在同一 worktree 跑门禁）② 必须记 **HEAD sha** ③ 计数类数字一律给「**命令 + 输出**」，禁止只写「我数了 N」。
  2. **B · 单源集中**：`tests/README.md` 一处列全四条取数命令（用例数 / 断言数 / `files=` / 行数），并写明各自「何时用、易错点」。其余文件（`checklists/pm.md` 第 110 条、`checklists/qa.md`、`checklists/rd-infra.md`）**一律只留指针 + 一句「不符即打回」**，不复制命令。
  3. **C · 三侧对齐**：`checklists/qa.md` 与 `checklists/rd-infra.md` 各加一条同源指针（当前只有 PM 卡有）；确保 RD 回执也受同一口径约束。
  4. **D · 反例**：在口径文本里给一条**不合格回执样例**（无 HEAD、无命令、只有结论），并写明「据此打回」。
- **非范围**（各带理由）
  - 不改脚本/门禁实现：理由 本批是「怎么报数」而非「怎么算数」，改实现回归面大且与本批要消灭的争议无关。
  - 不新增自动校验（如「归档时遗留项未收口 → warn」的 E1）：理由 那是另一条已评估的门槛型需求（连续 2 批「遗留项失忆」才升级），不夹带。
  - 不增加清单项数：理由 项数变化会引起卡/文档里的计数连锁（我们刚被同类问题咬过），只改文字。
  - 不改 `tests/t4` 的汇总输出格式：理由 输出契约已被多处断言依赖。

## 四、用户场景

- **画像 A（RD 写回执）**：跑完门禁，按单源命令取数，回执附「命令 + 输出 + HEAD」→ 不再被 QA 反推「你这个数怎么来的」。
- **画像 B（QA 复核）**：先看 HEAD 与工作区状态是否与 RD 一致；不一致就用「静默工作区」口径解释，而不是判「RD 造假」。
- **画像 C（PM 验收）**：任何数字一条命令复核；不一致以命令为准并当场订正（既有条款不变）。
- **关键路径**：跑门禁 → 取数（单源命令）→ 回执（命令 + 输出 + HEAD + 工作区状态）→ 复核方可 1:1 重放。
- **页面状态**：不适用（CLI/文档）。

## 五、业务规则

- **BR1 单源**：四条取数命令的**正文**只允许出现在 `tests/README.md`；其他文件出现即违规（用指针）。例外：本 PRD 与 QA/RD 报告可引用「命令串」作为证据。
- **BR2 回执三件套**：「测试」字段必须同时含 ① 命令 ② 输出（或输出摘要 + 可直接复跑的命令）③ HEAD sha。
- **BR3 静默工作区定义**：`git status --porcelain` 为空，且同一 worktree 无其他会话正在跑门禁。不满足 ⇒ 回执须显式标注「非静默（原因）」，且该数字不得作为验收依据。
- **BR4 零计数漂移**：`checklists/*.md` 的**条数**在改前/改后必须相同（只改文字/加指针，不加项）；差异即视为超范围。
- **BR5 三侧同源**：PM / QA / RD 三侧指针指向同一处，措辞可不同但不得各自复制命令。

## 六、NFRs

- **兼容**：不改任何命令行为与输出；`check` / `npm test` 数字不变（仅文档文件变化，`files=` 可能因 `.agents/**` 文本改动而**不变**，需说明）。
- **可核性**：`grep` 计数（命令串出现次数）+ 清单条数前后一致 + 样例回执对照。
- **不适用**：性能 · 安全 · 并发压测。

## 七、AC

- **AC1（主路径 · 回执口径三件套）**：`common/output-format.md` 的「测试」字段含三条硬要求（静默工作区 / HEAD sha / 命令 + 输出），且含一条**不合格样例**与之对照。
- **AC2（单源 · 命令正文唯一）**：`run.sh --list | tail -n +2 | wc -l`、`grep -c '\[PASS\]'`、`files=` 取数、行数取数的**正文**在仓库 `.agents/**` 与 `tests/README.md` 中合计各出现 **1 次**；`checklists/pm.md` 第 110 条与 `checklists/qa.md` / `rd-infra.md` 只含指针（断言：指针处命令串命中 0）。
- **AC3（三侧对齐）**：`checklists/qa.md` 与 `checklists/rd-infra.md` 各存在一条指向单源的条目；表述与该文件既有风格一致（问句/条目形式）。
- **AC4（零计数漂移 · 负向）**：`checklists/` 三份文件的条目数改前 = 改后（`grep -c '^- \[ \]\|^| '` 逐文件对照）；变动即 FAIL。
- **AC5（设计一致性 · 门禁）**：`check` rc=0（roles=6 · files=50 或变化有说明）· `npm test` rc=0 · `tests/t4` **20 用例**全 PASS · 发布口径 `test:t4:full` 非白名单 NOTE=0 · `roles.yaml` diff = 0。

# PRD：门户迁移 Vue 3 + TS，并建文档站（VitePress）

- 状态：**已交付并上线**（2026-11-17 · 合并 `c82b1e4` · 用户走查 16/16 通过）· Owner：PM
- 更新：2026-11-16
- 指针：上游 Issue（立项时补号）· 设计基线 `docs/designs/2026-11-13-portal-site.md`（T541，用户走查 15/15 通过）· 现有门户 `site/`（零构建四文件）· 部署 `.github/workflows/pages.yml`
- 优先级：战略筛子通过（对用户可见 + 降低上手门槛）· RICE 见附录（Score 12.0，P1）

## TL;DR（≤5 行）

- **做什么**：把手写静态门户 `site/` 换成一个 Vue 3 + TypeScript 的 VitePress 站（`apps/document`），门户内容做它的**首页**；新增文档页：舰队怎么用、七个角色各自的卡原文、角色之间怎么配合、内置插件怎么挑、进阶用法。
- **给谁**：第一次接触 nao 的开发者（首页 30 秒懂定位）＋ 已装想用深的人（文档站）。
- **成功标准**：`apps/document` 一条命令构建出静态站；首页文案与现有门户逐条对应；角色卡页正文由构建时从 `.agents/prompts/*.md` 注入（单一事实）；产物零外链（无 CDN / 外链字体 / 外链图 / 统计）；`check` + `npm test` 仍 rc=0。
- **不做什么**：不重做视觉（以现有门户为准）；不改角色卡正文与机制语义；不改 npm 发布面（`apps/` 不进包）；不做英文版 / 搜索服务端 / 博客。

## 一、问题证据

现有门户是零构建手写页（`site/index.html` 230 行 + `style.css` 16.7KB + `app.js` 3.6KB），只能承载「一段页」：装得起来以后没有下一位读者需要的深度内容（每张卡到底写了什么、角色之间谁派谁、5 个插件缺哪个会怎样）。

5 Whys：为什么用户装完仍反复问同几件事 → 因为深度内容只在 `.agents/prompts/*.md` 与仓库 `docs/` 里，面向用户的可读入口只有一段页 → 因为门户当时按「单页 + 零构建」立项（T541 非范围写明「文档站为非范围」）→ 因为那时优先解「让人 30 秒装起来」→ 现在装得起来的人多了，瓶颈从「装不装」转到「怎么用对」。

## 二、目标指标

- 北极星：文档站上线后 3 个月内，用户（含下游三仓）就「角色职责 / 配合规则 / 插件必要性」的重复提问 ≤2 次/月（以对话与 Issue 计数）。
- 支撑：站点构建时长 ≤90s（冷装 ≤5min）；首页 transmit ≤300KB gzip；角色卡页与卡原文的一致性断言 100% 通过。

## 三、范围 / 非范围

- **范围**：`apps/document`（VitePress + Vue 3 + TS，单站）· 门户 → 首页（保真）· 文档内容六章（快速开始 / 它怎么干活 / 七个角色 / 角色配合 / 插件选择 / 进阶用法 + FAQ + 术语表）· 构建期角色卡注入脚本 · `.github/workflows/pages.yml` 改为构建后上传 · 删除 `site/` · 根 `package.json` 增 `docs:dev` / `docs:build` / `docs:preview` 三个脚本。
- **非范围**：1) 重新设计视觉（理由：设计基线 T541 已过用户走查，重建只增返工）；2) 改角色卡正文 / 机制语义 / 闸门（理由：本批只做呈现层）；3) 英文站、全文搜索服务端、博客、版本化文档（理由：当前只有一个现行版本，成本 > 收益）；4) 把 `apps/` 纳入 npm 发布包（理由：发布面稳定，站点走 Pages）。

## 四、用户场景

- **画像 A（首次接触）**：搜到项目 → 落首页 → 读「三个毛病」→ 复制安装命令 → 点进「快速开始」。
- **画像 B（装完想用深）**：「qa 到底该干什么」→ 角色页读解说 → 展开「卡原文」核对细节 → 跳到「角色配合」看它和谁对接。
- **画像 C（选插件）**：「我缺什么」→ 插件页看 5 个内置插件各干什么、缺了会失去什么能力。
- **关键路径**：首页 → 快速开始 → 一个需求的完整旅程 → 角色页 → 插件页。
- **页面状态清单**：加载 / 空 / 错误 / 成功 —— 不适用（纯静态站，无数据请求、无用户态；构建失败即 CI 失败，不产出半成品）。

## 五、业务规则

- **单一事实**：角色卡正文只在 `.agents/prompts/*.md`；站点页由构建期注入，禁止在 `apps/document` 内手抄卡正文（搬运即违规）。
- **路径分工（防同目录冲突）**：VitePress `srcDir = apps/document/content`；PM 只写 `content/**/*.md`（内容），`rd-fe` 只写 `apps/document/.vitepress/**` 与 `components/**`（结构 / 主题 / 脚本）。
- **视觉唯一基准**：颜色 / 字阶 / 间距 / 圆角沿用设计基线 §四 token；VitePress 默认主题变量必须被覆盖到「无默认蓝、无默认字体族」。
- **通俗口径**：正文不裸用内部术语；每个内部术语首次出现处给半句话解释，并进术语表。
- **产物零外链**：不得引用 CDN 资源、外链字体、外链图片、统计脚本；正文中的 `a` 文本链接（GitHub / npm / pi.dev）不计入。
- **容错**：仓库缺 `.agents/prompts`（例如只装了发布包）时构建**不崩**——跳过注入、页面显示「卡原文见仓库」并打一条显式告警；`--strict` 模式下改为失败。

## 六、NFRs

- **构建**：Node 22（dev 与 CI 统一，`package.json engines` 保持 ≥18 供 npm 用户）；冷装 ≤5min、增量构建 ≤90s。
- **性能**：首页 JS/CSS 合计 ≤300KB gzip；首屏无阻塞第三方请求（0 个外部域名）。
- **可访问性**：对比度沿用设计基线 §四 实测值（正文 16.4:1 / 次要 8.0:1 / accent 6.3:1，暗色同达标）；键盘可达、焦点可见、跳过链接保留。
- **兼容**：现代常青浏览器（Chrome / Edge / Safari / Firefox 各最近 2 大版本）；深色跟随 `prefers-color-scheme`，不新增手动开关。
- **安全**：站点零运行时后端、零用户输入；构建脚本只读仓库文件，不联网。

## 七、AC

- 验证接缝：`npm run docs:build`（rc + 产物断言）+ 只读探针脚本（QA 自建，不入 `tests/`）+ 用户验收清单。QA 已确认：2026-11-16。
- AC1（主路径）：Given 干净 clone 且 `apps/document` 装好依赖，When 跑 `npm run docs:build`，Then rc=0 且 `apps/document/.vitepress/dist/index.html` 存在。
- AC2（主路径 · 首页保真）：Given 构建产物，When 打开首页，Then 六段（Hero / 三个毛病 / 七个角色 / 三步装好 / 常见问题 / 页脚）齐备，文案与 `site/index.html` 逐条对应（设计基线 §一 为准）。
- AC3（主路径 · 角色卡注入）：Given 构建产物，When 打开任一角色页，Then 展示的卡正文与该卡 `.agents/prompts/<card>.md` 正文逐段一致（构建期提取），且仓内 `apps/document` 不存在卡正文手抄副本。
- AC4（主路径 · 插件章）：Given 构建产物，When 打开插件页，Then 5 个内置插件齐备，包名与 `bin/nao-skill.js` 的 `PI_PLUGINS` 表一致（脚本比对断言），每个含「缺了会失去什么」一句。
- AC5（异常）：Given 仓库缺 `.agents/prompts`，When 构建，Then 默认 rc=0 并输出一条显式跳过告警；`--strict` 时 rc≠0。
- AC6（边界）：Given 视口 <720px 或系统深色模式，When 浏览首页与任一角色页，Then 导航可用、无横向溢出、对比度达标（用户验收清单逐项回填）。
- AC7（负向闭环 · 零外链）：Given 构建产物，When 全量扫描 dist，Then 无 `http(s)://` 资源引用（`a href` 文本链接除外）、无外链字体 / 图片 / 统计脚本。
- AC8（负向闭环 · 旧站退场）：Given 删除 `site/`，When 全仓 grep `site/` 与 `pages.yml` 校验，Then 无残留引用（历史 `docs/releases`、`docs/prds` 内的记录不计），Pages 工作流只上传 `apps/document` 产物。
- AC9（负向闭环 · 发布面不变）：Given 本批改动，When `npm pack --dry-run` 与 `npm test`，Then 包文件列表不含 `apps/`、`check` rc=0、`npm test` rc=0。
- AC10（设计一致性）：Given 设计基线 §四 token，When 抽查首页与内容页的色值 / 字阶 / 间距 / 圆角，Then 与 token 一一对应，VitePress 默认蓝与默认字体族 0 处残留。
- AC11（通俗性）：Given 术语表与正文，When 抽查「PRD / AC / 回执 / 门禁 / 闸门 / RICE」六词，Then 每词首次出现处有半句解释且术语表覆盖（用户验收清单核对）。

## 八、上线闭环

- 上线 = 合并后 Pages 自动构建部署（`https://nathan3303.github.io/nao-skills/`）；上线后用户验收清单核对线上首屏与一个角色页。
- 观测：构建失败即 Actions 红（不降级为旧产物）；上线 24h 内由用户抽查 3 个页面。
- 回滚：`git revert` 本需求那一条 squash 提交即整批撤回（含 `site/` 恢复），符合 BR1 单提交口径；不需手工迁移数据。

## 九、变更治理

- 本批为 `feat` 全通道，走 Issue + `feat/<issue>-docs-site` 分支 + 单 PR squash 合并；文档 / 台账 / 设计规格随同一 PR。
- 站点不单独发版（随下一次 PATCH 或 MINOR 记录）；`AGENTS.md` 只加一条指针（站点位置 + 构建命令 + 单一事实说明），不复制机制条款。
- 内容后续迭代走独立小批次（`docs(...)` 提交随各自任务 PR），不重开架构评审。

## 附录：战略筛子 / RICE 结论

- 战略筛子：① 对用户可见（直接降低上手与用深门槛）② 机制零耦合（只动呈现层）③ 可独立回滚（单提交）—— 通过。
- RICE：Reach 8（每期触达 ≈8 名新用户/下游）/ Impact 3（显著改进理解）/ Confidence 0.9 / Effort 1.8 人日·批 → **Score ≈ 12.0 → P1**。
- MoSCoW：Must = 首页保真 + 角色卡注入 + 插件章 + 零外链 + Pages 改造；Should = 术语表 + 进阶用法；Could = 内容页内链推荐区；Won't（本批）= 英文站 / 搜索服务端 / 视觉重做。
- Kano：首页与安装命令 = 基本型；角色卡原文与角色配合 = 期望型；「缺了会失去什么」的插件说明 = 兴奋型（差异化）。

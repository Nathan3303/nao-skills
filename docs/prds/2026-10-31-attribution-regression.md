# PRD：归属判定补常态回归 + BR5 摩擦修正

- 状态：开工卡已定稿（D1–D3 已拍板）· Owner：PM · 更新：2026-10-31
- 指针：Issue [#58](https://github.com/Nathan3303/nao-skills/issues/58) · 上游 = T534 QA 结论（`docs/reports/2026-10-31-T534-qa-verify.md` O1）+ T533/T534 收尾实测（`pull` 被工作区脏改阻挡）· ADR `docs/adr/2026-10-31-fleet-status-repo-attribution.md`
- 优先级：高（安全判据缺护栏）· RICE 结论 ≈ 26（附录）

## TL;DR（≤5 行）

- **做什么**：① 给「会话归属按仓判定」补 `tests/t4` **常态用例**（跨仓残留 / 归属不可判定两场景）+ 单行谓词**变异 harness**（恒真/恒假各须翻红点名）；② 修 BR5 摩擦（发布后事实改在下一 PR 首提交落地，不留工作区脏改）；③ 关闭过期台账行 `T533-O2`。
- **给谁**：维护机制包的人（护栏不再依赖一次性探针）、日常跑 `git pull` 的用户（不再被 PM 的未提交改动挡住）。
- **成功标准**：变异恒假 ⇒ `tests/t4` **必须翻红并点名**；`check`/`npm test`/`t4` 全绿；BR5 文本单源一致；过期行关闭零残留引用。
- **不做什么**：不改 `status` 判定逻辑本身（T534 已定稿）；不改 `close`/`ensure`；不重做探针识别口径（T534 C 项已完成）。

## 一、问题证据

- **A 现有缺陷（实测 · T534 QA 独立确认）**：把 `repo_contains_path` 改成恒假（全部判他仓）后，`tests/t4` 全量 **17/17 全 PASS、无一翻红**（用例 01–18 逐条核）。原因：`cases/09` 走 `close` 闸门、`cases/13` 验 `close` 末段、`cases/15` 只断言名字出现在 `status`（恒假下变成 `~` 行仍命中）—— **没有任何用例断言「本仓会话必须被认成本仓」「他仓会话不得带可执行 `close`」**。
- **后果**：归属判据属安全面（误杀他仓会话），却只由**一次性探针**（`docs/reports/`，不进 `tests/`）守护；下次谁改 `status`/谓词，常态门禁不会响。
- **B 流程摩擦（实测 · 2026-10-31）**：BR5 要求「发布后事实随下一任务 PR」，PM 遂把 `tasks-state` 改动留在工作区；用户执行 `git pull --ff-only` 时被拒（`pull.rebase=true` 遇未暂存变更即失败）。虽可用 stash 绕过，但**规则本身制造了周期性阻塞**。
- **C 台账过期（实测 · 2026-10-31）**：`T533-O2`「探针只认半角括号/冒号」在 T534 C 项已修（`docs/reports/2026-10-28-docs-ride-pr-probe.sh` 现含 `DOCS_SUBJECT_NORM` 全角归一 + 无编号 `docs:` + 大小写不敏感），但台账仍挂在待派发队列 ⇒ 若不清理，下批会重复劳动。
- **5 Whys（A）**：无翻红 ← 无用例断言归属三态 ← 该判据以一次性探针交付（T534 PRD 非范围「不动 `tests/t4`」）← 为控制批次体积 ← 未评估「安全判据必须有常态守护」这一门槛。

## 二、目标指标

- **北极星**：归属判据的**任一方向失效都会让常态门禁翻红并点名**（不再依赖人记得跑一次性探针）。
- 预期：新增 ≥1 个 t4 用例覆盖 local/other/unknown 三态；变异 harness 两个方向各产生 ≥1 条 FAIL 且输出含用例号。
- 观测：`tests/t4/run.sh` 的 PASS 断言计数（旧→新）+ 变异后 FAIL 点名清单 + `check`/`npm test` 精确数字。

## 三、范围 / 非范围

- **范围**
  1. **A · 常态用例**：`tests/t4/cases/` 新增一例（建议 `19-status-repo-attribution.sh`）—— 隔离 socket 夹具下构造①本仓派生会话 ②他仓派生会话（pane cwd = 仓外目录）③不可判定会话（pane/名册均无 cwd），断言：本仓行走 `!`/`·` 且含可执行 `close --task`；他仓行走 `~`、含「他仓」、**整行不含 `close --task`**；不可判定行走 `?`、含「归属不可判定」且不含 `close --task`；单仓场景零 `~`/`?` 行。`run.sh` 注册 + `tests/README.md` 用例行。
  2. **A · 变异 harness**：把 `repo_contains_path` 单行谓词纳入用例内变异自证（复制脚本到临时目录、改单行、断言恒真/恒假两方向各翻红并点名），**不得**在真仓库就地改文件（只读纪律）。
  3. **B · BR5 修正**：`github-flow.md` BR5 改为「发布后事实在**下一任务 PR 的首个文档提交**落地；其间不得留工作区脏改（需暂存用带标签 stash）」；`checklists/pm.md` 相应对齐（单源仍是 `github-flow.md`，清单只指针）。
  4. **C · 台账维护**：`docs/tasks-state.md` 关闭 `T533-O2`（写明已在 T534 C 项落地 + 证据路径），并确认全仓无残留引用。
- **非范围**（各带理由）
  - 不改 `status` 归属判定实现：理由 T534 已 arch 定稿 + QA 双向验证（ADR 已落地），本批只补护栏。
  - 不改 `close` / `ensure` / `task_state_class`：理由 与归属无关，改动面徒增回归风险（T534 已证零改动是安全选择）。
  - 不重复做探针识别口径：理由 T534 C 项已完成（`DOCS_SUBJECT_NORM` + 可选编号 + 大小写不敏感），本批只关闭台账行。
  - 不把一次性探针迁入 `tests/`：理由 探针含文本/结构断言与一次性夹具，常态化收益低；本批的常态护栏 = 新 t4 用例。
  - 不改 `docs/tasks-state.md` 的归档/分类结构：理由 与本批无关，触及 `task_state_class()` 契约。

## 四、用户场景

- **画像 A（维护者改 `status`）**：改坏归属 → `npm test` 当场翻红并点名用例号，不必记得去跑一次性探针。
- **画像 B（PM 日常）**：发布后要不要留未提交改动不再靠记忆——规则明确「落地在下一 PR 首提交」，`git pull` 不再被挡。
- **画像 C（接手者读台账）**：待派发队列不再出现「已修完但仍挂着」的行。
- **关键路径**：新增用例 → 变异自证 → 门禁 → PR。
- **页面状态**：不适用：CLI 输出，无 UI。

## 五、业务规则

- **BR1 只读变异**：变异必须在**临时副本**上做，真仓库文件零改动（前后 `git status` 空、md5 不变）；还原后必须复绿。
- **BR2 双向必红**：恒真与恒假**两个方向都必须**产生 FAIL 并点名；单方向即视为未完成（T534 的教训正是「只有一个方向被验过」）。
- **BR3 断言在「可执行性」上**：对不可判定/他仓行，断言必须落在「不含可执行 `close --task`」，而不是仅断言字面词出现（`cases/15` 的假绿根源）。
- **BR4 单源**：BR5 新口径单写在 `github-flow.md`，`checklists/pm.md` 只给指针。
- **BR5 夹具仓外**：夹具根不得落在任何 git 仓内（否则 toplevel 锚把「他仓」拉回本仓，用例假绿 —— T534 arch 已警示）。
- **BR6 计数诚实**：`check` 的 `files` 只统计 `.agents/**`；新增用例在 `tests/` ⇒ `files` 预期不变，须显式说明「不变」而非漏报。

## 六、NFRs

- **确定性**：用例离线、隔离 socket（`-S`）、不依赖真实他仓会话；连跑两次逐字一致。
- **离线性**：不触网（用例 02/07 的网络面极性规则照旧）。
- **可核性**：全部判据为 exit code + 断言计数 + 点名用例号。
- **不适用**：性能 —— 理由 仅新增 1 例（预计 <10s）；并发 —— 夹具用隔离 socket 天然隔离。

## 七、AC

- **验证接缝**：`tests/t4/cases/19-*.sh`（新常态用例 · 走 `tests/t4/run.sh`）+ `nao-fleet.sh check` + `npm test`；一次性探针可选复用（**不作为本批主接缝**）。
- **AC1（主路径 · 新用例在位且有效）**：新用例已被 `run.sh` 注册并在 `tests/README.md` 有行；真仓库上 `tests/t4/run.sh --case 19` PASS，断言覆盖三态（本仓含可执行 `close` / 他仓整行无可执行 `close` 且含「他仓」/ 不可判定含「归属不可判定」且无可执行 `close`）+ 单仓零 `~`/`?` 行；PASS 断言数须报出。
- **AC2（负向闭环 · 双向必红）**：变异 harness 实测 **恒真 ⇒ FAIL 且点名**（用例号 + 断言）；**恒假 ⇒ FAIL 且点名**；两方向均**只在临时副本**发生（真仓库 `git status` 空、被改文件 md5 前后一致），还原后全绿。**且必须给出「T534 时全量 17/17 无一翻红」已被本批改变的证据**（变异后出现的 FAIL 条数）。
- **AC3（边界 · BR5 单源新口径）**：`github-flow.md` BR5 含「下一任务 PR 首提交落地 / 不留工作区脏改 / 带标签 stash」三要素；`checklists/pm.md` 对应项为**指针**（不得复写命令细节）；两处不得出现互斥表述。
- **AC4（异常 · 台账过期行关闭）**：`docs/tasks-state.md` 中 `T533-O2` 行标注**已关闭**并给出证据路径（`docs/reports/2026-10-28-docs-ride-pr-probe.sh` 的 `DOCS_SUBJECT_NORM` / 可选编号 / 大小写不敏感）；`grep -c 'T533-O2'` 在待派发队列区为 0；不得残留「待派发」语义。
- **AC5（设计一致性 · 门禁与版本）**：`check` rc=0（roles=6 · **files 旧→新，预期不变并说明原因**）· `npm test` rc=0（例数）· `tests/t4/run.sh` 全量 PASS/FAIL/SKIP/DEGRADE 精确数字（发布口径 SKIP=0/DEGRADE=0/非白名单 NOTE=0）；如改 `checklists/pm.md` 计数须与标题/卡尾一致；`AGENTS.md` 零改动（本批无项目级新增）。

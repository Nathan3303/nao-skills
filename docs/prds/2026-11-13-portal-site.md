# 门户网站（nao-skills landing page）

- 状态：已定稿（已交付 · PR [#108](https://github.com/Nathan3303/nao-skills/pull/108) squash `5b15563` · 本批不发版）· 更新：2026-11-13 · Owner：PM
- 指针：事实源 `README.md` · 进阶口径 `docs/INSTALL.md` · 设计稿（待出）`docs/designs/`

## TL;DR

- **做什么**：给 nao-skills 建一个中文单页介绍站（landing page），纯静态、零外部依赖，托管 GitHub Pages 项目页。
- **给谁**：已用 pi 或正在评估 pi 的中文开发者——先看官网再决定装不装。
- **成功标准**：陌生人 30 秒内说清「这是什么 + 下一步做什么」，安装命令一键复制；零外部请求，移动端可用。
- **不做什么**：文档站、双语、截图/动图、自定义域名、任何统计脚本。

## 一、问题证据

- **现状**：`README.md` 约 12KB 长文，首屏后需滚动约 5 屏才到安装命令，外部没有任何「一眼看懂」的入口页面。
- **5 Whys**：为什么装的人少 → 不知道是什么 → README 信息密度高、读者需自行提炼 → 缺少面向陌生人的导流页 → 项目从未做过对外展示层。
- **证据强度**：弱。无访问/转化数据，判断依据为 README 结构与入口缺失；本 PRD 的收益假设 = 导流页降低首次理解成本（上线后以用户验收判定，不采集数据）。

## 二、目标指标

- **北极星**：首次访问 30 秒内能复述「7 个 AI 角色 + 你只回答问题与点确认」并找到安装命令。
- **拆解**：① 首屏含一句话定位与主 CTA；② 安装命令可一键复制；③ 七个角色一屏可扫完；④ 跳 GitHub / npm 入口各 ≥1 处。
- **预期值**：可用性检查全通过（见 AC）；Lighthouse 移动端 Performance ≥95、Accessibility ≥95。
- **口径说明**：零外部依赖 ⇒ 不埋点，指标以静态自查 + 用户验收替代，不做数据统计。

## 三、范围 / 非范围

- **范围 1**：新增 `site/`（`index.html` + 本地 CSS + 少量原生 JS：复制按钮、锚点导航），零构建、零依赖。
- **范围 2**：`.github/workflows/pages.yml` 发布 `site/` 到 GitHub Pages 项目页（`https://nathan3303.github.io/nao-skills/`）。
- **范围 3**：README 顶部加一行站点入口指针；并在安装段补半句「装最新版可省略 `@版本号`」（示例 pin 保留，属团队同款语境）。
- **范围 4**：`docs/designs/` 设计稿一份（uiux-designer 出，PM 验收前须 PASS）。
- **非范围 · 文档站**：理由 = 全量文档转网页需长期双源维护，本期只做导流，深内容跳 README/INSTALL。
- **非范围 · 中英双语**：理由 = 主要受众中文，双语维护成本约 1.6 倍，价值未验证。
- **非范围 · 真实截图/动图**：理由 = 需随 UI 与命令变化同步维护，且与「零外部依赖、轻量」冲突；改用 CSS 绘制的终端窗口示意 + 文字。
- **非范围 · 自定义域名**：理由 = 无域名预算与 DNS 运维需求，`github.io` 项目页足够。
- **非范围 · 统计/评论/搜索**：理由 = 与零外部依赖硬要求冲突。

## 四、用户场景

- **画像**：28–40 岁，会装 npm 包，已在用 pi 或正在对比多 Agent 方案，习惯「先看官网 → 再 clone/install」。
- **场景卡 A**：GitHub 仓库页 → 点站点入口 → 30 秒理解定位 → 复制安装命令 → 回终端执行。
- **场景卡 B**：同事安利 → 打开站点 → 扫七个角色 → 点 GitHub 看源码决定是否采用。
- **关键路径**：Hero（定位 + 安装命令 + 双入口）→ 三个毛病 → 七个角色 → 三步装好 → 常见问题 → 页脚 CTA。
- **页面状态清单**：加载 / 空 / 错误态 **不适用**（纯静态无数据请求，理由）；必须覆盖的状态 = ① 窄屏 ≤360px；② JS 禁用；③ 深色模式（`prefers-color-scheme`）；④ 锚点跳转与键盘焦点；⑤ 外链资源失败 **不适用**（无外链）。

## 五、业务规则

- **事实单源**：站点文案事实以 `README.md` 为准；冲突时改站点，不改 README。
- **宿主边界**：站点不得出现「支持 Claude Code / Codex / Cursor」类表述或暗示可互换（`AGENTS.md` 红线）。
- **零敏感值**：无绝对家目录路径、无 token、无内部台账内容。
- **命令一致**：站点安装命令与包名一致（`@nathan33/nao-skill`），且**不带版本 pin** —— 面向首次了解的陌生人，装最新版才对；README 的 `@0.21.3` 是项目级 pin 语境（团队 clone 同款），**两者语境不同，不算双源冲突**。
- **相对路径**：站内资源与链接一律相对路径，兼容 Pages 子路径 `/nao-skills/`。
- **不显示动态版本徽章**：徽章是外部图片 ⇒ 违反零依赖；改为文字「npm 最新版」链接。

## 六、NFRs

- **性能**：首屏可交互 < 1.5s；总传输 ≤ 200KB；请求数 ≤ 4（html / css / js / favicon）。
- **兼容**：Chrome / Safari / Firefox 最近两版，iOS Safari 16+，360px 起可用。
- **可访问性**：正文对比度 ≥ 4.5:1；全部交互可键盘完成且焦点可见；`h1` 唯一；复制反馈有 `aria-live`。
- **SEO/分享**：`title` / `description` / `og:title` / `og:description` 齐全；无外链字体。
- **离线**：本地双击 `index.html` 可完整显示（无 fetch、无绝对路径）。
- **安全**：无第三方脚本、无内联 `eval`、外链一律 `rel="noopener"`。

## 七、AC

- **AC1（主路径 · 首屏）**：Given 陌生访客打开站点，When 页面加载完成，Then 首屏（不滚动）可见一句话定位、安装命令、GitHub 与 npm 两个入口。
- **AC2（主路径 · 复制）**：Given 首屏安装命令旁有复制按钮且命令为 `pi install --local npm:@nathan33/nao-skill`，When 点击，Then 剪贴板内容与站点显示的命令逐字一致、按钮反馈「已复制」；且站点内命令块不含版本 pin（`grep -E '@[0-9]+\.[0-9]+'` 命中 0）。
- **AC3（主路径 · 角色区）**：Given 访客滚到角色区，When 浏览，Then 七个角色各一张卡（角色名 + 一句话职责），一屏内可扫完，且与 `roles.yaml` 角色数一致。
- **AC4（异常 · JS 禁用）**：Given 浏览器禁用 JS，When 打开站点，Then 全部内容可见、安装命令完整可选可手抄，无空白区块或依赖 JS 才出现的内容。
- **AC5（边界 · 窄屏）**：Given 360px 宽视口，When 打开，Then 无横向滚动、卡片单列、代码块可横向滚动不溢出页面。
- **AC6（负向闭环 · 事实与红线）**：Given 逐条比对站点文案与 README / `AGENTS.md`，When 发现事实冲突或宿主越界表述，Then 一律以 README 与红线为准修正；`grep -rn` 家目录路径与 token 结果为空。
- **AC7（NFR · 零外部依赖）**：Given 抓取页面全部资源引用，When 检查，Then 均为同域相对路径、外部请求数 = 0、总量 ≤ 200KB。
- **AC8（NFR · 可访问性与 SEO）**：Given 页面，When 检查，Then `title`/`description`/`og:*` 存在，`h1` 唯一，Tab 可遍历所有交互且焦点可见，正文对比度 ≥ 4.5:1。
- **AC9（设计一致性）**：Given `docs/designs/` 设计稿（设计师 PASS 版），When 对比实现，Then 字体层级/间距/主色与设计稿一致；有意偏差须在 PR 描述列出并说明理由。
- **AC10（上线闭环 · 部署）**：Given PR 合并到 main，When Pages workflow 运行，Then `https://nathan3303.github.io/nao-skills/` 返回 200，页面资源无 404；本地直接打开 `site/index.html` 同样完整。
- **AC11（变更治理 · 文档随 PR）**：Given 本次任务，When 交付，Then PRD / 设计稿 / README 指针 / `tasks-state` 台账全部在该需求分支随同一 PR 进 main。

## 八、上线闭环

- **部署**：合并 main 触发 Pages workflow；无灰度（静态页特性），回滚 = `git revert` 合并提交或删除 workflow 触发源。
- **监控**：不埋点；上线后 PM 自查清单 = 移动端 360px、禁用 JS、键盘 Tab、深色模式、外链可达。
- **验收**：UI 呈现类 ⇒ QA 产 `docs/reports/<编号>-user-acceptance.md` 用户验收清单，PM 审后交用户执行回填。

## 九、变更治理

- 变更走 Issue + 分支 `feat/<issue-id>-portal-site`，合并由 RD 在 PR 上 squash 执行，PM 只验收授权。
- **双源防线**：README 事实变更（安装命令、前置环境、角色名）时，同一 PR 必须同步站点；发版前 PM 核对一次。
- Hotfix 24h 内补 PRD 变更记录；文案措辞调整不算变更，不入本文档。

## 附：优先级与筛子

- **战略筛子**：命中「对外可见度 + 降低首次理解成本」，且不改机制内核、不新增运行时依赖 ⇒ **通过**。
- **MoSCoW**：Must = 单页六段内容 + 复制 + 零依赖 + Pages 部署；Should = 深色模式；Could = 角色卡 hover 细节；Won't = 文档站/双语/统计。
- **RICE**（估算，标注假设）：Reach 200/月（假设 GitHub + npm 导流）· Impact 2（高）· Confidence 60% · Effort 1.5 人日 ⇒ **RICE ≈ 160**，高于本仓待办中位数，排在本批。
- **Kano**：定位清晰属基本型（无则困惑），一键复制与七角色一屏属期望型，深色模式属无差异偏兴奋。

## 5. 业务规则

- **BR1 单源**：`.agents/` 是机制单一事实来源；`docs/tasks-archive.md` 只存**历史快照**，不承载任何活跃规则；活约束（口径 / 待裁量项）一律留在 `tasks-state.md`。
- **BR2 工具契约优先**：台账结构服务于 `task_state_class()` 的三条判定（归档标题措辞 / 非归档表内裸 id / 泛化提及）；任何格式美化不得破坏该契约。
- **BR3 只搬不改**：搬迁内容与原文逐行一致（允许的变化仅限：标题层级、必要分隔、指针行）。
- **BR4 零损失**：迁移条目数前后守恒，可机械核对。
- **BR5 短即纪律**：tasks-state 的**运行态**性质由行数守卫强制（AC2），防止再次膨胀。
- **BR6 格式禁令清单（QA 实测成文 · RD 落地硬约束）**：`sec` = 最近一个 `^#+ 空格` 标题的**整行文本**；归档判定 = `sec ~ /已验收|已归档|归档/`（**纯子串命中，无层级/位置语义**）；`norm()` **只**剥首尾空白与 `` ` ``/`**`；`END` 优先级 `arch > cell > seen > absent`。据此：
  - **A 类（→ 静默变 `closed` = 回收保护消失，最危险）**：运行态小节标题含「归档」字样；标题写成 `##已归档`（`#` 后缺空格 ⇒ 行归上一节）；围栏代码块内以 `# ` 开头的行被当真标题（**无 fence 感知**）；同一 id 同时出现在归档表与非归档表（`arch` 优先）。
  - **B 类（→ 静默变 `active` = 已归档任务 `close` 被误拒）**：**归档墙内插入不含「归档 / 已验收」字样的 `###` 子标题**（如 `### 最近 2 批`）⇒ 其后各行回落非归档区。**这是本批最易踩的一条**（与 §3.4「只留最近 2 批」的自然写法冲突）。
  - **C 类（→ 静默变 `mentioned`，`status` 会打印「仅散文提及」）**：`~~T…~~` 删除线 / `*T…*` 斜体 / `[T…](url)` 链接 / `T…（已闭环）` 括注 / 多 id 单元格 / 丢竖线的行 / 散文提 id（含 `` `T519` `` 反引号与 `wip(T519):`）。
  - **D 类（→ 静默变 `absent`，`status` 报「无记录」）**：`_T…_` 下划线（`_` 属词内字符）；带后缀单元格（`T508-RD` 对 id `T508`）；id 后紧连字母（`T519a`）或内含空格/全角；**id 仅出现在标题行**（标题行 `next` 跳过，不参与分类）。
  - **E 类（唯一安全写法）**：表格单元格 = 裸 `T519` / `` `T519` `` / `**T519**` / `` **`T519`** ``（四者等价）；五小节标题 `## ` + 文本逐字保留且**不得**含「归档」「已验收」子串（`## 已回执待验收` 已实测安全）；历史指针**禁止**在非归档区写裸 id 单元格（推荐整行删除，或写「已交付（见 `docs/tasks-archive.md`）」而不写编号）。

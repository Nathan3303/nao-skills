## 1. 问题证据

- `docs/tasks-state.md` 已 **226 行**，其中**运行态信息不足 15%**；快照区（L6–44）承载 T506–T518 约 20 条批次全文，与 `docs/prds/README.md` 索引、`docs/releases/` **三处重复**。
- 会话重开后「先读本快照」是**硬纪律**（PM 卡 §六 / `pm-operations.md` §三），红牌成本直接由台账长度决定；首读区越长，纪律越易被跳过。
- **实测缺陷（同一文件内自相矛盾 + 语义漂移）**：
  - 「进行中」表 L94–96 保留 **T511a/b/c 已闭环行**，且为**非归档标题下的裸 id 单元格** ⇒ `nao-fleet.sh` 的 `task_state_class()` 判为 **`active`**，与首行声明「本批次列已清空」矛盾；若将来对同编号执行 `close --task`，会被「仍在进行态」闸门**误拒**。
  - 「待派发队列」L83–87 的历史指针写作 `~~T517a~~`：`norm()` 只剥离 `` ` `` 与 `**`、不剥 `~~` ⇒ 靠**巧合**落入非阻断档 `mentioned`。写法**脆弱**，属未登记的隐式依赖。
- 硬约束（决定了本批边界）：该文件**不是纯人类文档，而是工具输入** —— `task_state_class()`（`.agents/scripts/nao-fleet.sh` L691–719）被 `close --task` 闸门（L1611–1619）与 `status` 残留检测（L1546–1556）消费。

## 2. 目标指标

- 主指标：`docs/tasks-state.md` 行数 **226 → ≤85**（−62% 以上），运行态占比 **>60%**。
- 质量指标：**历史信息零丢失**（逐条可追溯到 `docs/tasks-archive.md`）；`task_state_class()` 分类语义**零回归**（这是本批唯一真实风险面）。
- 非目标（明确不计入）：不追求「台账与 PRD 索引单源合一」的架构改造（另议）。

## 3. 范围 / 非范围

**范围内**
1. 新建 `docs/tasks-archive.md`：承接 (a) 快照区历史批次条目（T506–T518 逐条）、(b) 「已验收 / 已归档」表的旧批次行、(c) 两个「已闭环批次 · T507 / T508」附录、(d) 「侦察结论（2026-10-08）」节；**只搬迁，不改写事实**。
2. 重写 `docs/tasks-state.md` 为运行态骨架：`PM 接续快照`（按 `templates/tasks-state.md.example` 字段：当前阶段 / 当前 PRD / 未决决策点 / 待用户回答 / 未派发队列 / 下次唤醒条件 / 口头约束已落盘 / 需求分支 / 会话体检）+ 交接点 + **活约束两节**（「既定口径（长期有效）」与「待用户裁量后续项」**必须留在 tasks-state**，它们不是历史）+ 五个运行时表（标题名原样保留）。
3. 修正 §1 两处缺陷：T511a/b/c 移入归档区 / 迁入 archive（不再构成非归档区裸 id）；历史指针统一为不依赖 `~~` 的稳定写法。
4. 「已验收 / 已归档」小节**只保留最近 2 批**（T518、T517）+ 一行指向 `docs/tasks-archive.md` 的指针。
5. 头部规则 blockquote 增补一行「历史见 `docs/tasks-archive.md`」。

**非范围（带理由）**
- 不改 `.agents/scripts/nao-fleet.sh`：解析器行为本身无缺陷（缺陷在台账内容），改动需回归脚本类用例，收益/风险不成立。
- 不改 `.agents/templates/tasks-state.md.example`：其骨架字段即本批目标形态；新台账多出的两节「活约束」属项目级内容，**模板不应固化项目口径**。
- 不改 `tests/`、`bin/`、任何角色卡与技能文档：本批零行为变更。
- 不做「台账 ↔ `docs/prds/README.md` 去重单源化」：触及索引语义，另议另立。
- 不删除任何历史条目（只搬迁）。

## 4. 用户场景

- **PM 会话重开后**：读 `tasks-state.md` 首读区（≤85 行）即可完成「当前阶段 · 未决决策 · 口头约束」三行回读，不再被 20 条历史淹没。
- **PM 派发/回收时**：`close --task <编号>` 闸门读到的分类语义与台账事实**一致**（已闭环批次不再被误判 `active`）。
- **追溯历史时**：需查 T509 的验收结论 → 打开 `docs/tasks-archive.md` 或沿其指针到对应 PRD/report，**信息不丢**。

## 5. 业务规则

- **BR1 单源**：`.agents/` 是机制单一事实来源；`docs/tasks-archive.md` 只存**历史快照**，不承载任何活跃规则；活约束（口径 / 待裁量项）一律留在 `tasks-state.md`。
- **BR2 工具契约优先**：台账结构服务于 `task_state_class()` 的三条判定（归档标题措辞 / 非归档表内裸 id / 泛化提及）；任何格式美化不得破坏该契约。
- **BR3 只搬不改**：搬迁内容与原文逐行一致（允许的变化仅限：标题层级、必要分隔、指针行）。
- **BR4 零损失**：迁移条目数前后守恒，可机械核对。
- **BR5 短即纪律**：tasks-state 的**运行态**性质由行数守卫强制（AC2），防止再次膨胀。

## 6. 非功能需求（NFR）

- **可读性**：tasks-state 首读区 ≤85 行；单行 ≤120 字符（不新增超长行）。
- **可离线**：所有指针为**仓内相对路径**，无外链依赖（`docs/tasks-archive.md` 与既有 PRD 同仓）。
- **无分发影响**：`docs/` 不入 npm 包（`package.json files = ["bin/", ".agents/", "README.md", "LICENSE"]`）⇒ 本批**不影响发布产物**。
- **无测试影响**：`tests/` 不解析该文件内容（用例统一指向不存在的 `NAO_TASKS_STATE`）⇒ 门禁仅作回归确认。
- **零敏感值**：保持仓库红线（无 token / 私钥 / 绝对家目录路径）。注：历史条目中的 `~/Project/...` 写法与现状一致，仅**原样搬迁**，不新增。

## 7. 验收标准（AC）

- **AC1（结构一致性 · 主路径）**：`docs/tasks-state.md` 五小节标题**原样保留**：`## 待派发队列` · `## 进行中` · `## 已回执待验收` · `## 挂起（被抢占 / 降级）` · `## 已验收 / 已归档`；且归档小节标题含「已验收 / 已归档」字样。
- **AC2（容量守卫 · 边界）**：`wc -l docs/tasks-state.md` **≤85**。
- **AC3（历史守恒 · 主路径）**：`docs/tasks-archive.md` 存在且承接：(a) 迁移前快照区全部批次条目、(b) 已验收墙旧行、(c) T507 / T508 两附录、(d) 「侦察结论」节；条目计数与迁移前一致（**N 条**，由 RD 在回执中给出精确数字并逐条列出编号）；`tasks-state.md` 头部含指向它的**相对路径指针**。
- **AC4（工具契约不变量 · 负向闭环）**：以**只读探针**（`NAO_TASKS_STATE` 指向临时夹具文件，不触碰真台账）证明 `task_state_class()` 三条语义不变：① 迁移后任一历史 id **不再**判 `active`；② 在非归档表内写入裸 id 仍判 **`active`**（保护未验收任务的机制完好）；③ 归档区表内裸 id 判 **`closed`**；④ 泛化提及判 **`mentioned`**。任一不成立即 FAIL。
- **AC5（缺陷闭合 · 异常）**：`docs/tasks-state.md` 中 **T511a / T511b / T511c 不再作为非归档小节表内的裸 id 出现**；历史指针不使用依赖 `~~` 的写法（改用删除线以外的稳定形态，如括注「已闭环，勿重复派发」）。
- **AC6（全范围门禁 · 设计一致性）**：`bash .agents/scripts/nao-fleet.sh check` **exit=0**（roles=6，files 数不变）+ `npm test` **exit=0**，均给出精确数字。
- **AC7（零损失抽检）**：随机抽 ≥6 条迁移条目，与 **git 历史原文**（`git show HEAD:docs/tasks-state.md` 对应行）**逐行一致**（仅允许标题/分隔/指针差异）；`.agents/scripts/nao-fleet.sh`、`tests/`、`bin/` 在本批 diff 中**零命中**。
- **AC8（可追溯性）**：`docs/tasks-archive.md` 顶部声明其**非权威历史快照**性质，并指向 `docs/prds/README.md` 与 `docs/releases/` 作为权威来源（呼应 BR1）。

**AC 五覆盖自检**：主路径 = AC1/AC3/AC8；异常 = AC5（缺陷闭合）；边界 = AC2；负向闭环 = AC4（不变量被破坏即 FAIL）；设计一致性 = AC6/AC7（门禁 + 零越界 + 与模板/工具文档措辞一致）。

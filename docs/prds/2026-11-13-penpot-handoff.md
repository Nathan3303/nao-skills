# Penpot 出图协作闭环（设计产物 → 实现契约 + PM 派发闸门）

- 状态：待确认 · 更新：2026-11-13 · Owner：PM
- 指针：Issue [#110](https://github.com/Nathan3303/nao-skills/issues/110) · 触发批次 PRD `docs/prds/2026-11-13-portal-site.md` · 设计稿 `docs/designs/2026-11-13-portal-site.md`

## TL;DR

- **做什么**：把「设计稿交给实现」这件事从口头变成契约 —— 出图方必须写清图源、实现方必须按图写码、PM 不得越过用户直接开工。
- **给谁**：本仓三张角色卡（`uiux-designer` / `rd-fe` / `pm`）+ 设计技能 + 开工卡模板。
- **成功标准**：交付物含图源信息（可机械查）；实现前有「是否 Penpot 出图」检查项；开工卡含「设计验收模型」一问。
- **不做什么**：Penpot MCP 接入（另立项）· 导出文件格式规范 · 画板与实现的自动一致性检查。

## 一、问题证据

- **实测案例（T541 门户批次）**：rd-fe 首版严格按设计稿的**文字规格**实现，用户当场指出与 Penpot 四画板差距大 ⇒ 全部重做，返工一轮。
- **同批第二处**：PM（我）在设计稿 PASS 后**直接派 rd-fe 开工**，未经用户确认设计稿满意度 ⇒ 用户是在实现产物上才发现偏差。
- **第三处（F3）**：设计稿文字规格与画板自相矛盾（留白 96 vs 80、360 内边距 16 vs 24、字阶 6 档 vs 14 档），根因是**图源未作为唯一基准写清**。
- **5 Whys**：为什么返工 → 实现依据不是画板 → 因为 rd-fe 不知道 uiux 用了 Penpot 出图 → 因为交付物没有图源信息要求 → 因为角色卡没有「设计→实现」的交接契约；为什么用户晚知道 → 因为 PM 派发闸门里没有「设计稿需用户确认」这一环。
- **证据强度**：强（同一批次三处实证，用户原话约束）。

## 二、目标指标

- **北极星**：Penpot 出图批次里「实现按图、一轮通过」的比例上升（T541 为 2 轮）。
- **可机械查的拆解**：① uiux 交付物含「文件 id + 画板名/尺寸 + 图层命名」三项；② rd-fe 卡含「写码前检查」动作项；③ 开工卡含「设计验收模型」一问。
- **口径说明**：不埋点、不统计；以三张卡的可 grep 断言 + 一次真实批次（下一批设计类需求）验证。

## 三、范围 / 非范围

- **范围 1**：`.agents/prompts/uiux-designer.md`（v1 → v2）加**交付契约**：用 Penpot 等 MCP 出图时，交付必须写明图源信息（文件 id / 文件内页名 / 画板名与尺寸 / 图层命名规则），必要时**导出到仓内文件**作本地依据；仓库内不出现实例 URL 与凭证。
- **范围 2**：`.agents/prompts/frontend-developer.md`（v12 → v13）加**实现前置检查**：写码前必须确认 uiux 是否用 Penpot 出图；若是 ⇒ **以图为准实现**，不得只按文字规格自行发挥；允许反驳，但须**走流程回退**（回设计师 → 设计师改稿或出具带 AC 编号的可执行修改项 → 重新放行），不得在实现里静默偏离。
- **范围 3**：`.agents/prompts/product-manager.md`（v34 → v35）加**派发闸门**：uiux 用 Penpot 等 MCP 出图后，PM **不得直接派 RD**，须由用户确认设计稿满意；例外 = 用户明确托管；且**必须在任务开工前就问清**（开工确认卡新增一问「设计稿验收模型 = 用户本人确认 / 托管给 PM」）。
- **范围 4**：`.agents/skills/uiux-design.md` 交付物清单同步加「图源信息」项（与卡不双源：卡为纪律，技能为清单细则）。
- **范围 5**：开工卡模板落点（`.agents/skills/pm-operations.md` §一 派发协议 + `.agents/checklists/comm-templates.md` 开工确认卡）含该问；PM 卡 §六 给指针。
- **非范围 · Penpot MCP 接入**：理由 = 属独立的工具接入与隔离议题（已预占 T540），本批只定「用 MCP 出图之后怎么交接」。
- **非范围 · 导出文件格式规范**：理由 = 先要求「必要时导出」，格式随首次真实需要再定，避免过度设计。
- **非范围 · 自动一致性检查**（画板 ↔ 实现）：理由 = 需要图像比对能力，成本远超收益。
- **非范围 · 其他 MCP/工具**：理由 = 规则以「用绘图类 MCP 出图」表述，不绑定 Penpot 一家，避免下次换工具重写。

## 四、用户场景

- **画像**：用户（项目所有者）+ 三个角色协作；用户不参与实现，但**对视觉结果有最终决定权**。
- **场景卡 A（有 Penpot）**：PM 委托设计 → uiux 用 Penpot 出四画板 → 交付写明图源（文件 id/画板名/图层命名），必要时导出 → **用户确认设计** → PM 才派 rd-fe → rd-fe 先核图源 → 按图实现 → 有意偏差在 PR 描述列出。
- **场景卡 B（无 Penpot，纯文字规格）**：uiux 只给文字规格 → 本契约**不触发**（不强制图源）→ PM 仍须在开工卡问设计验收模型。
- **场景卡 C（rd-fe 认为图不合理）**：rd-fe 提出反驳 → **流程回退**：回设计师 → 设计师改稿或出具带 AC 编号的修改项 → 重新放行 → rd-fe 再实现。
- **关键路径**：PM 开工卡（含验收模型一问）→ uiux 交付（图源）→ 用户确认 → PM 派发 → rd-fe 前置检查 → 实现 → 验收。
- **页面状态清单**：不适用（纯文本机制，无界面）。

## 五、业务规则

- **R1 图源必写**：用绘图类 MCP 出图时，交付必须含「文件 id / 页名 / 画板名与尺寸 / 图层命名」四项；缺任一项视为交付未完成。
- **R2 图为准**：有图源时，**图是唯一实现基准**；文字规格与图冲突 ⇒ 以图为准并要求设计师改文字（未改前不得按文字实现）。
- **R3 反驳要走门**：rd-fe 的反驳只能经「回设计师」通道生效；**实现里的静默偏离**一律判缺陷（PR 描述必须列有意偏差）。
- **R4 用户确认闸门**：uiux 出图后 PM 不得直接派 RD；须用户确认（或用户在开工卡时明确选择托管）。
- **R5 一问前置**：开工确认卡必须含「设计稿验收模型」一问，**默认不托管**（不答 = 用户本人确认）。
- **R6 零凭证**：仓库内不得出现 MCP 实例 URL、token、绝对家目录路径；只保留可追溯标识。
- **R7 不绑定单一工具**：规则表述为「绘图类 MCP」，Penpot 是当前实例。

## 六、NFRs

- **文档体量**：三张卡**净增 ≤ 6 行/张**（短常驻，防膨胀）；技能文件 ≤ +3 行；模板 ≤ +2 行。
- **一致性**：同一规则只在一处写全，其余给指针（卡 = 纪律，技能 = 清单细则，模板 = 提问形状）。
- **版本纪律**：三张卡均 bump `version` + 更新 `updated`，并给广播文本。
- **可机械核**：每张卡的规则应可 `grep` 到关键字（如 `Penpot` / `图源` / `验收模型`），供 `check` 或复核使用。
- **不引入运行时依赖**：纯文本改动，`check` 的 `files` 计数不变（只改既有文件）。

## 七、AC

- **AC1**：Given `uiux-designer` 卡，When 查其交付要求，Then 含「文件 id / 页名 / 画板名与尺寸 / 图层命名」四项 + 「必要时导出到仓内文件」+ 「仓内无实例 URL 与凭证」。
- **AC2**：Given `frontend-developer` 卡，When 查实现前置，Then 含「写码前确认 uiux 是否用绘图 MCP 出图」+「是则严格按图实现」+「反驳须走流程回退（回设计师 → 改稿或带 AC 编号的修改项 → 重新放行）」。
- **AC3**：Given `product-manager` 卡，When 查派发闸门，Then 含「出图后不得直接派 RD，须用户确认（例外 = 明确托管）」+「开工卡必须新增一问，默认不托管」。
- **AC4**：Given `skills/uiux-design.md`，When 查交付物清单，Then 有「图源信息」项且与卡不重复矛盾（只放清单细则）。
- **AC5**：Given 开工卡模板（`pm-operations.md` §一 与 `comm-templates.md`），When 查模板，Then 含「设计稿验收模型：用户本人 / 托管给 PM」一问；PM 卡 §六/§十三 给指针而非复制。
- **AC6**：Given 三张卡，When 查版本，Then `version` 各 +1（uiux 2 / rd-fe 13 / pm 35）且 `updated` = 2026-11-13；并产出广播文本（`card <role> v<N>` 摘要）。
- **AC7**：Given 三张卡 + 技能 + 模板，When 查表述，Then **R1–R7 无遗漏、无互相矛盾**；同一规则只有一处写全（其余指针）。
- **AC8**：Given 反例，When uiux 未用绘图 MCP（纯文字规格），Then 契约不触发（不要求图源），但 AC3 的一问仍生效。
- **AC9**：Given 仓库，When 跑门禁，Then `bash .agents/scripts/nao-fleet.sh check` rc=0 且 `files` 计数不变；`npm test` rc=0。
- **AC10**：Given 文档，When 查敏感面，Then 三卡/技能/模板内无实例 URL、无 token、无绝对家目录路径（`grep` 0 命中）。

## 附：优先级

- **战略筛子**：命中「降低返工（今天实测 1 轮）+ 明确用户对视觉的决定权」，纯文本改动、零运行时风险 ⇒ **通过**。

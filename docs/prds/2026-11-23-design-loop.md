# PRD · 设计循环（灰模先行 · 外视评审）· T557

- 立项：2026-11-23 · 通道 `feat` · 目标版本 **v0.29.0 MINOR**（流程变更：PM 开工卡新增一问）
- 来源：用户 2026-11-23 提出「从 GitHub 读 Oil UI 与 antislop-ui-ux-skill 两个 SKILL 来补充 UI 设计流程」；四答已拍板（见 §五 BR0）· Issue [#158](https://github.com/Nathan3303/nao-skills/issues/158)

## TL;DR（≤5 行）

把「反 AI 味清单」升级成**可执行的设计循环**：先一句话说清这屏为谁存在 → 灰模里定组织（组织层面在灰模阶段改一次，比日后返工便宜得多）→ 上色实现 → 自查第二遍 → **派一个无上下文的会话做外视评审** → 只改清单上确认过的项。新增一份按需技能承载循环，角色卡只加红线与指针；PM 开工卡加一问（设计类需求必答「先灰模还是直接上色」）。

## 一、问题证据（现状缺口，逐条可查）

1. **灰模不是流程步骤**：`@.agents/skills/uiux-design.md` §二 把 ASCII 线框放在**降级档 ②**（无原型工具时的替代），不是「上色前必须先定组织」的闸门 ⇒ 现状允许直接出高保真规格。
2. **无多方向对比**：现状一次交付一份规格，没有「两个组织方案并排给用户选」的形态。
3. **「参考→概念非复制」无规矩**：`uiux-design.md` §五 只列反 AI 味现象，缺上游那条（照搬别人的配色/字体/版面 = 另一种 AI 味）。
4. **无独立外视评审**：设计产物只在 PM/QA 同一上下文里被自查，缺「无上下文者只按材料判」的入口；而我们有 intercom 多会话能力，天然可派。
5. **视觉验收无判据**：`@.agents/checklists/qa.md:24` **整改前**只说「应启动浏览器自动化（无头浏览器/截图对比）」，没有**声明视口、截哪几张、看什么、无能力时怎么降级**的可判定要求。
6. **跨需求无偏好载体**：`docs/designs/` 是一次性报告，用户上一批拒绝过的做法下一批会被重新提案（同类返工）。

## 二、目标指标

- 设计类需求**上色前必须有一次结构确认**（灰模或组织方案二选一），且确认内容可被第三方从报告里读到。
- 反 AI 味从「事后清单」变为「循环里的两次自查」（识别信号 → 定位到具体位置；实现后自查第二遍）。
- 外视评审**可派、可复现**：给材料清单固定（页面/视口/AC/设计报告），不给预期结论，只读。
- 视觉验收有机械判据：声明视口 + 截图清单（或明确降级理由）。

## 四、用户场景

- **新页面**：PM 问「先灰模还是直接上色」→ 选灰模 ⇒ uiux 出两版组织骨架（同一屏，导航/信息块位置不同）→ 用户选一版 → 上色规格 → 实现 → 外视评审出清单 → 只改确认项。
- **存量改版**：先盘点现有页面与 token，留基线截图，再进循环；品牌资产保留，只重定「历史上随手定下、从没被正式决定过的取值」。
- **只读评审**：不给改法，只给信号清单与位置（`文件:行` 或 `视口 + 区块名`），结论交 PM 决定是否开工。

## 五、业务规则

- **BR0（用户拍板 2026-11-23）**：① 只取方法、全部用自己的话重写 ② 新建 `.agents/skills/design-loop.md` + 现有文件只留指针 ③ 灰模先行做成 PM 开工卡必答一问 ④ T555 收尾后立项。
- **BR1**：设计类需求（定义沿用 `product-manager.md` 既有 BR2/BR2a 口径）开工时必须回答「灰模 / 直接上色」；不答 ⇒ 默认灰模。非设计类需求写「不适用」，不扩大范围。
- **BR2**：任何参考只取**概念**（层级、节奏、隐喻），不取**拷贝**（配色、字体、原样版面）；报告中须写「参考了什么、取了哪条概念、丢了什么视觉」。
- **BR3**：外视评审由 PM 另派**无上下文会话**（同仓另一 pane，`--task` 派生）；只给材料信封，不给预期结论与判据答案；被评审方不得先解释设计意图（防自证）。
- **BR4**：无看图 / 无浏览器能力时走降级：写明「未验证实际视觉」+ 给可核的文字判据（层级/间距/对比度数值），**不得**因此判阻塞。
- **BR5**：零第三方文本 —— 技能文件与卡里不得出现来自 Oil UI / antislop-ui-ux-skill 的原句（**已知边界：机械闸只挡精确串，翻译变体挡不住** ⇒ 由人工抽验兜：每次设计类交付 + QA 轮各读一遍，判有无成段照译）；只允许「方法来源」一行指针（含仓库 URL 与许可证名）。Oil UI 为 MIT（可借鉴改写需留出处）；antislop-ui-ux-skill 为 All Rights Reserved（**只用想法，不搬文本**）。

## 七、AC

### 主路径

- **AC1（路由可判）** `design-loop.md` §一 的 6 类任务各有「走几步 / 哪步可略」；抽 3 类由第三方按表能判出该走哪条，无「看情况」式表述。


### 异常（缺项即不成立）

- **AC2（灰模是闸门）** 技能文件明确规定「上色前须有组织确认」；`uiux-designer.md` 有一条红线指向它；PM 卡开工一问在 M3 落地（措辞可 grep 到、且与既有设计闸门不重复）。


### 边界

- **AC3（屏幕角色句）** 交付物要求一句**角色句**：模板 = 「这屏在 **<何时>** 帮 **<谁>** 完成 **<什么>**；**<哪件事>** 不在这里，它属于 **<哪一屏>**。」缺句 ⇒ 交付未完成（写进 M1 与 M2）。**本模板为本仓自行表述**（原「存在是为了 / 不是…的屏」写法是第三方作品原句的直译，已弃用，见 BR5）。

- **AC4（参考→概念）** 黄金律 + 报告字段（参考了什么/取了哪条概念/丢了什么视觉）在 M1 单源；§五 既有反 AI 味清单保留不重复。


### 可派可复现

- **AC5（外视评审可派）** M1 给出材料信封（页面/视口/AC/报告路径/禁止项/回执形状），并写明「被评审方不先解释意图」；PM 侧有可执行派发命令样例（`ensure <角色>@. --task T<n>` 形态）。

- **AC6（视觉验收判据）** `checklists/qa.md` 该条可勾选判定：① 声明视口清单 ② 截图或降级理由 ③ 空/加载/错误态 ④ 2 秒测试结论。四项缺任一 ⇒ 未过。


### 负向闭环

- **AC7（静态契约用例）** 新增 `cases/42`：断言 M1 文件存在且含 7 节标题、含关键词（灰模 / 概念 / 外视 / 视口 / 偏好）、**零第三方原句**（对 3 条特征串断言 0 命中，作为版权面机械闸）、`uiux-designer.md` 与 `product-manager.md` frontmatter `version` 已 bump、两个卡片含指向 M1 的指针、`checklists/qa.md` 四项判据关键词在位；并配 1 条负控（删掉 §四 黄金律 ⇒ 必红）。

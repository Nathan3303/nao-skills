# PRD：视觉测试移交用户侧（用户验收清单）

- 状态：已定稿 · 更新：2026-10-13 · Owner：PM（nao-skills 机制文档修订，QA 卡/技能/清单维护者 = PM）
- 指针：本 PRD 为 nao-skills 机制文档修订；上游决策 = 用户 2026-10-13 澄清三问拍板

## TL;DR（≤5 行）

- **做什么**：QA 的**视觉/UI 呈现验证**不做浏览器自动化（无头浏览器/截图对比等），改为**产出「用户验收清单」**移交用户人工执行。
- **给谁**：QA 角色卡与相关技能/清单；下游受影响 = 所有使用 nao 舰队的项目的 QA 会话行为。
- **成功标准**：QA 视觉层零自动化依赖；每次含 UI 呈现的交付必带用户验收清单；清单与 AC 映射、用户可操作可回填。
- **不做什么**：功能/交互 E2E（Playwright/Cypress）自动化保留；rd-fe 的 `ui-tokens-check.sh`（静态令牌扫描，非视觉测试）不动；不新建预览环境机制。

## 一、问题证据

- 用户观察：视觉类验证用无头浏览器/截图对比，成本高（维护脆弱、AI 生成 UI 需人眼判断「反 AI 味/风格一致」）、收益低（视觉是主观判断，自动化只能查机械指标）。
- 用户决策（2026-10-13 澄清拍板）：视觉测试移交用户侧；不需要无头浏览器或其他技术；移交时提供测试项目列表（测什么 / 怎么操作 / 结果应是什么）。
- 5 Whys 摘要：为什么视觉自动化贵 → 断言项不可机械化（风格/气质/体感）→ 为什么断言项不可机械化 → 视觉验收本质是人眼判断 → 谁是最权威的人眼 → 最终用户 → 结论：视觉验收应交付用户并给出可执行清单，而非自动化逼近。

## 二、目标指标

- QA 视觉层自动化断言数 **= 0**（截图对比/无头浏览器看 UI 呈现类项全部转为人工清单项）。
- UI 呈现类交付（改 UI 的需求批次）**100%** 附带用户验收清单（含 视觉一致性 / 四态 / 响应式 / 键盘可达 / 对比度 / reduced-motion / 禁 AI 默认样式 抽查）。
- 清单每项含「测什么 / 怎么操作 / 预期结果 / 对应 AC」，用户按清单操作可独立回填结果。

## 三、范围 / 非范围

**范围内**
- QA 卡（test-engineer.md）视觉职责改写：视觉/UI 呈现验证 → 产出「用户验收清单」并移交用户。
- test-engineer.md 技能包 test-design.md：视觉/UI 呈现测试节改为「用户验收清单方法」（含覆盖项清单与示例），删除/替换无头浏览器视觉自动化建议。
- checklists/qa.md：视觉相关红线/交付项同步（新增「用户验收清单」交付检查项）。
- 新增用户验收清单模板（`templates/user-acceptance.md.example` 或等价落点）+ deliverable-docs 文档类型表登记。
- PM 侧联动：PM 卡/checklists/pm.md 在验收闭环处补「UI 呈现类验收 = 用户验收清单（QA 产出 → PM 审 → 用户执行回填）」指针。

**非范围**
- 功能/交互 E2E（Playwright/Cypress）自动化**保留**，不动其规范。
- rd-fe 的 `ui-tokens-check.sh`（代码级令牌静态扫描）不动。
- 预览环境机制（有无、怎么起）不在本批改。
- 不删断言库/既有截图资产（存量随用随清，不追溯）。

## 四、用户场景

**QA 视角**：收到含 UI 呈现的派发 → 功能/交互测试照旧（自动化 + 手动）→ 视觉项**不启动浏览器自动化** → 按模板产出用户验收清单（对应 AC）→ 回执时附清单路径。
**PM 视角**：验收前审清单（覆盖项齐、可操作、含预期结果）→ 在 PR/验收环节把清单交用户 → 用户执行回填 → QA 据回填关闭/重开缺陷 → PM 归档。
**用户视角**：收到「用户验收清单」→ 按步骤操作（每步：做什么 → 怎么操作 → 预期见什么）→ 逐项勾 通过/不通过 + 备注（截图可选）→ 回传。

## 五、业务规则

- **清单覆盖项（最低集）**：视觉一致性（tokens/组件库/既有风格）· 四态（加载/空/错误/成功）· 响应式（关键断点）· 键盘可达（focus 可见）· 对比度 · `prefers-reduced-motion` · AI 默认样式抽查（frontend-design calibration 7 类）。凡需求涉及 UI 呈现的，按范围取用，不适用项写「不适用 + 理由」。
- **清单要素（每项必含）**：编号 · 对应 AC · 测什么（一句话）· 怎么操作（可执行步骤）· 预期结果（用户可判断的具体现象）。
- **回填闭环**：用户回填 通过 / 不通过（附理由或截图）；QA 据此关闭缺陷（通过）或 Reopen/新增（不通过）；缺陷管理仍走既有生命周期。
- **移交时点**：QA 回执（done）时附清单路径；PM 在验收环节安排用户执行——**用户在场**直接交用户；**无人值守**清单落盘 `docs/reports/<编号>-user-acceptance.md`，用户按需取用。
- **QA 红线更新**：不做视觉浏览器自动化（截图对比/无头浏览器验证 UI 呈现）为红线项；测试执行前确认不变（用户在场问用户 / 无人值守按开工确认卡）。

## 本次更新

**两个仓可以同时各跑一套角色了。** 以前在桌面版里，两个仓同时起「产品经理」会直接报名字冲突；现在第二个仓会自动换个名字（`pm2`）接着起来。这一版还加了一个开关，让新目录首次启动不再卡在「信任这个目录？」的提示上，并把 README 按普通读者的读法重写了一遍。

## ✨ 更好用了

- **多仓同时开工**：两个仓各起一套角色，第二个仓的同名角色会自动加编号（`pm2`、`qa2`…）。以前会直接报「名字已被占用」并起不来。
- **新目录首次启动不再卡住**：`ensure` 加上 `--trust-project`（或设 `NAO_TRUST_NEW_REPO=1`）后，第一次在某个目录拉起角色时，不再停下来等你按确认。默认不开，保持原来的安全行为。
- **README 重写**：按「普通读者能不能照着做」重排了结构，把「从旧名升级」的说明挪到后面，长句拆开，术语第一次出现时补了半句解释。
- **首页与文档站**：新增「手机上看舰队」一页；首页只留一个实心按钮，主次更清楚。

## ⚠️ 请留意（行为变更）

- **同名角色会自动编号了**：桌面版形态下，第二个仓的 `pm` 会变成 `pm2`（以前直接失败）。终端形态（TUI）不变，两个仓仍然都叫 `pm`。
- **同名但没有身份标签的终端 ⇒ 现在会拒绝并告诉你怎么办**（`hc ls` / `hc kill` / `--force`）。以前会静默再起一个，你会有两个同名终端。
- **`--trust-project` 会放宽该次启动的安全边界**：那一次启动的 AI 会加载该目录的项目级扩展与设置。只在你信任的目录用；它不写任何持久设置。
- **已知问题**：这种「同名但缺身份标签」的终端，`status` 仍会把它显示成「未运行」（实际在跑）。已登记待修，不影响使用。

## 🐛 修好了

- **README 里一处与站点矛盾的写法**：原文说「两个仓各跑各的、不撞车」，这在桌面版形态下不成立。现在明确分开两种形态写。
- **筛选卡片的图标检查**：页面引用的图标若与同页其它资源前缀不一致，现在会直接报错（以前配置写错也照样通过）。

# T537 架构评审：下游仓自定义角色会话（`ensure --card`）

- 状态：已定稿 · 更新：2026-11-01 · Owner：arch-designer
- 指针：PRD `docs/prds/2026-11-01-downstream-role-sessions.md`（附录 B = 开工卡 D1–D4）· 决策留痕 `docs/adr/2026-11-01-downstream-card-sessions.md` · 上游 ADR `docs/adr/2026-10-31-fleet-status-repo-attribution.md`（T530 三态）· `docs/adr/2026-10-14-subagent-session-identity-exclusion.md`（T525 排除面）

## TL;DR

- **结论：有条件可行**（范围不需改，AC 需增 3 条、BR 需增 3 条；见 §二）。
- 最关键的漏项不是 symlink，而是 **BR2 只做了"精确不相交"、没做"前缀不相交"**：卡 role 取 `qa-audit` 会抢走 `qa-` 枚举、`subagent-review` 会让会话"拉起即失联"。
- `close` 的常驻/一次性判别式现在是 `[[ -z "$task" ]]`，**结构与语义都不对**，必须改成显式 `IS_RESIDENT` 布尔，否则 AC4③ 必然假绿。
- `status` 扩前缀集方向可行，但必须靠"前缀不相交"把复杂度挡在 BR2，才能保住 6 角色既有行**逐字不变**（AC5③）。
- `--card` 的**语法绑定**PRD 未定，现解析器是全量 flag + 事后遍历 positional，`ensure qa --card x.md` 会静默整批生效 —— 必须定成目标级修饰符 + 两相执行（否则 BR6 零副作用不可达）。

## 一、可行性结论

**有条件可行。** 技术路径（复用 `build_system_prompt` / 派生回收 / 三态归属）成立，改动面仍是单文件 + `check` 一节 + 用例；不新增配置、不动清单、不改常驻语义。条件 = §二 的 Q1-① 与 Q2/Q3/Q4 的 5 条硬口径全部落地，且 §五 三个决策点先拍。

## 二、五问结论

### Q1 信任边界：symlink 用例不足以收敛，但方向对；缺的是"前缀不相交"

先改正定性：**BR3 是可审计边界，不是权限边界**（fleet 与调用者同 uid、同文件权限，调用者本就能任意改写工作区文件）。因此不做 uid/属主判定（多用户共享仓属非目标，写入"限制与已知边界"），只做**正确性 + 事故预防**六条：

1. **边界基准必须是 `--repo` 的 realpath**：`nao_phys_path`（`:1340`）复用；判据 = `realpath -e <card>` 的**父目录**与 `<realpath repo>/.agents/prompts` 相等（组件级，用 `repo_contains_path` `:1351` 的组件语义，不用裸字符串前缀）。`--repo` 本身是 symlink ⇒ 允许，但比较基准取其 realpath（否则 `repo/../` 形式可绕）。
2. **显式拒绝而非依赖 realpath 兜底**：入参含 `..` 段 ⇒ die；后缀非 `.md` ⇒ die；相对路径按 **realpath(repo)** 解析（不是 `$PWD`，否则 `--repo @other` 时两者分歧）；诊断文案必须含"该怎么办"（`卡必须位于 <repo>/.agents/prompts/`）。
3. **常规文件校验**（AC2 未覆盖的真实故障面）：解析后须为 regular file；排除 fifo/设备/目录 —— `cat` 一个 fifo 会让 `build_system_prompt` 永久挂死（不是"校验失败"，是拉起命令卡死）。加大小上限 **256 KiB**（超限 die：提示会被整段塞进 system prompt）。
4. **卡 role 字符集**：`^[a-z0-9][a-z0-9_-]*$`、不以 `-` 结尾、≤32 字符。理由：标题契约（`visible_session_names` `:681` 的 `s/^π - \([A-Za-z0-9_-]*\) - .*/\1/p`）与 `pane_cwd_snapshot`（`:1370`）的会话名正则都只认这个集合，越界即"起得来但看不见"。
5. **BR2 扩为三条（本评审最关键的一条）**：卡 role ① 不得等于任何 `ROLE_ORDER`/别名（现有）；② **不得以任何常驻 id/别名为 `<x>-` 前缀**（新增，防 `qa-audit` 抢 `qa-` 枚举，见 Q2）；③ **不得以 `subagent-` 开头**（T525 保留前缀，`check_alias_resolution` `:255` 已对清单强制同款 —— 否则该会话被 `subagent_in_field` 计成子代理、被 `cmd_close` `:1513` 直接拒收，拉起即失联）。
6. **内容不可信面显式声明**：卡正文 = 系统提示 = **完全可信输入**（"能写该仓者即定义角色"），fleet 只做 frontmatter/引用/EOL 的**一致性**校验，不做也不该做内容安全校验；`check` 对 CRLF 卡给 warn。另：卡在拉起时被复制进临时提示文件（`build_system_prompt` `:1067` 既有行为），会话中途改卡不影响在跑会话 —— 写进 README 一节。

结论：symlink 逃逸用例（AC2 第 5 项）只挡"误用"，挡不住"避开目录约定"；真正必须补的是 ①（比较基准）②（显式拒绝）③（挂死面）⑤（前缀不相交）。

### Q2 `status` 识别口径：可行，但必须"不相交 + 反链 + 后缀形状 floor"

- **前缀集**：`CARD_ROLE_SET` = `repo_anchor_roots`（`:1355`，主锚 `pwd -P` + git toplevel）下 `<root>/.agents/prompts/*.md` 的 `frontmatter role`（退化文件名）。用**锚根全集**而非裸 `$PWD`：否则在 `.agents/` 子目录跑 `status` 集合就空掉（与 T534 锚口径一致）。运行时读、不落状态文件（守"不新增配置"）。
- **枚举结构**：现有 `for role in "${ROLE_ORDER[@]}"` 循环（`:1481`）**逐字不动**，其后追加卡角色循环。因为 BR2② 保证前缀不相交，两条循环不可能抢同一名字 ⇒ 零回归**可证**，不需要重写既有循环，也不引入 `break` 顺序敏感问题。**这是把复杂度挡在 BR2 的唯一理由。**
- **卡集内部**：`a-b` 与 `a-b-c` 并存时现有"首个命中即 `break`"会错分 ⇒ `check` 对卡集**前缀嵌套直接报错**（前缀反链），`status` 仍用最长匹配作纵深防御（两行）。
- **floor（什么时候必须"不可判定"而不是猜）**：
  - F1 名册与 pane 两路 cwd 皆空 ⇒ 现有 `unknown`（`:1418`，不改，fail-closed 已正确）。
  - F2 名字命中卡集但仓不属本仓锚 ⇒ 走 T530 `~ 他仓 @ base`，**只标注、不给 `close` 命令**；且**不读他仓 `.agents/prompts`**（读他仓卡 = 越界读取，且把他仓角色名拉进本仓可信集）。
  - F3 名字既不命中静态集也不命中本仓卡集，但后缀形状像 nao 任务号（`^T[0-9]+$` / `^M[0-9]{8}-`）⇒ 单列一节「角色未识别（疑似 fleet 遗留）」+ 归属三态 + **不给命令** + 指路（卡被删/改名、他仓卡、overlay 改名）。必要性：卡被删后会话今天会**静默消失**（既不在静态循环、也不在 unattributed 告警面），与 T530「非静默」直接冲突。
  - F4 命中卡集但后缀非上述形状（如 `code-reviewer-notes`）⇒ 列名 + 「非任务编号后缀」+ **不给 tag/命令**。**此收紧只对新（卡）前缀生效**：静态前缀路径的既有行（含 `--task notes` 这类合法输入）必须逐字不变，否则 AC5③ 破。
- **与 T530 冲突判定**：无冲突，前提是 `session_repo_verdict`（`:1389`）与 `task_state_class`（`:737`）**完全复用**（不复制、不改判定），改动面只有"前缀集 + 命令构造"。唯一例外见 §五 D6。

### Q3 `close` 语义分叉：判别式必须换，双向断言给到固定锚

- 现状缺陷：`cmd_close` 用 `[[ -z "$task" ]]` 分叉（`:1540`），而卡会话无 `--task` 时名字就是裸 `<role>` ⇒ 一次性会话会被当成常驻、弹出 `:1541` 警告。**判别式与语义无关，必须换**。
- 定稿：解析目标后置显式布尔 `IS_RESIDENT`（命中 `ALIAS_ROLE`/`ROLE_ORDER` = 1；命中卡集 = 0），警告条件 = `IS_RESIDENT && -z task`。目标解析顺序：① `ALIAS_ROLE` 命中（resident）→ ② `<alias>-<task>`（含 `--task` 形式）→ ③ 卡集最长前缀 + 后缀为任务号（card）→ ④ 卡集精确等裸名（card）→ ⑤ die（消息含"下游卡角色需在本仓锚下存在 `.agents/prompts/<role>.md`"）。现 `cmd_close` 只查 `ALIAS_ROLE`，③④ 属新增分支，不改 ①②。
- 闸门分叉：`tasks-state` active 闸门（`:1547`）对**卡会话跳过**（只 log 一句）；在跑 turn 闸门（`:1600`）**不放宽**。理由：active 闸门防的是"丢打回返工上下文"，一次性评审会话的产物是回执/报告；且它天然在任务 active 期运行并被回收 ⇒ 不放宽就出现"要归档任务才能关评审会话"的顺序倒置，日常必堵。
- **双向断言（AC4③ 落地，断言固定前缀 + 子串，不断言整行）**：
  - **A 正向（常驻仍须警告）**：`ensure qa` → `close qa` ⇒ rc=0 · pane 消失 · stderr 含固定前缀 `[fleet] 常驻会话 qa：任务闭环后应 ensure --force 重开`。
  - **B 反向（卡会话不得警告）**：`ensure --card .agents/prompts/code-reviewer.md` → `close code-reviewer` ⇒ rc=0 · pane 消失 · stderr **不匹配** `常驻会话 .*ensure --force` · 且含新固定前缀 `[fleet] 一次性会话 code-reviewer（下游卡）`。
  - **C 正交（禁"整体静音"蒙过 B）**：A、B 同文件先后执行，断言 B 之后 A 的警告仍出现（防实现直接删掉 `:1541` 的 warn）。
  - **D 分叉不外溢**：`close --task T537 code-reviewer`（T537 仍 active）⇒ **成功**；反例 `close --task T537 qa` ⇒ 仍被拒（锁住"闸门放宽只对卡生效"）。
  - **E 若卡集前缀嵌套**：`check` 报错 + `status`/`close` 最长匹配不误杀（负控）。

### Q4 与既有能力划界：已写清，缺三条可执行边界（尤其 overlay 会让 `check` 假红）

- **B1 overlay 双源**：机械保证就是 BR2 —— overlay 下 `PROMPTS_DIR` 即下游 prompts 目录，其中卡 id 必在 `ROLE_ORDER` ⇒ `ensure --card` 必被拒。**但由此派生一个必须补的 `check` 口径**：当下游卡扫描目录 realpath == `$PROMPTS_DIR` realpath（overlay 生效）⇒ 该节**整体跳过**，否则常驻卡被 BR2 报成"冲突"，`check` 恒红。文档仍写"同一仓二选一"；机制侧靠这条跳过避免假红。
- **B2 pi-subagents 双用**：卡加 `name:`+`description:` 即被 subagents 扫到；该路径下**没有** `## 环境锚点` ⇒ 卡内 `@.agents/...` 不可解析。口径：允许双用，但①卡正文必须不依赖锚点才自洽；②`check` 对含 `name:` 的卡给一行 warn（"同时被 pi-subagents 视作 agent，`@.agents` 引用在 subagent 路径不可解析"）；③卡 `role`/`name` 均不得用 `nao-` 前缀（T527 六个 `nao-<role-id>` 唯一占位）。
- **B3 `--card` 语法（PRD 未定，必须定死）**：现解析器（`:1735` 起）把所有 flag 收成全局变量、再遍历 positional ⇒ `ensure qa --card x.md` 会让 `--card` 作用于整批（静默错绑）。定稿：`--card` / `--as` 为**目标级修饰符，绑定其后第一个 positional**；`--as` 只在同目标的 `--card` 之后合法；命令末尾悬挂 `--card`/`--as` ⇒ 用法错；`--card` 传给 `check`/`status`/`close` ⇒ 用法错（照 `-S` 守卫 `:1760` 的先例）。`cmd_ensure` 改**两相**：先全量解析+校验（卡、role、BR2、`--as`），全部通过后才逐个 `spawn_one` —— 否则混合批次里前面的目标已起 pane 才发现后面的卡非法，BR6"零副作用"不可达（AC2 会假绿）。
- **双源结论：不会**，条件是 B1 跳过 + BR2② 前缀不相交 + 卡集前缀反链三条同时落地。

### Q5 越界确认：留在本任务**合适**（有条件放行），另记一条流程缺陷

- 结论：按 D4 由 rd-infra-T537 **首步**按显式 sha push `a8a678a` 合适，不单列 `M<日期>-<slug>`。
- 理由：① 纯文档提交（`docs/releases/v0.20.4.md` / `docs/reports/2026-11-01-T536-qa-verify.md` / `docs/tasks-state.md`，+11/−5）已在本地 main，红线在 commit 时已发生，push 只是可见化；② 单开文档 PR 被 AGENTS.md「禁为文档单开 PR」直接排除；③ 单列 M 任务不改变红线性质，只多一个任务壳；④ 不 push 则本 PR diff 夹带 T536 收尾文档，污染 T537 验收面（复审前提 = diff 干净）。实测：`origin/main=21366dc`、`main=a8a678a`、`rev-list --left-right --count origin/main...main` = `0 1`，`feat/61` 正基于 `a8a678a`。
- 放行条件（写进 RD 首步）：a) 显式 sha；b) 先 `git fetch` 再断言 `git merge-base --is-ancestor origin/main a8a678a` 真 + `git rev-list --count origin/main..a8a678a` == 1（只推这 1 条）；c) `git push origin a8a678a:refs/heads/main`（显式 refspec，禁 `--force`）；d) push 后 `git fetch` 断言 `origin/main == a8a678a` 且本地 `main` 与之一致（杜绝下次再"本地领先"）；e) 回执记一行「已授权例外」。
- 流程缺陷（遗留）：根因 = T536 收尾文档 commit 到本地 main，违反「文档随任务 PR」。→ PM 侧预防：收尾/补注文档一律落该任务分支；开工卡自检加一行「`git rev-list origin/main..main` == 0」。

## 四、技术取舍（对照模式 + 不采纳理由）

1. **维持现状（手工起会话 + 人工 `kill-pane`）** —— 适用：一次性、不需回执身份；代价：游离于 pane 托管/status/回收纪律。不采纳（缺口即需求本体）。
2. **把下游角色登记进 `roles.yaml`** —— 适用：真正常驻的角色；代价：上游清单负担 + 6 角色断言连锁改。不采纳（BR1/定位：上游零负担）。
3. **overlay 清单（`NAO_SKILLS` 指下游清单）** —— 适用：下游要整套 6 角色自定义；代价：绑常驻语义 + 下游维护整份清单。不采纳为"能力化"，保留为二选一（文档说明互斥）。
4. **新增第 7 常驻角色（CodeReview）** —— 已由前置结论否决（`docs/tasks-state.md` 下批候选 ①）。
5. **pi-subagents 项目 agent** —— 适用：并行调研/评审、无回执身份；代价：无 pane 托管、无 `status`、nao 不回收。互补而非替代。
6. **采纳：`--card` 参数线 + 派生/一次性语义**（最小改动面：`resolve_role` 旁新增卡解析、`spawn_one` 接受外部卡路径、`check` 一节、`close` 布尔分叉、`status` 前缀集）。

## 五、需 PM 拍板的决策点

- **D5**：`status` 是否新增「角色未识别（疑似 fleet 遗留）」节（F3）。成本：一节文案 + 1 用例；替代：并入既有 `unattributed_pi_panes` warn 行（成本低但措辞失真：「标题不符契约」对合规标题是错的）。
- **D6**：既有行 `${dname%-*}` → `${dname%-"$id"}`（`:1493/1496` 三处命令构造）。现写法在任务号含 `-` 时（`--task` 允许 `[A-Za-z0-9_-]+`，如 `M20261014-pi-ext-update`）会把角色名截错 —— 现存缺陷。修则「既有行逐字不变」需对含 `-` 的任务号放宽；不修则卡会话必须另用一套命令构造（两套写法并存）。
- **D7**：`check` 对下游卡的严重度分级。建议：内容类问题（缺 `role`/`description`、CRLF、超限）→ warn（不红 rc）；机制类问题（与 `ROLE_ORDER` 冲突、卡集前缀嵌套）→ error（`rc=1`），因为机制在运行期必拒、闸门必须提前红。
- **D8**：卡会话跳过 `tasks-state` active 闸门（Q3）—— 这改变既有派生活跃闸门的**适用面**（不改既有分支行为），需 PM 确认接受。

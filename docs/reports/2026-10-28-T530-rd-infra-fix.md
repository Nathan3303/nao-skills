# T530 修复报告 —— close 误拒（跨 server pane id 撞号）

- 状态：待验收（v0.19.1 待发布；v0.19.0 不发布）· 更新：2026-10-28 · Owner：rd-infra
- 指针：Issue #48 · PRD `docs/prds/2026-10-27-strict-tmux-pi.md` · ADR `docs/adr/2026-10-27-strict-tmux-pi.md`

## TL;DR

- **目标**：解除 v0.19.0 发布阻断（`--case 09` AC3 真回收 FAIL）。
- **结论**：缺陷是**误拒（安全侧）**，不是误杀。根因不是「tmux 调用不认 `$TMUX`」（QA A/B 实测 + 本报告 §3 均证伪），而是 F1 自 pane 守卫**跨 server 比较裸 pane id**。判据改为**三态 + fail-closed**（QA 复核 D-1：不可判定必须拒，原「不可判定 ⇒ 不声称是自己」= fail-open，可致自身 pane 被回收）。
- **影响**：任何 pane id 与调用者 `$TMUX_PANE` 撞号的环境（默认 server 的 pane 编号 + 隔离/custom socket）`close` 都会拒绝正常回收；本次红态恰为 PM 的 `%0`。
- **待办**：PM 验收 → RD squash 合并 → v0.19.1（PATCH）发布。

## 1. 现象与复现

- `bash tests/t4/run.sh --case 09`：`[FAIL] AC3: 真回收失败——跨仓 pane %0 仍存活（rc=1）`。
- **环境相关性（关键）**：同一条命令，`TMUX_PANE=%7` ⇒ PASS；`TMUX_PANE=%0` ⇒ FAIL。
  即缺陷并非「偶发」，而是**取决于调用者自身 pane id 是否与目标 pane id 撞号**，故 PM 侧稳定复现、其他 pane 不显现。

## 2. 根因

`close` 解析出目标 pane（在 `$TMUX` 指向的 server 内，结果正确）后，F1 守卫用裸 id 比较判定「这是不是我自己的 pane」：

- `nao-fleet.sh:1418`（改前 1366）闸门：`[[ -n "$pane" && -n "$TMUX_PANE" && "$pane" == "$TMUX_PANE" ]]`
- `nao-fleet.sh:603`（改前 554）纵深（`pi_pids_for`）：同一比较

pane id（`%N`）是 **server 局部**命名空间 —— 每个 server 的首块 pane 都叫 `%0`。隔离 server 的目标 pane `%0` 与调用者默认 server 的 `$TMUX_PANE=%0` 字符串相同 ⇒ 误判「是自己」⇒ 拒绝回收。`$TMUX_PANE` 在此场景是**陈旧/外来**句柄（`$TMUX` 已被夹具改指隔离 server），因此「补 server 维度做 (socket, pane_id) 二元组比较」也修不掉：两边读出的 socket 都等于 `$TMUX` 首字段、id 都是 `%0`，二元组照样相等。

## 3. 被推翻的假设（留档，避免二次误判）

- 「裸 `tmux` 不认 `$TMUX`、全部打默认 server」不成立：`TMUX=<隔离 sock>,x,y tmux display-message -p '#{socket_path}'` 返回隔离 socket（tmux 3.8），夹具日志亦显示 kill 落在隔离 socket。
- 由此**未采纳**「给全部 tmux 调用加 `-S` 包装」的方案：88 处改动与缺陷无因果关系，且会扩大回归面。

## 4. 改动清单

1. `pane_hosts_caller()`（`nao-fleet.sh:463`）改为**三态**：`0` 确定是自己 · `1` 确定不是 · `2` 不可判定（`#{pane_pid}` 取不到 / `ps -o ppid=` 读不出 / 链断）。判据 = 目标 pane 的 `pane_pid` 是否为本进程（`$$`）祖先（OS 级事实，免疫跨 server 撞号；也覆盖 `$TMUX_PANE` 被清时旧判据失效的缺口）。
2. 新增 `self_pane_refuse()`（`nao-fleet.sh:481`）作为两个调用点共用闸门（`0` = 必须拒绝）：
   `rc=0` ⇒ 拒；`rc=2` **且** `pane == $TMUX_PANE` ⇒ 拒（保守侧）；`rc=2` 且不撞号 ⇒ 放行；`rc=1` ⇒ 放行。
   ⛔ `rc=2` 且不撞号**不得**拒 —— 否则 v0.19.0 的跨 server 误拒会复现（§6 演练 C 实证）。
3. 调用点 2 处改走该闸门：`cmd_close` F1 闸门（`nao-fleet.sh:1418`）、`pi_pids_for` 纵深（`nao-fleet.sh:603`）。
4. 用例 `tests/t4/cases/09-alias-guard.sh`：AC3 真回收组扩为四态（①正常 ②撞号必须成功 ③自身 pane 必须拒 ③b `ps` 不可读仍必须拒 ④不可判定且不撞号必须放行）+ 跨 server 见证；夹具统一 `env -u TMUX_PANE`；两条 `t4_note` 改 `t4_skip`；「已关闭」判据加固为「server 可达 **且** pane 不在」；O1 修正序列号在父 shell 自增（原 `$(stage_pane)` 是子 shell，自增丢失 ⇒ 三次都落到 `-s1`）。

**语义不放松**：真自身 pane（派生窗口继承 `$TMUX_PANE` 致名册错注册，T513-S2/T523/T525）祖先必命中 ⇒ 仍拒（§6 ③/③b 实证）。

## 6. 负控（红 / 绿证据）

隔离 server A（目标）与 B（见证）并存；默认 server 既有 pane 作只读见证：

1. **① 正常回收**（`-u TMUX_PANE`）：rc=0，目标 pane 消失；B 与默认 server 既有 pane 全存活。
2. **② 撞号回归**（`TMUX_PANE` 刻意等于目标 pane id = v0.19.0 红态）：修后 rc=0、目标消失、不报「拒绝回收」。
   **演练 A**（守卫回退为裸 id 比较）⇒ ② 红（`rc=1` + 目标存活 + 「拒绝回收」），与 v0.19.0 阻断现象一致；还原复绿。
3. **③ 自身 pane**（在目标 pane 内部真跑 `close`，`ps` 正常）：rc≠0 + 「拒绝回收」+ 该 pane 存活。
   **演练 B**（整体移除闸门）⇒ ③ 红（「调用者自身 pane 被回收」）；还原复绿。
4. **③b 自身 pane + `ps` 不可读**（伪造 `ps` 令 `ppid` 查询恒失败 = QA 的 SELF_KILLED 场景）：必须仍拒 ⇒ rc≠0 + 「拒绝回收」+ pane 存活。
   **演练 D-1**（回退为 fail-open：`rc=2 ⇒ 放行`）⇒ ③b 红（「调用者自身 pane 被回收…SELF_KILLED」）；还原复绿。③ 真 `ps` 仍绿 ⇒ 只在不可判定时破口。
5. **④ 不可判定且不撞号**（`ps` 不可读 + `$TMUX_PANE=%9`）⇒ 必须放行：rc=0、目标回收、不报「拒绝回收」。
   **演练 C**（过度矫正：`rc=2` 一律拒）⇒ ④ 红（rc=1 + 目标存活 + 「拒绝回收」）；还原复绿。

三态判据另有单元探针覆盖（`tmux`/`ps` 打桩，5 组）：祖先命中 `0/拒` · 链走到 init `1/放行` · `ps` 不可读+撞号 `2/拒` · `ps` 不可读+不撞号 `2/放行` · `pane_pid` 空缺+撞号 `2/拒`。

## 7. 未覆盖与风险

- 未覆盖：真实嵌套 tmux（外层 pane 内跑内层 server）的端到端手工复核 —— 用例以双隔离 server 等价覆盖撞号面。
- 风险（已收敛）：`ps -o ppid=` 不可读时判据为「不可判定」⇒ 撞号则保守拒（可能少回收一次、需人工核对），不撞号则放行（不卡死正常回收）。代价是极端环境下多一次人工干预，换来「绝不杀自己」。

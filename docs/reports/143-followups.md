## 一、`MIN_PI_VERSION` 阈值一致性断言不在快档覆盖内（`143-F1`）⇒ 接受（到期 2026-12-05）

证据：该断言位于 `tests/t4/cases/06`（单价 **58s** > 快档单价上限 15s）。QA 独立复验：把单源常量 `MIN_PI_VERSION` 1.4.0 → 1.3.0（文档不动）⇒ `run.sh --fast` **仍绿 92s / 498 PASS**，而同一棵树 `--case 06` **rc=1** 并点名协议 / README / INSTALL 三处声明不一致。

判定：已知漏检，**已在快档默认输出里显式声明**（「本档未覆盖」+ PR CI 全量兜底），符合 AC9；不为此放宽时长上限（纳 06 ⇒ 152.7s，破 ≤120s 目标）。

出口：**接受** · 到期 **2026-12-05** · owner `rd-infra` · 动作 = 若 `143-F2` 落地后 06 单价降到 ≤15s 则纳入快档并关闭本项；否则评估把该断言上提到 `nao-fleet.sh check`（机制改动，须另批 + ADR 判定）。

## 二、替身重档是快档覆盖率的真正瓶颈（`143-F2`）⇒ 接受（到期 2026-12-05）

证据：profile `docs/reports/143-profile.md` —— 全量 774.9s 中**真机类仅 10.9%**，**替身重档 62.9%**（`case 20` 单例 121s，内部 2884 次 `herdr-double` 调用，每次一个 node 进程）。

判定：不改判据硬塞，改为降低单价 —— 把 `herdr-double` 从「每次一个 node 进程」改为**常驻进程 + 薄客户端**（unix socket），预计非真机类合计从 487s 降到数十秒。

出口：**接受** · 到期 **2026-12-05** · owner `rd-infra` · 动作 = 立项时须带负控（替身语义与今逐条等价、状态隔离、并发安全），成功后 `28/33/06` 等契约主档可纳入快档，`143-F1` 一并关闭。风险：替身是全量套件的地基，改它属高风险工程，须独立批 + 全量双后端验证。

## 结论摘要

- **S1**：工具**进列表 ✓**、**原始名无 `mcp__` ✓**、**受 `--tools` 剔除 ✓**、**信任不影响注册**；但「9 个」是版本相关，**上游现在默认只暴露 `codegraph_explore`**。
- **S2**：最省且最可靠 = **两份 `settings.json` 的 `packages`**（`${PI_CODING_AGENT_DIR:-~/.pi/agent}` + `<cwd>/.pi/settings.json`）；`pi list` **+0.9s**（违 ≤0.2s）；**没有廉价来源能证「生效」**。
- **S3**：PRD 前提**不成立** —— 舰队恒带的 `--append-system-prompt` **整体抑制 `.pi/APPEND_SYSTEM.md` 读取**（实测），且插件 fallback 在 pi 1.4.0 **是死代码** ⇒ 舰队里**没有任何 system prompt 注入**：无重复、无顺序问题。
- **S4**：50 文件 / 488KB ⇒ 建索引**秒级**、产物**MB 以内~低 MB**；`serve --mcp` 3 进程树，**100–250MB/实例、6 会话 0.6–1.5GB**（估）。6 watcher 同索引 sync **未验证**。
- **S5**：插件零网络；**CLI 有匿名遥测**（`CODEGRAPH_TELEMETRY=0` 可关）；`PI_OFFLINE` 对两者均无效。
- **S6**：**可纯静态断言**（夹具 `HOME` + PATH stub + 夹具 `.codegraph/` + **`check -v`**）；真装类断言走 **SKIP 门**。

## 环境与命令

- pi 1.4.0 · codegraph CLI 缺失 · 本仓无 `.codegraph/` · 工作区有他人 WIP（`nao-fleet.sh` 宽度、`tasks-state.md`），本报告只新增自身文件；临时件全在 `/tmp` 已清理。
- 三个只读实验：① `pi --help -e <ext>` vs `pi list/--version` ⇒ 工厂是否在非会话加载 ② 真插件 + 假 `codegraph`（9 工具）跑 `pi --print`，读 jsonl `message.toolsAdded` ③ `.pi/APPEND_SYSTEM.md`（预置/工厂写）× `-a` × `--append-system-prompt`，读 `message.sections`。

## S1 工具可见性（实测）

- 假 MCP 返回 9 个 `codegraph_*` ⇒ `toolsAdded` 23 个含这 9 个；加 `--tools read,bash` ⇒ 只剩 read/bash（`docs/cli.md:120,128`）。
- `defaultTools` 只作用内置工具（`docs/settings.md:163`）⇒ 不误伤；`--no-tools`/`--no-extensions` 会剔除；用户级包扩展**不**受项目 trust 门控（`docs/security.md:51`）。
- 接线：`spawn_one` 不传 `--tools` ⇒ 今天安全；但卡片不得把「9 个工具名」写成事实。

## S2 检测来源

- 推荐 grep 两份 settings 的 `packages`，包名**从 `bin/nao-skill.js` 的 `PI_PLUGINS.codegraph` 单点抽**（BR5 单源，~5ms；`check` 基线 0.87s）。
- `pi list`：0.92s、无 `--json`、**无 `-a` 时项目 packages 不显示** ⇒ 不做检测源。node_modules 只证「装过」；`pi install -l` 物理落点文档未写 ⇒ **不可静态判定**。
- 「装过但禁用」全部来源误报（`extensions: []` / `autoload:false` / `-path`）⇒ 文案须写「已声明（未验证生效）」。
- 夹具：settings.json 最省（`HOME` 覆盖先例 `tests/t4/cases/03,04`）；PATH stub 3 行（`status` → `Index is up to date`）。
- 顺带：`check` 硬编码 `$HOME/.pi/agent/settings.json`（`:1219`），未用已定义的 `PI_AGENT_DIR`（`:344`）。

## S3 APPEND_SYSTEM 冲突（实测，与 PRD 相反）

- 无预置文件时工厂写的段**能**进 prompt（`sections.addendum` 命中）——但仅当 ① 项目已 trust（未加 `-a` 时 **不注入**）② **没有** `--append-system-prompt`。
- 带 `--append-system-prompt` ⇒ 文件内容**整段消失**（`addendum` 只剩 CLI 文本）⇒ 舰队 6 会话**永远走不到文件注入** ⇒ 无重复/无顺序问题。
- fallback 死代码证据：pi 1.4.0 只认 `event.systemPromptOptions.sections` 原地改（`examples/extensions/prompt-customizer.ts`、CHANGELOG 0.68.0）；同扩展对照 —— 改 `sections` 命中、`return {systemPrompt}` 0 命中。
- 残留：非会话调用也执行工厂（`pi --help -e` 实测执行），只有 `session_shutdown` 才 unlink ⇒ **`pi --help` 在已建索引仓永久留下该文件**；`--version`/`list` 不加载扩展、不残留。
- 竞态：写入方无 fallback，退出 unlink 后存活会话下次 reload 丢段（无崩溃）；并发首启可能双写（unlink 吞 ENOENT）。舰队语义下无实际影响。
- 副作用：该文件是 trust 门控资源 ⇒ 插件把「裸 `.pi`（不需 trust）」变「需 trust」；已 trust 仓无影响。

## S4 索引与资源（标「需实测」）

- 规模 50 文件 / 72 文件 488KB / ~7.9k 行 ⇒ `codegraph init` **秒级（≤10s 量级）**，`.codegraph/` **MB 以内~低 MB**（SQLite+FTS5，WAL 另计）。
- 内存 3 进程树 + SQLite + watcher ⇒ **100–250MB/实例**、6 会话 **0.6–1.5GB**（`ps -o rss` 逐 pid 实测）。
- 并发：上游称 `node:sqlite` WAL「并发读不被写阻塞」且有 `codegraph unlock` ⇒ 6 watcher 同时 sync 仍需一次「6 并发 serve + 连续改文件」观察 `database is locked`。
- 额外成本：插件在**工厂**里 spawn（违反 `docs/extensions.md:58`）⇒ 任何加载扩展的非会话调用都拉 sidecar 并做 connect-time 全树对账。

## S5 网络 / 离线

- 插件零网络（无 http/fetch/socket）；CLI 匿名遥测（README「Telemetry」）关法 `codegraph telemetry off` / `CODEGRAPH_TELEMETRY=0` / `DO_NOT_TRACK=1`；`upgrade` 亦走网（本批不触发）。
- `PI_OFFLINE`：两者都不读 ⇒ **离线行为不变**；若坚持「机制零网络」需 `ensure` 注入 `CODEGRAPH_TELEMETRY=0`（arch 裁定）。

## S6 回归可测性

- 静态：`HOME=<夹具>` + PATH stub（有/无 CLI）+ 夹具 `.codegraph/`（有/无）⇒ 四态文本；断言**必须跑 `check -v`**（默认单行摘要，`·` 不显示、`!` 只计数）。
- 真环境 ⇒ `t4_skip` 门（`command -v codegraph && [ -d .codegraph ]`）：`tools/list` 集合、`pi --help` 残留、遥测开关、6 并发锁。
- 变异负控（AC7）只做**文本断言**变异，不要写成「check 失败」（与 BR1 冲突）。

## ① 三态（建议 4 态）目标文本

- 无插件：`  · codegraph 插件未声明（可选增强；装：nao-skill plugins install codegraph）`
- 声明但 CLI 缺：`  ! codegraph 插件已声明但 codegraph CLI 不在 PATH ⇒ 原生工具不生效（装 CLI；回退 CLI/grep + 行段）`
- 有插件+CLI、无索引：`  ! codegraph 已就绪但当前仓无索引 ⇒ 原生工具不生效（建索引：codegraph init；回退 grep + 行段）`
- 齐备：`  ✓ codegraph 齐备（索引 up to date；原生入口 codegraph_explore）`；有改动：`  ! codegraph 索引 pending（watcher 会自动同步，或 codegraph sync）`
- 约定：全部 **rc 不变**；`!` 只用于「声明了但不生效」与「pending」；文本命令必须真实存在。

## ② `.pi/APPEND_SYSTEM.md` 进 `.gitignore`：**建议加（单文件，不用 `.pi/`）**

- ① 会话期创建/删除的副产物 ⇒ `git status` 变脏，破坏「工作区干净」与路径级暂存可见性 ② 它是 trust 门控资源，入库 = 强制下游 trust + 把过期英文段（含未装的 Semble 指令）注入所有会话 ③ BR6 已禁 nao 编辑它 ⇒ 跟踪「谁都不许改」的生成物无意义。
- ignore 只治「不入库」；AC8 应改为「会话退出后不存在 + `pi --help` 后无提交级污染」。

## ③ PRD 事实错误 / AC 不可测

- **§一「9 个原生工具」**：上游默认只暴露 `codegraph_explore`，余 8 需 `CODEGRAPH_MCP_TOOLS`；工具数随 CLI 版本漂移 ⇒ **AC3「9 个且与实测一致」不可测**（BR7 同）。
- **§一/§六 S3「已存在 ⇒ before_agent_start 每轮追加」「与卡片重复/覆盖」**：pi 1.4.0 下 fallback 死、CLI append 抑制文件 ⇒ **既无追加也无重复**。
- **§一「6 卡共 14 处」「5 处清单」**：实测 **16 次（13 行）/6 卡**、清单 **4 处/3 文件**；还漏 `skills/pm-operations.md`、`templates/AGENTS.md.example` 的纯 CLI 口径 ⇒ **AC4 grep 范围不完整**。
- **BR1「rc 不受影响」 vs 现存代码**：`cmd_check` 的 CodeGraph 段在 `Pending Changes` 时 **`rc=1`**（`nao-fleet.sh:1207` 附近）⇒ 与 BR1/AC2 冲突，AC9 又要求「无既有断言放松」。
- **AC5 与提示文本的 `codegraph init -i`**：上游无 `-i`（`-i/--init` 属 `codegraph install`）⇒ 会给出不存在的命令。
- **AC1**：默认 `check` 只打单行摘要 ⇒ 必须写「跑 `check -v`」。**AC7**：「变异命中预期 FAIL」与 BR1 冲突 ⇒ 应写「命中断言失败（提示行变化）」并说明 md5 校验对象（夹具 vs 仓库）。
- **AC8**：只覆盖「会话」；`pi --help` 类非会话加载**永久残留**，且舰队恒带 `--append-system-prompt` ⇒ 文件通路不生效，「退出后文件被删」不能证明注入可用。
- **§二「工具名与实测一致」**：CI 无法静态证明 ⇒ 拆「文档清单 + 静态断言同一清单」+「真环境 SKIP 门」。**§六 ≤0.2s** 与「用 `pi list`」互斥（0.92s）⇒ 范围须明写禁用。

## 缺陷

1. **致命**：fallback 在 pi 1.4.0 是死代码 ⇒ 有预置 APPEND_SYSTEM.md 的仓 = 零指引。
2. **致命**：`--append-system-prompt` 抑制该文件 ⇒ 舰队 6 会话文件注入 100% 不生效（不得宣称「插件注入已有指引」）。
3. **严重**：`pi --help` 类非会话调用永久残留该文件 ⇒ 威胁 AC8 与「工作区干净」。
4. **严重**：工具数 9 → 上游现默认 1 ⇒ AC3/BR7 事实错误。
5. **一般**：`init -i` 不存在；`Pending⇒rc=1` 与 BR1 冲突；检测硬编码 `$HOME`；计数/范围错（14 vs 16、5 vs 4、漏 2 文件）；遥测与 `PI_OFFLINE` 无效未处理。

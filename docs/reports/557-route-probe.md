# 报告 · AC1 路由可判实测（T557 设计循环 · 二轮修订）

- 日期：2026-11-23 · 执行：`rd-infra` · 对象：`.agents/skills/design-loop.md` §一 路由表 · 轮次：QA 点检后整改（Q1 P1）
- 目的：验证 AC1「抽 3 类任务由第三方按路由表能判出该走哪条」，并把 QA 指出的两处重叠与一处兜底误判修到可判。

## 一、结论

- **只给六类名称不可判**：名称层有两处重叠 ——「小改动 vs 单组件打磨」「新界面 vs 存量优化」。必须给可逐条判的判据。
- **二轮判据（四维）**：**① 取值层还是外观层（是否改状态集合 / 结构 / 尺寸圆角）· ② 组件数（1 / ≥2）· ③ 要不要并排多版 · ④ 新增页面或流程 vs 既有页面**。
- **R3 与 R5 允许叠加**：既有页要给多版时两条同时成立 —— 口径改为「顺序取 R3，且**继承 R5 的基线盘点**」，技能 `:12` 已改成「顺序消解 + 继承」，不再声称定义互斥。
- **兜底改向**：一条都不命中 ⇒ 按 **R5 轻量档**（基线 + S3 / S4），**禁止**兜底成 R2 新界面（QA Q1-③ 的误判点已消）。

## 二、3 类样本与逐谓词判定

规则序：R1 取值 → R2 新增页面/流程且单方向 → R3 同屏 ≥2 版组织 → R4 单组件形态/状态集合 → R5 既有页动层级 / 新增区块组件 / 动视觉系统 / ≥2 组件 → R6 只读评审。首个命中即停，R3 命中后继承 R5 基线步。

1. **样本 A**：登录按钮主色 `brand-600` → `brand-500`，其余不动。
   - R1 ✓（同属性、同结构、同状态集合的取值）· R2 ✗ · R3 ✗ · R4 ✗（不改状态集合 / 结构）· R5 ✗ ⇒ **R1**：S3 → S4，可略 S1/S2/S5。
2. **样本 B**：既有订单列表页新增筛选栏并调整区块顺序（只要一版组织）。
   - R1 ✗（改区块层级）· R2 ✗（页面是既有的）· R3 ✗（单版）· R4 ✗（不是单组件）· R5 ✓（既有页 + 动层级）⇒ **R5 全步档**：基线 + S1–S5 + CP1/2/3。
3. **样本 C**：重做 `Card` 组件的 hover / focus / 禁用三态与圆角，页面结构不动，该组件在 3 屏复用。
   - R1 ✗（改状态集合 / 结构）· R2 ✗ · R3 ✗ · R4 ✓（一个组件）⇒ **R4**：S2′ → S3 → S4，可略 S1/S5，**CP2 必过**。

## 三、QA 点检的三处边界（二轮新增，逐条判）

4. **多态换色**：主按钮底色 + hover 底色 + 禁用底色三处 token 值一起换，尺寸 / 圆角 / 布局 / 状态集合不动 ⇒ **R1**（取值层：同一状态集合内换值；R1 明写「含组件内多态取值」）。
5. **既有页多方向**：既有设置页给 2 个组织方案 ⇒ **R3**（判据是「要不要并排多版」），且**先做 R5 的基线盘点**，选定方向后按 R5 全步档走。
6. **既有页只加一个区块**：既有列表页新增筛选栏、不调区块序 ⇒ **R5 轻量档**（基线 + S3 / S4）；不再落到 R2，也不再「一条都不命中」（R5 明写「新增 ≥1 个区块或组件」）。

补测 5 例（范围闭合用）：4 处颜色替换 ⇒ R1（局部取值，不是系统）；同时重定整套字阶与间距 ⇒ R5（系统）；**整套字阶单类被系统性重定（5 档 → 7 档）⇒ R5 全步档**（P3-2：单类也够，不落 R1）；**同结构整套配色全换（档数不变、全部换值）⇒ R5**（第三轮：R1 已显式排除系统性重定，否则 R1 的首个命中会把 R5 挡成不可达）；**只改一个档的数值（如正文间距一档）⇒ R1**（局部零星）。

# 报告 · AC1 路由可判实测（T557 设计循环）

- 日期：2026-11-23 · 执行：`rd-infra` · 对象：`.agents/skills/design-loop.md` §一 路由表
- 目的：验证 AC1「抽 3 类任务由第三方按路由表能判出该走哪条」，并回报判据是否需要 PRD 修订。

## 一、结论

- **带判据的路由表可判**：3 类样本逐条命中唯一规则，无「看情况」。判据维度只有三个 —— **处数（取值 / 系统）· 组件数（1 个 / ≥2 个）· 是否新增页面或流程**。
- **只给六类名称不可判**：PRD §三/AC1 的六个类型名在名称层存在两处重叠 ——「小改动 vs 单组件打磨」、「新界面 vs 存量优化」。技能里用**互斥谓词**消解（下方 §三），不是靠上下文猜。建议 PRD 在 M1 条目补一句「路由表须给出互斥判据（处数 / 组件数 / 新增还是既有）」，范围不变。

## 二、3 类样本与逐谓词判定

规则序：R1 取值 → R2 新增页面/流程且单方向 → R3 同屏 ≥2 版组织 → R4 单组件形态/状态 → R5 既有页面改层级或动视觉系统 → R6 只读评审。首个命中即停。

1. **样本 A**：登录按钮主色 `brand-600` → `brand-500`，其余不动。
   - R1 ✓（只改取值）· R2 ✗（非新增页面/流程）· R3 ✗ · R4 ✗（组件形态与状态矩阵不变）· R5 ✗（不动层级/视觉系统）⇒ **R1**：走 S3 → S4，可略 S1/S2/S5。
2. **样本 B**：既有订单列表页新增筛选栏并调整区块顺序（只要一版组织）。
   - R1 ✗（改区块层级）· R2 ✗（页面是既有的，不是新增）· R3 ✗（要求单版）· R4 ✗（不是单组件）· R5 ✓（既有页面 + 动层级）⇒ **R5**：基线盘点 + S1–S5 + CP1/CP2/CP3。
3. **样本 C**：重做 `Card` 组件的 hover / focus / 禁用三态与圆角，页面结构不动，该组件在 3 屏复用。
   - R1 ✗（改组件形态与状态矩阵）· R2 ✗ · R3 ✗ · R4 ✓（一个组件、区块序列不变）⇒ **R4**：S2′ → S3 → S4，可略 S1/S5，**CP2 必过**（跨屏复用）。

补测 2 例（边界闭合用，不计入 AC1 的三类）：4 处颜色替换 ⇒ R1（取值，不是系统）；同时重定整套字阶与间距 ⇒ R5（视觉系统）。

## 三、互斥判据（技能内已落地）

- **取值 vs 系统**：改的是具体取值（文案 / token 值 / 间距档 / 颜色）⇒ R1；改的是视觉系统本身（≥2 类视觉维度）⇒ R5。
- **组件数**：动 1 个组件 ⇒ R4；动 ≥2 个组件 ⇒ R5。
- **新增 vs 既有**：新增页面或流程 ⇒ R2（单版）/ R3（≥2 版）；既有页面 ⇒ R5（动层级或视觉系统）/ R4（单组件）。
- **版数**：单版 ⇒ R2；≥2 版组织 ⇒ R3（R2 限定「单方向」，故不会抢先命中）。
- **兜底**：一条都不命中 ⇒ 按 R2 走完整循环（宁多一步）。

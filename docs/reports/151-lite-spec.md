## 一、现状断点（已核 HEAD `4b3019e`）

- `:4246` `repo="$(intercom_cwd_for "$name")"` —— 跨仓同名时**取首命中**；`:4248-4249` 的「按目标仓复核」**是同义反复**（拿首命中的 cwd 再过同一名册 ⇒ 恒等）⇒ 结构上零判别力。
- `$repo` 的消费者**按层**（D6 订正：上版把「回收句柄定位」与 liveness 混为一谈，错）：**① liveness 层** `term_liveness <name> [repo]` —— **两后端均按 repo 过滤**（tmux `intercom_online`/`find_pane_for`；herdr `repo_contains_path` 过滤快照行），是「repo 错 ⇒ 未运行 rc=0 假成功」的承重面（裸名分支经 `running` 直接消费；本分支下游仅 `pi_pids_for` 兜底经 `find_pane_for name repo` 触及）· **② 忙闲层** herdr 第二信号 `intercom_status_for <name> <repo>`（按仓过滤）· **③ 文案层** tmux 回收 warning 的 `cwd=$repo` · **④ 句柄定位/回收**（tmux `find_pane_for_any_repo`、herdr label rows）**不按 repo 过滤**。⇒ 四层过滤性不同，判据一律**按层命名**。
- `$fallback_repo`（`:4236`/`:4239`）= `ROLE_WS`（值 `.` ⇒ 语义「调用方 cwd」）或卡所在仓根。
- 既有：本分支**不给** `scope` 赋值（`term_reclaim` 第 5 参沿革）⇒ tmux T516 歧义闸门只见无 scope 派生。本批不改，登记 R3。

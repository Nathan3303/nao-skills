## 专门判断：PM 34 项红线 + 44 项清单，数量是否合理

先给实测：`pm.md` 共 96 个 checkbox（红线 34 + 清单 44 + 派单 5 + 收窗 5 + `fix` 8）；一个 **feat** 任务 PM 实勾 = 34+44+5+5 = **88 项**。

按你要的两个维度切（不按「看着多」）：

- **可机械判（命令能直接给结论）**：约 **12 项** —— main 提交数 / `wip(` / tag 指向 / 未推提交 / 分支名 / 暂存方式 / 计数自证 / notes 落盘 / `check` rc / 角色在线 / 降级标注 / 模型白名单。这 12 项的本质是「命令组」，逐条勾是**双重劳动**。
- **真发生过误判**（文档里有实测引用）：约 **13 项** —— #15（TASK-23 越界）· #17（T533 孤儿提交）· #25/#26（PR #149、`wip(` 判据自伤 #86/#113/#119）· #34（v0.20.4 假陈述）· #35（M20261014 维护型）· #31 · #22 · #29（T529）等。
- **岗位常识/教条**（无案例、无闸、与清单前 12 项重复）：约 **14 项** —— #1–#11 之中除 #2/#3 外的多数（无目标指标 / 边界不清 / 口头沟通 / 埋点 / 核心需求 / 5 Whys / 验收偏差 / grill / 页面状态清单）。这些属于「PRD 质量」，是**清单语义**，不该占红线名额。
- **与清单或彼此重复**：约 **5 项** —— #14 与 #24（PM 改代码 / 改源码构建）· #23 与 #24（直推 main / 亲自合并）· #25 与 #31（wip / 可读性）。

**结论：数量不是主要矛盾，分类是。** 34 这个数字本身没问题（红线多不是罪），问题是**红线里混进了清单项与常识项**：红线应收「越权 / 不可逆破坏 / 已发生且无闸」三类，其余下沉。
目标形态：红线 **34 → 18**（越权 7 / 不可逆 5 / 已发生无闸 6）· 清单 **44 → 38**（删 2 元项 + 合并 4 对重叠）· 机械可判 12 项改由「`check` + 一组 `git`/`gh` 命令」一次性给结论，人判项保留约 30。
效果：单任务人判面从 **88 → 约 56**，且 88 里最贵的「逐条假装核对」（12 项机器能判却靠人勾）消失。**重分类净变化 −20 行**（红线 −14 / 清单 −6）—— 与 F4（卡侧 −12）不重叠，两者分属不同文件。

## 加闸建议（「声明比判据强」的收敛）

今天撞的两次（`cases/06` 反向耦合 · `check` 的 `!` 行永不改 rc）属于同一族的两个子型，值得先分类再决定加什么：

- **a 型 · 无闸声明**：写「必须/硬性」但零机械判（本报告 F1/F3 与大多数红线；12 处「完整 N 项」声明也是 0 闸）。
- **b 型 · 闸判的不是同一物**：`cases/06` 用 check 输出 md5 当 golden ⇒ 改文案即红，而**文案违规不红**（反向耦合）。
- **c 型 · 闸只在 warn 层**：`!` 行永不改 rc ⇒ 「必红」类需求实际不可满足（T579 已因此把索引断言挪去 t4）。

- **G1（P1）· 清单计数闸**：`check` 新增 `check_checklist_counts()` —— 每份 `checklists/*.md` 的每个「完整 N 项」段头 == 该段 `- [ ]` 行数。判据：按 `^## ` 切段 + 段头正则取 N + `grep -c '^- \[ \]'`；不一致 ⇒ 一条 `  ! `（warn-only，与 PRD 探针同口径）。成本约 20 行 awk；**夹具现成**（`rd-infra.md` 现值 8 vs 9 天然是红样本，先红后绿）。反例：多段文件（`pm.md` 有 5 个段头）必须逐段配对，不能全文计数；子分组标题（`rd-fe.md` 的 `**通用**`）不切段。
- **G2（P2）· ADR 结构闸**：`check` 只探 PRD（≤150 行 / 9 模块 / AC 组 ≥5），ADR（≤60 行 / 必写 5 节 / 状态值域 4 值）**零闸**，而 `docs/adr/README.md` 已有 26 篇在用 ⇒ 结构漂移无人发现。建议同一探针加 `check_adr_structure()`（trace 面同 PRD：文件名日期 ≥ SINCE）。反例：`adr-index.md.example` 是 11 行骨架、不是 ADR，须按文件名 `YYYY-MM-DD-*.md` 过滤，否则骨架被误判。
- **G3（P2）· release notes 编号闸**：`release-notes.md §一.2` 禁内部编号/哈希/测试数字，全靠人工 checklist。建议发布前跑一条只读探针（`T[0-9]{3}` / `#[0-9]+` / 40 位 hex，**状态行豁免**，与 §一.6 一致）。注意 b 型陷阱：**判据不得写进 notes 正文**（`wip(` 判据自伤的老教训）。
- **G4（明确不加）· 并发/静默工作区检测**：`check` 的红线是**只读审计**（`check.sh:7`），做锁文件/写标记会破它。故 F19 只给 warn 级提示 + 纪律，不上锁。
- **G5（可选，零行）· 每条「必须」后追加 `[闸:check|t4|无]` 标记**：把「无闸」从隐含事实变成可统计字段（今天 302 个 checkbox 里无闸占比只能靠人估）。

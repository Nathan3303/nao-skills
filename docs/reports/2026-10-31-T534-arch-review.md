# T534 结构评审：`status` 残留判定加仓维度（A 项）

- 状态：已定稿（D5–D8 已拍板）· 更新：2026-10-31 · Owner：arch-designer
- 指针：PRD `docs/prds/2026-10-30-fleet-guards.md`（§一 证据 / §五 BR1–BR6 / §七 AC1–AC2）· ADR `docs/adr/2026-10-31-fleet-status-repo-attribution.md` · Issue [#56](https://github.com/Nathan3303/nao-skills/issues/56)

## 结论

**可行（有条件）**。A 项收敛为 `status` 单点改动 + 一次 tmux 快照；`close`/`ensure` **零改动**。条件 = 下方「降级」与「验收」两条机械证明进 AC（已并入 D5–D8 / AC6–AC7）。

## 定稿判据

- **本仓锚 ROOT**（每 run 一次）：主锚 `pwd -P`；`git -C "$PWD" rev-parse --show-toplevel` 成功且为 cwd 的**严格祖先**时并入锚集（覆盖在 `.agents/` 等子目录跑 `status`）。**不用** `roles.yaml` workspace（常为 `.`/子目录，且 `ensure` 支持 `@repo`）。
- **pane cwd**：一次 `tmux list-panes -a -F '#{pane_id}\t#{pane_title}\t#{pane_current_path}'` 快照，按标题契约 `^π - <会话名> - ` 建 name→(pane,cwd)；禁逐名 `find_pane_for`（O(N) 次 tmux，违 NFR「不引入额外 I/O 循环」）。`pane_current_path` = 前台进程 cwd（物理路径）⇒ 权威。
- **兜底**：名册 `intercom_roster` 的 name→cwd（注册时 cwd；pi 不 chdir）。优先级 **pane > 名册**，冲突取 pane、不 warn（防噪）。
- **归一与比对**：两侧物理归一（`(cd <p> && pwd -P)` → 失败退 `readlink -f` → 再退原串）+ **组件级**前缀 `[[ "$c" == "$r" || "$c" == "${r%/}"/* ]]`（禁裸字符串前缀：`/a/b` 不得命中 `/a/bc`）。软链与子目录（`…/nao-skills/.agents`）落在 ROOT 子树内 ⇒ 本仓。
- **同名多 pane**：本仓命中 ≥1 ⇒ 本仓（保持旧行为）；本仓 0 且他仓 ≥1 ⇒ 他仓；否则按名册 cwd；两侧皆无 ⇒ 不可判定。
- **实现纪律**：判据抽独立小函数 `repo_contains_path <root> <cwd>`（单行谓词），供 AC2 单行变异自证。

## 三处语义边界

- **`status`**：**先定归属、再判 tasks-state**（他仓不查本仓台账，杜绝误读）。本仓行四条 `cls` tag **逐字不变**。他仓行 `  ~ <dname>（他仓 @ <basename>）他仓会话，勿在本仓回收` —— 整行不含任何 `close` 命令形态（BR2）。不可判定行 `  ? <dname>（归属不可判定）→ 人工核对（勿在本仓回收）`。两类行仅在有条目时输出 ⇒ 单仓零新增行。
- **`close`**：**零改动**（BR3）。名册 cwd 优先的跨仓定位、`tests/t4/cases/09` 真跨仓回收契约保持——这也是不采「跨仓需 `--force` 硬闸」的理由（D6）。
- **`ensure`**：**零改动**。`running "$disp" "$repo"` 已三重仓约束（roster cwd 精确相等 / 标题 basename 匹配 / 兜底要求 roster cwd 匹配）⇒ 跨仓同名不会误判「已在运行」。已知弱点：两仓 basename 相同时标题层可互串（既有缺陷，非本批）。

## 不可判定降级（fail-closed）

fail-closed：只标注、不给可执行命令。依据 T530「不可判定时不得声称是自己」的**对偶**：同样不得声称「是本仓残留」。可判定性来源三条（标题 pane / 名册 cwd / 二者皆无 ⇒ 不可判定），正常 tmux 舰队必命中前两条；仅剩来源：进程已退（pane 空）、权限读不到 `/proc`、legacy `nao-*` detached 会话名。指路损失由 `close` 能力兜住（BR3）。

## 风险与兼容

- 他仓会话移出残留节 ⇒ 跨仓旧会话失去本仓指路（文案指路「在其所在仓执行」，能力未减）；不可判定会话同样只标注。
- **单仓/无他仓会话：`status` 输出逐字不变**（用 `git show main:...` 旧版改前/改后 diff 机械证明，AC7①）；`check` roles=6、files 数字不变；无持久态 ⇒ 回退 = 单条 `git revert`。
- 文档影响面（单源）：`.agents/skills/pm-operations.md:22` 加半句「他仓会话单列、勿在本仓回收」；`checklists/pm.md` 仅指针；`AGENTS.md` 零改动（D7 / AC6）。

## 验收夹具建议（一次性只读探针）

- **纪律**：复用 `cases/09`、`cases/15` 的隔离 socket（`-S <cache>/t534-sock/tmux-$(id -u)/default`），**禁裸 tmux**；夹具根 `FX` 放 `/tmp`（**不得落在任何 git 仓内**，否则 toplevel 锚会把 `OTHER` 拉进本仓）。
- **他仓会话**：`other=$CACHE/other-repo-nao-todo`（`mkdir` 即可）+ `new-session -c "$other"` + `select-pane -T "π - qa-T596 - nao-todo"` + 名册 `{"name":"qa-T596","cwd":"$other","tmuxPane":"<p>"}`。
- **本仓会话**：`-c "$FX"` + `π - qa-T534 - <basename FX>`，`tasks-state` 夹具内 T534 归档（⇒ `closed` 残留，保留可执行提示）。
- **断言**：① 本仓行含 `close --task T534 qa`；② `grep -c 'close --task T596'` = 0；③ `qa-T596` 若出现须同行含「他仓」且不含 `close`；④ AC2①：`status` 前后 `list-panes` id 集合 + `pane_pid` 全等，且 `tasks-state` 的 `git status --porcelain` 不变；⑤ BR3 能力：用**第二个**他仓 pane 真跑一次 `close --task T596 qa`，断言 rc=0 且目标 pane 消失（顺序勿打乱 ④）；⑥ 负控：副本单行变异 `repo_contains_path`（`return 0` ⇒ AC1 首句 FAIL；`return 1` ⇒ 本仓残留消失且 `cases/13`、`cases/15` close 闸门 FAIL，须点名用例）；⑦ 兼容：旧版脚本 vs 新版同一「仅本仓 pane」夹具下 `status` 逐字相同；⑧ 边界：`cd $FX/.agents` 跑（toplevel 锚）/ symlink→`$FX` 作 pane cwd（物理归一）/ `$FX-sibling` 作 pane cwd（前缀陷阱必判他仓）。

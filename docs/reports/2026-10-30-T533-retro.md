# L1 复盘：T533 验收收口提交未 push 即授权合并（孤儿提交）

- 指针：批次 T533 · PR [#55](https://github.com/Nathan3303/nao-skills/pull/55)（squash `2499157`）· 触发条件 = **漏闸**（兼返工 1 次）

## 一、发生了什么

- PM 收完 QA 回执后，在需求分支 `nao/pr-scope` 上提交 `da34de5`（三项收口：D1 广播登记 `card pm v28`→`v29` / O3 修正 PRD AC4 判据措辞 / O2 转办进待派发队列），**随后直接贴验收评论并授权 RD 合并，未 push 该提交**。
- RD 合并的是**远端 head**（`91a5fb4`）⇒ `da34de5` 成孤儿；main 上缺这三项收口，其中 D1 是 QA 唯一提出的未过项。
- 发现方式：发布提交前 grep `docs/tasks-state.md` 发现仍是 `card pm v28` ⇒ 反查 `git reflog` 确认提交在本地、不在 main。
- 影响：无用户可见影响（发布前已用 `cherry-pick -n` 把内容并入发布提交，main 最终状态正确）；代价 = PM 一轮返工 + 一次 self-inflicted 漏闸。

## 二、根因（三层）

1. **直接原因**：授权合并前的核对清单没有「分支本地与远端一致」这一项，PM 默认「我提交了就进去了」。
2. **机制缺口**：`checklists/pm.md` 合并项与 PM 卡 §六 合并闸门只核四件事（PR 标题可读 / main 恰 1 条 / 无 `wip()` / 工作区干净）——**四条都以远端为准，本地提交天然不在视野内**。而本批 BR4 恰好新增「PM 在需求分支做路径级提交」：PM 从此是该分支的**第二个提交者**，风险面是本批新引入的，闸门却沿用旧的四条。
3. **更深**：验收闭环的核对对象是「回执数字 + PR diff」，diff 取自远端 PR ⇒ **核对对象与被核事实不同源**。BR4 只写了「提交方只暂存自己的路径」，没写「提交方必须先 push 再授权」。

## 三、改了哪条机制

- **本批不做机制改动**（保持批次边界，避免发布提交夹带规则变更）：仅落本复盘 + `docs/tasks-state.md` 缺陷登记 + 防线转办 `T533-O4`。
- **下批（`T533-O4`，rd-infra）**：`checklists/pm.md` 合并项 + PM 卡 §六 合并闸门各 +1 条「授权合并前，需求分支无未推送提交（命令与判据见 §四）」。
- **不做**：不给 `nao-fleet.sh` 加自动闸门（PM 与 RD 同 worktree，脚本无法区分「未推送」「他人未推送」，误报成本高）。

## 四、可验证防线（三条命令 + 判据）

1. `git rev-list --count origin/<branch>..HEAD` = **0**（本地无远端缺的提交）。
2. `git status --porcelain` = **空**（无未提交改动，含路径级暂存残留）。
3. 分支设了 upstream 时：`git rev-parse HEAD` = `git rev-parse @{u}`（本地与追踪分支同点）。

**判据**：三条任一不满足 ⇒ **不得**贴验收评论、**不得**授权合并。适用范围 = 所有在分支上提交过的角色（本批起 PM 也是提交者之一），不限于 PM。

# T529 完整复盘（L1）：发布前置闸门拦下一次「QA 绿 + PM 判断错」的发布

- 状态：已定稿 · 更新：2026-10-28 · Owner：PM
- 触发（BR6 五条命中）：**返工 ≥1**（T530 修复两轮 + 一轮方向更正）· **同类第二次出现**（宿主/句柄判定类缺陷，T523/T525 已有两次同族补丁）

## 一、发生了什么

- **T529 主线**：删净宿主阶梯（1947→1591 行）、非 tmux `rc=3`、`check` 增 `pi ≥1.4.0`、`close` 收窄。QA 独立复核 **GO**（16/16、断言差额双口径、双向负控），PR #49 squash 合并。
- **PM 发布前置 `test:t4:full` FAIL**：`cases/09`「真回收失败——跨仓 pane %0 仍存活」。同一棵树 QA 报全绿、PM 报红。
- **PM 初判错**：认定「88 处 tmux 调用打默认 server」，据此让 RD「加 `-S` 包装、改 88 处调用」。
- **QA 用两条 A/B 实测推翻**：`TMUX=/tmp/nao-fake,1,0 tmux list-sessions` ⇒ 连不上该 socket（tmux 本就认 `$TMUX`）；差异只是 `$TMUX_PANE`（QA `%5` / PM `%0`）。
- **真凶**：自面板守卫拿 `$TMUX_PANE` 与隔离 server 解析出的 pane id 做**裸比较**，而 pane id（`%N`）是 **server 局部命名空间** ⇒ 撞号即误判「是自己」⇒ **误拒**（安全侧失败，但 `close` 不可用）。
- **修复**：改**进程归属判定**（`pane_hosts_caller`：目标 pane 的 `pane_pid` 是否本进程祖先）撤销错误方向；QA 随后判 D-1 **必修**（初版「不可判定 ⇒ 放行」= fail-open，实证「伪造 `ps` ⇒ 自身面板被回收」）⇒ 改**三态 fail-closed**。
- **结果**：v0.19.0 从未发布（tag 未建）⇒ 修复合并后发 **v0.19.1**；npm 已核验 `latest = 0.19.1` + integrity 逐字节一致。

## 二、根因（三层）

1. **用例层**：`cases/09` 结果**依赖调用者 pane id**（`$TMUX_PANE` 撞号才红）；且「真回收」在能力缺失时走 `t4_note`，而 NOTE 不进 `full` 的 SKIP/DEGRADE 判据 ⇒ 存在**掩盖通道**：断言可能从未执行却报绿。
2. **判断层**：PM 在**没有实测**的情况下下了根因结论，并据此给 RD 下达了**错误方向的实现指令**（若 RD 照办，会做一次无意义的大范围改写）。这恰好违反了 T528 协议里自己写下的「验证 = 命令 + exit code + 数字，禁『看起来没问题』」。
3. **机制层**：发布前置闸门与 QA 复核**跑在同一个隐含环境前提**下（都在 tmux 内、都用默认 socket），环境差异未被显式化 ⇒ 「谁绿谁红」取决于执行者的 `$TMUX_PANE`，属于**未被声明的输入**。

## 三、改了哪条机制（本批已落地）

- **NOTE 不得掩盖断言**：`cases/09` 两条 `t4_note` → `t4_skip`（能力缺失进 `full` 计分）；「已关闭」判据从「不在列表即算关掉」改为「**server 可达 且 pane 不在**」（server 崩了不再算成功）。
- **安全闸门方向**：F1「绝不杀自己」定为**不可判定也拒**（fail-closed），并把「不可判定但与自身无关 ⇒ 放行」写进注释，防止下一次为通过用例又掰回 fail-open。
- **护栏可证伪**：三态真值表 5 分支 + 三向破坏演练（回退裸 id / 移除闸门 / 一律拒），每条都能翻红并 md5 还原 —— 断言不再是「必然通过」。
- **PM 侧口径更正**：台账撤回「88 处打默认 server」，改记真因；RD 的「tmux 调用点改动 0 处」更正为「既有 0 改 + 新增 1 处只读 `display-message`」。

## 四、可验证防线（3 条建议，待用户拍板后另立小批）

1. **`full` 口径禁止 NOTE 掩盖**：把「能力缺失 ⇒ NOTE」统一改为 `SKIP`（`full` 计分），或令 `t4_note` 在 `T4_REQUIRE_FULL=1` 下计为 SKIP。验收：`full` 下 NOTE 计数恒为 0（或仅允许白名单三类静态 NOTE）。
2. **PM 根因纪律**：向 RD 派「根因 + 修复方向」类指令前，必须附**一条可执行实测命令与其输出**；无实测只能派「诊断任务」，不得直接派实现方向。验收：抽查 3 批派发消息，凡含「根因」断言者必带命令。
3. **发布前置双环境**：`test:t4:full` 至少跑两组 —— `$TMUX_PANE` 已设（撞号态）/ 显式 `env -u TMUX_PANE`；两者都 rc=0 才算过。验收：任一组红即阻断，且能复现 T529 红态。

## 3. F7 失败路径（严格按 PM 要求：字节不变 + 恰一行 warn + exit 0）

两种「无法安全文本去重」形态，均独立构造并实测：

| 形态 | 说明 | rc | 文件字节 | 「手工移除」warn | 其它迁移步骤 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| ① 单行 + 目标为**末位属性且无前置分隔逗号** | 无可安全裁剪的逗号 ⇒ `removeJsonProperty` 返回 `null` | 0 | **不变** | **恰 1 行** | 照常完成 |
| ② 单行 + **同名 key 重复** | 文本删除后目标 key 仍在 ⇒ 强制 `JSON.parse` 校验失败 | 0 | **不变** | **恰 1 行** | 照常完成 |

观测告警原文：`skills-lock.json 存在重复 frontend-design，但无法安全文本删除：请手工移除该条目；其余迁移步骤不受影响。`

> **口径说明（对 AC 文本的精确化）**：经穷举，**合法 JSON 输入下不存在「删除后 JSON 非法」的可达实例**——JSON 字符串中的引号必被转义（`\"frontend-design\"` 不匹配 `"frontend-design"\s*:`），且 `findJsonValueEnd` 对括号/字符串成对扫描，故失败态只能经 ① `null`（畸形态）或 ② 删除后校验不通过（同名 key 残留）到达。二者都由 `failed` 三态统一走「不改写 + 恰一行 warn」，与 AC-F7-3 的**实质要求**（不静默、不写坏）一致。**无实现缺陷，仅提示避免未来把 AC 文案误读为「必须构造出非法 JSON 输入」。**

## 8. ADR「已废弃」句的口径意见（回答 PM 三）

- **口径**：`AC-F3-3` 与 `AC-DOC` 均为 **OR 语义（README ∨ ADR）**——README 已把「`.agents/.nao-migrated` 已废弃、可安全删除」写清楚，**ADR 不写也不应导致 FAIL**；不能把「ADR 必须有」当硬门禁（否则形成「为过断言而写文档」的反向驱动）。
- **对 RD 该句（决策 1 末「（该文件已废弃，可安全删除）」）的意见：建议保留**。理由：ADR 决策 1 本身就写「存量文件（三仓 tracked）由 T511 pin PR 手动删除；代码不自动删」，紧跟一句「已废弃、可安全删除」是该决策的**自洽收尾**（读者无需跳到 README 即知处置），不属冗余。
- **结论**：README 为主入口、ADR 为决策存档；该句在 ADR 中语义正确、建议保留但**非验收硬条件**，若回退也不影响本报告 GO 结论。

# T544 实施报告：生产侧 `_TERM_HERDR_SERVER_START` 泄漏（Issue #116）

日期 2026-11-13 · rd-infra · 分支 `fix/116-herdr-flag-leak` · PATCH 0.23.3 · HEAD 见回执

## 结论

选 **B（不再用环境变量传信号）**，「摘旗标」（方案 A）降级为其一条**迁移带**。判据 3 决定：只要 `_term_herdr_exec`
仍**读**该变量，人为注入（或旧 server 留下的 pane env）就会误走 server-start 分支 ⇒「注入前后行为一致」结构上不可能成立。
做法：`_term_herdr_exec [--server-start] <子命令…>`（内部首参数，`shift` 掉，**不进 env**）· 唯一调用点
`_term_herdr_session_start` 改 `( _term_herdr_exec --server-start server … & )` · server-start 分支加
`-u _TERM_HERDR_SERVER_START`（旧 server 起的 pane 仍带历史旗标，不摘会被新 server 继承再复制给新 pane）⇒
**脚本内再无该变量的读取点** · 删除 `tests/t4/lib.sh` 的 `unset` 兜底（判据 6 附演练）。根因：`VAR=1 函数调用` 的
前置赋值被 bash 交给该函数的子进程；`env -u` 未含该变量 ⇒ 经 `setsid bash -c` 传给 `herdr server` ⇒ server spawn
的每个 pane 全继承 ⇒ pane 内每次调用都走 server-start 分支（子进程 `HERDR_*` 被枚举清空，含 `HERDR_SOCKET_PATH`）。

## 代价（PM 要求写明）

- **A 只加 `-u`（保留分支读 env）不足**：判据 3 不成立（注入即触发）；该分支还会长期对任何同名变量敞开。
- **B 保留 server-start 分支（原 `:418`）、不改 `session-start` 语义**：仍清宿主句柄 + 枚举清 `HERDR_*` + setsid，只换「谁算起
  server 者」的判据。server 自身无需知道自己是 server（`server` 是 herdr 子命令参数）。
- **B 的代价**：① 多一个内部首参数（herdr 无同名子命令、唯一调用点、静态可查）；② 迁移期仍需 `-u` 兜底；
  ③ 普通路径不摘用户 env 里的同名变量（无读取点 ⇒ inert，见 O2）。

## 判据证据（本机实测；我的常驻 pane 本身带该旗标 = 真实污染态）

**1 新 server 的 pane env 干净**（私有根 `XDG_CONFIG_HOME=/tmp/nao-t544-lab/config`，`HOME`/`TMPDIR` 同私有）：

```
调用方 pane env = _TERM_HERDR_SERVER_START=1
$ bash .agents/scripts/nao-fleet.sh session-start --session nao-t544-fixed   → rc=0「server 已就绪」
$ /proc/<server pid>/environ 中 grep -c _TERM_HERDR_SERVER_START            → 0
$ pane w1:p1 内 env | grep -E '^(HERDR_|_TERM_HERDR)' → 只 7 条 HERDR_*；该旗标 grep -c → 0
  正控：同法用 HEAD 版脚本起 nao-t544-old，同 pane 采集 → grep -c = 1（断言非空转）
```

**2 起 server 能力不变**：`session-start` 再跑 ⇒「已在运行（effect=0）」rc=0；`api snapshot` rc=0（真 server）；`status` rc=0。

**3 负控（注入该旗标 ⇒ 行为不变）**：PATH 前置 spy 桩记录每次 herdr 调用的 argv / `HERDR_*` 条数 / 是否 setsid。
pane 内跑 `close pm` 与 `status` 各两次（无注入 / `env _TERM_HERDR_SERVER_START=1`）：

```
close  无注入 → 5 calls · HERDR_VARS_N=7 · SID=3364061（= pane shell 同 SID ⇒ 无 setsid）
       注入   → 5 calls · HERDR_VARS_N=7 · SID=3364061               ⇒ argv 与结构全同
status 无注入 / 注入 → 4 calls · HERDR_VARS_N=7 · SID=3364061（两次同值）
对照（HEAD 版脚本 + 注入）→ 5 calls · HERDR_VARS_N=0 · 5 个互异 SID ⇒ 分支真走了，判据能分辨
```

唯一差异是 spy 的 `FLAG_N`（被注入变量本身进了子进程 env）= 输入回显，脚本无人读它。

**4 自面板 / 自我回收守卫（两环境各一次）**：pane `w1:p1` label 改 `pm`，在该 pane 内跑 `close pm`：

```
无注入   → 「拒绝回收 pm：…判为调用者自身（shell_pid 祖先链命中…）」rc=1 · pane 存活
注入旗标 → 逐字相同（diff 空）· rc=1 · pane 存活；反证（HEAD 版 + 注入）亦拒绝、pane 存活
  ⇒ F1 守卫读 **fleet 进程自身** env，本批不改其语义；`status` 两环境 diff 空（rc=0），fleet 自身
  HERDR_PANE_ID=[w1:p1] 非空 ⇒ 分支只清子进程 env
```

位相结论：泄漏的实际危害 = 每次 pane 调用都套 `env -u` + setsid + 子进程丢 `HERDR_SOCKET_PATH`，**不是**
「守卫拿到空 pane id」（四环境实测一致）。

**5 门禁**：`check` rc=0（roles=7 · files=54）· `npm test` rc=0（herdr 后端 30 PASS / 2 TMUX-ONLY · SKIP=0
DEGRADE=0 NOTE=10）· `npm run test:t4:full:dual` rc=0（组1 tmux / 组2 herdr 均 rc=0）。均宿主 pane **仍带该旗标** 下取得。

**6 测试侧 `unset` 冗余 ⇒ 删 + 演练**：旧实现不存在后它只掩盖生产侧。非空转自证（带旗标的宿主 env 下）：把
`nao-fleet.sh` 临时换回 HEAD 版（md5 `2c39d42…`）→ `run.sh --case 28` **[FAIL] B2① 等 18+ 条**（stub 的
`HERDR_*` 被清 ⇒ 前提闸门 rc=3）；换回本批版本（md5 `77f89b1…`）→ case 28 全 PASS。即删兜底把套件重新变成泄漏探测器。

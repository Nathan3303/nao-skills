# T544 实施报告：生产侧 `_TERM_HERDR_SERVER_START` 泄漏（Issue #116）

日期 2026-11-13 · rd-infra · 分支 `fix/116-herdr-flag-leak` · PATCH 0.23.3 · HEAD 见回执

## 结论

选 **B（不再用环境变量传信号）**，「摘旗标」（方案 A）降级为其一条**迁移带**。判据 3 决定：只要 `_term_herdr_exec` 仍
**读**该变量，人为注入（或旧 server 留下的 pane env）就会误走 server-start 分支 ⇒「注入前后行为一致」结构上不成立。
做法：`_term_herdr_exec [--server-start] <子命令…>`（内部首参数，`shift` 掉、**不进 env**）· 唯一调用点改
`( _term_herdr_exec --server-start server … & )` · 分支加 `-u _TERM_HERDR_SERVER_START`（旧 pane 的历史旗标不被新
server 继承）⇒ **脚本内再无该变量的读取点** · 删 `lib.sh` 的 `unset` 兜底 · 新增 C3⑤ 静态闸（判据 7）。根因：函数
调用的前置变量赋值会被 bash 连环境交给子进程；`env -u` 未含该变量 ⇒ 经 `setsid bash -c` 传给 `herdr server` ⇒
其 spawn 的每个 pane 全继承。

## 代价（PM 要求写明）

- **A 只加 `-u`（保留分支读 env）不足**：判据 3 不成立（注入即触发）；该分支还会长期对任何同名变量敞开。
- **B 保留 server-start 分支（原 `:418`）、不改 `session-start` 语义**：仍清宿主句柄 + 枚举清 `HERDR_*` + setsid，
  只换「谁算起 server 者」的判据。server 自身无需知道自己是 server（`server` 是 herdr 子命令参数）。
- **B 的代价**：① 多一个内部首参数（herdr 无同名子命令、唯一调用点、静态可查）；② 迁移期仍需 `-u` 兜底；③ 普通路径不摘用户 env 里的同名变量（无读取点 ⇒ inert，见 O2）。

## 用户可读影响（供 release notes 引用）

在 herdr pane 里跑舰队命令，不再每次都套一层「起 server」的净化执行（进程组脱离 + 子进程清空 `HERDR_*`）——后者会让 herdr CLI
丢掉 pane 自带的 `HERDR_SOCKET_PATH`，在自定义 `XDG_CONFIG_HOME`/符号链接配置下可能连到另一个会话的 socket；修复后按 pane 自身环境直连本会话。

## 遗留（三出口）

- **O1 接受（观察）**：`( … & )` 起的 server 有 1 个常驻 `bash` 壳（持已删启动日志 fd）。HEAD 版同形 ⇒ 非本批引入，
  与「后台派生继承 fd」同族；改动面超出 PM 边界。
- **O2 接受**：pane env 内人为注入的同名变量在普通调用路径不被摘（无读取点 ⇒ inert）；摘它要给每次调用加 `env -u`，
  改「唯一入口」形态 + golden 面，收益 0。
- **O3 已落地**：见判据 7（C3⑤ 静态闸 + 三条负控 + 就地注入演练）。

# T525 arch 结构评审报告：子代理会话（`subagent-*`）显式识别与排除

- 状态：已定稿 · 更新：2026-10-14 · Owner：arch-designer
- 指针：PRD `docs/prds/2026-10-14-subagent-isolation.md` · ADR `docs/adr/2026-10-14-subagent-session-identity-exclusion.md` · 分支 `nao/subagent-isolation`（base `3f57b0b`，RD 实现 `6554af6`/`a9a1574`/`ea32e20`）

## 一、可行性结论（输出信封）

- **有条件可行**：把「子代理会话不属舰队会话身份模型」从偶然成立改为显式契约；条件 = 排除点位置、E2 条目感知实现、`fallback_pane_for` claimed 保持三处口径一致（本报告 §二 已定稿，RD 已照此落地）。
- **风险清单**（影响 + 应对）：
  - `close subagent-*` 若误判到 `--task` 值 ⇒ 误杀合法派生 `qa-subagent-x`；应对：判定**只针对 `$target` 位置名** + T9 正控。
  - E2 若用纯值提取 ⇒ 无法按条目名排除；若用纯状态机 awk ⇒ 紧凑单行名册塌缩成末条、假告警；应对：`sed 's/},/}\n/g'` 对象边界切分 + 条目感知（`roster_pane_claims()`）+ T8。
  - 两处 claimed 若一并排除子代理 ⇒ `fallback_pane_for` 兜底误认领父 pane（新增误判）；应对：E2 只改 `unattributed_pi_panes`（D-A）。
  - 未来角色名占用 `subagent-` 前缀 ⇒ 被排除面吃掉；应对：`check_alias_resolution` 保留前缀守卫（id+alias）。
- **技术取舍及理由**：见 ADR `对照过的备选模式`（5 候选含「维持现状」基线 + 不采纳理由）。
- **需 PM 拍板决策点**（已裁定）：D-A 仅改 `unattributed_pi_panes`（反对两处 claimed 一致，已记录在案）；D-B 计数取 `visible_session_names`（与 `derived_in_field` 同源）；D-C 守卫折入 `check_alias_resolution`（非 `load_manifest`）。PM 裁定 = 均采纳 arch 默认建议。

## 二、逐条结构定稿（6 项）

1. **`close` 排除点位置** → `cmd_close` 目标解析**第一条语句**（`[[ -n "$target" ]] || die` 之后、`ALIAS_ROLE` 查表之前），锚首 glob `[[ "$target" == subagent-* ]]`。只判 `$target`（`close --task subagent-x qa` 是合法派生）、`--force` 不旁路、`die` 于任何 pane 定位之前。
2. **`status` 输出契约** → 逐字 `  · 另有 N 个子代理会话（subagent-*）· 生命周期由 pi-subagents 管理，nao 不回收`；位于「任务派生会话」节末、孤儿 pane 告警之前，**独立一行**；`N=0` 不打印；只计数不列名；`intercom list` 头行不呼应。`N` = `subagent_in_field()`（与 `derived_in_field` 同源 `visible_session_names`，已去重）。
3. **E2 收口** → `unattributed_pi_panes` 的 claimed 改条目感知 `roster_pane_claims()`：`name`↔`tmuxPane` 配对后过滤 `^subagent-`；**只改此处**；`fallback_pane_for` claimed 保持含子代理（D-A）。
4. **`check` 守卫** → 折入 `check_alias_resolution`（roles.yaml id+别名唯一枚举点），canonical id 与 alias 都查；与缩进/别名唯一性各自累积 `rc`；成功行追加「+ 无 subagent- 保留前缀」。
5. **ADR 门槛** → 达门槛，落 `docs/adr/2026-10-14-subagent-session-identity-exclusion.md`；实施类内容（本报告）下沉。
6. **文档指针** → `.agents/common/intercom-protocol.md` 加一行身份模型边界指针（不掺 ⑦ 条款）；`tests/README.md` + `docs/releases/v0.18.3.md`；AGENTS.md / 角色卡不改。

## 三、清单（必须 / 建议 / 明确不做）

**必须**（已对照 RD diff 满足）：
- `cmd_close`：`subagent-*` 锚首判定在解析最前、只查 `$target`、`--force` 不旁路、`rc≠0`、文案含 `subagent-` 与 `pi-subagents` 与「不归 nao 回收」、绝不触 pane。
- `cmd_status`：汇总行逐字措辞、派生节末独立行、`N=0` 不打印、只计数不列名、角色区不误报在线。
- E2：claimed 条目感知且过滤 `^subagent-`，**仅** `unattributed_pi_panes`；`fallback_pane_for` claimed 不变。
- 前缀精确：`subagentfoo` / 裸 `subagent` / `mysubagent-x` 不入排除面；`qa-subagent-x` 仍入派生区可 close。
- `running` / `ensure`：仅子代理在场时不判「已在运行 / 在线」（负向 + 正控）。
- `check_alias_resolution`：id+alias 保留前缀守卫，非法 `roles.yaml` ⇒ `check` rc≠0。
- 用例与注册：`tests/t4/cases/15-subagent-isolation.sh`（T1–T10 · 47 断言）+ `run.sh` 注册 `"15"` + usage `<01-15>`；断言只增不减（313 → 360）。
- 夹具纪律：真 tmux 隔离 socket（≠ 生产候选）+ `env -u TMUX -u TMUX_PANE` + 假名册逐字段 pretty-print + 收尾机制 `cleanup -S`。

**建议**：拦截统一走 `die`（exit 1，与既有目标解析失败一致）；孤儿告警第二行可补子代理排除提示（本轮未采纳为非必须）；helper 单点 `subagent_in_field` / `roster_pane_claims`。

**明确不做**：不动 `visible_session_names` 层语义；不动 `fallback_pane_for` / `intercom_pane_for`；不改 F1 自 pane 闸门与 `offline_verifiable`；不给 `ensure subagent-*` 加显式分支（仅负向断言）；不掺协议 ⑦ 条款；不做脚本拆分。

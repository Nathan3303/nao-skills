### 3.1 T513f（层③ 收紧）独立验证 —— 两树对照（**新增 AC10 · 13 断言**）

## 4. AC7 几何 golden（真 tmux 3.7c · 实测）

方法（可重复，ADR §五 命令）：独立 socket 建 `-x W -y H` 会话 → `ensure --force <角色…>`（桩 pi）→
`tmux list-panes -F '#{pane_index}:#{pane_width}x#{pane_height}@#{pane_left},#{pane_top}' | sort`。
golden 采集自**修复前 `cec4461`**，波1（`b729803`）逐值复测相同。

| 场景 | 参数 | 期望几何（golden） |
| :-- | :-- | :-- |
| main-row2 | W=152 H=34 N=4 | `1:52x34@0,0 2:49x16@53,0 3:49x17@53,17 4:49x34@103,0` |
| main-row2 窄列守卫→main-col | W=80 H=34 N=6 | `1:27x34@0,0 2:52x6@28,0 3:52x6@28,7 4:52x6@28,14 5:52x6@28,21 6:52x6@28,28` |
| main-col | W=152 H=34 N=4 | `1:52x34@0,0 2:99x11@53,0 3:99x11@53,12 4:99x10@53,24` |
| grid | W=152 H=34 N=4 | `1:75x16@0,0 2:76x16@76,0 3:75x17@0,17 4:76x17@76,17` |

附加断言：窄列守卫提示含**三个数字**且指名 `回退 main-col`；名册报在线时 `ensure qa rd-be` **判重跳过 qa**（pane 数 2 = 初始 1 + rd-be，输出含 `已在运行`，无 `已拉起 qa`）。

> 注：golden 与 tmux 版本强相关。若门禁机 tmux 版本不同（≠3.7c），几何值可能变化；此时应重采 golden 并同步脚本常量（重采命令见 §6）。

## 5. 覆盖限制（NFR5，**不得省略**）

- 本机**仅有 foot + Hyprland**。`ghostty` / `ptyxis` / 其它合成器（sway 等）路径**无法真测**。
- 因此 AC1/AC2/AC5/AC8 采用**桩/mock**（受控 PATH 替身）驱动真实 `nao-fleet.sh` 控制流，
  断言的是**调用契约与副作用**（是否创建会话 / 是否以 `--app-id`/`--dir` 开窗 / 是否按 class→pid 回收 / rc 与输出语义），
  **不是**真实窗口像素与真实桌面条目行为。
- 本报告与任何回执中**禁止使用「已验证」**描述 ghostty/ptyxis/其它合成器真机路径；
  应表述为「桩覆盖（stub-verified control flow）· 真机未验」。
- 真机主路径（foot + Hyprland）的**可见窗口命中**为**人工验收步骤**（**本脚本无对应 flag**）：PM/RD 在 tmux 外实拉一次，
  QA 脚本默认不打开真实窗口（人工步骤见 §6 第 5 条）。
- AC7 为**真 tmux**（隔离 socket），可信度高于桩；但同样只覆盖 tmux 布局几何，不覆盖真实 pi 的窗口标题/attach 竞态（该面由 `list-clients` 桩近似）。

**F4 判定式（推荐，前置采样：在备份/移除之前计算）**

```
needsShim(t) := A ∨ A′ ∨ B
  A  旧版真脚本存在 := exists(.agents/scripts/nao-fleet.sh) ∧ ¬isShimFile(该文件)
  A′ 已存在 shim      := exists(.agents/scripts/nao-fleet.sh) ∧  isShimFile(该文件)
  B  存在外部调用点  := ∃ 文件 f ∈ walk(t) \ IGNORE，且 f ∉ legacyAssetPaths(t)，

IGNORE            = .git/** · node_modules/** · .pi/** · .agents/.nao-obsolete/** · 二进制 · >1MiB
legacyAssetPaths  = {.agents/<LEGACY_TOP_DIRS|LEGACY_TOP_FILES|LEGACY_SKILL_ENTRIES>}

语义：migrate 默认按 needsShim；--shim 强制装 · --no-shim 强制不装（同时给出 → exit 2）
      init 默认装（新项目 = 明确接入舰队）；init --force → migrate 时传 forceShim=true，不被自动判定改写
```

### E4 F7 单行 lock 静默跳过（合成夹具实测）

- 夹具 A（`.agents/prompts/pm.md` + 单行 `skills-lock.json` 含 `frontend-design`）：migrate 输出**无任何 lock 相关告警**，`skills-lock.json` 逐字节不变，`frontend-design` 仍在（1 命中）⇒ 静默跳过去重。
- 根因：`removeJsonProperty` 用 `raw.slice(lineStart, nl).trim().startsWith('"key"')` 作行级守卫；单行 JSON 下 `lineStart=0`、首字符是 `{` ⇒ 返回 `null` ⇒ `stripLockDuplicate` 静默 `return false`。
- 对照：4 空格缩进与「属性独占一行 + 值压缩」两种形态均能正确删条（现有 test08 覆盖 4 空格）。
- 两仓真实 lock 缩进不同：nue-ui = **4 空格**，nao-todo-server = **2 空格** ⇒ 任何「结构化重写」都会整文件重排。当前两仓 lock 内已无 `frontend-design`（去重或本无该条）⇒ F7 属**潜在**缺陷。

### E5 相邻缺陷（本单发现，实测复现）

- **B2**：夹具 B（单行 lock 含 `frontend-design`，**无** legacy 资产）→ `migrate` 输出「未发现旧版全套 .agents/ 机制副本；按 init 处理。」⇒ `stripLockDuplicate` **不执行**，lock 保持 1 命中。即：`migrate()` 在 `!legacy.length` 时提前 `return init(...)`，锁去重被跳过。
- **B1**：`LEGACY_TOP_DIRS = ['prompts','common','checklists','templates']` 按**目录名**判定 nao 资产 ⇒ 项目自有的同名目录会被备份+移除（对 minimal 属正确命中；对「项目自用 `.agents/prompts`」是误伤面）。

### F4 `migrate` 无条件装 shim vs minimal「零 shim」

**选项对照（含不采纳理由）**

**推荐方案落地（(c)）**

1. 新增 `detectShimNeed(target)`（Node 实现，**不用 shell grep**，保证跨平台可复现）：按 §一 判定式；扫描时跳过 >1MiB 与二进制（含 NUL 字节）文件；`legacyAssetPaths` 复用现有 `LEGACY_*` 常量。

3. 参数解析（init/migrate 共用循环）：新增 `--shim` / `--no-shim`，互斥校验 → 冲突 `exit 2` + 可读错误；`init` 默认 `forceShim=true`；`init --force` 转 `migrate()` 时传递「显式接入」意图。

**判定式为什么「可复现、不误伤」**

- 可复现：输入 = 确定性文件树 + 固定 IGNORE 列表 + 固定 token 正则；无网络、无时间、无环境依赖；`.pi/**` 排除使结果不受是否已物化影响。
- 不误伤方向一（宁装不省）：A（曾装旧脚本）优先于一切；A′（已有 shim）保持；B 只要出现任意一处引用（docs/CI/配置）即装。
- 不误伤方向二（避免装无用 shim）：仅当「无旧脚本 ∧ 无 shim ∧ 全仓零引用」才跳过 —— 此时 shim 无任何调用点。
- 反例清单：① 曾用 fleet ⇒ A=true；② CI 里 `npx @nathan33/nao-skill exec check` ⇒ 命中 `nao-skill` ⇒ B=true；③ 文档提到过 fleet ⇒ B=true（保守多装）；④ 仅有 fx 自研 `.agents/prompts` ⇒ 三者皆假 ⇒ 跳过（正确）；⑤ 只有 `.pi/settings.json` pin（新形态仓，本就会有 shim）⇒ A′ 路径。
- 残余假阴性（已缓解但仍存在）：仓库计划将来接入、当前零引用 ⇒ 跳过 shim，但**有显式提示 + `--shim`**。

**三个已迁移仓兼容性（实测 E3）**：A′=true ⇒ 仍然装 shim；内容比对相同 ⇒ 不写文件、mtime/字节不变 ⇒ **重复 migrate 零变化**（唯一差异是 `.nao-version` 在 CLI 版本不同时更新——这是既有语义，不是本改动的回归）。

### F7 单行压缩 lock 静默跳过

**选项对照（含不采纳理由）**

| 方案 | 内容 | 采纳 | 理由 |
| :--- | :--- | :--- | :--- |
| (a) 仅告警保持原样 | 检测到该形态即 warn | ✗（仅作兜底） | 去重永不发生，与 §12-C「nao 包为唯一来源」目标冲突（重复来源长期存在） |
| (b) 结构化重写 | `JSON.stringify(parsed, null, 2)` 回写 | ✗ | 两仓缩进不同（4/2 空格），重写 = 整文件重排 → 违 F1 已确立的「其余字节不变」，且打破 test08 的 `keep-me` 逐字节断言；下游 review 噪音 |
| **(c) 属性级回退 + 校验 + 失败告警** | 行级失败 → 删属性 token + 一个逗号；`JSON.parse` 校验；失败则 warn + 不改写 | **✓** | 达成去重且不动其余字节；把 (a) 降级为最后兜底，消除「静默」 |

**推荐算法（`removeJsonProperty` 扩展）**

1. 保留现有行级路径（属性独占一行，最常见；含「值压缩在一行」形态）。
2. 行级失败时进入**属性级回退**（k = `"key"` 起点，ve = 值终点，二者现有实现已能算出）：
   - 若 `raw[ve..]` 跳过空格/Tab 后是 `,` ⇒ 删除 `[k, 逗号+1)`；
   - 否则视为末位属性 ⇒ 向前跳过空白找 `,` ⇒ 删除 `[该逗号, ve)`；
   - **不重排缩进、不增删空白**（前导空白与后续换行原样保留）。
3. **强制校验**：`JSON.parse(next)` 成功 ∧ key 不存在，否则放弃（属性级回退失去了行首守卫，校验是唯一保险）。
4. `stripLockDuplicate` 返回三态（`ok` / `absent` / `failed`）；`failed` 时 `warn` 一行「未能安全去重（未知 JSON 形态），请手工移除 `skills-lock.json` 的 `frontend-design`」，其余迁移步骤照常、exit 仍 0。

**为何不破坏「其余字节不变」**：删除范围严格限定为「该属性 token 的最高层键值 + **一个**分隔逗号」，不触碰其它属性的空白/缩进/顺序；`JSON.stringify` 式整文件重排被排除。

**影响面**：`removeJsonProperty`（新增回退路径）· `stripLockDuplicate`（返回值/告警）· `migrate`（消费告警）· test08 扩展（新增单行夹具 + 失败告警夹具）· README §下游迁移（去重不再受格式限制）。
**风险**：低。①属性级回退依赖 `JSON.parse` 兜底，缺守卫处不会静默写坏文件；②CRLF 下现有行级路径会残留一个空行（合法 JSON；建议本批顺带处理或文档标注，实测三仓为 LF）；③若值内含 `"key":` 字面（字符串）导致定位错误 → 校验失败 ⇒ 走告警分支（安全）。

**AC 草稿**

| # | 类型 | Given / When / Then |
| :--- | :--- | :--- |
| AC-F7-1 | 单行去重 | Given 单行压缩 `skills-lock.json`（含 `skills["frontend-design"]` 与其它若干条目），When `migrate`，Then 文件仍合法 JSON、`frontend-design` 命中 0、其余条目子串逐字节不变（与原文件比对，除被删 token+1 逗号外无差异） |
| AC-F7-2 | 格式保持 | Given 4 空格与 2 空格两种多行 lock（各含 `frontend-design`），When `migrate`，Then 与原文件「逐行去掉该条目块」的期望结果 `diff` 为空（沿用并扩展 test08） |
| AC-F7-3 | 失败不静默 | Given 无法安全文本删除的 lock 形态（构造：删除后 JSON 非法），When `migrate`，Then 文件字节不变 + 打印一行 `warn`（含「手工移除」），迁移其它部分完成、exit 0 |

夹具：合成夹具即可（三种形态）；可选把 nue-ui 的 4 空格 lock 作真实对照。

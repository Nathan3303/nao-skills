## 1. 根因与修复机制（证据摘要）

- 根因（PRD §一已收录）：`spawn_tmux` 的 `tmux split-window -h` 与整条布局链全部无 `-t`；tmux 无 `-t` 时落点 = 「当前窗口」（有 attached client ⇒ 用户视图），与调用者 pane（`$TMUX_PANE`）无关，且 `select-layout` / `set-window-option main-pane-width` 同样泄漏到用户窗口。
- 修复机制（ADR 决策 1–3）：入口一次性解析派生宿主窗口 → 归一化 `@<window_id>` → `-t` 贯穿创建/布局/选项/尺寸读取。本批实施所需机制均由下表隔离 socket 实测背书。

## 2. 实验环境与纪律

- 本机 tmux 3.7c；全部实验 `env -u TMUX -u TMUX_PANE tmux -L <隔离 socket>`（禁连真 server；T515 血训）；临时目录随 trap 清理；`script -qec`（pty）附加假 client 供无目标探测。
- 复现脚本：`/tmp/t517-drill.sh`（一次性；已自清理，关键数字下沉本文）。

## 3. 实验与结果（隔离 socket 钻孔，10/10 PASS）

① 机制：`split-window -h -t @W1`（W2 为用户视图当前窗）→ W1 pane 数 1→2；W2 pane 数 1→1（不变）；demo current window @1→@1（不变）。**核心：显式目标不移动用户视图、不外溢。**

② 机制：`set-window-option -t @W1 main-pane-width 55%` + `select-layout -t @W1 main-vertical` → W2 的 `main-pane-width` none→none、W2 `window_layout` 前 20 字符不变（`b25e,80x24,0,0,1…`，未被 main-vertical 改写）；`display-message -t` 分窗读尺寸各自独立（W1=W2=80x24，拓扑同尺寸）。

③ 定位链钻孔（提取 `resolve_host_window` + stub 运行，8 场景）：

- L2 主路径（TMUX_PANE=调用者 pane）→ `HOST_WINDOW=@0`（宿主窗）✓
- L1 显式覆盖 `@id` 跨窗 → `HOST_WINDOW=@1`（log 标注来源）✓
- L1 非法值（bogus）→ warn + 降级 L2 → `HOST_WINDOW=@0` ✓（不 die）
- L3 名册唯一命中（TMUX_PANE 空 + 假 client）→ `HOST_WINDOW=@0` + warn 标来源 ✓
- L3 同窗多 pane → 窗口去重后仍唯一 → `@0` ✓
- L3 两 pane 跨两窗 → warn 歧义（候选 @0 @1）+ 空（skip，不猜）✓
- L3 名册 pane 在**其它 session**（@2/other）→ 被 session 过滤排除 → 空（skip）✓（D-B 不跨 session 推断）
- L3 无 session（TMUX_PANE 空且无 client）→ warn「无从限定」→ 空（skip）✓

④ 幂等：L2 连跑 2 次 → `@0`/`@0` 一致（解析零副作用）。

## 4. 实施中发现的关键事实（影响实现口径）

1. **`$TMUX` 环境第二段不是 `#{session_id}`**：实测 `$TMUX=/tmp/tmux-1000/default,477982,0` 而 `#{session_id}`=`$0`（隔离 server 同：`997675` vs `$0`）。⇒ **不能解析 `$TMUX` 第二段来识别「本 session」**；D-B 的 session 限定改用 `display-message -p -t "$TMUX_PANE" '#{session_id}'`（调用者 pane 的 session，权威且不依赖 client 视图）。TMUX_PANE 空时回退无目标探测（取 client 当前 session；多 session 歧义时保守 skip）。
2. **tmux 3.7c 格式串不展开 `\t`**（`od -c` 证实字面 `\t`）⇒ 分隔符必须用 `$'\t'` 真 tab；本批 L3 的 `list-panes -a -F` 采用与既有代码一致的 `$'\t'` 写法。
3. **单行 JSON 的 awk 贪婪匹配只取「最后一条」** `cwd/tmuxPane`（`.*` 贪婪跨条目）。pi-intercom 实际输出为多行 pretty（既有 `intercom_pane_for` 同款解析在生产可用）；为对紧凑布局同样正确，L3 解析前先 `sed 's/},/}\n/g'` 按对象边界拆行（紧凑/pretty 双状实测同输出）。
4. 无 client 时无目标 `display-message -p` 落到「最近 session」，非调用者 session ⇒ TMUX_PANE 空 + 多 session 场景 L3 保守 skip（安全方向：宁可不建，不跨 session 猜）。

## 5. 落地映射（nao-fleet.sh → PRD AC）

- `resolve_host_window()`（`cmd_ensure` 入口调用一次，全局 `HOST_WINDOW` 复用）→ §五定位链 / NFR（L1/L2 ≤1 次 tmux 调用、L3 ≤2 次）
- `spawn_tmux()`：`[[ -n "$HOST_WINDOW" ]] || return 0`（D-A warn+skip，禁无 `-t` 续建）+ `split-window -h -t "$HOST_WINDOW"` → AC2/AC3/AC5a
- `apply_tmux_layout()`：顶部 `[[ -n "$HOST_WINDOW" ]] || return 0`（PM 指定）；尺寸读 `display-message -t`、pane 数 `list-panes -t`、grid/main-row2 的 `select-layout -t` 及其失败回退 → AC4/AC5d（窄列守卫按宿主窗宽）
- `apply_main_col()`：`set-window-option -t` + `select-layout -t`（含两处回退）→ AC4（选项不外溢）
- 非范围未动：`new-session -d` 分支、`spawn_tmux_attach`（阶梯③④⑤）、`status`/`close` 定位
- 单窗口零回归（AC1）：目标解析后与修前逐值一致（pane 数、几何、布局模式都由宿主窗数据驱动）

## 6. 降级链行为（每级可观测、来源标注）

- L1 `NAO_TMUX_HOST_WINDOW` 命中 → `log` 标注来源；非 `@id` 形式 → warn 建议 `@id`；解析失败 → warn（带原值）+ 沿链降级
- L2 `TMUX_PANE` → `window_id` 命中 → 静默（主路径）；失败 → warn（pane 已关？）
- L3 命中 → warn 标来源（名册 tmuxPane + cwd=本仓 + 仅本 session）；歧义（>1 窗）/无命中 → warn + 不猜
- L4 → 解析处 warn 一次（含完整原因链 + 建议设 `NAO_TMUX_HOST_WINDOW`），spawn 端静默跳过，rc 不劣化

## 7. 已知边界（设计内，非缺陷）

- L3 的 cwd 过滤按精确匹配（`repo_abspath($PWD)`），从子目录调用 fleet 时可能无命中 → 走 L4（可用显式覆盖）；与既有 `intercom_online` 语义一致。
- `ensure` 非 tmux 宿主（阶梯③④⑤）不经 `resolve_host_window`，行为与修前一致（PRD 非范围）。
- TMUX_PANE 空且多 session 时 L3 保守 skip：宁可不建，不跨 session 推断（D-B）。

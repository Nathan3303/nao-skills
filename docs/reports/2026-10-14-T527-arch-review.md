## 一、可行性结论（输出信封）

- **有条件可行 → 采纳候选 ⑥「运行时注册扩展」（E-lite）**。条件 = ① M1 零 LLM 可达性探针通过（RD 已跑通）② 接受新增一类包工件（Pi extension）及其行为面 ③ tools 策略按 §九 拍板项定（Phase 1 不设）。
- **风险清单**（影响 + 应对）见 §七；**技术取舍及理由**见 §二（六候选含不采纳理由）；**需 PM 拍板的决策点**见 §九（D1–D6 已裁定）。
- 六候选逐条不采纳理由证明：A/B/C/F 四条静态路线均**不成立或代价过高**，故「不做（D）」仅在「消费者未就绪」时才是正确延期选项，而非终态。

**E-lite 的机制证据**（本会话零 LLM 实测 · pi-subagents 0.78.0）
- 公开契约：`pi-subagents:runtime-agent-register:v1`（`docs/extension-api.md`；0.67.0 文档已含该节，属长期面）；监听在**扩展装配期**注册（`src/extension/index.js:735`），早于 `session_start` 派发。
- 假 `pi.events` 总线全链路实证：`registerRuntimeAgentEventListener(pi)` + 6× `registerAgentViaEvents` → `listRuntimeAgentConfigs(pi)` = **6 条**（`nao-pm/nao-arch-designer/nao-rd-fe/nao-rd-be/nao-qa/nao-rd-infra`）· `inheritProjectContext=true` · `systemPromptMode=replace`。
- 边界实测：`advertise` 被显式拒（`unknown fields: advertise`）；agent 名**不拦** `subagent-` 前缀（须我方自钉）；文档只写 `{description, systemPrompt, tools?}`，实现面还接受 `systemPromptMode / inheritProjectContext / tools / model / ...`。

## 三、采纳方案结构定稿（E-lite）

1. **工件**：`.agents/extensions/nao-role-agents.mjs`（207 行）= 可导出**纯装配**（`buildRoleAgentDefinitions` 读 `.agents/prompts/*.md` + `.agents/roles.yaml`，零副本）+ 薄 glue（`session_start` 先 `dispose` 再注册 / `session_shutdown` dispose / 失败仅 warn / `NAO_ROLE_AGENTS=off`）。
2. **定义口径**：`systemPrompt` = 卡正文（去 frontmatter，**内部逐字节保留、仅首尾空白归一**——上游 registry 硬性要求 `systemPrompt.trim() === systemPrompt`）+ `\n## 环境锚点\n` + 与 `nao-fleet.sh:1068` **逐字一致**的锚点行；`systemPromptMode=replace` + `inheritProjectContext=true`（保卡内 `AGENTS.md` 最高优先级契约）；`description` 取自卡 frontmatter。
3. **命名/清单**：`nao-<role-id>` ×6，与 `.agents/roles.yaml` **双向一一对应**；**不设 alias**（`mergeRuntimeAgents` 对同名/同 alias 冲突抛错）；**不占 `subagent-`**；不设 `tools`/`model`/`advertise`。
4. **分发**：`package.json` `pi` 段仅增 `extensions`（保留 `skills`；**不**声明 `pi.prompts`、**不**引用 `.agents/prompts` ⇒ AC8/BR2 不破）。
5. **门禁**：`check` 增 1 条「`pi.extensions` 声明 + 文件存在」断言（**非包根跳过不判 FAIL**，保 `cases/09` 夹具）；新增 `cases/17`（只读 Node 探针 + 假 `pi.events` 总线）。
6. **文档**：协议子代理小节加**指针一行**（舰队 = `--append-system-prompt`；子代理 = 运行时注册；同卡同锚），不掺 ⑦ 条款。

## 四、清单（必须满足 / 建议 / 明确不做）

**必须满足**
- 单一事实零副本：扩展**运行时**读卡（无生成物、无静态副本入库）——理由：静态路线复制 40 KB 且带不了机器相关锚点。
- 同卡同锚：`systemPrompt` 卡正文逐字节 + 锚点行与 `nao-fleet.sh:1068` 逐字一致 + `replace`/`inheritProjectContext`——理由：卡自述的 `AGENTS.md` 契约与 `@.agents/...` 引用必须可解析。
- 命名纪律：`nao-<role-id>` ×6 ↔ `roles.yaml` 双向一致；不设裸 alias；不占 `subagent-`——理由：防下游同名冲突 + 兼容 T525 身份模型。
- 韧性 + 幂等：失败仅 warn 不 throw；`session_start` 先 dispose 再注册、`session_shutdown` dispose（连跑 2 次 effect=0）——理由：不伤会话 + 幂等红线。
- 机械门禁：`cases/17`（装配字节 / 锚点 cross-assert / 命名双向 / schema + `listRuntimeAgentConfigs`==6 / 幂等 / 逃生阀 / 三态负控）+ `check` 断言——理由：零 LLM、确定性、可回归。
- 探针纪律：缺 `pi-subagents` ⇒ SKIP；不断言其内部文案；事件名 + version 作契约点记录——理由：防升版脆断（T526 同纪律）。
- ADR（跨角色长期契约 + 分发/信任面）+ 协议指针——理由：防「同一角色两套提示词」误读。

**建议**
- 逃生阀 `NAO_ROLE_AGENTS=off`（已采纳）——理由：行为面扩散时的现场止血。
- QA **一次 live 实证**（真 pi 会话 `subagent list` 见 6 项 + `inheritProjectContext` 是否被 honor）——理由：实现面字段与加载前提只有真 pi 可验；不被 honor 则回落「systemPrompt 内嵌『先读工作区根 `AGENTS.md`』指示行」。
- 后续批次讨论：`pm`/`arch-designer` 的只读 tools 白名单（需先定 `bash` 取舍）、`inheritSkills`——理由：把卡红线从文本升级为工具约束。

**明确不做**
- 不建静态 agent 文件 / 不写 `.agents/pi-agents/`；不用 `agentOverrides.systemPrompt`；不做卡片即 agent。
- 不做 `advertise`（机制不支持）。
- 不设 `model`（沿用 operator；T512 §4.5 model 白名单缺口**继续记录**）。
- 不改舰队 `--append-system-prompt`、不改 6 张卡正文、不在门禁内真跑 LLM 子代理、不做配置安装器。

## 七、负控与失败模式全文 + 两条口径

**两条口径（防后人误读）**
1. **动态读卡 ⇒ 改卡正文两端自动同步，不构成 FAIL**。能 FAIL 的是：① **破坏不变量的编辑**（`frontmatter role:` 与 `roles.yaml` 不一致、卡文件缺失/改名、锚点行被改写、声明被删、加 `advertise`）；② **夹具副本**改卡（M-A：在 `$T4_CACHE_DIR` 副本上改 1 行，用来证明字节比对**不是自证**）。
2. **命名纪律与 T525 身份模型的关系**：`nao-<role-id>` / 不设裸 alias / 不占 `subagent-`；agent 名与舰队会话名是**不同命名空间**（pi-subagents 不拦 `subagent-` 前缀，故由 `cases/17` 自钉）；子代理会话名仍为 `subagent-nao-qa-<runid>` ⇒ 命中 `^subagent-` 排除面，**T525 身份模型与 `status`/`close` 语义不变**。

**主要失败模式（影响 → 应对）**
- R1 加载时序/可达：`session_start` 时监听未就绪 → emit 后校验 `request.result`；无 owner ⇒ 仅 warn；M1 零 LLM 探针已实证。
- R2 未文档化字段（`systemPromptMode`/`inheritProjectContext`）→ `cases/17` schema 探针钉接受面；行为面 QA 一次 live 实证；不被 honor ⇒ 回落内嵌指示行。
- R3 trust 未授予 ⇒ 包不加载 ⇒ 无 agent（静默）→ 文档写明前提（同 `pi.skills`）。
- R4 下游同名/同 alias agent ⇒ merge 期抛 → `nao-` 前缀 + 不设 alias + 失败仅 warn（最坏=无 agent）。
- R5 reload/resume/`--no-extensions` → 先 dispose 再注册；文档 + 逃生阀。
- R6 事件 v1 升版脆断 → 版本常量 + 探针 + T526 BR6 纪律。
- R7 行为面扩散（每 trusted 会话加载）→ 文档 + `NAO_ROLE_AGENTS=off`。
- R8 `check` 不覆盖运行时 → 分层：静态门禁（`check` + `cases/17`）+ 一次性 live 实证。

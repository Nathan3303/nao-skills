## 五、live 实证（真 pi · 已披露成本）

- **PM 指定路线失败**：`pi install -l --approve npm:/tmp/…/nao-skill-0.18.4.tgz` ⇒ `pi list -a` 列出该包，但会话**不加载其资源**（`subagent list` 仅 builtin，`nao-qa` unknown）。根因：pi 加载器按**注册表名**解析 `npm:` 源，本地 tarball 只被 npm 装上、不被加载；`npm:file:<tgz>` 同样失败；裸 `<tgz>` 更糟（pi 把 `.tgz` 当扩展代码执行 ⇒ `Failed to load extension …: BuildMessage: Unexpected`，会话 rc=1）。
- **可用路线（等价 manifest）**：`pi install -l --approve <本地目录>`（tarball 内容解包）⇒ 扩展工厂加载、`session_start` 触发（夹具内注入 stderr 探针自证 `module loaded` + `hasRoleMechanism=true`）⇒ **`subagent list` 列出全部 6 个 `nao-*`**。
- **npm 注册表路线旁证**：`pi install -l --approve npm:@nathan33/nao-skill@0.18.4`（现网版，无扩展）⇒ 其 `nao-fleet` skill **确实加载**，证 **npm 注册表项目包会加载其资源**；`pi.extensions` 走同一 `pi` manifest 解析面。
- **`inheritProjectContext` 追一层**：夹具 `AGENTS.md` 埋标记 `T527_PROJECT_MARKER_Zx7Q`；父会话起 `nao-qa` 后子代理回 `MARKER=Zx7Q` / `HAS_QA_CARD=yes` / `HAS_PI_BASE=no`。对 `--mode json` 全量 NDJSON 做 node 解析：**全会话工具调用只有 `subagent`**（无 `read`/`bash`）⇒ 标记只可能来自**继承的项目上下文** ⇒ honor；`replace` 亦 honor。ADR 预留的回落（systemPrompt 内嵌「先读工作区根 `AGENTS.md`」）**不需要**。
- **附带发现**：`.pi/extensions/*.mjs` **不被目录发现**（`.js`/`.ts` 会）；但 **manifest 声明的 `.mjs` 正常加载** ⇒ 对本批无影响。
- 成本披露：诊断链路约 20 次极短 `pi -p` 会话（默认 deepseek-flash）+ 1 次两步 live（list + nao-qa）；均短提示、零仓库写入。

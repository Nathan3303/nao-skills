## 一、逐页 13 条（§四 质量门禁）

文法（6 条）

1. **人称**：全文「你」，没有「用户 / 操作者 / 使用者」。
2. **一步一动作**：每个操作步骤只含一个动作。
3. **术语**：没有未解释的技术术语（首现即半句解释）。
4. **禁表达**：没有营销词、套话开头（「本文档介绍了」）、模糊指代（「相关设置」「上述功能」）。B 档豁免其中的技术黑话词表（接口 / 参数 / 字段 / 部署 / 实例 / 端点 / 环境变量 / 回调）。
5. **界面文字**：按钮/菜单用「」包裹且与界面一致（不近义改写）。
6. **叫法一致**：同一事物全文一个叫法；**跨页同源文案必须一致**（`faq` ↔ `index` 的 5 条问答、`glossary` ↔ 正文）。

Markdown（7 条）

7. **标题**：不跳级、不加序号（「一、」「1.」）、写用户会说的话（不是功能模块名）、标题下紧跟正文。
8. **列表**：有序只用于有先后的步骤；无序只用于并列项；一项一件事；嵌套 ≤2 层。
9. **表格**：只用于多行多列对应关系；两列且内容短不用表格；表头不用「参数 / 字段名 / 类型」。
10. **加粗**：只标关键动作与易错点；每段 ≤2 处；不「通篇加粗」（术语名整名加粗属违规）。
11. **代码**：无代码块；行内代码仅在「需原样复制」时出现（A 档）。B 档豁免命令 / 配置 / JSON / 目录树。
12. **引用与提示块**：≤2 个；引用块只用于真需要单独拎出的提醒；`> [!NOTE]` 型须确认渲染环境。
13. **装饰**：无装饰性分隔线、无 emoji 标记、不用 `<details>` 折叠必读步骤（FAQ 的「按需展开」判为可选，允许）。

## 二、5 个风险页专项判据（逐页停下确认，不许机械套用）

1. **`glossary.md`** —— `scope` 词条保留「**已弃用 + 一句现状**」写法（PM 裁定 2026-11-26：升级用户可能在旧配置里真的见到 `.agents/fleet-scope`，术语表要能搜到解释；**不判红**，也**不要**整条删除）；`rd-be-T1` 类过时示例改或删；术语名不再整名加粗；定义句拆「是什么 / 什么时候用」两段；定义里的技术词保留但补半句。

3. **`how/acceptance.md`** —— 回执示例代码块保留（`§二.5` 原样照抄例外）；示例里的**项目特定数字**（`npm test`、`128 例`）必须标注「换成你项目的」。
4. **`advanced/custom-cards.md`** —— 模板 block 内**不许去 `## 一、职责` 序号、不许删 frontmatter**（那是照抄件）；只查模板外的正文。

## 三、判红标准（红 = 阻断；「建议」不阻断）

判红：

- **会误导操作**的残留：错指令、错字、过时 golden、示例与当前实现不符且无说明、`scope` / `rd-be-T1` 旧口径、命令被删导致无法照做。
- **§四 硬项**：出现「用户 / 操作者」；标题带序号；一页 `>3` 个提示块；折叠必读步骤；A 档出现代码块（原样照抄例外除外）；两列短内容用表格。
- **同源不一致**：`faq` ↔ `index` 的 5 条问答任一处不同步；`glossary` 与正文叫法不一致。
- **改坏了**：模板示例被改（去序号 / 删 frontmatter）、可复制命令被删、可选展开被扩成必读长篇。

不判红（只记建议）：加粗偏多但每段 ≤2 处；个别长句 60–70 字；措辞可再日常化；标题可更好但语义正确。

红旗记录格式：`<页>:<行> · <条款号> · 实际 · 期望`。

## 附录：判例（T576 实测，最容易判错的四类）

**1. YAML 终端示意怎么判（`index.md`）**
- 载体不是围栏块也要按 `§二.10` 判：`kind: cmd` 是动作本身，`kind: ok` 描述**紧邻那条命令**的后果，`kind: muted` 可放「下一步指引」，但不得混入多步后果。
- 数字归属：`✓ 体检通过 · 7 个角色可开工` 里的 7 来自 `check` 自己的 `roles=7`，**不是窗口数**；窗口数只能出现在 `ensure` 之后，且必须等于该 `ensure` 的目标数（本轮反例：check 后写「你会看到 7 个窗口」，而示例 `ensure` 只 3 个）。
- 判法：先找每条 `text` 的「归属命令」，再看数字来源，最后才看措辞。

**2. 围栏内模板怎么判（`advanced/custom-cards.md`）**
- 必须用**位置判定**：解析 ``` 区间，判断 token 是否落在区间内；**全文 grep 会假红**（示例正文里的 `## 一、职责` 会被当成真标题、frontmatter 被当成真元数据）。
- 判据：模板内是**要照抄的内容**，序号与元数据都属内容，不算违规；模板**外**的正文才按 `§二.1`/`§一.4` 判。

**3. 加粗 21 处为什么放行（`roles/*` 7 页）**
- 形态：7 页 × 3 条「典型误用」标签 = **并列列表项各一处** ⇒ `§二.4` 判例允许。
- 复核顺序：先看形态（并列项各一处 ⇒ 允许），再用语义判据确认（读者读这句会不会因此避免一次返工）。
- 反例：术语名整名加粗（`glossary` 原 28 处）⇒ 违规；「看起来重要」而不是「会出错」⇒ 违规。

**4. 同源复制 vs 各页独立解释（`§二.11` 的边界）**
- `§二.11` 只抓「**同一段说明的复制**」（逐字或近乎逐字相同 ⇒ 必须同步 / 改引用）。
- 各页对同一术语给的**半句解释**措辞不同，**不判** —— 否则 `glossary` 与几乎所有页都会红。
- 判据一句话：**删掉其中一处，另一页会不会语义缺失**？会缺失 ⇒ 是独立解释，保留；不缺失 ⇒ 是复制，按同源判。

**判定顺序（避免指标驱动）**
1. 先过 `[阻断]`（会让读者做错/看不懂）：示意归属、同源一致、弃用项是否保留、模板是否被改坏。
2. 再过 `[建议]`（读起来是否顺）：长句、加粗密度、措辞。
3. 最后才看总量（如「183 处加粗」）—— **数量不是问题数**；本轮 183 处里真正该改的是「术语名整名加粗」一类，其余是并列项标签。

## 二、七项裁决（逐项：结论 / 理由 / 落地口径）

### A1 `Pending Changes ⇒ rc=1` → **降为 warn（唯一选项）**

- 理由：rc=1 现语义 = 机制资产缺陷（缺文件 / 缩进 / EOL / 别名 / 交叉引用 / pi 版本）；**索引 pending 是正常工作态**（一次编辑即 stale，watcher 会同步，6 会话并发下是稳态）。让稳态长期拉红 ⇒ PM 开始忽略红，真失败信号被侵蚀；也与用户拍板的 warn-only 直接冲突，「保留 + 豁免」等于把 codegraph 变成门禁却又声称不是。
- 口径：删除 `cmd_check` CodeGraph 段的 `rc=1`；**`--strict` 亦不升级**（codegraph 永不进 rc 通道，函数头注释写明）；pending 保留可观测性 = `!` 前缀（进默认摘要 `warn=N`）+ `-v` 给真实命令 `codegraph sync`。
- 断言：`check` / `check --strict` 在 5 组夹具（含「齐备 + pending」）下 rc 恒 0；AC1 第五组由「验 rc=1」改为「验 rc=0 + pending 文本」。
- 连带：PRD §五 BR1 附一行豁免说明 + AC9 显式登记「既有断言放松：Pending 由 rc=1 → warn」；`tests/` 内若有依赖该 rc 的断言须同批改（实测 grep 无，见 §三 T4）。

### A2 四态 → **采纳**；四态文本**采纳为机制契约**（前缀级）

- 理由：三态无法解释「有插件有索引但无 CLI」（用户按提示装索引后仍不生效，是最大的误导路径）；`!` 只用于「声明了但不生效」+ pending，语义与既有约定一致。
- 判定顺序（严格短路，先命中先输出）：① 两份 settings `packages` 含包名（`npm:<pkg>` 或裸 `<pkg>`，与 `bin/nao-skill.js` 同口径）→ ② `command -v codegraph` → ③ `<repo>/.codegraph` → ④ `codegraph status` 文本。
- 6 行文本（契约前缀，`·`/`!` 决定是否计入默认摘要 warn）：
  1. `· codegraph 插件未声明` + 装法命令
  2. `! codegraph 插件已声明但 CLI 不在 PATH` + 回退提示
  3. `! codegraph 已就绪但当前仓无索引` + `codegraph init` + 资源一句
  4. `✓ codegraph 齐备` + 原生入口 `codegraph_explore`
  5. `! codegraph 索引 pending` + `codegraph sync`
  6. `! codegraph status 输出不可解析`
- 组合落位（防歧义）：未声明 ≈ 压倒一切（有索引/有 CLI 都报 1）；已声明 + 无 CLI + 有索引 → 2（CLI 是前置）；齐备 + 有改动 → 5。
- 契约化范围：用例断言**固定前缀 + 命令子串**，不断言整行（防文案微调误伤）；变异负控只改提示文本 ⇒ 命中断言失败，`check` rc 不变。
- 单实现：抽 `codegraph_state <repo>` 唯一发射点，`cmd_check`（对 `$PWD`）与 `ensure`（对各 repo）共用 ⇒ 删除 `cmd_check:1200-1215` 的重复 awk 逻辑；文本常量集中 `CG_MSG_*`（新增态只改一处）。
- **BR5 单源修正（须改 PRD）**：运行时**不**从 `bin/nao-skill.js` sed 抽包名 —— 跨语言抽取会静默取空 ⇒ 假「未声明」，且 shim-only 安装可能无 `bin/`。改为 fleet 常量 `CODEGRAPH_PKG` + **用例等值断言**（两文件抽包名比对，漂移即 `npm test` 硬失败）。
- 顺带修：settings 路径用已定义的 `PI_AGENT_DIR`（现状硬编码 `$HOME/.pi/agent`，是既存缺陷）。
- 性能：两条 json 用 grep 子串匹配（与既有 pi-web-access 段同法），禁 `pi list`。

### A3 `CODEGRAPH_TELEMETRY=0` → **注入（舰队 spawn 期，单点）**

- 理由：项目红线「机制零网络」；机制推荐的入口（原生 → CLI）会拉起 CLI，其遥测即**机制触发的网络副作用** —— 只靠文档让用户自己关，等于把红线转嫁给用户且默认违规。代价一行 shell，零新依赖、可逆。
- 位置：`spawn_one` 的 `inner` 字符串（`cd <repo> && export CODEGRAPH_TELEMETRY=0 && exec pi ...`）。**不能**用 ensure 侧 `export`：tmux pane 继承 **tmux server** 环境，ensure 的进程环境不可靠传递，且不可断言。
- 不加 `DO_NOT_TRACK=1`：过宽（影响会话内其它工具），留给用户手工；本项目只钉己方确定的变量。
- 失效兜底：上游变量名是外部契约 ⇒ 技能/README 保留手工关法（`codegraph telemetry off`）；ADR 限制节记一句；M 任务实测 env 生效性（无网则标未验证）。
- 断言：`cases/18` 断言 `spawn_one` 体内含该字面量 + `ensure` 生成命令含该前缀；负控删除该行 ⇒ 断言失败。
- 边界：只覆盖舰队会话；用户手工终端不受影响（文档一行）。

### A4 `.gitignore` 加 `.pi/APPEND_SYSTEM.md`（单文件） → **采纳**

- 理由：会话期生成/删除的副产物（脏 `git status` 破坏路径级暂存可见性）+ trust 门控资源（入库即强制下游 trust 并把过期英文段注入所有会话）+ BR6 禁 nao 编辑它 ⇒ 跟踪一个「谁都不许改」的生成物无意义。
- 口径：本仓 `.gitignore` 在既有 `.codegraph/` 段旁加注释 + 单文件模式；**不 ignore 整个 `.pi/`**（settings.json 属项目配置，可能应入库）。
- 下游分发：**无** `.gitignore` 管理机制（实测 grep 无）⇒ 只在 `templates/AGENTS.md.example`「副产物」一句 + 技能副产物小节给指针，不新建生成器（超范围）。
- AC8 改写：断言「会话退出后不存在」+「`pi --help -e` 残留被 ignore 覆盖、提交中零命中」，**不**断言文件必不存在。

### A5 卡片只写 `codegraph_explore` → **采纳**；「插件不供 system prompt 指引」**只写在技能**（带版本戳）

- 理由：上游默认只暴露 1 个工具，写死多名即腐蚀点；卡片定位是「场景句 + 指针」，正文归技能（单源）。「注入不生效」是 **pi 1.4.0 × 插件 0.1.0 的组合事实**，不是机制条款 —— 写进 6 卡会散 6 处、pi 升级后更难清；写在技能一行 + ADR 限制节，带 `截至 pi 1.4.0 / pi-codegraph 0.1.0` 戳即可见地过期。
- 卡片逐字口径：「代码定位：原生入口 `codegraph_explore`（需插件 + CLI + 索引齐备）→ CLI → `grep -rn` + 行段；详情见 `@.agents/skills/codegraph.md`」。
- 禁用词断言：卡内 `codegraph_(search|callers|callees|impact|node|context|files|status)` 零命中（`codegraph_explore` 除外）；6 卡 `version` +1、`updated` 更新（BR8）。

### A6 sidecar 内存 → **可接受**（口径已按实测复议 → §七 B1/B4）

- 结构事实（决定性）：「只在派生会话 / 按 role 启用」**在机制内不可实现** —— 激活条件 = cwd 有 `.codegraph/`，spawn 发生在**扩展工厂期**；机制侧唯一杠杆 = 该仓建不建索引。故「按需启用」等价于「只给需要的仓建索引」：本批只本仓，下游默认无索引 ⇒ 下游零成本、零泄漏面。
- 实测（CLI 1.6.2 / 本仓 / 6 会话）：进程树全集 **PSS 675.7MB**（RSS 求和 1439.0MB 是量纲错误，见 B1）⇒ 落「600MB–1.2GB」档 = 接受 + README 一行。
- 阈値、加性判据与并发结论 → §七 B1 / B4。
- 不做：机制侧定时 `codegraph sync`（BR4）、自动删索引、用 `--tools`/`--no-extensions` 抑制插件（会误伤其它扩展）。

### A7 非会话残留（文件 + daemon） → **已知限制 + 用户侧规避；不做机制侧清理**

- 实测触发面比「`pi --help -e`」宽：已建索引仓内**任何加载扩展的 `pi` 调用**（`pi list` / `pi install` / `pi --help -e`）都会 ① 重写 `.pi/APPEND_SYSTEM.md` ② spawn 一个 **ppid=systemd 的孤儿 daemon**（本会话复现）；`pi --version` 不加载（0 副作用）。
- 残留有界：daemon 按仓注册并去重（重复调用复用同一 pid）⇒ 每仓最多 1 棵，≈177MB RSS / 134MB PSS。
- 不代跑清理的理由：BR6 禁写插件产物；**无法区分用户自建**同名文件；`pkill -f codegraph.js` 在 daemon argv 不含仓库身份 ⇒ 跨仓误杀活跃 sidecar；上游无 `--stop`。
- 口径与实测有效的规避法 → §七 B2；`check` 不对文件/daemon 加断言。
- 上游修好后撤该限制，不设到期。

## 三、实测结论（原「待实测」项已被 M 任务闭合）

- **T1 已证伪（现实现无误）**：`status` 原文 = `✓ Index is up to date` / `Pending Changes:` + `Modified:  1 files` / `⚠ Not initialized` ⇒ 三个匹配串**全中**，只需删 `:1207` 的 `rc=1`，文案不动。
- **T2 已定**：`-i` 被接受但标 Deprecated ⇒ 机制文案一律 `codegraph init`。
- **T4 已闭合**：本仓 + 下游三仓 scripts/CI 0 命中；nao-todo CHANGELOG 有同一放松先例（索引警告不计退出码）⇒ 支持 A1。
- **T5 已闭合**：`strace` 下 `:443` connect 由 1 → 0（`codegraph telemetry off` + `CODEGRAPH_TELEMETRY=0`）⇒ A3 注入有效。
- **T3 部分闭合**：6 并发 `status` rc 全 0、`database is locked`/`sqlite_busy` 0 命中；**未闭合** = 6 会话全集 PSS 需在**舰队真重启后**复测（现网会话启动于建索引之前 ⇒ 无 sidecar；索引创建不回溯激活）。

## 四、实现风险排序（Top 3）

1. **6 会话全集内存（至多剩部分未验）**——锁已实测通过（6 并发 rc 全 0）；**未闭合** = 舰队真重启后的全集 PSS 复测。影响：可能推翻用户拍板的「本仓起索引」；应对：重启后复测，回退 = 删索引（幂等、无数据损失）。
2. **rc 放松的隐性依赖**——影响：某些脚本/人把「索引过期」当 red，改 warn 后**静默失效**，且 AC9「无悄然放松」最易在此破；应对：PRD 显式豁免 + 台账登记 + 下游影响点名（T4 已 grep 为 0）。

## 七、复议（B1–B4 · M20261028-codegraph 实测后）

### B1 门口径 → **改用「进程树全集 PSS 求和」**；阈值带保留 + 新增加性判据

- 量纲缺陷成立：`pgrep -f 'codegraph serve'` 只命中 6 个 launcher（真实 cmdline = `codegraph.js serve --mcp --path …`），漏 worker/watchdog/daemon；RSS 求和把共享页重复计入（6 会话 1439MB vs 物理 675.7MB）。
- 口径：**进程树全集 PSS 之和**（`ps -eo pid,rss=,pss=,args` 或 `smaps_rollup`）；PSS 仅 Linux 可得 ⇒ 非 Linux 记 RSS 全集并注明高估。
- 阈值（PSS 全集，本机 15GB / 可用 8GB）：≤600MB 接受；**600–1200MB 接受 + README「资源」一行 + 台账记实测**（本次 675.7MB 落此档）；>1200MB 或任一并发读出现锁错 ⇒ 删 `.codegraph/` 降级。
- 加性判据（防「会话数线性放大」误判）：**同仓边际 ≈ +70–90MB PSS/会话**（daemon 按仓共享），每新增一个「有索引的仓」≈ **+155MB**（daemon 128 + watchdog 27）⇒ 多仓 fleet 的成本按**仓数**算，不按会话数。

### B2 daemon 泄漏 → **文档 + 用户侧规避（实测有效）；机制侧一刀不切**

- 结论：不入 `cleanup`/`close`。理由见 A7 +：`pkill -f 'codegraph.js serve'` 在 daemon argv 不含仓库身份 ⇒ **跨仓误杀活跃 sidecar**；只能靠 `codegraph daemons` 交互解析，机制无权代用户决定杀谁。
- 用户侧规避（本会话实测，可直接写文档）：
  - 已建索引仓内做**非会话** pi 动作 ⇒ 换 cwd：`( cd /tmp && pi list )` → daemon 0 / 文件 0（对照：仓内 `pi list` → daemon 1 + 文件重写）。
  - 已泄漏 ⇒ `codegraph daemons`（交互选停）或 `kill <pid>`；单棵 ≈177MB RSS / 134MB PSS，每仓上限 1 棵。
- 机制侧只守一件事：**不新增 daemon 断言**（扫进程 = 新检测面 + 需真 CLI + 把上游 bug 变门禁）。

### B3 status 契约 → **保持文本前缀契约**；并**默认 `check` 不 fork**（`-v`/`ensure` 才 fork）

- 选文本不选 `--json`：① 三条匹配串在 1.6.2 **实测全中**（T1 证伪）② 无 jq 依赖下 JSON 仍需 3–4 次 `grep -o` + 算术，脆性不减 ③ `--json` 无上游文档/版本承诺，schema 漂移风险与文案漂移相当 ④ 失败模式可接受（不可解析 ⇒ `!` 行，不红）。
- 但**量级必须裁**：`codegraph status` 实测 **0.37–0.42s**（node 启动主导）**已超 PRD「check 增量 ≤0.2s」**；实测它不 spawn daemon（前后 0 进程）⇒ 只涉耗时，不涉泄漏。
- 裁决：默认 `check` **零外部进程**（两份 settings + `command -v` + `[ -d .codegraph ]`）；pending / 不可解析两行只在 `-v` 与 `ensure`（同一函数 `full=1`）。理由：pending 是 warn 级非阻塞信号，不值得在派发热路径付 +46%（0.87s→1.3s）；且把「默认路径零第三方进程」变成可断言的不变量。
- 补偿（BR9 不静默）：默认摘要 `✓ codegraph 齐备（索引新鲜度用 -v 查）`。
- 断言（`cases/18`）：记录型 PATH stub 下默认 `check` 的 codegraph 调用次数 = **0**，`check -v` = **1**；三态 + 不可解析兜底各命中一次。

### B4 本仓索引 → **保留**（不降级为演示后删）

- 保留理由：6 并发锁通过；泄漏有界（每仓 1 棵、去重）；同仓 6 会话 PSS 675.7MB ≈ 可用内存 8%；回退成本恒为一条 `rm -rf .codegraph`（588KB，秒级可重建）。
- 三条运营口径必须随 PRD 落地：① 非会话 pi 动作在非索引 cwd 执行（B2）② 成本只在**舰队重启后**出现（现存会话启动于建索引前 ⇒ 无 sidecar；索引创建不回溯激活）③ 下游仍默认无索引。

### 可直接抄进 PRD 的修订文本

- **§六 性能（替换）**：`check` 默认路径增量 ≤0.05s 且**零外部进程**（两份 `settings.json` + `command -v` + 一次目录判定）；`-v` / `ensure` 允许每仓一次 `codegraph status`（实测 0.37–0.42s，上限 0.6s）；禁用 `pi list`（0.92s）。

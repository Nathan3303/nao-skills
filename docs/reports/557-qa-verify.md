### 1.3 结论：补进去的“互斥判据”方向对，但仍未真正互斥

**Q1-①（P1）R1 与 R4 在“组件外观 / 状态矩阵”上重叠**

- 证据：`design-loop.md:14` R1 允许“颜色替换”，同时要求“不改组件外观与状态矩阵”；`design-loop.md:20` R4 又把“重做一个组件的外观或状态矩阵（多态、hover / focus / 禁用、尺寸）”归 R4。
- 不可判样本：「主按钮底色、hover 底色、禁用底色三处 token 值一起换，尺寸/圆角/布局/状态集合不动」⇒ 按“颜色=取值”是 R1，按“改了状态矩阵/组件外观”是 R4；边界判例 `:29` 只覆盖“主色 A→B，其余不动”，覆盖不到多态取值。
- 最小改法：把 R1 改成“只改**取值**（文案 / token 值 / 间距档 / 颜色值，**含组件内多态取值**），不改**状态集合**、尺寸、圆角、结构”；把 R4 改成“重做组件**形态或状态集合**（新增/删除状态、改尺寸/圆角/结构），不是只换取值”。这样“多态换色”唯一落 R1，“新增禁用态/改圆角”唯一落 R4。

**Q1-②（P1）R3 与 R5 对“既有页面多方向”不互斥，且丢 R5 的基线盘点**

- 证据：`design-loop.md:18` R3 明说“新增或改版都适用”；`design-loop.md:22` R5 是“既有页面改版，且动区块层级 / 动视觉系统 / 重做 ≥2 组件”。既有设置页给 2 个组织方案 ⇒ 两条都命中；按 `:12` 顺序取 R3，但 R3 的后续只写“按其任务类型走 S3–S5”（`:19`），**R5 的“先盘点基线”与 CP1/CP2/CP3 全走（`:23`）被跳过**。
- 同时，`:12` 的“定义互斥”与事实不符：R3/R5 在此样本上并不互斥，只是被顺序消解。
- 最小改法：R3 补一句“既有页面 ⇒ 先做 R5 的基线盘点；选定方向后按 R5 走全步”；把 `:12` 的“定义互斥”改成“按 R1→R6 取首个命中（下列重叠由顺序消解）”，不要再声称定义互斥。

**Q1-③（P3）既有页“只新增一个组件、不调顺序”可能无规则命中**

- 证据：R5 三个条件都不满足（未动层级、未动视觉系统、未重做 ≥2 组件）；R4 要求“重做**一个**组件”，不覆盖“新增一个组件”；R1 要求不改区块层级、不新增页面或流程，且新增组件不属于“只改取值”；于是落到 `:12` 兜底 R2（新界面）。
- 影响：路由不唯一性由兜底保证，但类型判错（既有页被当新界面），且 R5 的基线盘点被绕过。
- 最小改法：R5 条件补“或向既有页面**新增 ≥1 个区块/组件**”；或把 R4 扩成“新增/重做**单个**组件”。

**对 RD 探针的评价**：`557-route-probe.md` 的 3 个样本（颜色/R1、既有列表+筛选+调序/R5、卡片三态/R4）都落在安全区；补测 2 例（4 处颜色/R1、整套字阶/R5）也没打到 R1/R4 的多态换色与 R3/R5 的既有页多方向。因此其“带判据的路由表可判”只对所选样本成立，不能推出“谓词边界可判”。

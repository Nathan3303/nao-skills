## 怎么打开

- 最快（不需要联网、不需要装东西）：在仓库里双击 `site/index.html`，用浏览器直接打开。
- 换浏览器/模拟手机（任选其一）：
  - 本机 Python：在仓库根执行 `cd site && python3 -m http.server 8000`，浏览器打开 `http://localhost:8000/`。
  - 有 Node：在仓库根执行 `npx serve site`，按提示的地址打开（首次会联网装 serve，离线时用上一条）。
- 用时约 8–10 分钟。窗口尺寸怎么调：浏览器窗口右边缘往左拖到最窄，或用开发者工具的设备模式选 360 宽。

## 检查项

### 一、主路径（陌生人能不能 30 秒看懂）

**1. 首屏说清「这是什么 + 下一步」**（对应 AC1）
- 怎么操作：打开页面，**不要滚动**，看第一屏。
- 应当看到：一句话定位（「给你的 pi 配一支开发小队」这类）、一条安装命令 `pi install --local npm:@nathan33/nao-skill` 和旁边的「复制」按钮、以及 GitHub 与 npm 两个入口，全部在**不滚动**就能看见的范围内。
- 回填：`- [ ] 通过`　`- [ ] 不通过（写现象）`

**2. 一键复制，粘贴出来一字不差**（对应 AC2）
- 怎么操作：点「复制」，然后把内容粘到一个空文本文件或终端里；再等 2 秒看按钮。
- 应当看到：按钮约 0.1 秒内变成「已复制 ✓」并出现一行小字提示；粘贴出来的命令与屏幕上显示的**完全一致**（不多空格、不带版本号）；约 1.8 秒后按钮自己变回「复制」、小字消失。
- 回填：`- [ ] 通过`　`- [ ] 不通过（写现象）`

**3. 七个角色一眼扫得完**（对应 AC3）
- 怎么操作：滚到「七个角色，各管一段」。
- 应当看到：正好 7 张卡，每张「角色名 + 一句话职责」；桌面宽度下排成 3 列（3+3+1，最后一行那张靠左、不被拉宽）；每张卡的职责不超过两行。
- 回填：`- [ ] 通过`　`- [ ] 不通过（写现象）`

### 二、边界与降级

**4. 关掉 JavaScript 也能读全**（对应 AC4）
- 怎么操作：浏览器设置里禁用 JavaScript（Chrome：设置 → 隐私和安全 → 网站设置 → JavaScript → 不允许），再打开页面。
- 应当看到：定位、安装命令、三个毛病、七张角色卡、三步装好、五个常见问题、页脚全在；命令可以手动选中复制；没有空白区块或「点了没反应像是坏了」的按钮。
- 回填：`- [ ] 通过`　`- [ ] 不通过（写现象）`

**5. 手机宽度不破版**（对应 AC5）
- 怎么操作：把窗口拖到最窄（约 360px），从上到下滚一遍；横向试着左右拖页面。
- 应当看到：**页面本身**不能左右滚动；卡片变成一列；命令块里的长命令不会把页面撑开（需要时可以只在代码块内左右滑）；文字不溢出屏幕边缘。
- 回填：`- [ ] 通过`　`- [ ] 不通过（写现象）`

### 三、可访问性与观感

**6. 只用键盘能走完**（对应 AC8）
- 怎么操作：鼠标不点页面，反复按 Tab（Shift+Tab 往回），看焦点框；按 Enter 打开某个常见问题。
- 应当看到：第一个 Tab 出现「跳到主内容」；之后焦点按顺序经过导航、复制按钮、各处链接、五个问题的标题；**每一个焦点位置都有清楚的蓝色描边**，不出现「焦点跑到看不见的地方」。
- 回填：`- [ ] 通过`　`- [ ] 不通过（写现象）`

**7. 深色模式能看清**（对应 AC8）
- 怎么操作：把系统切到深色外观（或浏览器/系统设置里强制深色），重新打开页面。
- 应当看到：背景变深蓝黑、文字变浅灰白，正文与次要说明都清晰可读；卡片靠细边框分层（不是一团发灰的方块）；终端示意块与页面背景仍能区分。
- 回填：`- [ ] 通过`　`- [ ] 不通过（写现象）`

### 四、与设计稿（Penpot 四画板 + 设计规范）的视觉对照

> 对照物：`docs/designs/2026-11-13-portal-site.md` 的「视觉规范 / 视觉令牌 / 断点」三节 + 本机 Penpot 文件「项目门户页面」四画板（`page-desktop-1440` / `page-mobile-360` / `frame-states` / `frame-dark-hero`）。
> 我实测的数值（主色、字号、圆角、版心）与设计稿一致；下面几条是**只有看着才能判**的观感差异。

**8. 强调色克制，只有一处「蓝」**（对应 AC9）
- 怎么操作：整页扫一遍，数一数有几处显眼的蓝。
- 应当看到：蓝色只出现在链接、主按钮（复制 / GitHub 实心按钮）、键盘焦点框、导航「当前段」这几类地方，且都是同一种蓝；其余靠黑/灰/字重区分，没有第二套强调色（比如又蓝又绿又紫）。
- 回填：`- [ ] 通过`　`- [ ] 不通过（写现象）`

**9. 字阶有层次，不糊成一片**（对应 AC9）
- 怎么操作：看大标题 → 小节标题（三个毛病 / 七个角色…）→ 卡片标题 → 正文 → 小字说明，视线按这个顺序走一遍。
- 应当看到：每一层**肉眼可辨地更小**，相邻两层不会「几乎一样大」；也没有某一处小字小到要凑近看（角色英文 id、页脚版权这种辅助小字应仍可读）。
- 回填：`- [ ] 通过`　`- [ ] 不通过（写现象）`

**10. 留白密度像设计稿那样「松」**（对应 AC9）
- 怎么操作：对比整页节奏与桌面画板 `page-desktop-1440`（或手机画板）。
- 应当看到：区块之间有明显留白（约 3–4 行文字的高度感），区块内部元素相对紧凑；整页读起来不挤、也不用疯狂滚动才见下一个区块。
- 回填：`- [ ] 通过`　`- [ ] 不通过（写现象）`

**11. 卡片是「细边框 + 小圆角」，不是模板感**（对应 AC9）
- 怎么操作：鼠标移到任意卡片上（亮色模式）。
- 应当看到：卡片是 1px 浅灰描边 + 小圆角，平时几乎无阴影；悬停才出现极淡的投影；**没有**大圆角 + 灰阴影 + 奶油底色那种通用模板感。
- 回填：`- [ ] 通过`　`- [ ] 不通过（写现象）`

**12. 首屏终端示意像设计稿那样**（对应 AC9）
- 怎么操作：桌面宽度看首屏右侧（窄屏应看不到它）。
- 应当看到：一个深色窗口，顶部三个小圆点，里面是 `$` 提示符 + 命令行 + 绿色 ✓ 成功行 + 一行浅色「你：…」；这是纯 CSS 画的示意，不抢主体，也不要出现截图/动图。
- 回填：`- [ ] 通过`　`- [ ] 不通过（写现象）`

**13. 断点布局与画板一致**（对应 AC9）
- 怎么操作：窗口分别拉到约 1440、900、600 宽各看一次「七个角色」和首屏。
- 应当看到：宽屏三列（3+3+1）、中宽两列、窄屏一列；窄屏顶栏只剩品牌与四个锚点（GitHub 药丸可以隐藏）；首屏在窄屏时终端示意消失，命令仍在第一屏。
- 回填：`- [ ] 通过`　`- [ ] 不通过（写现象）`

**14. 导航会指出「你在哪一段」**（对应 AC9）
- 怎么操作：慢慢往下滚到「七个角色」「三步装好」等段落，看顶部导航。
- 应当看到：对应的锚点变成蓝色并带下划线，其他锚点恢复灰色；点锚点能平滑跳到该段，且段落标题不被顶栏挡住。
- 回填：`- [ ] 通过`　`- [ ] 不通过（写现象）`

**15. 常见问题与页脚顺手**（附带，不属于 AC，但用户会遇到）
- 怎么操作：逐个点开五个常见问题；再看页脚入口。
- 应当看到：问题展开/收起不跳动、`+` 变 `−`；「会改我的代码库吗」这类答案能直接读；页脚有 GitHub、读 README、npm 三个入口且都能点开。
- 回填：`- [ ] 通过`　`- [ ] 不通过（写现象）`

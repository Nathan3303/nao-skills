## ② 四条 TBD 裁定（判据 / 反例 / 负控）

**TBD-1 判定边界 —— 用结构自描述谓词，不加开关。** 谓词：`docs/README.md` 存在且三段标题逐字齐（`## 一、任务批次` / `## 二、版本` / `## 三、决策时间线`）+ 三张表头逐字；任务目录形态 `docs/(T[0-9]+|M[0-9]{8}-[a-z0-9-]+)-[a-z0-9-]+/`。
判据：两者问的不是一件事 —— `NAO_PRD_STRUCT_SINCE` 回答「49 篇旧 PRD 里哪些进追溯面」（旧语料无结构，只能靠文件名日期）；本条回答「本仓是否已在新布局」。新布局零旧语料，目录形态本身即证据。
反例：下游仓本有自建 `docs/README.md` + `docs/T123-x/` ⇒ 误判。缓解：三段逐字齐才启用；若 `docs/T*/` 目录内含契约文件名（`prd.md` / `qa-verify.md` / `arch-review.md`）而索引缺段 ⇒ 单条「半启用」提示（不静默）。
负控：删掉索引一段标题 ⇒ 索引断言应停摆，此时「半启用」提示**必须**出现（否则删索引即静默免责）。**不与 `NAO_PRD_STRUCT_SINCE` 统一**：变量化会让同仓不同会话/CI 判定不同（NFR「零静默降级」失守），且 `git revert` 后残留环境语义。

**TBD-2 「必须红」的载体 = `tests/t4`；`check` 只做可观测。** 双层：`check` 增 `check_docs_index()`（warn-only、不计 `warn=`、摘要单行回显，与「PRD 结构」同口径）；`tests/t4/cases/53-docs-index.sh`（夹具 + 变异负控 + 本仓零输出 + golden md5；编号须 >52，46–50 已随编排器退役、禁复用）。
判据：`check` 的 rc 只由 `✗` 触发，语义 = 机制完整性；`!` 行**永不改 rc** ⇒ 删一行仍「check: OK」、CI 绿。把内容类判据做成 rc≠0 又会破 AC7（老仓零输出）与下游仓可用性。全量门禁只认 `npm test` / `test:t4:full`，故「删掉一行必须红」只有 t4 承载得住。先例：`cases/36`（同一 warn-only 探针的持久用例，含 N1–N3 变异负控）。
反例：t4 直接断言「本仓 docs 与索引一致」⇒ 立项中途（已建目录、未加行）必假红。故行为断言走夹具，本仓只断言「探针零输出」（同 `cases/36 ⑦`），一致性用 md5 钉住。
负控：删调用行 ⇒ 夹具 4 条必红；去掉 `! 索引` 排除名单 ⇒ `warn=` 必现；取反幽灵行判据 ⇒ AC3 必红。

**TBD-3 最小机读结构 = 4 列表 + 逐字表头 + 严格单元格文法**（表格走 `deliverable-docs` §七 例外③，须在该节显式登记「索引表」）。
字段：任务段 `任务号 | 目录 | 一句话 | Issue/PR`（机读：前两列）；版本段 `版本 | 权威路径 | 发布日期`（全列机读）；时间线段 `日期 | 决策 | 任务号 | 状态`（决策格内 `[…](adr-*.md)` 相对链接）。
文法：任务号 `^T[0-9]+$|^M[0-9]{8}-[a-z0-9-]+$`；目录首段 = 任务号；版本 `^v[0-9]+\.[0-9]+\.[0-9]+`；日期 ISO；状态只判前缀（`提议` / `已接受` / `已废弃`）。单元格禁 `|`；**先剥 ``` 围栏再解析**（现 PRD 探针承认不剥，这里不行：误报会进 t4 红）。
双向断言：目录↔行（AC2/AC3）· 版本唯一 + 路径存在 + basename = `release-notes-<版本>.md` · 任务目录内 `release-notes-v*.md` 必在版本段恰 1 行 · 每篇 `adr-*.md` 在时间线恰 1 行 · `docs/*.md` ⊆ {README, tasks-state, tasks-archive, INSTALL, ARCHITECTURE}（「一级唯一索引」的机械判据，现状已满足）。
反例：现版本段有一行 `停更说明`（非版本）⇒ 文法必红。修法：删该行（§四 历史已含同一信息）；缺格/多格 ⇒ 单列「格式非法」，不得静默跳过。

**TBD-4 并存期话术 —— 改「权威份」判据，不列路径清单。** `release-notes.md` 实测 3 处（L15 / L22 / L57，非 5 处）改为：权威落盘 = 归属任务目录的 `release-notes-v<X.Y.Z>.md`（路径约定正文只在 `deliverable-docs` §十）；`docs/releases/` = 2026-11-27 前历史，只读不追加。
并存不成双源的唯一判据：**同一版本号全仓只有一个文件**（旧版本只可能在 `docs/releases/`，新版本只可能在任务目录）——可被 `check` 机械核（版本段 ↔ 文件双向），「两处都写」是异常而非并存。
反例：照抄 `gh release create --notes-file docs/releases/<v>.md`（`github-flow` L107、`product-manager.md` L158）⇒ 新版本落历史目录、索引无行 ⇒ AC10 红。负控：在 `docs/releases/` 造一个与索引同版本的新文件 ⇒ 必报「版本重复 / 未登记」。

## ③ 风险与应对

1. 改动面大（约 28 文件 / 90+ 处），其中 5 张角色卡须各 bump `version` 并 intercom 广播 ⇒ 角色卡与机制正文**同批**改，禁分批（否则卡与清单互相矛盾）。
2. 「主产物必在」若做成硬断言，`fix` 通道（无 PRD）必假红 ⇒ 探针只判「已存在的产物」形态，缺 PRD 归 PM 清单管。
3. 索引是单点：PM 忘加行 = 全仓文档不可发现 ⇒ `check` 必须摘要常驻回显（不能只藏 `-v`）。
4. 1229 处旧指针与 71 份 `docs/releases/` 长期并存 ⇒ 文档只可写「历史冻结」，禁写「已废弃」，否则等于宣布存量链接失效。

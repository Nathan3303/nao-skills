# v0.17.2 — 架构决策记录（ADR）立规矩：写决策的写决策，「怎么落地」另存

- 状态：已发布 · 更新：2026-10-14 · Owner：PM

## 一句话

架构决策记录（ADR）第一次有了统一骨架与硬边界：**必写 5 节 + 可选 3 节**、参考来源恒为末节、头部恰 4 字段；「怎么落地」这类内容（实施闸门 / 接线清单 / 实现细节）明确另存评审报告，于是 60 行上限不再形同虚设 —— 顺带补齐 ADR 与索引的官方模板，索引里那一列「决策」也收敛成一行短结论。

## ✨ 更好用了

- **写 ADR 有官方模板可抄** —— 新增 ADR 骨架与索引骨架两个模板，字段、节序、状态取值都不用再猜；下游项目直接复制，格式不再漂移。
- **ADR 回到「一屏读完」** —— 实测 7 篇里 5 篇超 60 行（最长 154 行 = 上限的 2.5 倍），根因是 ADR 兼收了「怎么落地」；现在这类内容明确另存评审报告，ADR 只留背景 / 决策 / 理由 / 对照过的备选模式 / 后果与边界。
- **决策索引一眼可扫** —— 索引「决策」列从上百字整段结论收敛为一行短结论（实测最长 16 字），细节留在各自 ADR 里。
- **不再有两套字段** —— 删掉了与「对照过的备选模式」语义重叠、长期空转的旧字段；字段口径只在规范里定义一处。

- **本版不改动能力包** —— 改动全部落在机制文档与 `docs/`（不进包），因此 `@nathan33/nao-skill` **不重发**；`package.json` 与 README 的安装版本仍为 **0.17.0**，安装命令无需改动。`v0.17.2` 只作本批机制治理的留痕。

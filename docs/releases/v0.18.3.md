# v0.18.3 — 舰队不再把子代理会话当成自己人

- 状态：待发布（v0.18.3 · PATCH；npm 重发由用户执行）· 更新：2026-10-14 · Owner：PM

## 本次更新

这一版把一件一直「靠命名巧合成立」的事变成明确规则：会话内由子代理工具（pi-subagents）拉起的子代理会话（名字以 `subagent-` 开头）**不属于舰队会话**。看舰队状态时它们只会以一行数字出现，不会再混进角色或任务列表；想回收它们会被明确拒绝，并告诉你该去哪里处理 —— 父会话绝不会因此被误关。

## ✨ 更好用了

- **状态里一眼看清有几路子代理** —— 查看舰队状态时，如果名册里存在子代理会话，末尾会多出一行「另有 N 个子代理会话」，只报数量、不逐个罗列，也不再让它们混进角色在线表或任务派生表。没有子代理时这一行不出现（零噪音）。

## 🐛 修好了

- **回收提示不再打太极** —— 过去对子代理会话执行回收，只会得到一句笼统的「未知角色或派生会话名」，你无从判断是自己名字写错，还是它根本不归舰队管。现在会明确告诉你：这是子代理会话，生命周期由子代理工具管理，请用它的停止／保留机制处理。
- **孤儿窗口不再被悄悄吞掉** —— 极端情况下，一个本应提示「无法归属会话名」的终端窗口，会因为某个子代理会话恰好登记了同一个窗口句柄而被误以为「已有归属」，提示就此消失。现在归属判定只看非子代理会话，这类窗口会重新出现在提示里，避免问题被掩盖。

## ⚠️ 请留意

- **`close subagent-...` 会被拒绝，且不受强制参数影响** —— 这类名字一律拒绝回收，加不加强制参数都一样（强制参数只对角色会话的两处安全检查生效）。父会话不会受牵连。
- **角色名不能用 `subagent-` 开头** —— 这个前缀保留给子代理会话。若把角色 id 或别名起成 `subagent-*`，体检命令会直接报错并说明原因（`subagentfoo` / `mysubagent-x` / 裸 `subagent` 不受影响）。
- **npm 包本版重新发布** —— 这一版改到了随包分发到用户机器的工具脚本，因此重新发布：registry 上的版本从 `0.18.2` 升到 `0.18.3`。

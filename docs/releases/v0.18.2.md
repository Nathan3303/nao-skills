# v0.18.2 — 提示语只说能兑现的话，测试缓存不再堆积

- 状态：已发布（v0.18.2 · tag + Release 已发；npm 重发由用户执行后核验）· 更新：2026-10-14 · Owner：PM

## 本次更新

这版补上两处「说了却做不到、做了却没人收尾」的小毛病：回收会话时给出的提示不再建议一个在该场景下无效的参数；跑测试产生的临时缓存目录能自动收尾——全部通过就清干净，有失败才保留现场。

## 🐛 修好了

- **回收提示不再指错路** —— 当工具既看不到终端句柄、又读不到会话名单，因而无法判断某个会话是否还在时，它给出的提示里以前还附带一句「可以用某个参数跳过」。可这个参数在这种情况并不生效，照着做只会再次被拒绝，让人误以为工具坏了。现在这句会误导人的建议已经删掉，提示只保留真正可行的做法（用会话名单人工核对；确认已退出后忽略）。
- **跑完测试不再往系统临时目录堆东西** —— 测试套件过去每跑一次就在系统临时目录里留一个缓存文件夹，从不回收，时间久了会积一大堆（本机实测已攒到 129 个）。现在：跑成功就自动清理；跑失败则保留现场并在结尾打印路径，方便查看每个用例的日志；你自己指定的缓存目录永远不会被删。

## ⚠️ 请留意

- **失败现场仍然保留** —— 只有全部通过时才会自动清理缓存。一旦有失败（或发布前的严格模式判定失败），缓存目录会保留并在结尾打印出来，其中包含每个用例的日志，方便定位问题。
- **想手动留下现场，设一个环境变量即可** —— 跑之前设 `T4_KEEP_CACHE=1`，无论成功失败都会保留缓存目录；这是给需要留证的场景用的开关，没有新增命令行参数。
- **只读命令不再产生目录** —— 只列用例（`--list`）、只看前置探测（`--preflight`）、以及把参数写错时，都不会再新建缓存目录。
- **npm 包本版重新发布** —— 上一次改动只动了仓库内的测试，所以没有重发 npm 包。这一版改到了会被打进包里、随包分发到用户机器的文件，因此本版重新发布：registry 上的版本会从 `0.17.3` 直接跳到 `0.18.2`（期间 `0.18.0` / `0.18.1` 的包内变化一并带上）。

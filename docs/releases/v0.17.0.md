# v0.17.0 — 聊透了直接出 PRD，写 PRD 前先把「怎么验」定下来

- 状态：已发布 · 更新：2026-10-14 · Owner：PM

## 一句话

需求已经聊清楚时，PM 不再重复盘问，直接成稿；并且在动笔写 PRD 之前，先把「这个需求将从哪里被验证」定下来、交给 QA 确认。

## ✨ 更好用了

- **聊透了就不再重复问** —— 这个需求如果已经有澄清结论、有原型或设计稿、有架构决定，或者你明说「讨论够了」，PM 会直接把这些整理成 PRD，不再从头盘问一遍。
- **写 PRD 前先定「验证接缝」** —— PM 先提出「这个需求从哪里验」（尽量只留一个、优先用现成的），由 QA 确认或改成更高层的位置，结论写在 PRD 验收标准的第一行。以后「验什么」和「怎么验」从一开始就是同一件事，不再等开发完才对齐。
- **PRD 有可复制骨架了** —— 新增 PRD 模板，复制即用，不再靠记忆拼九个模块。
- **「这版不做什么」必须写理由** —— PRD 的非范围条目现在每条都要给理由，避免「当初为什么不做」随时间丢失。

## ⚠️ 请留意

- 只有需求**确实已成熟**才会跳过盘问；四条判定一条都不满足时，仍然照旧逐层追问。
- 跳过盘问不等于可以省模块：仍会跑一遍缺口检查，缺「目标指标、性能与安全基线、上线监控、变更流程」这类内容时，先列缺口补齐，不带缺口出稿。
- 产出物仍然叫 **PRD**，没有第二种叫法。
- 本次更新改动了 PM 与 QA 两张角色卡的内容（卡版本各自 +1）；如果你的项目 pin 了旧版本，升级后会读到新卡与新技能。

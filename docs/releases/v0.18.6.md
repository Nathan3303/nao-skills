# v0.18.6 — 任务收尾必须交代遗留项

- 状态：待发布（tag + Release 由 PM 发，npm 重发由用户执行）· 更新：2026-10-27 · Owner：PM

## 本次更新

这一版补的是**「活干完了」这件事本身**。以前只要派发、回执、验收、合并这条链路走完就算结束，至于过程中冒出来的告警、待批动作、暂时压下的问题，没有人被要求交代——它们打印出来，然后随会话关闭一起消失。现在每次收尾都要回答四个问题，**遗留项只有三种合法去处**，没有第四种。

## ✨ 更好用了

- **收尾要说清楚四件事**：这次交付了什么（在哪能独立读到）· 怎么验证的（命令与结果，不接受「我看着没问题」）· 有没有遗留（没有也要明说「无」）· 谁来接手（状态写在哪、下一步谁做什么）。
- **外部命令跑完不等于完成**：更新依赖、升级工具这类动作，输出里每一条警告、报错、待批脚本都必须有归宿——已处置 / 明确接受（带到期日）/ 转成待办。**「先放着」不算归宿**。
- **回执多了「遗留」一栏**：交接时可以一眼看出这次留了几件事、去哪了。零遗留写「无」，不允许省略字段。
- **复盘按重量分级**：日常小改动写一行就够；只有遇到返工、漏了流程、事故、同类问题第二次出现、或用户投诉，才写完整复盘（发生了什么 / 根因 / 改了哪条机制 / 可验证的防线）。

## ⚠️ 请留意

- **这是纪律，不是围栏**：本版**没有**加自动拦截，违规不会被脚本挡住，靠会话遵守 + 收尾核对；想要硬约束需另行评估。
- **回执格式变了**：如果你有脚本解析回执文本，需要认得新的「遗留」字段；按旧格式写的回执会被视为缺项。
- **两处角色卡更新**：产品经理卡与工程基座卡（新增任务完成闸门 / 维护型完成标准），**已开的会话需重开**才生效。
- **遗留项台账落在报告目录**：每条记录带编号、来源、严重度、去处与到期；已发布的版本不删，改发下一个补丁。

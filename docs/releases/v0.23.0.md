# v0.23.0 — 默认终端后端换成 herdr：一条命令可回退

- 状态：待核验（tag / Release 待发；npm 发布后按唯一判据回填）· 更新：2026-11-11 · Owner：PM

## 本次更新

**这是行为变更：默认终端后端从 tmux 换成 herdr。**

**你要做的只有一件事** —— 二选一：

- **继续用 tmux（什么都不想改）**：`export NAO_TERMINAL=tmux`。行为和 0.22 完全一致，命令、输出、布局都不变。
- **用 herdr**：装 `herdr ≥ 0.9.1` → `herdr integration install pi` → `nao-fleet.sh session-start --session <名>` → **在那个会话的 pane 里**跑 `ensure`。

> 不设这个环境变量、又不在 herdr 会话里跑 ⇒ 舰队命令会直接报错退出并告诉你这两条路（**不会**静默换回 tmux —— 同一命令在不同机器上跑出不同后端，比报错更难查）。

## 为什么换

三个老毛病，根子都在「靠猜」：

- **身份靠猜**：以前靠终端标题认会话，而标题会被 shell 提示符改写 —— 这就是之前偶发假红的根源。herdr 下身份取结构化事实（pane label + agent 状态），不读标题。
- **归属靠猜**：以前靠 pane 的当前目录反推「这个会话属于哪个仓」，踩过他仓误判。herdr 的 workspace 自带仓库锚点。
- **就绪靠猜**：以前靠轮询标题等它「看起来好了」。herdr 下要等到「观测到状态迁移」才算就绪，超时会逐条告诉你缺哪一条。

## 保留的退路

- **`NAO_TERMINAL=tmux` 至少保留 2 个 MINOR 且 ≥90 天**；真要移除时会先发一个 MINOR 的弃用说明，**不会静默删**。
- 发布闸门改成**两个后端各跑一次**（`npm run test:t4:full:dual`）：tmux 侧的零回归由固定的 golden 逐字对照，不是靠"看起来没动"。
- CI / 自动化请**显式**设置后端（`NAO_TERMINAL=tmux` 或 `NAO_TEST_TERMINAL=herdr`），不要依赖默认值 —— 默认值会随版本演进。

## 顺带修掉的

- 多仓并发时「第二个仓静默跳过」：现在必须显式声明 scope（`.agents/fleet-scope` 或 `ensure --scope <slug>`），没声明就直接报错并列出冲突会话，而不是悄悄顶掉第一个。
- `--force` 不再向正在运行的程序注入按键（前台不是 shell 时会拒绝并给改法）。
- 一批跨机假红：测试夹具不再依赖宿主 tmux 配置（`pane-base-index`）、不再复用上一次的缓存目录。

## 升级方式

```bash
npm i -D @nathan33/nao-skill@0.23.0
.agents/scripts/nao-fleet.sh check     # 体检；默认 herdr 且没装会打红并给两条命令
```

**升级与否由你的仓库自行决定**，我们不修改你仓库的 `AGENTS.md`。完整前提链、空间判据与回退说明见 `docs/INSTALL.md` 的「herdr 后端」一节。

# v0.30.1

- 状态：**待核验** · 更新：2026-11-24 · Owner：product-manager

## 一句话概括

**`ensure` 现在会对调用方说实话**：一个角色都没拉起来时返回失败（以前恒为成功）；桌面版拿不到放置信息时不再偷偷多起一个终端。

## ⚠️ 请留意（行为变更，会影响脚本判断）

- **`ensure` 全部角色都失败 ⇒ 返回 `1`**（以前恒为 `0`）。部分成功 + 部分失败仍返回 `0`，纯跳过（已在运行）仍返回 `0`。
- **「就绪门超时」也算失败**：角色起来了但没在时限内就绪，计入失败；若那是唯一目标 ⇒ 整次 `ensure` 返回 `1`。这一条取代了 #96 B4 时期「超时只进计数、`rc` 仍 0」的旧裁定 —— 理由是摘要已写「失败 1」却回 `rc=0`，对调用方是自相矛盾。
- **如果你的脚本/CI 靠 `ensure` 的 `rc` 判断成败，请复核一遍**；只想「尽力拉起、不看结果」的用法，请显式忽略 `rc`。
- 不想要这些变化 ⇒ 把机制版本 pin 回 `≤0.30.0`。

## ✨ 更好用了

- **`check` 不再说「唯一后端」**：改为「`NAO_TERMINAL=herdr`（形态 TUI；desktop app 走 `NAO_TERMINAL=app`）」，与 0.30.0 起的双形态一致；`--help` 里「给其他任何值都会被拒」那句契约错误同步订正。
- **静态闸覆盖更多写法**：`if` / `then` / `else` / `elif` / `while` / `until` / `do` / `!` 关键字位、`command -x`、`sudo [-u 用户]` 前缀下的裸调 `hc` 都会被抓住并报行号；`case` 分支位（`pat) hc …`）同样覆盖。

## 🐛 修好了

- **拿不到放置信息时不再多起一个终端**：桌面版若丢失 `labels` 键，以前会被判「不在运行」⇒ `ensure` 起第二个同角色终端。现在判 `unknown` ⇒ 拒绝自动起、给一行指路，并与「失败」一样计入失败（桌面版与 TUI 同一条原则：拿不到证据就不动手）。
- **告警不再重复刷屏**：同一终端的探针被调用两次会打两条相同告警；现在恰一条，并有断言钉住（`grep -c` 精确等值，不是「至少一条」）。
- **两条零覆盖的断言补上了**：`cases/44` 的「纯跳过 ⇒ `rc=0`」负控此前实际走的是「成功拉起」路径（断言在但抓不住），改为连跑两次 + 终端数不变；`cases/44` 一处反引号未转义的断言标签会让测试运行期真的执行 `command hc`，已修。
- **测试用例 29 的旧契约订正**：就绪门超时的期望 `rc` 由 `0` 改为 `1`（见上「行为变更」），其余 17 条断言一字未动。

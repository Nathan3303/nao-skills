## 一句话概括

**说明书终于跟实现说的一样了，体检也会主动提醒两件容易忘的事。**

## ✨ 更好用了

- **体检会提醒「说的和做的不一致」**：如果你项目的说明文件里写的终端后端（默认 herdr / tmux 回退）与实际实现不符，`check` 会给一条提示 —— 不会再出现"照着说明做却跑不起来"。
- **体检会提醒滞留的暂存改动**：仓库里如果有放置超过 6 小时的 `git stash`，会提醒你「合并后的事实可能还压在暂存里」。当天存取的不会打扰你。
- **ADR 不再是无条件产出**：只有真正涉及结构性决策时才写；没有决策时，评审报告里明写「本批不需要 ADR」即可 —— 不再出现"按用户口径交付却被自家清单判未过"。
- **同一个规矩只写一处**：代码定位规范（三段阶梯）与交付三件套（静默工作区 / HEAD / 命令+输出）已各自收敛到单一出处，其余位置只保留一句话指路。改规矩不必再手改十个文件。

## 🐛 修好了

- **hotfix 是否走 PR 有了唯一答案**（此前同一个文件的标题与正文互相矛盾）：结论是走 PR 快速合并 —— 白名单免的是完整评审，不是 PR 本身，主干仍只收单条合并、保留可追溯性。
- **说明文档里的 pi 版本门槛不再会悄悄过期**：文档声明的门槛与实现里的常量必须一致，不一致时测试会直接报错。
- **npm 安装形态下体检不再误报**（此前每次体检会多一条无意义的警告）。
- **终端后端的隔离更彻底**：测试与工具不再把宿主的终端环境变量带进被试进程（`HERDR_*`、`NAO_SKILLS`、`NAO_STASH_ROOT` 三处渗漏已堵并加了反向断言）。

## ⚠️ 请留意

- **两处新增的体检提示是「提醒」而非「报错」**：不会让 `check` 返回非 0；介意的化按提示修正即可。
- **暂存改动提醒有 6 小时门槛**：当天合并后按规矩临时存的改动不会触发；如果你习惯长期留着 stash，会看到它（这正是提醒的目的）。
- **角色卡说明有更新**（六张）：如果你已经拉起过常驻会话，**本轮会话仍是旧卡内容，建议重开**才能生效。

## 📦 更小更快

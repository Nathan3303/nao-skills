# v0.22.3 — 发布闸门不再因「机器一时慢」变红

- 状态：**未上 npm（内容已含在 v0.22.4 / v0.22.5，本版被直接取代）** · tag 与 Release 已发并保留（不删除已发 tag）· 更新：2026-11-06 · Owner：PM

## 本次更新

**这一版没有面向使用者的功能变化，命令行为与 v0.22.2 完全一致。** 它修的是两件反复消耗我们时间的事。

第一件：唯一那个「真的把会话拉起来加载技能」的冒烟测试，机器繁忙时会偶发超时。超时本来是「无法判定」，但发布闸门把它当红 ⇒ 一天之内红过 4 次，每次都要人判断「是真坏了还是抖了一下」。现在改成：**只在「超时或没有任何输出」这一种情况下自动再试一次**，其它失败（进程异常退出、输出解析失败）**照旧直接判红、绝不重试**。也就是说——它吸收的是「机器一时慢」，不是「坏」。

第二件：合并记录里的提交说明，原来是自动把工作期的小步提交标题拼进去（含被反复修订的旧说法），读起来像流水账。现在合并一律用需求描述当正文，**main 上一条提交 = 一段说人话的说明**。

## ✨ 更好用了

（本版无使用者可见的新能力。）

间接好处：如果你把测试门禁接进自己的流水线，**它不再因为一次偶发的慢而要求你人工复核**；而它仍然红的时候，红的就是真问题。

## ⚠️ 请留意

- **命令与输出没有变化**：`ensure` / `status` / `close` / `check` 与 v0.22.2 一致。
- **最坏等待变长**：断网或没有可用凭据时，这一条冒烟最多会多等一次（约 180 秒）。已经收敛过：没有凭据时直接跳过重试，不需要等。
- **重试不会掩盖故障**：非超时的失败一次就判红；两次都超时仍按「无法判定」处理（发布闸门照旧判红）。这条在两轮独立复核里都用「造一个假故障」的方式验过。

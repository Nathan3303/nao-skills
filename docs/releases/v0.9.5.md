# v0.9.5 — 修复：`.mts` 探针触发下游 TS 项目 `vp check` 报错（上游类型自检补位）

- 状态：已发布 · 更新：2026-09-30 · Owner：PM

## 一句话

**修复**：v0.9.4 新增的 `.agents/scripts/intercom-probe.mts` 在 **strict 类型检查**下报 2 处 `TS7006`（`(s) => …` 隐式 `any`），导致把 `.agents/**` 纳入 `vp check`（`tsc`）的**下游 TS 项目**（nao-todo / nue-ui）required `check` 变红、PR 无法合并。本版为探针补上显式类型（**行为零变化**），并在 nao-skills 仓内新增对 `.agents/**` 内 TS/MTS 的**类型自检**，把这类缺陷拦在上游发布前。

## 根因

- `intercom-probe.mts` 用**动态 `import()`** 从 `$PI_AGENT_DIR` 载入 pi-intercom 的内部模块，TS 无法解析 ⇒ `client.listSessions()` 返回 `any` ⇒ `.filter((s) => …)` / `.map((s) => …)` 的参数 `s` 隐式 `any`。
- nao-skills 自身无类型检查，故发布时未暴露；nao-todo 的 CI `check`（`pnpm exec vp check`，扫 1271 文件，含 `.agents/**`）执行 `tsc` 时命中：
  ```
  .agents/scripts/intercom-probe.mts(44,14): error TS7006: Parameter 's' implicitly has an 'any' type.
  .agents/scripts/intercom-probe.mts(45,11): error TS7006: Parameter 's' implicitly has an 'any' type.
  ```
- `// @ts-nocheck` 不可用：下游 lint 规则 `ban-ts-comment` 直接报错。

## 修复

- **探针显式定型**（行为零变化，仅加类型）：
  ```ts
  type ProbeSession = { id: string; name?: string; model?: string; status?: string; cwd: string; tmuxPane?: string; pid?: number };
  const sessions = (await client.listSessions()) as ProbeSession[];
  ```
- **上游类型自检（防复发）**：新增 `tsconfig.agents.json`（覆盖 `.agents/scripts/**/*.mts|ts`，strict）与 `package.json` 脚本：
  - `npm run check:agents` → `tsc -p tsconfig.agents.json`
  - `npm test` / `npm run prepack` → 先跑 `nao-fleet.sh check`，再跑 `check:agents`
  - devDependencies：`typescript ^5.4.5`、`@types/node ^20.19.0`（仅自检用，`files` 白名单不含 `node_modules`，不进入发布包）

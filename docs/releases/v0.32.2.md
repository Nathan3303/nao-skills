## 本次更新

**修好了「在 herdr 桌面版里拉起会话总是失败并回滚」的问题。**

症状是每次执行拉起命令都会看到下面这句，然后刚出现的那个工作区又从侧栏消失：

```
放置验证失败：收养超时（… doc 未见终端 tN 在目标 tab 的 root 树里）⇒ 回滚（kill → rm）
```

实际上桌面版**已经正确建好了**那个工作区、标签页和终端 —— 是我们这边「确认它建好了没有」的判据读错了，于是误判成失败并主动撤回。现在判据能正确认出结果，拉起一次就成。

## ⚠️ 请留意

- 只影响桌面版后端（`NAO_TERMINAL=app`）；**TUI 路径与既有命令行为完全不变**。
- 之前若你因为这个问题改用 TUI，升级后可以再试桌面版。
- 无需改任何配置；不需要调整之前那两个放宽用的环境变量。

## 技术细节（可略过）

- 根因：布局文档里**标签页默认没有名字**（空字段），而解析用 `IFS=$'\t' read` 时 bash 会**压缩连续 TAB** ⇒ 终端列表左移一格、末字段为空 ⇒ 收养判据恒判「未命中」⇒ 回滚。同一份行被两处消费（收养校验与放置预处理），一处修好全部。
- 修法：输出空名字时填占位符 `-`（名字不参与任何判定）；非空名字原样保留。
- 测试夹具改为**与真机同形**（标签页名字默认为空）—— 这正是此前「夹具绿、真机红」的缺口；`cases/45` 补两条断言钉住写法。
- 失败演练：回退修复 ⇒ `--case 45` 4 条红（含与真机同文案的「未出现放置验证失败」）；还原 ⇒ PASS。
- 门禁：`check` rc=0（roles=7 · `files=67`）· `--case 44/45` PASS · 全量 44 PASS / 2 FAIL（`case 27/41` 在未改动的 main 上同样 FAIL：本机 app pane 缺 `HERDR_SOCKET_PATH`/`HERDR_SESSION`，环境性，非本版引入）。
- 升级方式：`pi install --local npm:@nathan33/nao-skill@0.32.2`
- 回滚：`git revert <本次发布合并提交>`。

- 修订：2026-11-25 首版。

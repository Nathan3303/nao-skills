## 🐛 修好了

- **同名跨仓时 `close` 认错仓**（Issue #146）：本机名册里若有两条同名会话（不同仓），`close <裸名>` 以前直接取**第一条命中**的仓 —— 后果是忙闲闸门 / 回收定位 / 提示文案全落到**他仓**：本仓在跑的会话被误拒，或者**他仓的 pane 被误回收**。
  现在先按**你所在的仓**过滤：本仓唯一命中就正常回收；本仓并列就**拒绝并列出全部候选 cwd**（不猜）；本仓 0 命中才回落「全 session 唯一同 core」。
- **「跑测试的人」会影响门禁结果**：一天内连续三次（`HERDR_*` → `NAO_STASH_ROOT` → `HOME` / agent 根）。最典型的表现是：**你的 pi 会话名恰好叫 `pm` 时，全量门禁稳定红**在一条与自己无关的用例上。现在夹具的环境净化收成**一个入口**，调用点不再各自打补丁。

## ⚠️ 请留意

- **`close` 的行为变更面只有一处**：同名跨仓且「本仓 0 命中 + 他仓不唯一」时，以前「取首命中」，现在**拒绝并列出候选 cwd**。**唯一命中时行为不变**（包括跨仓唯一命中的旧用法）。
- **同仓下有两条同名会话没有「全名」写法可区分**：升级后的提示会直接指路 `intercom list` 人工核对 —— 这是刻意不猜（两条同名 pane 在句柄层无法区分谁是谁）。
- **两种既有边界仍在**（已记入 QA 报告，不属本版引入）：① 名册条目缺 `cwd` 时该条目对仓过滤不可见；② herdr 后端下「名册缺 cwd」仍可能报「未运行（无需回收）」。
- **落 `close` 时多看一行 `@ <仓>`**：回执里 `@` 后面的路径就是本次实际认定的仓，这是最快的自证方式。

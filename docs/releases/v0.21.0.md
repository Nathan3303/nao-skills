# v0.21.0 — 用你自己项目里的角色卡，一键拉起会话

- 状态：已发布（tag + Release 待发 · npm 待重发）· 更新：2026-11-01 · Owner：PM

## 本次更新

以前只有机制包里那 6 个常驻角色能被一键拉起：会话在哪个窗口、能不能被看到、能不能被回收，全都由舰队管。轮到「这一批我想临时加一个审查角色」时，你只能手工开终端跑 `pi`——它不算舰队会话，`status` 看不到它，`close` 也管不了它，用完之后是不是还挂在屏幕上只能靠你自己记。

这一版补上中间那档：**把角色卡放在你自己项目的 `.agents/prompts/` 里，一条 `ensure --card` 就能拉起会话，而且它与 6 个常驻角色享受同等待遇**——落在同一个窗口布局、`status` 里看得到、`close` 能回收、残留能被查出来。上游的角色清单一个字都没动。

## ✨ 更好用了

- **自己的角色卡能直接拉起**：`bash .agents/scripts/nao-fleet.sh ensure --card .agents/prompts/code-reviewer.md --task T537`。卡正文会连同机制包路径一起注入会话，所以卡里对机制文件的引用照常可用。
- **与常驻角色同等托管**：起出来的会话进入舰队布局、出现在 `status`、能被 `close` 回收；批次结束就收，不再有"忘了关"的游离会话。
- **同一张卡可以起多份**：`--as code-reviewer-notes` 起第二个会话，用名字后缀区分（`--task` 的并行隔离同样可用）。
- **不会起出"管不到"的会话**：`--as` 只允许改后缀、不允许换角色前缀——因为舰队是靠名字前缀认身份的，改了前缀就等于起出一个看不见、收不回的会话，这种情况直接报错拦下。
- **卡被删/改名后会话不会凭空消失**：`status` 新增「角色未识别（疑似 fleet 遗留）」一节，把这类会话列出来并给出排查方向（卡被删？卡在别的仓？overlay 改过名？）。
- **`check` 会提前拦住问题**：你自己项目的卡如果和 6 个常驻角色撞名或抢前缀（比如 `qa-audit` 会抢 `qa-` 的名），`check` 直接红灯并点名；内容的轻问题（缺描述、行尾是 CRLF、卡太大）只黄灯提示，不挡门禁。

## ⚠️ 请留意

- **卡的位置是固定的**：只能放在 `<项目>/.agents/prompts/<名字>.md`；必须是普通 `.md` 文件（软链接逃逸到目录外、fifo、超过 256 KiB 都会被拒——fifo 会让读取永久挂住，所以在打开前就拦住）。
- **卡内的 `role` 不能与常驻角色撞名或抢前缀**：`qa`、`qa-audit`、`subagent-xxx`、`nao-xxx` 都会被拒；合法名字是 `^[a-z0-9][a-z0-9_-]*$`、不超过 32 字符。
- **`--as` 只能改后缀**：`code-reviewer-notes` ✓、`audit` ✗（会脱离角色前缀，导致无法管理）。
- **卡就是系统提示，等于完全可信输入**：谁能写那个目录，谁就能定义这个角色的行为。fleet 只做一致性与边界校验，不做内容安全校验——这是设计边界，不是疏漏。
- **卡会与 pi-subagents 共用同一批文件**：如果卡里写了 `name:` 字段，它同时会被当子代理加载，此时卡里的 `@.agents/...` 引用不可解析（子代理路径没有机制包锚点）。`check` 会对此给一行提示。
- **与「把下游角色变成常驻」的旧做法二选一**：老办法（把 `NAO_SKILLS` 指向自己的一份清单目录）会让下游角色变成常驻；两种做法同一仓别并用，否则清单与名册会出现两个来源。
- **卡被删之后**：会话会出现在「角色未识别」一节，按提示人工处理（该节**不给**可执行回收命令，避免误导）。

## 技术细节（可略过）

- 版本 `0.21.0`（MINOR）· Issue [#61](https://github.com/Nathan3303/nao-skills/issues/61) · PR [#62](https://github.com/Nathan3303/nao-skills/pull/62) squash `2b4ade3` · PRD `docs/prds/2026-11-01-downstream-role-sessions.md`（AC1–AC8）· 架构评审 `docs/reports/2026-11-01-T537-arch.md` · ADR `docs/adr/2026-11-01-downstream-card-sessions.md` · QA 报告 `docs/reports/2026-11-01-T537-qa-verify.md` · RD 报告 `docs/reports/2026-11-01-T537-rd.md`。
- **`--card` / `--as` 是目标级修饰符**：绑定其后的第一个目标；悬挂、连写、或传给 `check`/`status`/`close` 一律按用法错拒绝（旧版解析器会把 `--card` 当全局开关，`ensure qa --card x.md` 会静默整批生效）。
- **两相执行**：先对全部目标做解析与校验，全部通过后才开始建 pane——混合批次里前一项合法、后一项卡非法时，**一个 pane 都不会建**。
- **常驻/一次性判别改为显式布尔**：旧实现用「有没有 `--task`」推断，卡会话裸名时会被误判成常驻并弹出「应 `ensure --force` 重开」的提示；现在按「是否命中角色清单」判定，一次性会话单独打印标识，且跳过 `tasks-state` 的 active 闸门（在跑 turn 拦阻不放宽）。
- **另一处既有缺陷顺手修了**：`status` 里 `close --task <编号>` 的提示命令用 `${dname%-*}` 截角色名，任务号含 `-` 时（如 `M20261014-pi-ext-update`）会截出 `rd-infra-M20261014-pi-ext`；现改为按已解析的角色名截断。这是本版**唯一**允许变化的既有输出行，其余 `ensure`/`status`/`close` 输出与上一版逐字等价（零回归探针 `docs/reports/2026-11-01-T537-probe.sh`）。

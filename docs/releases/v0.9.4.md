# v0.9.4 — 修复：标题被改写时会话无法回收 + 固化发布配置

- 状态：已发布 · 更新：2026-09-30 · Owner：PM

## 一句话

**修复**两类问题：① `nao-fleet.sh status/close/ensure` 在**终端标题被外部改写**（实测变为 `pi:c`，不再匹配 `π - <会话名> - <仓库名>`）时定位不到 pane —— `close` 两条路径都回收不了（无 `--force` 判「非 tmux 宿主」、加 `--force` 又「未找到 pane/会话/进程」）；现按三层后备精确定位并正常回收，且**正常标题场景不回归**。② `package.json` 固化 `publishConfig.access=public`，避免 scoped 包每次发布手加 `--access public`。

## 修复① 标题被改写时的会话定位与回收

### 现象（PM 实测）

回收会话时 pane 标题被改写为 `pi:c` ⇒ `close` 判「**非 tmux 宿主，无法确认是否在跑 turn**」拒绝；加 `--force` 又报「**未找到 `<name>` 的 pane/会话/进程**（可能刚好退出）」——**两种路径都回收不了**，只能手工 `tmux kill-pane`。

### 根因

旧实现只按「终端标题契约」定位 pane（`find_pane_for` 匹配 `pane_title == "π - <会话名> - <repo basename>"`）。标题一旦被外部改写即恒失配：
- `running()` 经 pi-intercom 名册仍判「在线」→ 进入回收流程；
- 但 pane 取不到 ⇒ 闸门②落「非 tmux 宿主」拒绝；
- `--force` 后所有落地分支（pane / tmux 会话 / screen / 进程）都依赖该 pane ⇒ 全部落空。

### 方案（三层后备 `find_pane_for`，逐层给依据）

| 层 | 依据 | 说明 |
| :--- | :--- | :--- |
| ① 终端标题契约 | pi 自设 `π - <会话名> - <repo>` | 最快路径，不变 |
| ② pi-intercom 名册 `tmuxPane` | 会话注册时读取 `$TMUX_PANE`（`pi-intercom/types.ts`：进程生命周期内**不可变**，与窗口/标题改名无关） | **权威**；标题被改写仍可精确定位 |
| ③ 本仓「未被认领 pi pane」唯一兜底 | `pane_current_command=pi`（与标题/argv 无关）+ `pane_current_path=repo`；排除已被标题契约或名册 `tmuxPane` 认领的 pane | ② 不可用时的启发式；**多于 1 个候选即 warn 并不猜** |

- 名册由新的 `.agents/scripts/intercom-probe.mts` 获取（含 `tmuxPane`）；探针不可用回退 pi-intercom 官方 `cli.ts list --json`（无 `tmuxPane`），再叠加层③；**任一路径都不得静默 no-op**，三层均未命中仍 `exit` 非 0。
- **不使用**已废弃的 `pgrep --name`（v0.7.1 因 pi 改写 argv ⇒ 恒失配而弃用；见脚本头注释）。

### 附带修复

- **`status` 名册回退失效（潜伏 bug）**：`visible_session_names` 中 `screen -ls` 在无 socket 时 `rc=1`，`set -e`+`pipefail` 令枚举在到达 `intercom_roster` 前中断 ⇒ 标题被改写的会话在 `status` 中消失。现各枚举 `|| true`，名册回退恢复生效。
- **闸门②「在跑 turn」漏判**：`pane_busy` 只看 pane 末 3 行，而 pi 状态行（如 `⠦ Working`）上方还有分隔线、实测落在第 4 行以外 ⇒ 在跑 turn 会话被误回收。现扫描末 12 行，并叠加名册活动状态（`thinking` / `tool:*` 等）双重信号。

### 行为对照（实测）

| 场景 | 改动前 | 改动后 |
| :--- | :--- | :--- |
| 标题被改写 + 空闲 `close` | rc=1（非 tmux 宿主） | **rc=0，已回收**（层②） |
| 标题被改写 + 空闲 `close --force` | rc=1（未找到 pane/会话/进程） | rc=0 已回收 |
| 探针不可用（仅官方 CLI）+ 标题被改写 | rc=1 | **rc=0，已回收**（层③） |
| 正常标题 + 在跑 turn `close` | rc=1 拒绝 | 拒绝（不变；名册状态 + pane 双信号） |
| 正常标题 + 空闲 `close` | rc=0 | rc=0（不变） |

## 修复② 固化发布配置

### 现象

发布 `@nathan33/nao-skill@0.9.3` 时必须手加 `--access public`（scoped 包默认 restricted）；漏加则首次发布不成功（registry 无该版本）。

### 改动

`package.json` 新增：

```json
"publishConfig": {
  "access": "public",
  "registry": "https://registry.npmjs.org/"
}
```

### 验证

`npm publish --dry-run`（**不带** `--access public`）输出：

```
npm notice Publishing to https://registry.npmjs.org/ with tag latest and public access (dry-run)
+ @nathan33/nao-skill@0.9.4
```

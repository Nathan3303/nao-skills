# 本次更新

**这一版让「迁移旧项目」更聪明也更诚实：默认只在真的需要时才写转发入口，纯文档项目不再被凭空塞进一个用不上的脚本；同时修好了重复技能记录在某些文件格式下被悄悄跳过的问题。升级方式不变。**

## ✨ 更好用了

- **迁移会自己判断要不要装入口**：执行 `migrate` 时，工具会先看这个项目里还有没有旧脚本、是否已经装过入口、以及全仓有没有实际引用（文档、CI、脚本里出现过 `nao-fleet` / `nao-skill` / `NAO_SKILLS`）。只有命中时才写入转发入口；如果一个纯文档项目完全没引用，就**跳过不写**，并明确告诉你「判定为纯文档迁移，未写入口」——不再凭空多出一个用不上的文件。
- **想强制就强制**：新增 `--shim`（一定写）和 `--no-shim`（一定不写）两个开关。将来打算接入、但眼下还没引用，就用 `--shim` 明确表态；两个开关同时给会直接报错退出，不会含糊其辞。

## 🐛 修好了

- **重复技能记录不再「看文件排版行事」**：有些项目里记录技能来源的 `skills-lock.json` 被格式化工具压成了一整行，过去遇到这种形态会**悄悄跳过**去重，重复来源一直留着；现在无论是单行还是多行，都会照常去掉重复条目，并且**只动该条目本身，其余内容（含缩进）逐字节不变**。
- **去重不再依赖「有没有旧资产」**：此前如果项目没有旧版遗留文件，去重这一步会被顺带跳过；现在只要存在重复条目就会执行。
- **实在删不了会说出来**：极少数无法安全删除的形态（删了会让文件不再是合法 JSON），现在会**打印明确告警并提示手工移除**，文件保持原样，其余迁移步骤照常完成、命令仍然成功退出——不再静默失败。
- **迁移不再写一个没人看的旧标记**：旧版会额外写一个从未被读取的 `.nao-migrated` 文件，且新版升级后它不会更新、容易误导；现在这类文件已废弃、不再读写，可以安全删除。

## ⚠️ 请留意

- **纯文档项目迁移后不再有 `.agents/scripts/nao-fleet.sh`**：如果你的项目属于这种情况、并且打算之后调用舰队命令，请迁移时加 `--shim`，或后续手动补齐。
- **`.agents/.nao-migrated` 已废弃**：它只是一个历史遗留标记，不再被读写；删掉它不影响任何功能。
- **行为不变的保证**：已经正常接入的项目重复迁移，转发入口内容与修改时间都不变，不会产生多余改动。

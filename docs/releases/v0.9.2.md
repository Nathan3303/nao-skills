# v0.9.2 — 修复：`bash qq-notify` 会误执行注释、可能误发

- 状态：已发布 · 更新：2026-09-25 · Owner：PM

## 一句话

**修复**：用 `bash .agents/scripts/qq-notify` 调起时，shell 会把脚本头部的注释当命令执行（glob / 重定向 / **真实管道**）——本仓历史上正因此**误发过一条真实 QQ 消息**；现加 `exec` 转交守卫彻底封堵。

## 修复（用户可见）

- **`bash <脚本>` / `sh <脚本>` 不再执行注释内容**：脚本头部改为多语言守卫
  ```sh
  #!/bin/sh
  //bin/true; exec node "$0" "$@"
  ```
  `sh/bash` 读到第 2 行即 `exec node`（自动转交 Node）；`node <脚本>` 时第 2 行是 JS 注释 ⇒ 正常解析。**四种调用形式输出逐字一致**：`./qq-notify` · `node qq-notify` · `sh qq-notify` · `bash qq-notify`。
- **头部去危险形态**：JSDoc 改为 `//` 行注释，消灭「以 `*` 独占开头的行」「`echo … | …` 管道示例」「`<openid>` / `<path>` 尖括号占位」等会被 shell 误解释的写法（占位符改为 `OPENID` / `PATH`，管道示例改为「stdin 管道」文字描述）。
- **新增 `check` 校验**：`nao-fleet.sh check` 增加 **shell 转交守卫存在性**校验（第 1 行须 `#!/bin/sh`、第 2 行须含 `exec node "$0" "$@"`），缺失 ⇒ `rc=1`（防回归）。
- **文档层禁令**：脚本头部与 `.agents/skills/qq-notify.md` 均写明 **⛔ 禁用 `bash <本脚本>`** 及原因，并给出正确形式。

## 行为（用户可见）

- 正常使用**无变化**：`./qq-notify` / `node qq-notify` 行为、退出码（0/1/2/3）、输出格式与 v0.9.1 **完全一致**。
- 被误用时行为**从「静默执行注释」变为「正常转交 Node」**（配置缺失则按既有路径 exit 1 + 修复提示）。

## 限制

- 守卫依赖 `node` 在 `PATH` 中：若 `node` 不可用，`sh/bash <脚本>` 会以非 0 退出（不会执行注释）。
- `bash -c "$(cat qq-notify)"` 这类**先展开再执行**的写法不在守卫覆盖内（守卫只保护「脚本文件被 shell 读入」这一路径）——仍应避免。

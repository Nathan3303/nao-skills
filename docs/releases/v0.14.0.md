# 本次更新

**这一版让你不在 tmux 里也能用舰队：每个角色会打开一个看得见的终端窗口，而不是悄悄跑到后台；宿主不可用时立刻报错并告诉你怎么办，不再「说拉起来了、其实什么都没有」。**

## ✨ 更好用了

- **不在 tmux 里也能看见舰队**：直接在普通终端里拉起，每个角色会开一个独立的可见窗口（窗口标识带角色名），你当场就能看到它在跑什么——不再是「后台有个会话，屏幕上什么都没有」。
- **有 tmux 也保持看得见**：机器上装 tmux 时，会为每个角色建一个会话，并自动开一个窗口贴到这个会话上——既看得见，又保留原有的分屏与布局能力。
- **无桌面会话（如 SSH）需要你明确表态**：默认拒绝拉起并说明原因；确实要后台跑，加 `--background`，工具会建好后台会话并打印一行可直接复制的 `tmux attach` 命令。
- **在线状态会说明它的来源**：不在 tmux 里时，在跑状态来自舰队名册，`status` 会明确标注「turn 判定来源 = 名册」，不假装和 tmux 里一样精确。

## 🐛 修好了

- **不再假成功**：以前宿主程序没装，也会打印「已拉起」，但其实什么都没起；现在打印「已拉起」之前，一定会先确认窗口/会话/进程真的在。
- **不再劈头盖脸报一行系统错误**：没有任何可用宿主时，以前会直接抛出一行「找不到命令」然后异常结束；现在给出一行清楚的原因和一条可复制的恢复命令。
- **失败不留尾巴**：拉起失败不会留下半开的窗口或会话，也不会让状态表误报某角色在线。
- **不会把别的角色的新窗口误认成你的**：判重更严格——只有在名册里确认该角色确实运行在本项目、并且候选窗口唯一时才认领，避免「明明没起却说已在运行」而跳过。
- **`close` 不会再把你自己正在用的窗口/会话关掉**：某些情况下（本版新增的窗口宿主路径会放大这条既有缺陷）角色的窗口标识可能被登记成你自己所在的窗格，旧版 `close` 会顺手把你当前的窗口当成目标关掉——若那是窗口里最后一个窗格，整个窗口就消失了。现在 `close` 一旦发现目标正是你自己所在的窗格，会**直接拒绝并说明原因**，绝不误关。

## ⚠️ 请留意

- **无桌面会话默认不再后台拉起**：SSH 等无图形环境里直接拉起会被明确拒绝；请加 `--background`，或用 `NAO_TERMINAL` 指定一个可用宿主。
- **`NAO_TERMINAL` 现在只接受 `tmux` / `foot` / `ghostty` / `ptyxis` / `screen`**：写其它值会被视为环境不可用并退出，而不是默默换一个宿主。
- **非 tmux 宿主的回收按窗口标识进行**：`close <角色>` 会按窗口标识定位并结束对应进程；若系统缺少窗口查询工具，工具会明确提示「无法校验窗口可见性」，而不是谎报成功。

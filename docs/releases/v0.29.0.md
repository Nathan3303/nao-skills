## 一句话概括

**两件事：**① 设计类需求有了真正的流程（先定组织、再上色、再由一个不认识你的会话挑毛病）；② **修掉一个会把你自己的窗口整个关掉的严重缺陷** —— 如果你在 0.28.0 遇到过「跑完 `ensure`，自己那个 pi 窗口突然消失」，就是它干的。

## ⚠️ 请留意

- **0.28.0 的严重缺陷已修**：在「你自己手起的 pi 窗口所在的那个 workspace 里」跑 `ensure`，旧版会把那个 workspace 当成空的**直接关掉**，连带杀掉你的会话。本版修好了：关之前会再用真实窗口列表确认一次，**确认不了就不关**（宁可报错也不动你的窗口）。升级即可，无需改任何配置。
- **设计类需求会多问一句**：「先出灰模再上色，还是直接上色？」—— 这是新增的开工必答项。不回答就按「先灰模」走（先在无色骨架里把区块顺序定下来，再上色）。不想被问就说「直接上色」。
- **设计类交付多一道关**：实现后由 PM 另派**一个不知道你的设计意图的会话**做外视评审，只报「哪里有问题 + 位置」，不给改法；你确认过的问题才改。

## ✨ 更好用了

- **设计流程从「清单」变「循环」**：任务先分类（小改动 / 新界面 / 多方向对比 / 单组件打磨 / 存量优化 / 只读评审）—— 改一个按钮颜色只走两步，改版才走全流程，不再一律套全套。
- **灰模先行**：上色之前先在无色骨架里定「放什么、谁先谁后、入口在哪」。改组织在灰模阶段最便宜，上色后再改要返工。
- **参考 → 概念，不抄外观**：设计报告要写清「参考了什么 / 取了哪条概念 / 丢了什么视觉」。照搬别人的配色和版面，是另一种「AI 味」。
- **视觉验收变成四项可勾**：声明测过哪些视口 / 截图（或写清为什么截不了）/ 空·加载·错误三态 / 「2 秒内能不能看出这屏是干嘛的」。
- **同屏多方向可选**：需要比较时给 2 版（最多 3 版）同屏骨架并排给你选，而不是一次只给一份完整规格。

## 🐛 修好了

- **`ensure` 误关你自己的 workspace（会杀会话）**：旧版判断「这个 workspace 里还有没有窗口」时，遇到**没有标签的窗口**（也就是你自己起的 pi）会读错字段，于是永远判「空」⇒ 直接关闭。本版把这条通路彻底改掉，并在关闭前加了一道「用真实窗口列表再确认」的硬拦：**拿不到证据就不关**。同时修了同一起因导致的 9 处连带判断（会话复用判重、槽位取名、仓归属、tab 归属、`status` 快照等）。
- **`status` 侧同族隐患**：快照字段里空值会让后续字段错位，一并规范化。

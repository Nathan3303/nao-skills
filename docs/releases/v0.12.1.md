# 本次更新

**这一版修好了三个会被日常用到的问题：角色别名命令终于真的能用、体检能提前拦下错误的角色清单、跨项目的后台会话也能干净回收了。升级方式不变，下游项目无需改动。**

## ✨ 更好用了

- **别名命令可以直接用了**：`ensure arch`（等于 `arch-designer`）、`ensure infra`（等于 `rd-infra`）此前会报「未知角色」，现在按文档照抄即可。README 的示例命令（`ensure pm arch rd-fe rd-be qa rd-infra`）现在能一次跑通。
- **体检会主动报错，而不是默默放过**：`check` 现在会逐条校验角色清单里的别名——某个别名解析不到、某个角色的规范名没登记、两个角色用了同一个别名，都会以非 0 退出并**指名是哪个别名/哪个角色**有问题，不再等真的拉起会话时才发现。
- **跨项目的后台会话能回收了**：在 A 项目里回收跑在 B 项目的派生会话（如 `close --task T508 qa`），此前会误报「未运行（无需回收）」而实际窗口还在，只能手动关；现在会正确定位并关闭目标窗口。
- **回收命令更顺手**：派生会话名可以直接作目标——`close qa-T508` 与 `close --task T508 qa` 等价（此前后者报「未知角色」、前者静默无操作）。
- **定位不了就报错，不再假装成功**：当会话确实找不到、或名册与窗口状态对不上时，`close` 会以非 0 退出并给出可操作的诊断，不再出现「说没在跑、窗口却还在」的假阴性。

## ⚠️ 请留意（这一版行为有变化）

- **回收失败不再是静默成功**：如果目标会话定位不到，`close` 现在会**非 0 退出**并打印诊断。此前可能返回 0，脚本里若依赖退出码需要留意。
- **`--force` 语义不变**：仍在跑 turn 或任务仍在进行态时，默认拒绝回收；确需强制仍可加 `--force`。

# v0.23.3 — 内部标记不再跑进你的终端环境

- 状态：待核验（tag / Release 待发；npm 发布后按唯一判据回填）· 更新：2026-11-13 · Owner：PM

## 本次更新

**修一个看不见但会咬人的问题：舰队脚本启动 herdr 会话时，把一个内部标记写进了每个终端面板的环境变量。**

那个标记本来只用来告诉脚本「这个进程是我起的 server」，但它是通过环境变量传的，于是被 server 继承、再复制给它开出来的**每一个**面板。后果有两个：

- 每次在面板里跑舰队命令，都会误以为自己该「去起 server」：多套一层环境清理和进程组脱离，白绕一圈。
- 绕这一圈的过程中，**子进程会丢掉 herdr 的 socket 路径**。用自定义配置目录（`XDG_CONFIG_HOME`）或符号链接的场景下，可能连到**另一个会话**的 socket。

现在改成用**参数**传这个身份，不再进环境：

- 新起的 server 与它开出的面板，环境里**不再有这个标记**（实测：修复前 1 条 → 修复后 0 条）。
- 起 server 的能力不变（`session-start`、`api snapshot`、`status` 都正常）。
- 顺手删掉了测试侧为绕开这个泄漏加的临时兜底；删掉之后，如果有人把旧写法加回来，测试套件会**直接红**（这也是我们验证过它确实是泄漏探测器的方式）。

## 你会感觉到什么

- 已经启动的 server 和面板里**仍然带着这个旧标记**，但脚本已经不再读它 —— 没有任何实际影响。
- 想要面板环境也干净，重起 server（`session-start --session <名>`）或重开面板即可。
- 在面板里跑命令时不再多绕那一层，也就不会再有「子进程丢 socket 路径」的隐患。

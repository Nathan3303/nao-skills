# v0.19.2 — 闸门更硬：跳过断言不再能混过，发布前两组环境都要绿

- 状态：已发布（v0.19.2 · tag + Release 已发；npm 重发已核验）· 更新：2026-10-28 · Owner：PM

## 本次更新

这一版不新增功能，改的是**怎么判定「通过」**。上一版发布前出过一次事故苗头：同一份代码，负责复核的会话判定全绿，做发布的那个人却红——差别只是「它在哪个面板里跑」。本版把这类「绿得不真」的漏洞堵掉三处：**跳过断言要登记理由**、**发布前必须两组环境都绿**、**下结论前必须先跑一条命令**。

## ✨ 更好用了

- **跳过断言必须登记理由**：测试里不再允许「因为环境不齐就悄悄跳过、还报表通过」。跳过必须带一个已登记的类别（静态替代证据 / 版本未发布改对照 / 迁移入口降级），未登记的一律判失败并点名是哪个用例哪一类 —— 也就是说，**跳过的东西会被看得见**。
- **发布前两组环境都跑一遍**：新增一条命令 `npm run test:t4:full:dual`，它把同一套测试在「面板上下文存在」和「面板上下文不存在」两种情况下各跑一次，**任一不过就不算过**，并直接告诉你是哪一组挂的。发布前置改成以它为准。
- **下结论前先跑一条命令**：产品侧流程新增一条硬性 —— 只要要给出「根因 + 怎么修」这种判断，必须附上**实际执行过的命令和输出**；没实测只能派「先去复现/诊断」的任务。这条是针对上一版那次误判定的：当时给出的根因是错的，差一步就让实现方做了一次无用的大改。

## ⚠️ 请留意

- **日常测试不受影响**：`npm test` 的行为没变（仍只计数、不因环境降级变红）。严格化只发生在发布前置那条命令上。
- **发布前置更慢**：从约 74 秒变成约 3 分钟（两组串跑）。这是有意的——上一版漏掉的就是这第二组。
- **新增跳过类别要走流程**：想让某个测试合法跳过，必须先在白名单里登记类别并写明理由（`tests/README.md` 有说明），否则发布会拦下来。
- **已经跳过的四条说明仍保留**：它们是合法的前提说明（静态替代证据、版本未发布、缺迁移入口），只是现在带上了类别标签。其中两条在当前发布态**天然不命中**，所以你会看到「白名单命中 2 条」而不是 4 条。

## 一句话概括

**一支舰队现在能跨仓干活了：写一个 `.agents/fleet.yaml` 声明联动仓（如 `api` / `web`），就能把角色直接派到那个仓里，而它们仍是同一支舰队、同一个窗口区。**

## ✨ 更好用了

- **多仓编队**：主仓放一份 `.agents/fleet.yaml`：
  ```yaml
  slug: alpha
  repos:
    api: ../api
    web: ../web
  ```
  之后 `ensure rd-be@api` 就会把后端开发派到 `../api` 里干活，会话名是 `rd-be@api`，**仍落在 `alpha` 这同一个窗口区**。
- **按仓分组的标签页**：herdr 里的 tab 标签写成 `<组前缀>/<名字>`（主仓组前缀固定 `main`），一眼看得出哪个窗口在工作在哪个仓 —— 不再靠「凭记忆数第几个 tab」。
- **`status` 同时告诉你两件事**：会话属于哪支舰队（`·fleet=`）、工作在哪个仓（`·code=`）；读不到就显式打 `?`，不猜。

## ⚠️ 请留意

- **不写 manifest 的仓库完全不受影响**：没有 `.agents/fleet.yaml` 时 `ensure` / `check` / `status` / `close` 的输出与 v0.25.2 **逐字一致**（唯一偏差曾被 QA 抓出来过：`status` 常驻行多了一个空格，已修）。
- **`@` 有两种写法，按唯一顺序判定**：① 先当**仓代号**（manifest 里的 `api`）② 不是代号就仍按**仓路径**（旧用法，如 `ensure rd-be@../api`）③ 两者同时命中且路径不同 ⇒ **直接报错**（不替你选）④ 都未命中 ⇒ 报错并列出可用代号。**不会**「先试代号、失败再当路径」——那样会把「派错仓」伪装成成功。
- **代号有硬约束**：`code ≤16` · 角色名 `≤32` · 全名 `≤48`；撞线直接报错并告诉你该缩短哪一段，**不会自动截短**。另外 manifest 里代号**不得与 `slug` 相同**、联动仓**不得**叫 `main`（`main` 保留给主仓）。
- **`--fleet` 与 manifest 打架会报错**：`--fleet` 的值 ≠ `manifest.slug`、或 `fleet.yaml` 与 `.agents/fleet-scope` 分歧 ⇒ 直接失败（不静默取一个）。优先级：`--fleet` > `fleet-scope` > `manifest.slug` > 仓 slug。
- **改 manifest 会让下一次调用立刻失败**（如果有非法行）：解析结果只在本次进程内，不写盘、不沿用上次。
- **tmux 回退后端没有 tab 概念**：分组信息在 tmux 下不可表达（会以 NOTE 点名，不假装成功）。

# v0.9.0 — 新增 `rd-infra` 角色 + 舰队 tmux 布局守卫

- 状态：已发布 · 更新：2026-09-25 · Owner：PM

## 一句话

舰队多一个专精角色「工程基座」（CI/构建发布/脚本守卫/依赖安全/仓库治理），并给 tmux 布局补上 `main-col` 与**窄列自动回退**——窗口再挤也不会中断拉起。

## 亮点

- **新增角色 `rd-infra`（别名 `infra`）**：`.agents/prompts/infra-engineer.md`（v1，65 行）+ `.agents/checklists/rd-infra.md` + `roles.yaml`
  - 判定口诀：**改「业务行为」⇒ `rd-fe`/`rd-be`；改「怎么构建 / 怎么验 / 怎么发 / 怎么治理」⇒ `rd-infra`**
  - 例外：架构取舍先经 `arch-designer`；**不自验自己的守卫**（验收由 `qa`/`pm` 独立执行）；触碰业务语义时拆单
  - 自检红线：幂等 / 零密钥与零机器特定值 / 最小权限 / 可自证（含失败演练）/ 跨项目兼容 / 精确提交
- **PM 路由纪律**：PM 卡 §六 新增「工程基座类派 `rd-infra`，不再由 `rd-be` 兜底」；§九 转发对象补 `rd-infra`；`checklists/pm.md` 增路由核对项（v20）
- **tmux 布局三选一**（`NAO_TMUX_LAYOUT`）：`main-row2`（默认，不变）· **新增 `main-col`**（委托内建 `main-vertical`，主会话在左、其余右列竖排）· `grid`
  - **新增 `NAO_TMUX_MIN_PANE_WIDTH`**（默认 30，合法 10..80）：`main-row2` 最窄非主 pane 低于阈值 ⇒ **自动回退 `main-col`**；右列仍不足 ⇒ **再回退 `grid`**（打印带三个数字的 warn）
  - 守卫与构建**共用同一段几何计算**（`main_row2_geom`），防两处漂移

## 行为（用户可见）

- `ensure` 支持 `infra` / `rd-infra`；`check` 报告 **`roles=6`**，并新增布局合法值校验与 `NAO_TMUX_MIN_PANE_WIDTH` 校验。
- **窄窗口不再中断拉起**：`tmux split-window` 失败（`no space for new pane` / 宿主上限）现在被捕获 → warn（说明已跳过该 pane）→ **其余角色继续拉起**；改动前会因 `set -e` **中断整轮 ensure**（实测：8 列窗口下旧语义只成功 2 个 pane 即中止）。
- 宽窗口**零行为变化**：`W=152 / 6 pane` 下几何与改动前逐值一致（`52x34 32x16 32x17 32x16 32x17 33x34`）。
- 实测回退：`W=80 / 6 pane`（旧几何最窄 16 列）⇒ 回退 `main-col`（右列 52）；`W=45 / 6 pane` ⇒ 二级回退 `grid`。

## 限制

1. **只保证宽度，不保证高度**：`main-col` 下 pane 数多时右列高度会塌陷（如 `152×6` ⇒ 每 pane 6 行）。阈值只约束宽度。
2. **`main-pane-width` 是 window option**：脚本会写当前窗口该项，影响该窗口的 `main-*` 布局（`main-horizontal` 用 `main-pane-height`，不受影响）——属有意的副作用。
3. **`other-pane-width` 优先级更高**：若用户自行设过该选项，主 pane 百分比会被压过；脚本不设它，**两者不要同时用**。
4. **极窄窗口无解**：窗口小到连 pane 都放不下时 tmux 直接拒绝 split（已知会 warn + 跳过），任何布局都救不了。
5. 阈值 30 是**经验值**（约等于可读代码的最小宽度），非硬约束；可用 `NAO_TMUX_MIN_PANE_WIDTH` 覆盖。

## 升级注意

`npm i -g @nathan33/nao-skill@0.9.0`，或项目内 `nao-skill update`。

- 角色卡版本：**`rd-infra v1`（新）** / `pm v20`（路由纪律）/ `rd-fe v10` / `rd-be v10` / `qa v11` / `arch v10`。
- **已拉起的会话需重开**（`nao-fleet.sh ensure --force <角色>`）才会加载新卡与路由纪律。
- 默认布局不变（`main-row2`），既有习惯不受影响；窄窗口才会触发回退提示。
- 无数据迁移。

## 回滚

`git revert <merge commit>`；布局回退与守卫均为 `nao-fleet.sh` 内部逻辑，回滚后行为回到 v0.8.1。

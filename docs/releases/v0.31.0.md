## 本次更新

**设计类需求现在分两条路走**，不再是「一律从头开始」：

- **新页面 / 新流程**（此前没有任何可对照成品）⇒ 走方向探索 + token 计划 + 复核，再写码
- **改既有界面**（有 git 历史、已合入实现、基线截图或活站任一）⇒ 走九遍修法：审计 → 方向五行（确认后）→ 逐遍修 → 终检

判定不看「像不像 AI 生成」，只看两件可对 diff 直接判定的事：该屏入口是**新增文件**还是**既有文件**、改动前**有没有可对照的存量**。改既有界面时再分两档：区块序未变 = 清洁档（间距/颜色/终检），区块序变了 = 改版档（九遍全跑，先过灰模确认）。

**为什么这么分**：给新界面套「重构九遍」会空转，给存量界面套「方向探索」会重做一遍已经存在的东西。

## 你需要知道的

- 只对**设计类需求**生效；后端、脚本、文档类需求不读这条路径
- 判定由 PM 在派单里**带档位词**，不由实现者自行判断；判错了在 PR 里按「该屏此前是否存在」一刀切纠正
- 新建页面**不读**九遍修法；读取入口在 `frontend-developer` 卡的按需技能行与 `design-loop.md §八` 首句

# 本次更新

**这一版把 nao 机制改成 pi 原生包分发：项目里不再铺开一堆文件，只留一个转发入口；安装、升级、迁移都更利落，舰队多了一个能被普通会话发现的入口。**

## ✨ 更好用了

- **项目更干净**：接入后项目里只多一个入口脚本；角色卡、清单、按需技能、小工具都放进依赖包，不再铺满项目目录。
- **普通会话也能找到舰队**：pi 的 skill 列表里出现「nao 舰队」入口，用户提需求时能被路由到舰队并给出拉起指引。
- **升级就是升依赖**：升级机制 = 改一次版本号并更新依赖，不再逐个覆盖项目里的文件。

## ⚠️ 请留意（这一版行为有变化）

- **旧项目要迁移一次**：以前把整套机制铺进项目的用户，运行一次迁移命令即可——旧文件会被备份（可回退），入口脚本换成新的，原来的命令照常可用。
- **团队 / CI 需要一条显式的准备步骤**：机制包不随仓库分发；干净检出后要显式执行一次安装命令把它准备好。离线环境请**先准备好再运行**。
- **「项目内文件逐字节一致」的校验不再适用**：完整性改为按依赖包版本保证（详见 README「发布形态与完整性判据」）。
- **入口找不到机制包时不会假装成功**：会以非 0 退出并给出一行可读提示与恢复命令。

## 📦 更小更快

- 项目内机制足迹从 6 个目录收敛为 1 个入口脚本；常驻上下文只增加 1 条入口说明。

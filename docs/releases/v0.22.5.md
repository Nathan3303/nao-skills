# v0.22.5 — 机器再忙，测试也不再随机变红

- 状态：待核验（tag / Release 已发；npm 发布后按唯一判据回填）· 更新：2026-11-06 · Owner：PM

## 本次更新

**这一版没有面向使用者的功能变化，命令行为与 v0.22.4 完全一致。** 它治的是一个「时好时坏」的毛病——**机器一忙，某条检查就随机变红**。

这条检查验的是「某个会话到底属于哪个仓库」。它靠给每个测试窗口贴一个标题标签来识别归属，而原来的贴法是「外部命令贴上去」。问题在于：窗口里的 shell 会自己把标题刷回 `用户名@主机:路径`——机器闲的时候外部命令贴得快、能赢；**机器一忙，shell 的刷新晚到一步，就把标签冲掉了**。标签一丢，检查就只能退回去按登记表猜，于是猜错、报红。

现在改成：**标题由窗口里的进程自己打印**（打印一次就转入空闲，之后没有任何东西能覆盖它），并且贴完会**等一下确认标题真的生效**——等不到就直接判红，不会拿着错误的前提继续跑、也不会偷偷降级。

结果：同样的检查，负载高到 10 以上连跑 12 次全绿；而如果你人为把归属判断改坏，它**立刻精确报红**（没被「等一下」吃掉）。

间接好处：**你看到的红就是真红**。这条检查此前一天内误报 5 次，每次都要人判断「是真坏了还是机器慢」——那种「重跑一次就好了」的检查，等于没有检查。

## ⚠️ 请留意

- **命令与输出没有变化**：`ensure` / `status` / `close` / `check` 与 v0.22.4 一致。
- **有一处行为变了（仅测试夹具）**：测试里创建的窗口，其内部进程现在是「打印标题后空闲等待」，不再是交互 shell。如果你有脚本直接复用过旧的测试夹具写法（外部命令贴标题），**请在标题含引号时改用参数传递**——否则会破。
- **错误引号的旧写法则会失败得很难看**：这次特意验证过，含单引号的标题在旧写法下会直接破（且是明确报错，不会静默）。

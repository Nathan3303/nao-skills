# v0.23.2 — 设计稿交接不再靠口头：实现前先看图，动工前先问你

- 状态：待核验（tag / Release 待发；npm 发布后按唯一判据回填）· 更新：2026-11-13 · Owner：PM

## 本次更新

**如果你用绘图工具出设计图（当前是 Penpot），这一版改了三件事。**

- **交付必须写清图在哪**：用了绘图类 MCP 出图时，设计师的交付要写明四项 —— 文件 id、文件内页名、画板名与尺寸、图层命名规则；必要时把图导出到仓库里当本地依据。缺一项就算交付没完成。
- **实现方先看图再写码**：动手前先确认这次有没有图。**有图就以图为准** —— 文字说明和图冲突时按图实现，并要求设计师把文字改过来，不许「按文字自己发挥」。觉得图不合理可以反驳，但要走流程（回设计师改稿，或给出带验收编号的具体修改项，重新放行），**不能在代码里偷偷偏离**。
- **出图后 PM 不会直接开工**：设计师交出图之后，PM 必须先问你「设计稿满意吗」才会派人实现。你不回答 = 默认**你自己确认**（我们不会替你默认「托管给 PM」）。开工确认时也会先问清这一项。

## 为什么改

上一版做门户站时踩了三处（都发生在同一批里）：

1. 实现方严格按设计稿的**文字说明**写，做完你一看和画板差得远 —— 整轮重做。
2. 我把设计稿验收通过后**直接派人开工**，你是在成品上才发现偏差，而不是在图上。
3. 设计稿的文字说明和画板本身对不上（留白写 96、画板是 80；字阶写 6 档、画板是 14 档），因为没把「图」定为唯一基准。

根子都是同一件事：**设计稿交出去之后，没有一个写下来的交接规则**。这版就是把规则写进角色卡。

## 你会感觉到什么

- 设计类需求会多一问（「设计稿验收模型：你本人 / 托管给我」）。这是有意的：宁可多问一句，也不替你拍板。
- 设计师的交付会多四项图源信息；如果是纯文字规格（没出图），这条不触发。
- 已经跑着的会话不会自动生效 —— **重开该角色会话**才读到新规则。

# v0.9.3 — 修复：`nao-fleet.sh close` 回收空闲会话时崩溃

- 状态：已发布 · 更新：2026-09-30 · Owner：PM

## 一句话

**修复**：`nao-fleet.sh close <角色|会话名>` 在回收**空闲**（未在跑 turn）会话时，过闸门后崩于 `bus: 未绑定的变量`（`set -u`）——会话未被回收；现改为显式双分支赋值，空闲会话能正常回收，忙碌会话仍按原语义拒绝。

## 修复（用户可见）

- **空闲会话回收不再崩溃**：`close rd-be-T1` / `close --task T1 rd-be` 命中空闲 pane 时，从「rc≠0 + `bus: 未绑定的变量`」变为 **rc=0 + `已回收 <会话>`**。
- **闸门语义完全不变**：在跑 turn 的会话仍**拒绝回收**（rc=1 + 提示），`--force` 仍可强制回收（rc=0）。
- **根因**：`pane_busy "$pane" && bus="…"` 在 `pane_busy` 返回假时 `&&` 短路，`bus` 从未赋值；随后 `[[ -n "$bus" && … ]]` 在 `set -u` 下报未绑定。现改为
  `if pane_busy "$pane"; then bus="…"; else bus=""; fi`，保证两个分支都赋值。

## 行为（用户可见）

| 场景 | 改动前 | 改动后 |
| :--- | :--- | :--- |
| 空闲会话 `close` | rc=1，`bus` 未绑定，未回收 | rc=0，已回收 |
| 在跑 turn `close` | 正常拒绝 rc=1 | 拒绝（不变） |
| 在跑 turn `close --force` | rc=0 强制回收 | 强制回收（不变） |

## 自查报告（审计）

- 全脚本 `&& <变量>=` / `|| <变量>=` 赋值点共 25 处：**仅本处**存在「变量可能未赋值」风险；其余 24 处（算术夹取 `(( … )) && var=`、`found`/`ok`/`seen`/`rc`/`disp`/`repo` 等）均在引用前已被赋初值，无 `set -u` 隐患。

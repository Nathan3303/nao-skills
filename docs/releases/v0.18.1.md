# v0.18.1 — 会话回收的在线判定有了回归护栏

- 状态：待发布（v0.18.1 · 门禁数字由发布节点 PM 定稿）· 更新：2026-10-14 · Owner：PM

## 本次更新

这版给「回收会话」加了一道回归护栏：当无法确认某个会话是否还在线时，回收命令不会再悄悄报一句「未运行」就当成功；这条判据本身也被纳入默认门禁，以后谁把它改坏，跑一次 `npm test` 就会当场拦下。

## 🐛 修好了

- **「已回收」不再可能是空话** —— 在既看不到终端句柄、又读不到会话名册的环境里，回收命令以前可能直接报「未运行（无需回收）」并成功退出，让人以为现场已经收拾干净，实际可能仍有残留。现在这种情况一律非 0 退出并说明原因（无法确认在线状态），只有确实能判定为离线时才报「未运行（无需回收）」。
- **判据被改坏会被门禁拦下** —— 这条「能不能断言离线」的判据以前没有任何自动检查：即使被误删、被改成恒真、或被悄悄收窄，全量验证仍然全绿。现在默认门禁里多了一条用例专盯它，三种改坏方式都会以非 0 退出。

## ⚠️ 请留意

- **机制行为没有变化** —— 本版只新增回归检查，机制脚本一字未改；回收命令对使用者的可见行为与 v0.18.0 相同，只是原来那条「不可确认就静默成功」的隐患现在被测试钉住了。
- **`npm test` 用例数 12 → 13，时长略增** —— 新增用例是纯本地进程断言，不联网、不真开窗，整体仍在两分钟量级。
- **本版不重发 npm 包** —— 包内容与 v0.18.0 无差异（改动只在仓库内的测试），registry 版本号不变。

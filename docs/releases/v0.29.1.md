# v0.29.1

- 状态：**待核验**（发布后按 `dist-tags.latest` + `dist.integrity` 与本地 `npm pack` 逐字节核验后回填）· 更新：2026-11-24 · Owner：product-manager

## 一句话概括

**把「会话叫什么、怎么找它」这件事一次性说对。** 上一版把会话名改短了（`pm` / `qa(T558)`），但**说明书还在教老写法**——这版把 README、安装手册、`--help` 和 `status` 的示例全改成现在的真实形态，并给旧写法一条明确的退场说明。

## ⚠️ 请留意

- **名字里不再有 `@`**：常驻是 `pm` / `qa` / `qa2`，带任务的是 `rd-be(T1)`、`qa2(T558)`。一个仓库 = 一个 herdr workspace，**两个仓各跑各的，不需要任何配置**。
- **`ensure rd-be@api` 里的 `@api` 不是名字的一部分**，它是「**去哪个仓干活**」的选择符（`api` 是联动仓清单里的短代号，或一个仓路径）。
- **四个旧开关已弃用**（给了只会打一行提示、不生效）：`--fleet`、`--scope`、项目里的 `.agents/fleet-scope`、`.agents/fleet.yaml` 的 `slug:`。放置位置一律按**仓库本身**算。
- **升级前起的旧名会话还在**（例如 `pm@nao-todo`）：`status` 能看见、`ask` 能按原名发，但 **`send`/`handover` 会把带 `@` 的收件人当「另一台机器」而失败** ⇒ 给会话发消息请用会话 id。
- **还没准备好？** 把机制版本 pin 回 `≤0.29.0` 即可继续用旧写法。

## ✨ 更好用了

- **说明书与实现对齐**：README 的「会话名」段、安装手册的「会话命名与多仓」整节重写，并新增一张**弃用对照表**（旧入口 → 现在发生什么 → 怎么迁移）。
- **`--help` 不再教旧写法**：用法头按现在的命名契约重写，新用户不会先学一套错规则。
- **`status` 的示例改成真实形态**：以前那行示例给的是 `rd-be-T1` 这类早就不产生的名字。
- **联动仓清单简化**：只写「短代号 → 路径」映射；旧的舰队名字段（`slug:`）读到只提示、不生效。

## 🐛 修好了

- **派单/回执发错人**（今天真实发生过两次）：多个仓各有一个 `pm` 时，按名字发给「`pm`」会**确定性地**落到另一个仓。现在规则写死：**给别的会话发东西用会话 id**（或名字 + 目录），并在工具使用处的模板旁标了「正文里的收件人必须与实际投递参数一致」。
- **常驻协议里的过期规则**：每个会话都会读的那份协作协议，之前还写着带 `@` 的旧名字和「回 PM」这种裸名说法 —— 现在与现行命名一致，并明确「旧名只读、`send` 不接受」。

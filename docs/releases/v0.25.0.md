## 一句话概括

**同一个终端里可以并排跑好几支舰队了，每支各管一个仓；`ensure pm` 那种"明明拉起来了却报失败"的假红灯也没了。**

## ✨ 更好用了

- **一个终端里跑多支舰队，零配置**：每个仓各 `ensure` 一次就能并排开几支队伍，各自落各自的窗口区，会话名会自动带上仓名（`pm@api` / `pm@web`）。以前第二支会被"同名会话已存在"挡住，必须手写一个配置文件才行。
- **可以给舰队起名了**：`ensure --fleet alpha` 直接指定这支队伍的名字，名字同时决定它开在哪个窗口区、能不能和别的队伍共存。**记住这一条就够：一个名字 = 一支舰队 = 一个窗口区 = 一份唯一性。**
- **`ensure pm` 不再假失败**：以前默认配置下它会报"就绪门超时"并以失败退出（其实会话已经建好了），自动化按退出码判断就会误判、你也会反复重试。现在正常返回成功。
- **每个会话的工作目录真的是你的仓**：以前在部分情况下会跑到终端后端自己的目录里去，导致 pi 一开场就问"信任这个目录吗"，或者重复拉起时报"同核心但不同仓"。现在 pane 就在你 `cd` 的那个仓。
- **`--scope` 换成 `--fleet`**：旧参数还能用，只是会提示一句"已弃用"。

## 🐛 修好了

- **版本自检不再拖累拉起**：那条"检查有没有新版本"的提示以前是塞在启动参数里、让 pi 一上来就先干活，而拉起流程又在等它空闲 —— 两边互相等，最后判成失败。现在改成**会话就绪之后**再把提示送进去；万一提示送不进去（比如会话正忙），也只是提醒一句，**不会**把这次拉起标成失败。
- **测试里两处"看起来通过、其实没验到"的地方**：一处是把报错输出当成正文来比对（所以永远"对不上"），一处是测试替身比真机宽松（真机上会报错的情形在替身里照过）。两处都补上了能失败的对照。

## ⚠️ 请留意

- **会话名现在一定带 `@<仓名>`**（如 `rd-be@api`）。如果你有脚本或习惯按裸名（`rd-be`）操作，请改用全名，或者就地把命令跑在对应仓里 —— 裸名会按"你当前所在仓"自动解析。
- **升级前已经开着的会话不会被改名、也不会被顶掉**：在同一个仓里按裸名 `close pm` 仍然能命中它，而且不会再起出第二个 PM。
- **两支队算出同一个名字时会直接报错**并列出在场会话 —— 这是故意的（同名会话会互相顶掉，静默拉起等于给你一个"看起来有两支、其实只有一支"的舰队）。要分开就给不同的 `--fleet`。
- **仓目录名很长时**，默认名字会被自动截短（会提示一行）；如果你显式用 `--fleet` 给了超长的名字，则直接报错并告诉你要缩哪一段。
- **用 tmux 回退后端时**，那条版本自检提示会被压成一行（多行形态在 tmux 下拿不到稳定的粘贴协商）——内容不变。

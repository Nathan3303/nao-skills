# v0.32.0

## 本次更新

**调度从「人记得派单」变成「机制自己转」，顺带让同机多仓协作不再串门。** 这一版把编排器的三个阶段一次交付：任务队列与回执有了机器可读的唯一来源，主调度会话不在线时任务也能按队列往前走，同机的多个仓里出现同名角色时也不会互相投递。

### 队列与回执：台账不再靠手写

以前 tasks-state 是人写的 Markdown，回执是散文，机器读不了、也没法判真假。现在队列是机器可读的单源，台账由它单向渲染（手改后再渲染会被发现并覆盖回去）；回执改成有字段约定的文件，「说通过了但拿不出日志 / 少字段」会被直接判红。**你能得到什么**：任务状态的唯一事实不再是一份可能过期的手写文档；想核对一条完成回执，验的是文件与日志，不是对方的口头结论。

### 主调度缺席也能推进

新增一次性调度器：主调度会话不在线时，它按队列把无依赖阻塞、无卡住的任务继续往前推（派单、15 分钟无回执追问、90 分钟无进展且仓没有任何变化时标为阻塞并通知）。**默认关闭**，要显式启用才跑；带系统服务单元与幂等安装，装两次不会产生第二份配置。它**永远不会**自动合并、自动发版或推主干 —— 合并与发版仍是人的决定。

### 一眼看全 + 多仓不串门

新增看板：一条命令看全队列（按状态计数、阻塞项带原因、在飞项、最近回执摘要），也提供机器可读输出给自动化用。看板的数字与队列来自同一次读取，**不会出现半新半旧的混合值**。同时收紧派单归属：同一台机器上两个仓都有同名角色时，派单只投给「本仓 + 任务号对得上」的那个会话；归属判不清就跳过并点名，**宁可少派一次，也不投错仓**。

## ⚠️ 请留意

- **编排器默认不启用**：升级本身不会开始自动调度；需要显式安装并启用定时器才会运行。
- **多仓归属变严是行为变更**：同名角色 + 归属不可判定时，这一条会**跳过不投**（并在日志里点名），而不是像以前那样按名字猜一个。需要派单时请确保目标会话的仓归属可判定。
- **既有命令行为不变**：`status` / `check` 的文本输出逐字不变；新增的机器可读输出只是多一个输出面，不影响旧调用。

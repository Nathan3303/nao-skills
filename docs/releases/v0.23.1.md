# v0.23.1 — 多个项目同时开工：各自的会话落回各自的工作区

- 状态：待核验（tag / Release 待发；npm 发布后按唯一判据回填）· 更新：2026-11-13 · Owner：PM

## 本次更新

**修一个会让人以为「会话没起来」的毛病：跨项目拉起角色时，会话跑到了你当前所在的工作区里。**

以前在 herdr 界面里同时开两个项目（两个工作区），从 A 项目所在的窗口去给 B 项目拉角色，B 的会话会出现在 **A 的工作区**里；而且哪怕 B 项目声明了自己的 scope，会话名也可能不带 scope。

现在：

- **每个项目落到自己的工作区**：放置键改成「项目仓的目录名」（声明了 scope 就用 scope 名），不再借用当前窗口的会话名。
- **不再有「调用方工作区」这回事**：跨项目落错由结构上不可能发生，不需要你额外配置。
- 会话名规则**完全不变**（`角色-任务`，声明 scope 时带 `@scope`）。

**升级后第一次 `ensure` 会发生什么**（三种情况）：

- 旧工作区名 ≈ 项目目录名 ⇒ 直接复用，你什么都不会感觉到。
- 旧工作区名 = 你声明的 scope（如 `todo`）⇒ 继续复用，也不用管。
- 旧工作区名既不是目录名也不是 scope（即以前那种按会话名建出来的）⇒ 会新建一个按目录名的工作区；旧的那个留着变空壳，**手动关一次**即可 `herdr workspace close <旧名>`（或忽略，不影响使用）。

## 为什么改

「1 个工作区放 1 个项目」本来就是这样设计的，但放置键取的是「会话名里的 scope，没有就取当前窗口的会话名」。而 scope 是**可选**的、当前窗口的会话名是**环境**——把可选项和环境当键用，跨项目时就必然错位。

现在键恒有值（项目目录名），scope 只负责会话身份，两件事各自单一来源。

# v0.21.1 — 名册抖动时，`status` 不再把你的会话认成「说不清是谁的」

- 状态：已发布（tag + Release 待发 · npm 待重发）· 更新：2026-11-02 · Owner：PM

## 本次更新

`status` 判断一个会话「属于哪个仓」时，本来有两路依据：一是会话自己所在的窗口工作目录（最权威），二是 pi-intercom 的在线名册。第一路从引入那天起就有个字段读错了位——把窗口编号当成了会话名去建索引，查询时又用会话名去拿，于是**永远取不到值**，每次都在用第二路兜底。

平时看不出问题，因为名册通常在线。但只要名册抖一下（探针超时、broker 重启、没装 intercom），兜底那路也空了，`status` 就会把**你自己仓里的**会话标成「归属不可判定」——而按设计这种情况**不给回收命令**（防止误杀他仓会话）。结果就是：会话明明在屏幕上，你却不敢动它。

这一版把那个字段读序修正过来，让第一路真正生效：**名册不可用时，按会话自己的工作目录判定归属**，该给回收命令的照给；真正两路都拿不到时，仍然保守地显示「归属不可判定」且不给命令。

## ✨ 更好用了

- **名册挂了也能认出自己的会话**：`status` 按窗口工作目录判定，本仓会话照常显示、照常给出 `close` 命令。
- **他仓会话仍不会被误杀**：他仓窗口仍标为「他仓」且整行不含可执行命令。
- **「窗口工作目录优先于名册」这条设计真正生效了**：两者冲突时按窗口判定（此前只在代码里写着，实际从未跑到）。
- **真正无法判定时依旧保守**：两路都拿不到 ⇒ 仍显示「归属不可判定」、仍不给命令（这条没被为修好上面几条而牺牲）。
- **正常环境下你看到的输出一字不差**：名册可用时的 `status` 与上一版**逐字等价**（真机真探针两轮四份输出，md5 全同）。

## ⚠️ 请留意

- **只有一种场景的可见差异**：名册不可用时，原本显示 `? …（归属不可判定）` 的行会变成正常的本仓/他仓判定。正常环境无变化。
- **同一会话分屏（多个窗口）时按整体判定**：仍是「把所有 pane 的目录一起看」，不会只认第一个窗口——分屏时若一半在本仓、一半在他仓，仍按本仓优先（与既有语义一致）。
- **这条修复不影响回收安全性**：`close` 的闸门（在跑 turn 拒绝、任务状态闸门）一个字没改。

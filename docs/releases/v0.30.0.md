## 一句话概括

**舰队现在也能跑在 herdr 桌面版里了。** 桌面版窗口里执行 `export NAO_TERMINAL=app`，`ensure` / `status` / `close` / `cleanup` 就按桌面版的规矩工作；不设这个变量，一切照旧走 herdr TUI。

## ⚠️ 请留意

- **默认不变**：不设 `NAO_TERMINAL`（或设成 `herdr`）仍是 herdr TUI，行为与 0.29.x 完全一致 —— 本版对 TUI 路径是**零改动**（同一批命令在两个版本上逐字比对，输出一致）。
- **两套形态不共享会话**：TUI 里起的舰队在桌面版里看不到，反之亦然。这是 herdr 官方设计，不是本项目的取舍。想换形态 ⇒ 在原形态里 `close`，再到另一形态 `ensure`。
- **窗口没开就别跑 `ensure`**：桌面版窗口不在时，`ensure` 会直接 `exit 3` 并让你先开窗，**不会**先起一个终端再回滚。原因是放置位置由窗口写，窗口不在时任何放置都不会成立。
- **放置是否成功看结构，不看界面标签**：舰队写完 `herdr.space` / `herdr.tab` 后会读回桌面版的布局文档确认终端真在那个 tab 里；对不上就关掉刚建的终端并报错。桌面版界面上显示的分组名是它自己算的，可能与实际结构不一致，别用它判断。
- **`--keep` 不等于「窗口关了会话还在」**：桌面版的 `keep` 语义是「core 丢失后就地换一个 shell、标签保留」，程序退出后终端仍然会关闭。看到 `--all` 里有残留终端，先当作**幽灵**处理（`close` 会回收），别当成在线会话。
- **还没准备好？** 把机制版本 pin 回 `≤0.29.1` 即可，桌面版后端在旧版里不存在。

## ✨ 更好用了

- **同一个仓库两种形态都能用**：桌面版里一个 space = 一个仓、一个 tab = 一个角色/任务，和 TUI 的 workspace/tab 语义对齐。放不进去的仓会新建 space，不覆盖你已有的布局。
- **失败会先说人话**：窗口没开 / `herdr-app` 不在 PATH / 布局文档不可用 / 布局契约版本太旧，四种情况各有独立的错误与指路，不会退化成「终端建了又没了」。
- **不会悄悄起一堆终端**：同一 workspace 里同角色已在运行就跳过；起终端时显式断开父子关系（桌面版默认子终端会随父终端退出，不断开就会出现「父窗一关，舰队全灭」）。
- **清理有明确边界**：桌面版的 `cleanup --session` 只清**带放置标签**的终端，不碰你的 core 与其它窗口。

## 🐛 修好了

- **静态闸的单向漏检（本版自查发现并修掉）**：上一版新加的「app 区间不得裸调 `hc`」闸门，对 `command hc …`、`HC_SOCKET=… hc …`，以及**把统一执行入口整体删掉**这三种形态全部放行 —— 最后一种尤其荒谬：删掉入口反而「全部合规」。现在闸门覆盖 env/`command` 前缀，并额外断言「执行入口定义恰一处」，四种变异实测全部变红。
- **健康探针的列数错位**：桌面版终端存活判断曾按 13 个字段解析 12 列输出，导致**所有** app 终端被判成「残留」。已修，并有断言钉住。

## 技术细节（可略过）

- **实现形态**（PR [#169](https://github.com/Nathan3303/nao-skills/pull/169) squash `bc6c0c3` · 19 文件 +1912/−55）：`NAO_TERMINAL=app` 作为第二后端，与 herdr TUI 并列（非替换）；`term-impl-app` 区间 + 门面分支 + `check` 新增 app 节。
- **四条硬护栏**（都有静态断言 + 真机证据）：① 起终端一律 `--no-parent`（否则父终端结束会带走子终端）② 连接固定用 `HC_SOCKET=$HC_TERMINAL_SOCKET`（`HC_TERMINAL_SOCKET` 不参与路由，写错会静默新建空 core）③ 失败判据读 JSON `error` 而非 rc（`hc` 会 rc=0 + `{"error":…}`）④ 放置验证读 `doc.get herdr-app` 结构（`where` 是界面 label，实测会与实际结构不一致）。
- **测试隔离**（arch 评审结论 ③「部分隔离」）：`hc` 的真实调用在私有 core（`XDG_RUNTIME_DIR` / `XDG_STATE_HOME` / `HC_SESSION` 指向临时目录）下自动化；**真实收养**（窗口写布局）与 ensure/close 的界面效果无法自动化，标 `[SKIP]` 转人工验收 —— 自动化会污染你正在用的桌面版。
- **白名单形态变更**：`cases/06` 的「默认值探针块白名单」从**计数**改为**显式文件名列表**（`06` / `28` / `44`），新增或删除一个 marker 文件立刻变红，不再随个数漂移。
- 门禁（合并前实测）：`check` rc=0（roles=7 · files=53）· `npm test` rc=0（**41 例 · 2581 PASS / 0 FAIL** · SKIP=0 / DEGRADE=0 / NOTE=18 全白名单）。
- **已知边界/后续**（[#170](https://github.com/Nathan3303/nao-skills/issues/170)，到期 2027-05-24）：`check` 仍印「唯一后端」（被 AC1 逐字锁死，故未在本批改文案）· `ensure` 全败仍 rc=0（与 0.29.1 同形）· 静态闸仍不覆盖 `if`/`then`/`while`/`!` 等关键字位裸调 · `hc schema` 只判可执行 + 布局契约版本，未做字段级校验。

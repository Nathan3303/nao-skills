# v0.21.3 — `ensure` 不再谎报「已拉起」：成功 / 跳过 / 失败各说各的

- 状态：**待核验**（npm 未核验；tag/Release 待发）· 更新：2026-11-02 · Owner：PM

## 本次更新

两件事，一件你能直接看到，一件在后台。

**你能看到的**：以前 `ensure` 拉不起会话时（窗口太窄、宿主窗口已关、pane 已达上限）依然会打印一行 `[tmux] 已拉起 <角色> @ <仓库>`——你据此去 `intercom list` 找，什么也没有，很像工具坏了。这一版把三种结果分开：成功照旧打印那一行（内容一字未改），跳过和失败**不再打印**它，只在末尾摘要里如实计数：`已拉起 1 个会话（成功 1 / 跳过 0 / 失败 0）`。

**后台那件**：我们自己的门禁数字有了可复现的口径——回执必须带「跑门禁时的 HEAD、工作区是否干净、每个数字对应的命令与输出」，四条取数命令集中在 `tests/README.md` 一处，PM/QA/RD 三侧只留指针。最近几批反复出现「21 例还是 20 例」「+7 还是 +5」这类对不上的数字，根因就是没人写清数字是怎么得来的。

## ✨ 更好用了

- **失败不再伪装成功**：pane 没建成就不会打印「已拉起」，你不用再去名册里找一个不存在的会话。
- **一眼看清一批的结果**：末尾摘要给出「成功 / 跳过 / 失败」三类计数，合计等于你本次的目标数。
- **失败原因没被藏起来**：两条诊断信息（窗口过窄/已关闭/已达上限）原样保留，摘要只报数、不吞因。
- **退出码没变**：任一目标失败时 `ensure` 仍然返回 `0`（现有脚本不受影响；要改成非 0 是另一件事，需单独评估）。

## ⚠️ 请留意

- **摘要行的形态变了**：`已拉起 N 个会话；…` → `已拉起 N 个会话（成功 N / 跳过 M / 失败 K）；…`。保留原有前缀以避免破坏既有习惯；三类全为 0 时不打印（与以前一致）。
- **成功行本身一个字没改**：`[tmux] 已拉起 <角色> @ <仓库>（layout=…）` 与 `--model` 变体都与旧版逐字相同。
- **回执写法有了新要求**（对我们内部）：门禁数字必须能在静默工作区用一条命令复现，且回执要记 HEAD。这条不影响你使用命令。

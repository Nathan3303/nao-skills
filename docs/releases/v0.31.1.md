# v0.31.1

状态：**待核验**

## 本次更新

**修好了「在 herdr 桌面版里跑 `ensure`，终端刚起来就被回滚」这个 bug。** 如果你在 nao-todo 或别的仓里见过下面这句，就是它：

```
[fleet] 放置验证失败：终端 t10 不在目标 tab 的 root 树里 ⇒ 回滚（kill → rm）
```

现在不会再误报了。两条根因同时修掉（缺一个都还会复发）：

- **收养是异步的** —— 桌面版对「新建终端」的落库请求是「先应答、后应用」，旧代码起来后只查一次布局就判定成败，几乎必然读到「还没落库」；现在改为有限轮询（默认 10×0.5s，可用 `NAO_APP_ADOPT_TRIES`/`NAO_APP_ADOPT_INTERVAL` 调整）。
- **陈旧 space id 不再沿用** —— 桌面版重启后 space/tab 的 id 会重新生成。旧逻辑会把布局里查不到的旧 id 塞回映射继续用，而桌面版对「不认识的 id」会自己新建一个，于是请求的旧 id 永远落不了地。现在查不到就换一个新的 id，交给桌面版建。

顺带改了两件小事：

- **报错分家**：「目标 space 不存在」和「收养超时」现在会分别提示，不再混成一句。
- **`check` 增加桌面版前提提示**（窗口没在跑 / `hc` 不在 PATH），只提示不改变退出码。

## 需要你知道的

- **默认行为不变**：不设 `NAO_TERMINAL` 仍走 TUI，两条路径互不影响。
- 桌面版里**同一仓已有但空的 space/残留终端不会被清理** —— 本版只做「不再沿用错误 id」。
- 前置：herdr desktop app 窗口在跑 + `hc` 可用 + pi ≥1.4.0。

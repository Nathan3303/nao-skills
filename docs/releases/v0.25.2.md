## 一句话概括

**指定全名 `close <角色>@<舰队>` 时，同名跨仓不再随手抓一个仓；顺带修好一条会让「快档自查」直接报错的登记遗漏。**

## 🐛 修好了

- **全名 `close` 也会认错仓**：`close <core>@<fleet>` 以前同样按名册**第一条命中**定仓 —— 两个仓里有同名会话时，可能把你指定的那个指到别人仓去，连带忙闲判断和回收定位全错。现在按「**同一个名字对应几个仓**」来判断：
  - 只有一个 ⇒ 照旧采用（**跨仓唯一命中也照旧能回收**，旧用法不受影响）；
  - 不止一个 ⇒ **拒绝并列出候选路径**，不猜。
- **同一路径的重复记录不再被当成「多仓歧义」**：名册里同一条会话重复登记时，以前会报「目标歧义」并让你去分辨仓；现在按路径去重后再判断，并在文案里直接说清「名册共 N 条记录，含同名同仓重复条目，不要当成多仓歧义」。
- **`npm run test:fast` 被打断**（上一版的登记遗漏）：上一版新增用例没进快档分类表 ⇒ 快档门禁直接报「参数错误」而失败。现在已登记，快档恢复可用；**全量 `npm test` 不覆盖这条自检**，所以之前「全量绿」并不会暴露它。

## ⚠️ 请留意

- **裸名与全名的口径有意不同**：`close <角色>`（裸名）在「同一仓里有多个同名会话/多个同名窗口」时**仍然拒绝**、不做任何猜测 —— 因为裸名多一层风险，猜错就会关掉不该关的。全名是你**显式指定**的，因此在路径去重后唯一时直接采用。这条非对称已记入台账（到期会重新评估能否统一）。
- **两种既有边界仍在**（不属本版引入，已登记）：名册条目缺 `cwd` 时该条目对仓过滤不可见；herdr 后端下「名册缺 cwd」仍可能报「未运行（无需回收）」。
- **看回执里的 `@ <路径>`**：那是本次实际认定的仓，最快的自证方式。

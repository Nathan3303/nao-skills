# v0.20.2 — 别把别的仓库的会话当成自己的：残留提示按仓归属，且不再给会误删的命令

- 状态：已发布（v0.20.2 · tag + Release 已发；npm 重发已核验）· 更新：2026-10-31 · Owner：PM

## 本次更新

同时开多个项目时，「查一下有没有该收的会话」这条命令会把**别的仓库**里正在跑的会话算成你自己的残留，还贴心地附一句可以直接复制执行的回收命令——照着做，删掉的是另一个项目的会话。这一版修的就是这个：**残留判定先看「这个会话在哪个仓库」，不是自己的就不再列进你的残留、也不再给你回收命令**。顺带补上一条团队流程自检：合并前必须先确认「本地提交都已推送」，避免合并进去的内容和本地实际交付的不一致。

## ✨ 更好用了

- **只算自己仓库的残留**：别的仓库的会话不再混进你的「残留」清单，一眼就知道还有哪些该收。
- **不再给出会误删的命令**：其他仓库的会话会被单独标出来（写着它属于哪个仓库），但**不给**可直接执行的回收命令——想收它，去它所在的仓库处理。
- **判不出来时不乱说**：实在判断不了归属（比如进程已退出、权限不足），只提示「归属不可判定，请人工核对」，**不会**再谎报成「这是你仓库的残留」。
- **合并前的一致自检**：团队流程新增一条硬性——合并前确认本地分支没有「未推送的提交」，避免出现「本地改了、合并进去的却是旧版本」。

## ⚠️ 请留意

- **行为变化**：其他仓库的会话在本仓库**不再**给出回收命令；要回收请到它所属的仓库执行（能力本身没删，只是不再在本仓库指路）。
- **单仓库用户无感**：只有一个仓库、没有跨仓会话时，输出与之前**逐字一致**（已用旧版 vs 新版逐字比对验证）。
- **判断不了就不指路**：归属不可判定时只标注、不指路，属有意的保守选择（宁可让你多看一眼，也不给你一条可能删错东西的命令）。
- **两仓同名时仍有已知边界**：两个仓库目录同名时，会话归属在极少数情况下可能互相串（已在 ADR 记录，后续处理）。

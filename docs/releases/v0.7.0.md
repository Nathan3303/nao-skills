# v0.7.0 — Git 流程改为 GitHub Flow

- 状态：已发布 · 更新：2026-09-24 · Owner：PM

## 一句话

每个需求一条分支一个 PR，验收通过后合并成 **1 条可读提交**——main 不再被几十条开发提交刷花。

## 行为变化（用户可见）

- **提交流程**：工作期提交只落在需求分支 `feat/<issue-id>-<slug>`，main 只接收合并后的结果；提交信息要求写「用户能看到什么」，不再出现纯编号 / 类名的提交
- **合并方式**：验收通过后由研发角色 squash 合并，main 上每个需求恰好 1 条提交
- **职责变化**：PM 只做验收授权、Issue、tag/release 与仓库治理，**不再亲自合并或推送 main**
- **状态可追踪**：Issue 作为入口与摘要，正文留在 `docs/`，只在立项 / 派发 / 验收 / 合并 / 发布 5 个节点同步
- **发布**：优先用 `gh` 生成 Release，不可用时降级 `git tag`；离线或没有远端时流程自动降级，不阻断交付
- **体检**：`nao-fleet.sh check` 在 GitHub 远端下会提示 PR 模板缺失（warn，不阻断派发）

## 升级

`npm i -g @nathan33/nao-skill@0.7.0`，或项目内 `nao-skill update`。

- 角色卡版本：`pm v18` / `rd-fe v10` / `rd-be v10` / `qa v11` / `arch v10`
- **已拉起的会话需重开**（`nao-fleet.sh ensure --force <角色>`）才会加载新流程；否则旧会话可能仍按「批次分支 + 终签收敛」行事
- 新流程首次使用前，PM 需建 `.github/pull_request_template.md`（`check` 会提示）

## 回滚

`git revert <merge commit>`；本版本为纯 Markdown 规范 + 脚本提示变更，无数据迁移。

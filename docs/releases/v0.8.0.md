# v0.8.0 — QQ 主动推送（舰队一等能力）

- 状态：已发布 · 更新：2026-09-25 · Owner：PM

## 一句话

关键节点不用盯屏：PM 把**批次进度 / 验收结论 / 发版合并 / 异常阻塞**四类节点主动推到你 QQ；默认不打扰，推送失败也不阻断交付。

## 亮点（新增能力）

- **新增 `.agents/scripts/qq-notify`**（Node，零外部依赖，可执行）：QQ 官方机器人「主动消息」推送器
  - 配置优先级：`--config <path>` > 环境变量 `QQ_NOTIFY_CONFIG` > `~/.pi/agent/pi-agent-qqbot.json`
  - 用法：`qq-notify "文本"` · `--to <openid>` · `--dry-run` · stdin 管道 · `-h/--help`
  - 退出码：`0` 成功 · `1` 参数/配置错 · `2` 取 token 失败 · `3` 发送失败
  - 安全：绝不打印/落盘 `clientSecret` 与 `access_token`；错误输出截断；无配置给可执行修复提示，不抛栈
- **新增技能 `.agents/skills/qq-notify.md`**：能力边界（平台权限与月度配额）、四类节点、禁刷屏纪律、退出码、sandbox vs prod、跨项目路径
- **PM 角色卡新增 §十四「关键节点主动推送（可选能力）」**：只放纪律与一句话用法，实现细节在技能文件

## 行为（用户可见）

- **只推四类节点**：批次进度汇总 / 验收结论 / 发版或合并完成 / 异常阻塞；**一个节点最多一条**，禁刷屏。
- **默认 sandbox**；正式发布通知才考虑 prod（两者权限与收件人不通用）。
- **默认不主动打扰**：未配置 `pi-agent-qqbot` 即视为未启用；推送失败只把 `notify=fail(exit=<n>)` 记入回执风险项，**不阻断交付**。
- `nao-fleet.sh check` 新增 qq-notify 契约校验：**存在 + 可执行 + 行尾全 LF + 无 Tab + `node --check` 语法**，任一不过即 `rc=1` 并列出原因。

## 限制

- QQ 官方**主动消息**受账号权限与**月度配额**限制；配额用尽 / 未开通权限 → exit 3，**不重试轰炸**。
- 仅**单向推送**：不接收消息、不做被动回复、不做定时调度与退避重发。
- **跨格式可移植**：脚本无扩展名，用动态 `import()` 包在 async IIFE 中，兼容宿主项目 `"type": "module"` 与 CommonJS 两种解析（Node ≥18）。

## 升级注意

`npm i -g @nathan33/nao-skill@0.8.0`，或项目内 `nao-skill update`。

- **无需改动 `bin/nao-skill.js`**：安装器按 `.agents/` 目录树整包复制，新文件自动随安装分发（无需白名单）。
- **可选能力**：不配置 `~/.pi/agent/pi-agent-qqbot.json` 不影响任何既有流程。
- 角色卡版本：`pm v19`（新增 §十四）/ `rd-fe v10` / `rd-be v10` / `qa v11` / `arch v10`。
- 首次使用前先自检连通性：`.agents/scripts/qq-notify --dry-run "自检"`（`0` = 取 token 成功）。

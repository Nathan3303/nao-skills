# v0.17.3 — 发布标题统一成版本号，说明回到正文

- 状态：已发布 · 更新：2026-10-14 · Owner：PM

## 一句话

从这一版起，GitHub 上每个 Release 的标题**就是版本号本身**（如 `v0.17.3`），不再挂一长串副题 —— 版本列表一眼扫完、跨仓能对齐；「这版改了什么」仍然写，只是回到正文最前面。

## ✨ 更好用了

- **版本列表干净了** —— 以前标题里塞满副题（`v0.17.2 — 文档模板与格式约定：ADR 结构契约 + 骨架单源 + 索引模板`），在列表页和命令行里会撑破宽度；现在统一为裸版本号，版本号与标题永远一致，不用再靠分隔符去猜哪段是版本。
- **描述没有丢，只是换了位置** —— 一句话概括固定放在正文最前「本次更新」段；想快速知道这版改了什么，点进去第一行就是，不用在标题里挤。
- **规则写在一处，下游仓同样适用** —— 标题口径固化进发版说明规范的硬约束（连核对清单与红线各补一条），用同一个机制包的下游项目发版时照同一形态，跨仓 Release 可以直接对比。

## ⚠️ 请留意

- **这是口径变更，只对今后的发版生效** —— 已经发过的 Release 标题保持原样，不做追溯改写；从下一版起，新发的 Release 标题都不带描述性文本。
- **如果你在用命令行读标题**（如脚本里解析 `gh release list`），今后标题与 tag 完全相等（`vX.Y.Z`，预发布如 `vX.Y.Z-beta.1`），解析更简单；依赖「标题里带描述」的脚本需要改为读正文。

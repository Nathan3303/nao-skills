# 文档站（门户 → VitePress 首页的移植规格）

- 状态：待 PM 验收 → 用户确认 · 更新：2026-11-16 · Owner：uiux-designer

- 交付档位：**① 结构化文字规格**（不重做视觉、不出图、不新增画板；基准即结论，本文只做映射与取舍）

## 一、信息架构

- **首页 = 现状单页，结构不动**：六段顺序 Hero / 三个毛病 / 七个角色 / 三步装好 / 常见问题 / 页脚横幅；不套 VitePress 默认 `home` 版式（其居中 hero 与 features 网格无法承载复制按钮、终端示意、三步序号、`<details>` FAQ，硬改等于重做视觉）⇒ 首页走 `layout: page` + 六段各自组件包裹，保留主题顶栏与跳过链接。
- **文案单一源在 content 侧**（PM 所有）：六段文案含 FAQ 5 条、七角色 ≤24 字职责、三组命令块，全部写在 `content/**`；结构与样式在 `.vitepress/` + `components/`（rd-fe 所有）只做包裹与取值，**禁手抄文案**（否则 AC2 逐条对应必漂移）。
- **进首页 / 移入文档页**：Hero、三个毛病、页脚横幅 = 仅首页；七个角色 = 首页 7 卡（名称 + 职责）＋点击进角色页；三步装好 = 首页保留 3 步与命令块，`快速开始` 页是同一三步的展开（前置细目、插件、体检、排错），命令复用同一源不重写；常见问题 = 首页保留 5 条，`常见问题` 页 = 同 5 条同源 + 追加条目；文档页不重复营销 Hero 与页脚 CTA。
- **顶栏 4 位**（沿用基线「4 项、品牌左 / GitHub 右」的结构）：`nao-skills`（首页）· `文档`（快速开始）· `角色`（七个角色组）· `插件` · `GitHub`（外链新标签）。原顶栏 4 锚点降级为 Hero 下方一行**跳读条**（三个毛病 / 七个角色 / 三步装好 / 常见问题），<720 一行横滑（沿用基线 §一 规则）——站点变多层后顶栏须承载全局导航，这是对基线唯一的有意取舍。
- **侧栏 7 组 + 2 尾项**（总 ≈18 页，两层，不超三层）：快速开始（装前置 / 装机制 / 拉队开工 / 排错）· 它怎么干活（一个需求的旅程 / 验收与回执）· 七个角色（7 页，顺序与名称取 `roles.yaml`，目录禁手写）· 角色配合（谁派谁 / 冲突与升级）· 插件选择（内置 5 个）· 进阶用法（多项目布局 / 自定义角色卡）· 常见问题 · 术语表。
- **首屏不迷路**：Hero 双入口 = GitHub + 快速开始（npm 文字链保留），跳读条给页内四落点，侧栏永远显示「快速开始」，任一深层页 ≤2 次点击回首页。
- **角色页 = 一页两区**（AC3）：上「人话解说」（≤原文 1/3 行数，只答「管什么 / 不管什么 / 怎么跟它对话 / 典型误用」，**禁复述卡内闸门与红线**——复述会让读者拿解说替代原文）；下「卡原文」（构建期注入，原样渲染，默认展开，不折叠以免读者以为不存在）。
- **来源标注（防误解为权威）**：原文区标题固定「卡原文（构建期注入，未改写）」，其上一行徽标 `来源 · .agents/prompts/<card>.md · v<N> · 构建期注入`（图标 + 文字，不靠颜色）；解说区首行固定一句「本页解说是通俗说明，与卡原文冲突时以卡原文为准」；两区之间一条 `border-subtle` 分隔 + 小标题「人话版 ↑ / 权威原文 ↓」。
## 二、流程

1. 画像 A：落首页 → 30 秒读定位 → 点「复制」（≤100ms 变「已复制 ✓」）→ 点 Hero 的「快速开始」。
2. 画像 B：首页七卡 → 角色页读解说 → 同页下滑看卡原文核对 → 侧栏跳「角色配合」。
3. 画像 C：顶栏「插件」→ 5 卡对照，读「缺了会失去什么」→ 回侧栏「进阶用法」。
4. 异常 · 剪贴板被拒：不弹窗，自动全选命令，文案「已选中，请按 ⌘/Ctrl+C」，1.8s 复原（原 `app.js` 行为平移为 Vue 组件）。
5. 异常 · 仓缺 `.agents/prompts`（AC5）：角色页原文区显示「卡原文见仓库」+ 一条提醒，构建不崩；`--strict` 失败。解说不受影响。
6. 异常 · JS 关：原文为构建期静态 HTML 仍完整可读，复制按钮保留但不生效，FAQ 走原生 `<details>`；加载 / 空 / 错误 / 无权限：不适用（纯静态站无数据请求、无用户态）。
## 三、视觉规范

- 首页逐项沿用基准 §三（h1 39/1.2 窄 31/1.25 · h2 25/1.3 窄 22 · 卡标题 16/600 · 正文 16/1.7 · 辅 13/1.6 · 区块 80/64 窄 64/48 · 卡 1px `border-subtle` + 12 · 终端 CSS 绘制 <720 隐藏），不改。
- 内容页扩展（**材料够就升级，不新增数值**）：h1 取 31（窄 25，内容页不用营销大标题）· h2 25（22）· h3 20 · 正文 16/1.7 · 代码与表格 13–14 · 阅读栏 720（16px 下 ≈44 汉字/行）· 内容页区块 80/64（窄 64/48）· 侧栏项间 8、组间 24。
- 强调仍唯一：`accent` 只给链接、实心 CTA、焦点环、导航当前项（首页与侧栏同一口径）；其余靠字重与留白分层。**数量口径**：实心 CTA 全场 **1 个** = Hero 的「复制」；次入口用 ghost（1px `--nh-border`、44px 高），再次用文字链。
- 终端示意内容纪律：行数不锁 5（现 6）；每行只能是 `$` 命令 / `✓` 输出 / `pi>` 输入 / `→` 响应四类，**禁写面向读者的解说与站内导航语**。
- 形态红线不外扩：无渐变 / 玻璃拟态 / 发光 / 装饰插画 / emoji 标题，圆角 ≤14；提示块（callout）用 `surface-sunken` + `border-subtle`，不用默认彩色底。
## 四、token（映射口径 + 默认残留清零点）

- 颜色 ← 基准 §四 亮 / 暗两套值，逐项落到主题变量：`--vp-c-bg` ← `surface-page` · `--vp-c-bg-alt` / `--vp-c-bg-soft` / `--vp-code-block-bg` ← `surface-sunken` · `--vp-c-text-1` ← `text-primary` · `--vp-c-text-2` ← `text-secondary` · `--vp-c-text-3` ← `text-tertiary` · `--vp-c-divider` / `--vp-c-border` / `--vp-c-gutter` ← `border-subtle` · `--vp-c-brand-1` ← `accent`（链接）· `--vp-c-brand-2` ← `accent`（hover 加深 `#1B45C0` / 暗 `#2A5BE0`）· `--vp-c-brand-3` ← `accent-solid` · `--vp-c-brand-soft` ← `surface-sunken`（禁默认蓝底）· `--vp-c-tip` / `-warning` / `-danger` / `-important` ← `text-secondary`（提示块靠底色与描边区分，不引入黄绿红）。
- **默认蓝 / 默认字体族清零点（AC10 抽查必列 9 处）**：正文与侧栏链接 · 按钮 `.VPButton`（半径 999）· 搜索框 · 提示块 · 导航与侧栏当前项 · 右栏 TOC 指示条 · 外链箭头图标 · 代码块复制按钮 · `.VPNavBar` 的默认 `backdrop-filter` 模糊（改实色 `surface-page`，形态红线禁玻璃感）。
- 字体族：`--vp-font-family-base` ← 基准 sans 栈（零外链）；`--vp-font-family-mono` ← 基准 mono 栈。深色不设手动开关：隐藏 `.VPSwitchAppearance`，`appearance` 保留 auto，深色仍由 `prefers-color-scheme` 驱动。
- 字阶：内容页 h1 / h2 / h3 / 正文 / 代码 / 辅助全部落在基准 14 档内（11–39），**不新增 px 值**。
- 间距与布局维度：`--vp-nav-height: 56`（= 基准顶栏 56）· `--vp-sidebar-width: 264` · `--vp-layout-max-width: 1128`（版心 1080 + 左右 24）· 阅读栏 720 · 右 TOC 200；间距只取 4 的倍数，间距 token 仍为 `4…80` 那 14 档。
- 圆角：代码块 / 提示块 / 卡片 12 · 小控件 8 · 按钮与胶囊 999 · 终端 14（仅首页 Hero，不移植到内容页）。阴影只亮色 hover 用 `0 1px 2px rgba(16,24,40,.06)`，暗色一律改描边分层。层级 `z-header 10` / `z-toast 20`；侧栏抽屉遮罩用 `surface-sunken` 加描边，不引入透明度新值。
## 五、状态

- 复制按钮（首页命令块 + 代码块复制）：默认「复制」→ 成功「已复制 ✓」→ 失败「已选中，请按 ⌘/Ctrl+C」（1.8s 复原）· focus 2px `accent` 环 · 成功不单靠颜色（文案 + 符号）· 反馈走 `aria-live="polite"` 独立区。代码块右上角复制按钮（默认主题自带）必须走同一组件与同一文案，禁两套视觉。
- FAQ：默认 5 条全收起（一屏扫完），展开 `+ → −`；首页与 FAQ 页同一渲染，收起态一致。
- 角色页原文区：正常 = 展开可读；缺仓 = 「卡原文见仓库」+ 一行提醒（非纯色，配图标）；两态都不隐藏周边导航。
- 导航当前态：首页跳读条 `aria-current="true"` + accent 文字 + 2px 下划线（沿用 `app.js` 的 IntersectionObserver 口径）；侧栏当前页 `aria-current="page"`。无 JS 仅失高亮，跳转不受影响。
- 极值：命令超长 `overflow-x: auto` 不换行；角色职责 2 行截断 + `title`；表格 <720 横滚；加载 / 空 / 错误 / 无权限：不适用（同 §二 6）。
## 六、断点

- 首页沿用基准 §六：≥1080 两栏 Hero + 角色 3 列 · 720–1079 单栏 + 角色 2 列 + 终端缩 3 行 · <720 全单列、终端隐藏、跳读条横滑、留白 64/48；360 硬边界不变（padding 24、正文 16 不缩、`min-width:0`、禁 `100vw`、不用 `overflow-x:hidden` 掩盖）。
- 内容页三档（由基线推导，非新 token）：**≥1280** 三栏（侧栏 264 + 阅读 720 + TOC 200）· **1040–1279** 两栏（TOC 隐藏，= 264 + 24 + 720 + 24 + 8 取整）· **720–1039** 侧栏收为抽屉、阅读栏占满 · **<720** 单列、正文 16、代码与表格横滚、H1 25。
- 必须在 VitePress 里显式覆盖的 6 项：① `.VPSidebar` 抽屉遮罩与阴影 → `border-subtle` 描边 + `surface-sunken`；② 移动端顶部 `.VPLocalNav` 高度与命中区（≥44）；③ 右栏 TOC 在 1280 以下隐藏；④ `<720` 正文 `padding 24`（默认更窄）；⑤ 顶栏固定高度 56（默认 64）；⑥ 代码块、表格、提示块的横向滚动容器（禁全站 `overflow-x:hidden`）。
- 深色（AC6）：跟随系统，无开关；暗色 surface 抬亮（`#0B0F14` / `#121A26`）、只用描边分层不用阴影、终端保留暗面 + 描边；暗色次要/正文对比度取基准实测 8.8:1 / 16.4:1 档。
## 七、可用性

- 主路径点击数：首页 → 复制 1 次 → 快速开始 1 次（≤3）；角色页到卡原文 **0 次**（同页，禁折叠成第二次点击）；术语解释 0 次（行内），术语表 1 次（可选深挖）。
- 反馈：复制 ≤100ms 出文案；侧栏与跳读条为静态跳转无阻塞过渡；平滑滚动可被「减少动效」关闭；禁 >400ms 阻塞动效。
- 防误操作：本批无破坏性操作；外链一律新标签 + `rel="noopener"`，站内锚点不新开。
## 八、无障碍

- 每页 `h1` 唯一（首页 = 品牌大标题，内容页 = 页面标题），`h2`/`h3` 不跳级；`<nav aria-label>` + `<main>` + `<footer>`；终端示意 `aria-hidden="true"`。
- 角色页两区用 `<section aria-labelledby>` 各自命名，来源徽标图标 + 文字双承载，**不靠颜色**区分「解说 / 原文」。
- 键盘：保留并改写主题跳过链接为「跳到主内容」；全部链接/按钮 Tab 可达、`focus-visible` 2px `accent` + 2px offset（禁裸 `outline:none`）；命中区 ≥44×44（跳读条、侧栏项、汉堡、复制按钮）；抽屉开合符合主题默认焦点行为并 Esc 可关。
- 对比度沿用基准 §四 实测值（正文 16.4:1 / 次要 8.0:1 / accent 6.3:1；暗色 8.8 / 8.1），实现后由用户清单复核。

## AC 结论（设计侧）

- AC2 PASS：六段归属与单一源规则已定（§一）——首页六段齐备、文案只存 content 一处；唯一有意取舍 = 顶栏 4 锚点降级为 Hero 下方跳读条，待用户走查确认。
- AC3 PASS：一页两区 + 默认展开 + 来源徽标 + 「冲突以原文为准」声明（§一）；`apps/document` 内禁解说复述卡内闸门与红线。
- AC6 PASS（设计侧）：三档断点、深色规则、6 项显式覆盖列全（§六）；实现后按用户清单逐项回填。
- AC10 PASS（映射口径）：颜色 / 字阶 / 间距 / 圆角逐项落到主题变量，9 处默认残留清零点列出（§四）；抽查按实测色值与 px 判。
- AC11 PASS：行内半句解释 + 术语表双轨（§一 已给形态）；六词形态：PRD（把需求写成可验收的文档）· AC（逐条可判定的验收条件）· 回执（干完给 PM 的结论单）· 门禁（自动检查，rc=0 才算过）· 闸门（某角色放行前必须先出的书面结论）· RICE（按触达×影响×信心÷成本打分排优先级）；**门禁 ≠ 闸门**，两者各给半句且术语表分开列。
- 遗留：① 顶栏锚点取舍与内容页 h1 取 31（不取 39）两处为基线外推导，交用户 AC2/AC10 走查确认；② 内容页 1280 / 1040 门限为新增推导值（未引入新 token 数值）；③ 主题变量名以实现覆盖为准，AC10 以实测色值/字号判，不以变量名判；④ 搜索本批不启用（PRD 非范围），后续批次可加离线 local provider。

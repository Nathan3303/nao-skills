**结论摘要**：P1 CTA 主次成立且**比你写的更严重**（Hero 3 个实心、全页 4 个，基准写「全页唯一」）· P1 终端内容成立，但「卡比左栏高」**方向反了**（卡 280px < 左栏 442px）· H1 `<br>` **不改**（360 实测仍 2 行、无溢出；去掉反而在桌面塌成 1 行）· 右上 GitHub「同权重」不成立（已是 accent），但查出**双 ↗**。

## 一、CTA 行主次（P1）

- 实测（1440）：`复制` 74×32 实心 `#1D4ED8` · `GitHub` 100×44 实心 · `快速开始` 110×44 实心 · `npm 最新版` 文字链；页脚 `GitHub` 100×44 实心（`.nh-footer .pill`）⇒ **Hero 3 个实心、全页 4 个**。
- 依据：portal §一「主 CTA = 复制安装命令（**全页唯一实心按钮**）」；docs-site §三「accent 只给链接、实心 CTA、焦点环」——后半句字面允许无限个实心，是实现跑偏的口子（§五 改基准）。
- 改法：`复制` 保持唯一实心（32px 视觉高 + `::after` 44 命中区不动；放大到 44 会把命令块撑高 12px）。`快速开始` → `.pill-ghost`，但基准 ghost 是 36px/13px，hero 需覆盖：`min-height:44px; padding:0 var(--nh-sp-6); font-size:var(--nh-fs-15); border:1px solid var(--nh-border); color:var(--nh-text)`。`GitHub` → `.cta-text`（accent 文字链，同 npm）。顺序改 `快速开始 → GitHub → npm 最新版`。
- 数据侧：`types.ts` 的 `HomeLink.style` 增 `'ghost'`，`HomeHero.vue` 增一条分支；`index.md` 只改 `style` 与顺序，不增字段。
- 页脚同规则违例 1 个：建议同批（`.pill` → `.pill-ghost` 一行）；若你认为「页脚二次转化要实心」，就改基准而不是改实现（§五 二选一）。

## 二、终端卡内容（P1）

- 实测：`.term` 280px vs `.hero-copy` 442px，`align-items:center` ⇒ 上下各 81px；卡底 473 恰好 ≈ CTA 行顶 470（差 3px），视觉上是「卡到按钮处收住」，不是坏对齐。**「卡比左栏高」与实测相反**。
- 第 5 行「3 个会话窗口逐个亮起（要拉满 7 个，照快速开始里的三步走）」是**给读者的解说**：终端不会知道「快速开始」是站内哪一页；第 6 行「你：」是叙述体，`cursor` 实测 `animationName: none`（7×14 静态块，不闪）⇒ 观感卡住成立。
- 改法（`content/index.md` 的 `terminal`，仍 6 行、高度不变）：第 5 行 → `→ pm 接单 · 已派给 arch / rd-fe`（`muted`）；第 6 行 → `❯ 想加一个登录页`（`muted`），删 `cursor: true`。`$` 是 shell、`❯` 是 pi 提示符，两个提示符正好区分「敲命令」与「跟小队说话」；「入 → 响应」构成完整回路，比闪烁光标更能说明产品，且不引入新动画（无 reduced-motion 分支）。`❯` 若无字形（截图出现豆腐块）退回 `>`。
- 连带清理：`types.ts` 删 `cursor?`、`TerminalMock.vue` 删光标 span、`home.css` 删 `.term-cursor`，否则成死代码。

## 三、H1 硬 `<br>`（不改）

- 实测：360 → 31px、2 行、行宽 128 / 215（容器 312），`scrollWidth == clientWidth` 无溢出；720 / 1440 → 39px、2 行（160 / 270）。**任何宽度都没出现第 3 行**。
- 反证：整句单行宽 435px，≥1080 的 h1 容器 600px ⇒ **去掉 `<br>` 会在桌面塌成 1 行**，丢两行节奏；360 下自然折行（单行 346 > 312）断点随宽度浮动，不可控。
- 结论：`<br>` 是内容侧控制断行的有意设计，保留；风险只在「改文案忘改数组」，属内容纪律。

## 四、右上 GitHub ↗（P2）

- 实测：nav 的 GitHub 已是 `rgb(29,78,216)`（accent），另三个是 `#475467`，并带 VitePress 外链图标 ⇒ **不同权重**，`target=_blank` / `rel=noopener` 齐备。
- 真问题：**双箭头** —— 链接文本里的字面 `↗`（蓝）+ VitePress 自动图标（灰）同屏（5× 放大可辨）。改法：`config.mts` nav 的 `text: 'GitHub ↗'` → `'GitHub'`（1 处），图标自动保留；读屏也不再念「上箭头」。
- 页脚文字链仍带字面 `↗`（那里无 CSS 图标，不重复）：P3，要免读屏念箭头需给 `HomeLink` 加 `arrow` 字段包 `aria-hidden`，本批不做。

## 五、`2026-11-16-docs-site.md` 要小修（2 处）

1. §三「强调仍唯一」补齐数量与形态：「实心 CTA 全场 1 个 = Hero 的『复制』；次入口用 ghost（1px `--nh-border`、44px 高），再次用文字链」。
2. §三 终端示意补内容纪律：「行数不锁 5（现 6）；每行只能是 `$` 命令 / `✓` 输出 / `❯` 输入 / `→` 响应四类，禁写面向读者的解说与站内导航语」。
- 不用改：h1 39/31 与 `<br>` 不冲突；`<720` 隐藏终端、两栏、留白 80/64 与实测一致。

## 六、建议不改（防为改而改）

- 终端 `<720` 隐藏：保留。信息损失 0（同一条命令在 `cmd-box`、7 个角色在 lead），360 首屏预算靠它让位。
- Hero `align-items:center`：保留。改 end 会把卡压到 274px 起（H1 之下），丢掉「标题旁就是证据」的对位。
- 终端 6 行高度：保留。为对齐加行 = 内容注水；卡底与 CTA 顶已有 3px 巧合对齐。
- nav GitHub 用 accent：保留（链接用 accent 是基准允许项，不是等权）。
- `复制` 32px 视觉高：保留（命中区已 44；fill 权重 > 尺寸，仍是唯一主点）。

# 让队列自己往前走

前面几页讲的都是「你或 PM 在的时候」怎么干活。这一页讲的是**没人在的时候**：任务能不能自己往下走一步。

能把这件事做完的是一组命令，跟着机制包一起发（在包内的 `bin/` 下，与 `.agents/` 同级）。它们默认**不启用**，你不开就完全不跑。

## 先说一件容易踩的事：这些命令在哪跑

编排器的命令**打包在机制包里**，不在你的项目里。你的项目根只有 `.agents/scripts/nao-fleet.sh` 这一个转发入口，没有 `bin/`。

所以本页所有 `node bin/nao-orch …` 都要求在**机制包目录**里执行：

```bash
cd .pi/npm/node_modules/@nathan33/nao-skill    # pi 安装机制包的位置
ls bin/                                          # 应该能看到 nao-orch 和 nao-queue
```

（如果你是在机制包自己的仓库里读这一页，那个目录就是仓库根，可以直接跑。）

> 这一条现在是硬限制：**编排器只在机制包目录里能用**。让它在任意项目里直接可用（`nao-orch` 上 PATH、systemd 单元指向包内路径）是下一步要补的，当前版本没做到。

## 先说结论：现在要不要用它

**如果你（或 PM 角色）一直在场，暂时不用开它。** 它的价值只有一个场景：没人在盯的时候，让队列里的活自己往前走一步。

而且它**只对「队列里有排队中的任务」有意义**。队列空着，跑多少次都是零动作。

所以正确的启用顺序是：先有活、再开机；不是先装定时器，再想怎么用。

## 怎么开始用（三步，按顺序）

### 往队列里加一行

队列是一份 JSONL 文件（一个任务一行）。目前没有「加任务」的命令，直接编辑 `docs/queue.jsonl` 追加一行即可：

```json
{"id":"T900","kind":"feat","title":"把登录页的错误提示改成中文","state":"queued","prio":"P2","deps":[],"repo":"nao-skills","branch":"","owner":"rd-fe","qa":"qa","acs":["AC1"],"attempt":0,"created":"2026-11-26","updated":"2026-11-26","blocked_reason":""}
```

几个字段的意思：

| 字段 | 填什么 |
|---|---|
| `id` | 任务号，和 Issue 号最好对得上 |
| `state` | 新任务填 `queued`（排队等派） |
| `owner` | 派给哪个角色（`rd-fe` / `rd-be` / `rd-infra` / `qa` …） |
| `acs` | 验收条件编号，给回执和 QA 对照用 |
| `deps` | 依赖的任务号；写了的必须都完成才会派 |

写完先校验一次，它会告诉你字段有没有漏、状态合不合法：

```bash
node bin/nao-queue validate
```

### 手动跑一次，看它怎么想

**别急着装定时器**，先手动跑一次看清楚：

```bash
node bin/nao-orch tick      # 跑一次：该派的派出去，然后退出
node bin/nao-orch board     # 看结果：谁被派了、谁在等、谁卡住了
```

**注意：跑之前知道它会真的动手**：`tick` 会把排队中的任务**真的派出去**（起对应角色的会话、发消息给它）。想先看而不动手，用 `board`——它只读不写。

如果它什么都没做，看输出那一行：`waiting=2` 表示那两个任务在等（目标角色正忙），`skipped=1` 表示跳过了。`dispatch` 为 0 就是没派。

### 觉得顺手了再装定时

**在普通项目里先别装。** 当前版本的定时单元会把执行路径写成「你的项目根 `/bin/nao-orch`」，而下游项目根本没有这个文件——装完之后定时器每次都会启动失败，而且不会有任何提示告诉你它一直没跑。

也就是说：**手动 `tick` / `board` 现在就能用；定时跑要等这条修完**（跟踪在 Issue #228）。在机制包自己的仓库里使用不受这个限制。

修好之后的用法如下：

```bash
node bin/nao-orch doctor                    # 先体检：node/herdr/pi/git/队列/状态查询 都通才装
node bin/nao-orch install-systemd --enable   # 装成定时任务，默认两分钟一轮
```

只装不让它跑（先观察）：

```bash
node bin/nao-orch install-systemd            # 装但不启用；之后 systemctl --user start nao-orch.timer
```

想关掉：

```bash
node bin/nao-orch uninstall-systemd
```

装的时候它会先体检，任一项不通就**拒绝安装并说明缺什么**（注意：体检**不检查**定时单元的启动路径是否存在，所以它能拦住「缺 node/herdr」，拦不住「装了跑不起来」——这正是上面那条限制）。

## 它管什么、不管什么

先说不做的，免得你期待错：

- **不会替你合并代码**。合并、发版、往主干推送这三件事，它一行都碰不到——这是写死在代码里的限制，不是配置项。
- **不会替你判断做得好不好**。测试跑不跑、验收过不过，仍然要人（或 QA 角色）来定。
- **不会读你的会话内容**，也不会自己拆需求。

它只做一件事：**照着队列，把该派的活派出去，然后盯着有没有人接。**

## 三样东西

### 队列与回执

任务的唯一真相是一份队列文件 `docs/queue.jsonl`，一行一个任务。它记录状态、负责人、依赖、验收条件。

配套的是回执：每个任务干完后交一份 `docs/queue/<任务号>.receipt.json`，里面写清楚「改了什么、检查结果、验收条件怎么验的、有什么没做的」。

回执不是给人看的散文，是**有字段的**：缺字段、或者写着「测试通过」却给不出日志路径，都会被直接判红。这样「完成」就不是一句口头结论，而是一份能核的东西。

常用的三条：

```bash
node bin/nao-queue validate                          # 检查队列和回执是否自洽
node bin/nao-queue render                            # 把队列渲染成台账（单向，手改会被覆盖）
node bin/nao-queue receipt-line --id T1              # 输出一行机读结论，给脚本用
```

### 定时派单

`tick` 是一次性的调度动作：扫一遍队列，把能派的派出去，然后退出。它不常驻，所以不怕「进程半死」——挂了就是这一次没跑，下一次重来。

```bash
node bin/nao-orch tick                # 跑一次
node bin/nao-orch board               # 看板：队列现状一眼看完
node bin/nao-orch doctor              # 安装前的体检
node bin/nao-orch install-systemd     # 装成定时任务（默认不启用）
```

一次跑下来它会做四件事：

1. **派**：把该干的活派给对应角色，并叫醒负责人。
2. **等一下**：如果那个人正在忙，就跳过这一条，不打断他。
3. **催一次**：派出去 15 分钟没有任何回应，标成「等待回执」并追问一次——只追问一次，不会变成刷屏。
4. **冻住**：有人接了活、但 90 分钟内代码一点没动，标成「卡住」并通知你来看。

**默认是关的**。要它真的定时跑，得先装定时任务并显式启用：

```bash
node bin/nao-orch install-systemd --enable --interval 2m
```

装完是两分钟一轮。安装是幂等的——装两次不会出现两份配置。想停就 `uninstall-systemd`。

### 看板

`node bin/nao-orch board` 给出队列全貌：各状态各有几条、哪些卡住了（带原因）、在飞的有哪些、最近的回执。

它的数字和队列来自**同一次读取**，所以不会出现「计数和列表对不上」这种半新半旧的情况。要机器读就加 `--json`。

## 给自动化用：`status --json`

如果你的脚本需要知道「现在哪些角色在线、在忙什么」，不必去解析给人看的文字：

```bash
.agents/scripts/nao-fleet.sh status --json
```

它输出结构化结果（在线与否、忙闲三态、在哪个目录、属于哪个仓、能不能投递）。文字版的 `status` 输出**完全没有变**，加这个只是多开一扇门。

## 现在还没做的

- **队列里的任务只到「谁在做」**。做完之后要 QA 验收、要人合并，这段仍然是人的事。
- **看板不做多仓汇总**。一个仓一个看板，跨仓对比还没有。
- **「卡住」只在有人接了活且代码没动时判**。派出去没人接的情况走「催一次」那条，不重复报。

需要这些能力的时候再提——机制本身是按「能做多少、说多少」写的，不会先画大饼。

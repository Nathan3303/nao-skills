# 验收与回执

「干完了」这三个字没有信息量。舰队用两样东西替代它：**回执**（干完交的结论单）和**门禁**（能自动跑的检查）。

## 回执长什么样

默认是短版，四行：

```text
[T1] done | 测试：npm test exit=0 · 128 例 / 0 红 | PR #12
未过项：无
遗留：无
```

有阻塞、有风险、要你拍板时升级为长版，多出「阻塞点 / 风险 / 需决策 / 遗留归口」几段。规矩是：**回执里的数字必须能复现**——写清命令、当时的工作区状态、当时的提交号，而不是「我数了一下」。

## 门禁与闸门不是一回事

- **门禁**（自动）：跑命令，返回 0 才算过。比如「体检返回 0」「测试全绿」。它只判断机器能判断的事。
- **闸门**（人工放行）：某角色动手前必须先拿到一份书面结论。比如设计产物没经你确认，PM 不许派前端开工；PM 没验收通过，研发不许合并。
- 记住这一句就够：**门禁看返回码，闸门看有没有那份书面结论。**

## 什么样的 AC 才算合格

一条一句，五类都要有：主路径、异常、边界、负向闭环（该失败的东西确实失败了）、设计一致性。写完自检一遍——**换个人能不能只凭这句话判定通过与否**。判不了就是没写清。

## 任务完成 ≠ 命令退出 0

命令退出 0 只说明「这次执行没报错」，不代表任务做完。收尾要过四类：产物齐、验证数字齐、遗留项有归口、交接写清。

## 遗留项三出口

不许「先记着」。每条遗留当场归到一个出口：

- **关闭**：已经解决，写明依据。
- **接受**：商量好接受它，写明**到期日**，那天必须再看一次。
- **转办**：变成一个新任务，进待派发队列。

零遗留就显式写「无」，不是留空。

## 什么情况要做复盘

返工一次以上、漏了闸门、出了事故、同类问题第二次、用户投诉——命中任一条，写一份完整复盘：发生了什么、根因、改了什么规矩、怎么防下次。都没命中就写一行。

# 排错

先记住一条：看返回码。`0` 是过，`1` 是执行了但失败，`2` 是用法错，`3` 是前提不满足（命令压根没执行）。

## 体检报红

| 症状 | 多半是 | 怎么办 |
| --- | --- | --- |
| 提示 pi 版本不足 | pi 低于 1.4.0 | 升级 pi；舰队依赖它的多会话能力 |
| `exit 3` / 提示不在终端后端里 | 直接在普通 shell 里跑 | 进 herdr 的会话，在那个 pane 里跑 |
| 提示角色清单解析失败 | `roles.yaml` 被改坏（缩进 / Tab） | 用空格缩进；改回可解析的最小结构 |
| 提示角色卡 frontmatter 不符 | 卡里 `role` 与清单 id 对不上 | 要么改卡、要么改清单，别两边各写一个 |
| 提示交叉引用缺失 | 卡里 `@路径` 指向的文件不在了 | 修路径或删引用 |

失败时体检会自己展开明细；想主动看全量加 `-v`。

## 拉起失败

- 提示必须进入终端后端：同上——先在 pane 里。
- 提示已在运行或同名会话已存在：同一个仓里已经有这个角色的会话。要并行做另一个任务，用 `ensure --task <编号> rd-be`（会话名仍是角色名，任务号只进元数据）；确需重开同一个会话才加 `--force`。
  跨仓同名不会冲突，因为每个仓一个 workspace，不需要设 scope。`--scope` 或 `.agents/fleet-scope` 都已弃用，写了只会打一行提示然后被忽略。
- 提示模型不在白名单：`ensure -m <模型>` 只接受白名单里的取值，换一个或去掉 `-m`。

## 有残留会话

```bash
.agents/scripts/nao-fleet.sh status              # 谁在线、哪些是残留
.agents/scripts/nao-fleet.sh close --task T1 rd-be   # 回收某个派生会话
```

`status` 会在残留行直接给出可执行的回收命令。目标在别的项目里也能回收——定位不到时它会非 0 退出并打印诊断，不会假装回收成功。

## 升级之后

改了版本 pin 后跑 `pi update --extensions`，然后重开会话——角色卡是会话启动时注入的，旧会话里还是旧卡。

重开前先读一遍项目里的 `docs/tasks-state.md`（PM 维护的接续快照），事不丢。

## 还是不行

把 `check -v` 的完整输出贴给 PM 会话，让它判断是机制问题还是环境问题——不要自己改机制文件来「绕过报错」。

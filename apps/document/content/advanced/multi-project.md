# 多项目布局

一个仓一套机制。三个仓就是三套，各自 `pi install --local`、各自 `.pi/settings.json`、各自一份 `AGENTS.md`。

## 为什么要各装一份

机制是项目级的：`.pi/settings.json` 的版本 pin 进仓库，团队 clone 下来就是同款；项目约定写在项目根，AI 每次会话都会读。装在全局会变成「谁先装谁生效」，供不了团队。

## 两个仓同时跑：不用设 scope

会话名形如 `<角色>[<槽位号>]`，不含仓名。区分仓库靠绑定单位：herdr 是「1 workspace / 仓」，workspace 标签取仓基键（仓目录名归一化，如 `api`、`web`）。

所以两个仓的 `rd-be` 各在自己的 workspace 里，互不干扰、也不会互相顶掉。

**注意后端差异**：上面说的是 Herdr TUI 形态（名字按 workspace 隔离，跨仓同名互不影响）。用桌面 app 形态（`NAO_TERMINAL=app`）时，终端名字在 `herdr-core` 里**全局唯一** —— 两个仓同时起同名角色会报 `name_taken`，需要给第二个仓让号（`pm2`…）。详见[手机上看舰队](/advanced/mobile)。

- 不用写任何配置文件：两个仓各自在自己的目录里 `ensure rd-be` 即可。
- 要显式指定目标仓：`ensure rd-be@main` —— `@main` 指 `.agents/fleet.yaml` 所在的主仓，不需要在 manifest 里定义。本仓没有 manifest 时它会直接报错，这时改用 `ensure rd-be@<仓路径>`，或者直接 `cd` 到目标仓再 `ensure`。
- scope 家族已弃用：`--scope`、`--fleet`、`.agents/fleet-scope`、`fleet.yaml` 的 `slug:` 都只打一行提示后被忽略，放置键恒为仓基键；旧文档里 `rd-be@api` 那种会话名不会再生成。
- 同一个仓里的同角色：已在线就跳过（提示「已在运行」，`--force` 才重开）；并行做两个任务用 `--task <编号>` 开派生会话（会话名仍是 `rd-be`、`rd-be2`，任务号只进元数据）。
- `status` 按事实判定归属（本仓、他仓、归属不可判定）。`close <角色>` 按当前仓解析，同名跨仓歧义时直接报错并列出候选，不猜。

## 跨仓并行

- 布局上，herdr 是「1 workspace / 仓 + 1 tab / 角色」，放置键恒为仓基键，所以两个仓的窗格不会混在一起。
- 派生会话用 `--task <编号>` 隔离。并行两个任务时，不要共用同一个常驻会话。
- 需要从 A 仓回收 B 仓的残留会话也可以：`status` 会给出可执行命令；定位不到时非 0 退出并打印诊断，不假装成功。

## 升级：谁先升，谁要跟

机制以 npm 包为准。某个仓升了版本、别的仓没升，是常态——不要用「我这边是好的」来判断别人。每个仓的 `.pi/settings.json` 决定它自己用哪版。

上游发新版时会提示你（只提示，不自动升）。要不要升、什么时候升，你定。升完跑 `pi update --extensions` 并重开会话——角色卡是启动时注入的，旧会话仍是旧卡。

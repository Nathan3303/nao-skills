# 插件选择

舰队不是「装上就能跑」的空壳——它同时要**装 5 个 pi 插件**才凑齐能力。一条命令装全部：

```bash
npx @nathan33/nao-skill plugins install-all
```

想知道装到哪了：`npx @nathan33/nao-skill plugins list`（列出已装 / 缺失）。

## 五个插件

### `intercom` · 包名 `pi-intercom`

**干什么**：会话之间互相发消息、派活、要回执。
**何时用**：自动——你没有直接操作它的时候，它一直在用。
**缺了失去什么**：**整套机制失效**。不能派活、不能要回执、不能回收会话，七个角色退化成七个互不知道对方存在的聊天窗口。这是唯一「必需」的那个。

### `ask-me` · 包名 `pi-ask-me`

**干什么**：把需要你拍板的问题做成带选项的提问面板，收集答案再继续。
**何时用**：开工确认、优先级取舍、要你选 A 还是 B 的地方。
**缺了失去什么**：不是不能干活，而是你的拍板散落在聊天记录里——没有结构化答案，PM 只能靠「我记得你说了……」推进，容易跑偏。

### `subagents` · 包名 `pi-subagents`

**干什么**：在一个会话内部再开子代理，把一段独立工作丢出去并行做。
**何时用**：需要并行检索、并行评审、或把一次性的重活隔离出去时。
**缺了失去什么**：失去会话内的并行能力。舰队本身仍能跑（角色会话是另一套机制），只是每个角色只能一件一件做。

### `web-access` · 包名 `pi-web-access`

**干什么**：让角色能上网查资料，并把抓来的内容落成文件而不是塞进聊天。
**何时用**：PM 查产品形态、架构师对照业界方案、排查依赖问题。
**缺了失去什么**：角色只能凭训练知识判断。做产品与选型时会明显变保守——它们会开始「按常见做法」而不是按实际证据。

### `codegraph` · 包名 `@sean_pedersen/pi-codegraph`

**干什么**：给代码建索引，按符号定位、查调用者、算改动影响面。
**何时用**：改动前定位、判断「改这个会崩哪里」。
**缺了失去什么**：退回全文搜索。大仓里定位会慢很多，也更容易漏掉间接依赖——不致命，但每天都在花你的时间。

## 怎么挑

只装一个的话，装 `intercom`。其余按你实际会用的能力加：会拍板就加 `ask-me`，要查资料就加 `web-access`，仓大就加 `codegraph`，需要并行就加 `subagents`。

装完**重启会话**才生效。

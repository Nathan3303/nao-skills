# 谁派谁

七个人格在一个仓库里干活，最常见的事故不是「干错了」，而是「两个人同时在改」。

## 只有一个人派活

**PM 是唯一调度者。** 派发从它手上出去，回执回到它手上。研发之间不互相指派任务——需要对方配合时，走 PM，或者直接说清「我要什么」，别自己开单。

## 一次派发要带四样

1. **编号**（任务号，用来对账与回收会话）
2. **范围**（改动面：哪些目录、哪些文件归你）
3. **引用路径**（需求文档 / 设计规格 / 报告的路径，让对方自己读，不贴全文）
4. **验收条件编号 + 回执级别**（短回执还是长回执）

少了第四样，回执质量就会随机。

## 正当的横向协作

- **研发 ← 架构师**：实现前确认方案，有疑问就问，别自己改方案。
- **研发 ← 设计师**：界面有歧义看设计规格；规格不够就退回要求补，不要即兴发挥。
- **测试 ← 全部**：复核是它的职责，被复核方应当配合给出可复现的命令，而不是「我这边是好的」。
- 横向沟通可以直连（会话之间可以直接发消息），但**结论要回到 PM**，否则台账上没有记录，等于没发生。

## 常驻会话 vs 派生会话

- **常驻**：`pm`、`rd-be` 这种，被复用，跨多个任务。
- **派生**：`rd-be` 这种，一个任务一个，验收完就回收（任务号不进名字，只进元数据，如 `rd-be2` 是第二个槽位）。并行做两个任务时用派生会话，避免同仓同名冲突。

会话名**不带仓名**（形如 `<角色>[<槽位号>]`）：每个仓一个 workspace，两个仓同时跑同一套角色不会冲突。`--scope` / `.agents/fleet-scope` 已弃用，写了只打一行提示后被忽略；要指定目标仓用 `ensure <角色>@<仓>`。想按任务找会话的记录，用 `nao-fleet.sh logs <角色> --task <编号>`。
